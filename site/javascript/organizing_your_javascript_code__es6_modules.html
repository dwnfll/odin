ES6 Modules

イントロダクション

前のレッスンでモジュールパターンについて学び、変数や関数を整理する助けとして使ってみました。ここ数個のプロジェクトのどこかで、あなたはこう思ったことさえあるかもしれません。「もっと複雑なプロジェクトはどう管理すればいいんだろう?ファイルが長くなりすぎてしまう!コードを整理のために複数のファイルに分割できたら素晴らしいのに!」複数のファイルを使うことは、まさにこの理由から非常に便利です。

モジュールパターンはこれまで、これを管理するのを助ける上で大きな役割を果たしてきましたが、ES6(ES2015と呼ばれることもあります)のリリースにより、実際の「モジュール」が与えられ、そのため「ES6モジュール」や「ESM」としばしば呼ばれるようになりました。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • ES6モジュールとは何で、そこからどうインポート・エクスポートするかを説明します。
  • デフォルトエクスポートと名前付きエクスポートの違いを説明します。
  • CommonJSモジュールとES6モジュールの主な違いを説明します。

ES6モジュール以前: グローバルスコープの問題

ES6以前の例でモダンな構文を使うこと

let/constやアロー関数はES6以前には存在しませんでしたが、ES6以前の例でもそれらを引き続き使っていきます。それらは、このセクションの主な焦点であるグローバルスコープとモジュールパターンに関して、物事がどう機能するかを変えることはありません。

one.jsとtwo.jsという2つのスクリプトがあり、それらをHTMLで別々のスクリプトとしてリンクしているとしましょう。

<script src="one.js" defer></script>
<script src="two.js" defer></script>
// one.js
const greeting = "Hello, Odinite!";
// two.js
console.log(greeting);

HTMLを開くと、greetingがtwo.jsで一度も定義されていないにもかかわらず、"Hello, Odinite!"がコンソールにログ出力されるのが分かります!それは、2つのスクリプトが、あたかもその順序で2行を持つ一つのファイルだけを書いたかのように、同じグローバルスコープに次々と読み込まれたからです。もしtwo.jsのスクリプトタグを先に置いていたら、代わりにgreeting is not definedというエラーが出ていたでしょう。なぜなら、変数を定義する前にconsole.logを実行しようとするからです。

これはつまり、複数のJavaScriptファイルを使っていても、それらは結局同じグローバルスコープを共有することになるということです。私たちのトップレベルの変数は安全ではありません!

ESM以前は、何かをIIFEでラップすることができ、これによりまったく同じように実行されるものの、その中の変数はグローバルではなく、その関数にスコープされるようになりました。

// one.js
(() => {
  const greeting = "Hello, Odinite!";
})();

これで、コンソールにgreeting is not definedというエラーが出るようになります。なぜなら、私たちがログ出力できるgreetingというグローバル変数がもう存在しないからです!しかし、一部のものだけを他のファイルに公開したい場合はどうすればよいでしょうか?私たちのIIFEからそれらのものをグローバルスコープに返しつつ、他のものはプライベートに保つことができます!

// one.js
const greeting = (() => {
  const greetingString = "Hello, Odinite!";
  const farewellString = "Bye bye, Odinite!";
  return greetingString;
})();

これで、グローバル変数greetingは"Hello, Odinite!"を含むことになり、two.jsからの私たちのコードはこれを正常にコンソールにログ出力します。しかし、greetingStringとfarewellStringのどちらもIIFEにローカルであり、グローバルではありません。違いは、greetingStringがIIFEから明示的にreturnされ、greetingに割り当てられているため、関数の外からアクセス可能になっているのに対し、farewellStringはreturnされていないため、two.jsでは完全にアクセス不可能なままだということです。これを通して、私たちは一つのファイルから何を公開し、それに続くすべてのファイルで利用可能にするかを選べます!これが、IIFEがしばしば「モジュールパターン」と呼ばれた理由です。なぜなら、それらは「本物のモジュール」が与えられる前に、複数のファイルにまたがってモジュール式のコードを書けるようにしてくれたからです。

しかし今では、ESMを使えば、この特定の目的のためにIIFEを使う必要はもうありません。

ES6モジュール

ESMを使うと、物事をもう少しコントロールできるようになります。それぞれのファイルはデフォルトで独自のプライベートスコープを持ち、そのファイルから何をエクスポートするかを選べるだけでなく、他のファイルに何をインポートするかも選べます。ですので、何かをエクスポートしたからといって、それが自動的に他の場所で利用可能になるわけではありません。それは、別のファイルでそれを明示的にインポートした場合にのみ、そのファイルで利用可能になります。たくさんのコントロールですね!

モジュールスコープはグローバルスコープではない

ESMを使うとき、それぞれのモジュールは独自のプライベートスコープを持ち、そこでファイル間の伝達にimport/exportを使います。モジュール内のトップレベルの変数は、グローバルスコープではアクセスできません。

インポートとエクスポート

実際にどうやってインポート・エクスポートするのでしょうか?いかにもJavaScriptらしく、インポートとエクスポートには一つだけでなく2つの種類があります: defaultとnamedです。これらは基本的に同じ種類のことを行いますが、ほんの少しだけ違います。同じファイルの中で混ぜて使うことさえできます。

まず、異なるインポート/エクスポートの構文を示しますが、スクリプトをES6モジュールとしてもリンクする必要があるため、このコードはまだ動作しません。それについてはこのセクションの後で扱います。

名前付きエクスポート

以前のone.jsとtwo.jsの例を使いましょう。まず、one.jsからgreetingとfarewellの文字列をエクスポートする必要があります。

何かを名前付きエクスポートとしてエクスポートするには、その宣言の前にexportキーワードを付けるか、ファイルのどこか(通常は末尾)にexport { }を追加します。波括弧の中には、エクスポートしたいものの名前のリストが含まれます。どちらの方法を使っても構いませんし、名前付きエクスポートとして好きなだけたくさんのものをエクスポートできます。

// one.js
export const greeting = "Hello, Odinite!";
export const farewell = "Bye bye, Odinite!";

あるいは、別の行で:

// one.js
const greeting = "Hello, Odinite!";
const farewell = "Bye bye, Odinite!";
export { greeting, farewell };

さて、two.jsでこれらの変数をインポートしましょう!何をインポートするかをコントロールできることを覚えておいてください。ですので、greeting変数だけが必要なら、それだけを単独でインポートできます。もし別のファイルがfarewell変数(あるいは両方)を必要とするなら、そのファイルは必要なものをインポートすればよいのです。インポートしなければ?使えません。名前付きインポートを行うには、インポートしたいものの名前を{ }の中に指定し、インポート元のファイルへのパスを提供する必要があります(後でサードパーティのライブラリをインポートするときには、完全なファイルパスの代わりにライブラリの名前を使うだけで構いません)。

ファイルパスにはテンプレート文字列を使えないことに注意してください。シングルクォートかダブルクォートの文字列だけです。

// two.js
import { greeting, farewell } from "./one.js";

console.log(greeting); // "Hello, Odinite!"
console.log(farewell); // "Bye bye, Odinite!"

名前付きインポート/エクスポートはオブジェクトリテラルとは違う!

名前付きインポート/エクスポートで{ }を使うのは特殊な構文であり、オブジェクトリテラルを宣言することやオブジェクトの分割代入とは何の関係もありません。

export { greeting, farewell };

import { greeting, farewell } from "./one.js";

上記では、greetingとfarewellキーを含むオブジェクトをエクスポートしているわけでも、インポート時にそれらのキーを持つオブジェクトを分割代入しているわけでもありません。私たちは単に名前付きインポート/エクスポートの構文を使っているだけです。

デフォルトエクスポート

名前付きエクスポートとは対照的に、一つのファイルはデフォルトエクスポートを一つしか持てません。この方法でエクスポートされたものには名前が付いていないため、どこかでそれをインポートするときに、どんな名前を付けるか自分で決めることができます。

ファイルから何かをデフォルトエクスポートとしてエクスポートするには、適切な宣言の前にexport defaultを付けてインラインで行うこともできますし、ファイルの末尾で、今度は波括弧を使わずにエクスポートすることもできます。これもまた、どちらの方法でも完全に問題ありません。インラインで変数をデフォルトエクスポートしたい場合、defaultキーワードが変数宣言を置き換えるため、式を直接エクスポートすることになる点に注意してください。

one.jsからgreeting文字列をデフォルトエクスポートしてみましょう。

// one.js
export default "Hello, Odinite!";

あるいは、別の行で:

// one.js
const greeting = "Hello, Odinite!";
export default greeting;

さて、two.jsでその文字列をデフォルトインポートできます。覚えておいてください、デフォルトエクスポートされたものをインポートしているので、好きな名前を付けることができます。one.jsではその変数はgreetingと呼ばれていましたが、望むならtwo.jsでそう呼ぶ必要はありません。デフォルトインポートの際は、名前付きインポート用の波括弧は使いません。

// two.js
import helloOdinite from "./one.js";

console.log(helloOdinite); // "Hello, Odinite!"

同じファイルの中でデフォルトエクスポートと名前付きエクスポートの両方を使うことができます。紛らわしいことに、一つのファイルは複数の名前付きエクスポートを持てるがデフォルトエクスポートは一つしか持てないという事実を除けば、どちらをいつ使うべきかについて、普遍的に合意されたルールは実は特にありません。モジュールから単一のものだけをエクスポートする必要がある場合、デフォルトエクスポートを使うのを好む人もいれば、単一の名前付きエクスポートを使うのを好む人もいます。どちらも機能するので、好きな方を使ってください。あるいはチームで作業しているなら、チームが好む方を使ってください。

one.jsからgreeting文字列をデフォルトエクスポートし、farewell文字列を名前付きエクスポートとしてエクスポートしてみましょう。

// one.js
export default "Hello, Odinite!";
export const farewell = "Bye bye, Odinite!";

それから、two.jsで両方をインポートできます。greeting文字列はデフォルトインポートする必要があり(これは好きな名前を付けられることも意味します)、farewell文字列は名前付きインポートする必要があります。

// two.js
import greeting, { farewell } from "./one.js";

console.log(greeting); // "Hello, Odinite!"
console.log(farewell); // "Bye bye, Odinite!"

エントリーポイント

ESMを使うとき、すべてのJavaScriptファイルを順番にHTMLに追加する代わりに、単一のファイル - エントリーポイント - だけをリンクする必要があります。

<script src="two.js" type="module"></script>

なぜtwo.jsが私たちのエントリーポイントなのでしょうか?さて、上記の例では、two.jsはone.jsから変数をインポートしています。つまりtwo.jsはone.jsに依存しているということであり、次のような依存関係グラフがあることになります:

importer  depends on  exporter
two.js <-------------- one.js

two.jsをモジュールとして読み込むとき、ブラウザはそれがone.jsに依存していることを見て、そのファイルからもコードを読み込みます。もし代わりにone.jsをエントリーポイントとして使っていたら、ブラウザはそれが他のどのファイルにも依存していないことを見て、それ以外は何もしなかったでしょう。私たちのtwo.jsからのコードは使われず、何もログ出力されなかったでしょう!

もし何かをエクスポートする別のファイルthree.jsがあり、two.jsがそこからインポートしていたら、two.jsは依然として私たちのエントリーポイントであり、今度はone.jsとthree.jsの両方に依存することになります。

two.js <-------------- one.js
              └------- three.js

あるいは、two.jsの代わりに、one.jsがthree.jsからインポートしているとしましょう。その場合でも、two.jsは依然として私たちのエントリーポイントであり、one.jsを通して間接的にthree.jsに依存することになります。

two.js <-------------- one.js <-------------- three.js

ブラウザが追加のファイルの依存関係を私たちの代わりに処理してくれるため、スクリプトタグは一つだけで済んだことに注意してください。また、type="module"が自動的にスクリプトの実行を遅延してくれるため、defer属性を追加する必要もありませんでした。

もしレッスンの最初にあったIIFEの例で一緒に手を動かしていたなら、JavaScriptをimportとexportを使うように書き直し、エントリーポイントだけをモジュールスクリプトとしてリンクしてみてください。ブラウザのセキュリティ上の理由から、ブラウザでHTMLファイルを直接開いた場合、ES6モジュールは読み込めません。ですので、まだ使っていなければ、Visual Studio CodeのLive Preview拡張機能を必ず使ってください。

CommonJS

これまでの道のりで、importやexportの代わりにrequireやmodule.exportsのような構文を使う、CommonJS(CJS)と呼ばれるものに出会ったことがあるかもしれません。Foundationsコースの私たちのJavaScript演習でこれを見たのを覚えているかもしれません(ずいぶん遠くまで来ましたね)!これはNode.jsで使うために設計されたモジュールシステムで、ESMとは少し異なる働き方をし、ブラウザが理解できるものではありません。

CJSは今でもNode.jsのコードでかなり多く使われていますが、近年ではNode.jsでもESMが人気を集めてきています。今のところ、私たちはブラウザで実行するコードを書くことに焦点を当てているので、ESMに時間を費やしていきます。もしFull Stack JavaScriptパスウェイを進めているなら、Node.jsのコースで後ほどCJSについてさらに詳しく扱います。

課題

  1. いつも通り、JavaScriptのキーワードや概念について最も学べるのはMDNのドキュメントからなので、exportについてのドキュメントとimportについてのドキュメントをチェックしてみてください。エイリアスや名前空間のインポートなど、このレッスンで扱わなかった、それらについての小さな追加事項がいくつかあります。
