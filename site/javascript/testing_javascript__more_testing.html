More Testing

イントロダクション

テストにおける重要な基本概念の一つが、分離(isolation)です。一度に一つのメソッドだけをテストすべきであり、ある関数のためのテストは、理想的には、外部の関数が正しく振る舞うことに依存すべきではありません。特に、その関数が他の場所でテストされている場合はなおさらです(とはいえ、どんな理想もそうであるように、これが常に可能あるいは実用的とは限りません)。この主な理由は、あなたのテストが失敗したとき、できるだけ早くその失敗の原因を絞り込めるようにしたいからです。もしいくつもの関数に依存するテストがあると、正確に何がうまくいっていないのかを判断するのが難しくなることがあります。

純粋関数

コードを書く際にTDDを使うことにはたくさんの利点があります。最大の利点の一つは、最初はそれほど明白ではありません - それは、より良いコードを書く助けとなるということです。初期のプロジェクトのいくつかを振り返ってみると、おそらく、すべてがいかに密結合であるかに気づくでしょう。あなたのすべての関数は、コードの他の部分にある関数への参照を含んでおり、コード全体がDOMメソッドやconsole.log()で埋め尽くされています。

密結合なコードはテストしづらいものです!次のような関数のためにテストを書こうとすることを想像してみてください:

function guessingGame() {
  const magicNumber = 22;
  const guess = prompt('guess a number between 1 and 100!');
  if (guess > magicNumber) {
    alert('YOUR GUESS IS TOO BIG');
  } else if (guess < magicNumber) {
    alert('YOUR GUESS IS TOO SMALL');
  } else if (guess == magicNumber) {
    alert('YOU DID IT! 🎉');
  } else {
    return 'INVALID INPUT';
  }
}

これをテスト可能にするには、起こっているすべての異なることを分割する必要があります。まず、promptとalert関数はブラウザに組み込まれているため、テストする必要はありません。それらは私たちのプログラムにとって外部のものであり、それらを書いた人がすでにテストしています。私たちが実際にテストする必要があるのは数値のロジックであり、それを他の関数から解きほぐすことで、ずっと簡単になります:

function evaluateGuess(magicNumber, guess) {
  if (guess > magicNumber) {
    return 'YOUR GUESS IS TOO BIG';
  } else if (guess < magicNumber) {
    return 'YOUR GUESS IS TOO SMALL';
  } else if (guess == magicNumber) {
    return 'YOU DID IT! 🎉';
  } else {
    return 'INVALID INPUT';
  }
}

function guessingGame() {
  const magicNumber = 22;
  const guess = prompt('guess a number between 1 and 100!');
  const message = evaluateGuess(magicNumber, guess);
  alert(message);
}

guessingGame();

この例では、私たちが本当にテストする必要があるのはevaluateGuess関数だけであり、これは明確な入力と出力を持ち、外部の関数を一切呼び出さないため、テストするのがずっと簡単です。この実装はまた、拡張するのがずっと簡単なので、ずっと素敵でもあります。もしpromptとalertをDOMを操作するメソッドに切り替えたいなら、今ならそれをより簡単に行うことができますし、ユーザーに複数回推測させることでゲームをより高度にしたいなら、それもより簡単です。

もしこのプログラムをTDDで書いていたら、最初から2つ目の例のような見た目になっていた可能性が非常に高いでしょう。テスト駆動開発は、純粋関数を書くことを促すため、より良いプログラムのアーキテクチャを促進してくれます。

モッキング

「密結合なコード」の問題には、2つの解決策があります。1つ目、そして最良の選択肢は、上記で行ったように、コードからそれらの依存関係を取り除くことですが、それが常に可能とは限りません。2つ目の選択肢はモッキングです - あなたが望む通りに正確に振る舞う、関数の「偽の」バージョンを書くことです。例えば、DOMの入力から情報を取得する関数をテストしているなら、テストを実行するためだけにウェブページをセットアップし、入力に何かを動的に挿入する必要は本当はないはずです。モック関数を使えば、常に特定の値を返す、入力を取得する関数の偽のバージョンを作成し、あなたのテストでそれを使うことができます。
