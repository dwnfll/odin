Recursive Methods

日本語訳

← javascript

Learn how making a function call itself can be helpful for making big problems into smaller problems

イントロダクション

再帰とは、関数が自分自身を呼び出すという考え方です。それがすべてです。これは、大きな問題を取り、それをどんどん小さな部分に分解していき(「分割統治」)、何らかの答えが得られてチェーン全体が巻き戻されるまで、その解決策を元の関数に戻し続けるために使われます。

分割統治アルゴリズムについてのWikipediaの項目より:

コンピューターサイエンスにおいて、分割統治(D&C)は、多分岐の再帰に基づく重要なアルゴリズム設計パラダイムです。分割統治アルゴリズムは、問題を、直接解けるほど単純になるまで、同じ(あるいは関連する)種類の2つ以上の部分問題に再帰的に分解することで機能します。それから、部分問題への解答が組み合わされ、元の問題への解答が与えられます。

再帰を使う正しい方法と間違った方法もあります。実のところ、再帰的に解決できるどんな問題も、あなたがすでに知っていて愛用しているイテレータを使って解決することもできます。もし「ここでは単にwhileループを使えばよかったのでは?」と自分に問いかけているなら、おそらくそうすべきだったのでしょう。問題に対して再帰的な解決策を使うことになることはそれほど多くありませんが、それがいつ良いアイデアになり得るかについての感覚はつかんでおくべきです。一部の問題はまた、あまりにも多くの部分に分解されすぎて、あなたのコンピューターのメモリを完全に圧迫してしまいます。そこにはバランスがあります。

この短いレッスンでは、いつ、どうやって再帰を使うかについてさらに学ぶ機会があり、それから次のプロジェクトで、それを実際に応用する機会があります(実際に試してみるまでは、おそらく本当には身につかないでしょうから)。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • なぜ再帰が大きな問題を解決するのに役立つテクニックなのかを理解します。
  • 再帰的な解決策を使うことの限界を認識します。
  • どんな種類の問題が、再帰の代わりにループを使う方がうまく解決できるかを見分けます。
  • 「再帰の深さ」という概念が何を意味するかを学びます。
  • 「スタックオーバーフロー」とは何か(ウェブサイトの方ではなく、概念としての)を理解します。
  • なぜスタックオーバーフローが再帰の問題に関連するのかを学びます。

    デバッガーを使おう!

    再帰関数の中で何が起きているかを層ごとに追跡しようとするのは、かなり難しいことがあります。そんな苦労をする必要はありません!もしまだ、いくつかの問題を解決する際にデバッガーを活用していなければ(もしそうなら、多くのものを見逃してきたことになります!)、コードフローのナビゲートをずっと簡単にしてくれるデバッガーに慣れておくのに、今ほど良いタイミングはありません。
