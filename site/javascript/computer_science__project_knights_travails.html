Lets build Knights Travails

イントロダクション

これで、DFS(深さ優先探索)とBFS(幅優先探索)のプロになりました。それでは、これらの探索アルゴリズムを実際の問題に使ってみましょう。

このプロジェクトでは、二分木に似ている(が同一ではない)データ構造である、グラフを使う必要があります。グラフとは何かについての良い入門として、Khan Academyの「Describing Graphs」を参照してください。グラフの表現方法についてのセクションも忘れずに見ておいてください。コード内でグラフを実際にどう実装するかについて、良いアイデアが得られるはずです。

十分な手数があれば、標準的な8x8のチェス盤上のナイトは、どのマスからでも他のどのマスへも移動できます。ナイトの基本的な動きは、前に2マス進んで横に1マス動くか、前に1マス進んで横に2マス動くかのどちらかです。ナイトはどの方向を向いていてもかまいません。

この問題では、チェス盤はグラフとして表現できます:

盤上の各マスは、ノード(または頂点)です。 あるマスからのナイトの有効な移動は、頂点同士の間の辺(またはつながり)を表します。 つまり、ナイトの移動における最短経路を見つける問題は、グラフの走査問題になります。目標は、グラフ(チェス盤)を走査して、2つのノード(開始位置と終了位置)の間の最短経路を見つけることです。

頂点と辺

このグラフにおける頂点は、チェス盤上で取り得るそれぞれの位置であり、[x, y]のような座標のペアで表されます。ここでxとyは0から7の間の値です。 辺は、頂点間でのナイトの有効な移動です。例えば、[0,0]から、ナイトは[2,1]や[1,2]などに移動できます。これらの移動はそれぞれ、頂点[0,0]と、他の到達可能な頂点との間のつながりを表します。

グラフの表現

この問題を解く際、頂点と辺を持つグラフオブジェクトを明示的に作成する必要はありません。代わりに、グラフは暗黙的なものと考えることができます。ナイトは特定の頂点から始まり、アルゴリズムは盤を走査しながら、他の頂点(盤上の位置)への可能なすべての移動(辺)を動的に探索していきます。

課題

あなたの課題は、あるマスから別のマスへ移動する最短経路を、ナイトが途中で止まるすべてのマスを出力することによって示す、knightMoves関数を作ることです。

盤は2次元座標を持っていると考えることができます。そのため、関数の呼び出しは次のようになります:

knightMoves([0,0],[1,2]) // returns [[0,0],[1,2]]

複数の最短経路

最速の経路が複数存在することもあります。その例を以下に示します。ルールに従っていて、可能な限り最短の経路になっている限り、どの答えも正解です。

  • knightMoves([0,0],[3,3])は[[0,0],[2,1],[3,3]]または[[0,0],[1,2],[3,3]]を返すことがあります。
  • knightMoves([3,3],[0,0])は[[3,3],[2,1],[0,0]]または[[3,3],[1,2],[0,0]]を返すことがあります。
  • knightMoves([0,0],[7,7])は[[0,0],[2,1],[4,2],[6,3],[4,4],[6,5],[7,7]]または[[0,0],[2,1],[4,2],[6,3],[7,5],[5,6],[7,7]]、あるいは他にありうる最短経路を返すことがあります。
  1. 盤とナイトのルールについて考え、必ずそれに従うようにしてください。
  2. どのマスからも、複数の移動が可能です。それらを扱うことができるデータ構造を選んでください。盤の外に出るような移動は許可しないでください。
  3. ここではDFSとBFSのどちらも有効ですが、それぞれがどのように機能するかをよく考えてください。どちらか一方は、終わりのない循環にはまり込んでしまう可能性への対処が必要になります。

  4. 選んだ探索アルゴリズムを使って、開始のマス(またはノード)と終了のマスの間の最短経路を見つけてください。その経路全体がどのようなものかを出力してください。例えば:

    > knightMoves([3,3],[4,3])
=> You made it in 3 moves!  Here's your path:
  [3,3]
  [4,5]
  [2,4]
  [4,3]
