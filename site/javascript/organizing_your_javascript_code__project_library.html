Library 日本語訳

Library

イントロダクション

前のレッスンの「Book」の例を拡張して、小さなLibraryアプリに変えていきましょう。

課題

  1. まだであれば、スケルトンのHTML/CSS/JSファイルを持つプロジェクトのGitリポジトリをセットアップしてください。ここから先は、あなたがすでにこれを行ったものと仮定していきます。

  2. あなたのすべてのbookオブジェクトは配列に保存されることになるので、bookのためのコンストラクタが必要です。それから、いくつかの引数を受け取り、それらの引数からbookを作成し、その新しいbookオブジェクトを配列に保存できる別の関数を、(コンストラクタの中ではなく)スクリプトに追加してください。また、あなたのすべてのbookオブジェクトは一意のidを持つべきであり、これはcrypto.randomUUID()を使って生成できます。これにより、それぞれのbookが一意で安定した識別子を持つことが保証され、bookが削除されたり並べ替えられたりしたときの問題を防げます。あなたのコードは次のようなものになるはずです(ここでは関数のパラメータを省いた基本的な骨組みだけを示しています):

    const myLibrary = [];

function Book() {
  // the constructor...
}

function addBookToLibrary() {
  // take params, create a book then store it in the array
}

  3. 配列をループして、それぞれのbookをページに表示する関数を書いてください。何らかのテーブルに表示しても構いませんし、それぞれを独自の「カード」に表示しても構いません。表示を確認できるように、今のところは手動で配列にいくつかのbookを追加しておくと役立つかもしれません。 - bookのデータをまず配列に保存するよりも、bookの表示を直接操作する方が簡単に見えるかもしれませんが、ここから先は、これらの責務を分けて考えるべきです。この概念については後でさらに深く掘り下げますが、アプリケーションを開発する際、私たちは同じ基盤となるデータを使って、さまざまな方法で要素(私たちのlibraryやそのbookのような)を再作成できる柔軟性を望みます。したがって、ユーザーにbookを表示するためのロジックと、すべての情報を保持するbookの構造体は、別個のものとして考えてください。この分離により、あなたのコードの保守性と拡張性が向上します。

  4. ユーザーが新しいbookの詳細(著者、タイトル、ページ数、読んだかどうか、その他あなたが望むもの)を入力し、それをlibraryに追加できるようにするフォームを表示する「New Book」ボタンを追加してください。このフォームをどう表示するかはあなた次第です。例えば、サイドバーにフォームを表示したいと思うかもしれませんし、<dialog>タグを使ってダイアログとモーダルを探ってみたいと思うかもしれません。どうやるにせよ、フォームを送信すると期待通りのことが起こらないという問題に、おそらく遭遇するでしょう。それは、submitのinputがデフォルトでデータをサーバーに送信しようとするからです。ここでevent.preventDefault();が役立ちます。event.preventDefaultのドキュメントをチェックして、この問題をどう解決できるか見てみてください!
  5. それぞれのbookの表示に、そのbookをlibraryから削除するボタンを追加してください。 - あなたのDOM要素を、何らかの方法で実際のbookオブジェクトと関連付ける必要があります。一つの簡単な解決策は、それぞれのbookオブジェクトの一意のidに対応するdata属性を与えることです。
  6. それぞれのbookの表示に、そのreadステータスを変更するボタンを追加してください。 - これを実現するには、bookインスタンスのreadステータスを切り替えるBookプロトタイプ関数を作成したいところです。

永続的なストレージは不要です

ページの再読み込みの間、情報を保存するための何らかのストレージを追加する必要はありません。
