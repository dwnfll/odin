Covers object constructors and prototypal inheritance

オブジェクトコンストラクタ

すべてのオブジェクトの内容をオブジェクトリテラルで手動で書き出すことは、必ずしも現実的ではありません。複数作る必要のある特定の種類のオブジェクトがある場合、それらを作成するより良い方法は、オブジェクトコンストラクタを使うことです。これは実は単なる関数です:

function Player(name, marker) {
  this.name = name;
  this.marker = marker;
}

唯一の違いは、newキーワードを使って関数を呼び出すことでそれを使うということです:

const player = new Player("steve", "X");
console.log(player.name); // "steve"

これは、(newキーワードなしで)Player("steve", "X")を呼び出すのとは同じではありません。newと共に関数を呼び出すと、新しいオブジェクトが作られ、その関数の中のthisがそのオブジェクトを指すようになり、そのオブジェクトが関数の.prototypeプロパティから継承するようになります(これについては後ほど詳しく説明します)。それから、新しいオブジェクトが返されます(コンストラクタ関数の中でreturnの値を指定していなくても)。

オブジェクトリテラルの方法で作成されたオブジェクトと同様に、オブジェクトに関数を追加できます:

function Player(name, marker) {
  this.name = name;
  this.marker = marker;
  this.sayName = function() {
    console.log(this.name);
  };
}

const player1 = new Player("steve", "X");
const player2 = new Player("also steve", "O");
player1.sayName(); // logs "steve"
player2.sayName(); // logs "also steve"

コンストラクタを保護する

コンストラクタは間違ってnewを使わずに呼び出されてしまうことがあり、それは新しいオブジェクトやthisのバインディングに関することを何も行わないため、追跡しづらいエラーを引き起こしてしまいます。そのため、コンストラクタを保護すべきです。次のようにnew.targetメタプロパティを使うことができ、これはPlayerがnewなしで呼び出されるとエラーを投げます:

function Player(name, marker) {
  if (!new.target) {
    throw Error("You must use the 'new' operator to call the constructor");
  }
  this.name = name;
  this.marker = marker;
  this.sayName = function() {
    console.log(this.name);
  };
}

演習

「Book」オブジェクトを作るためのコンストラクタを書いてください。これは次のプロジェクトで再び扱います。あなたのbookオブジェクトは、本のtitle、author、pagesの数、そしてその本をread(読んだ)かどうかを持つべきです。

コンストラクタの中に、次のように本の情報を報告できるinfo()関数を入れてください:

console.log(theHobbit.info()); // "The Hobbit by J.R.R. Tolkien, 295 pages, not read yet"

console.log vs return

デモのためにconsole.log()を呼び出す関数の例を使っていますが、関数に直接ものをログ出力させるよりも、一般的にはreturnで値を返すようにする方が賢明です。そうすることで、その関数が何をするかに縛られることなく、値を好きなところに渡すことができます。常に値をログ出力したいとは限らないからです。

プロトタイプ

JavaScriptでは、すべてのオブジェクトは別のオブジェクトにリンクでき、これはそのオブジェクトのプロトタイプ(その[[Prototype]]としても知られています)と呼ばれます。あるプロパティやメソッドがオブジェクト自体に見つからない場合、JavaScriptはそれを[[Prototype]]の中で探します。

これを分解してみましょう。

1. JavaScriptのすべてのオブジェクトは[[Prototype]]を持っている

ここはかなり単純な文ですね!JavaScriptのすべてのオブジェクトは[[Prototype]]を持っています。ですので、例えば、前に出てきたplayer1とplayer2オブジェクト(Player(name, marker)オブジェクトコンストラクタで作成されたもの)も[[Prototype]]を持っています。さて、[[Prototype]]を持つとはどういうことでしょうか?そもそも、あるオブジェクトの[[Prototype]]とは何なのでしょうか?

2. [[Prototype]]は別のオブジェクトである

この文もかなり単純に見えますね![[Prototype]]は単なる別のオブジェクトです - 繰り返しになりますが、player1やplayer2オブジェクトのようなものです。[[Prototype]]オブジェクトはプロパティや関数を持つことができ、それはちょうどPlayerオブジェクトが.name、.markerのようなプロパティや.sayName()のような関数を持っているのと同じです。

3. …そして元のオブジェクトはそれから継承し、その[[Prototype]]のすべてのメソッドとプロパティにアクセスできる

ここで「元のオブジェクト」とは、player1やplayer2のようなオブジェクトを指します。これらのオブジェクトは「継承する」、つまり言い換えると、これらのオブジェクトは、それらが定義されている場合、[[Prototype]]のプロパティや関数にアクセスできると言われます。例えば、もし[[Prototype]]に.sayHello()関数が定義されていれば、player1はまるでそれが自分自身の関数であるかのように、その関数にアクセスできます - player1.sayHello()というようにです。しかし、.sayHello()関数を呼び出せるのはplayer1だけではありません。player2もそれを呼び出すことができます。なぜなら、それはplayer2の[[Prototype]]にも定義されているからです!それがどう機能するか、そして自分自身でどうやってこれを行えるかの詳細を知るために、読み進めてください!

オブジェクトの[[Prototype]]にアクセスする

概念的には、オブジェクトの[[Prototype]]が何であるかを知った、あるいは少なくともイメージできるようになったと感じているかもしれません。しかし、あるオブジェクトのプロトタイプが何であるかを、どうやって知る、あるいは実際に見るのでしょうか?見てみましょう。以下のコードをブラウザの開発者コンソールで実行してみることができます。(前に出てきたplayer1とplayer2オブジェクトを作成しておいてください!)

Object.getPrototypeOf(player1) === Player.prototype; // returns true
Object.getPrototypeOf(player2) === Player.prototype; // returns true

さて、このコードを理解するために、先ほどの3つのポイントを使ってみましょう:

  1. JavaScriptのすべてのオブジェクトは[[Prototype]]を持っている:
    • オブジェクトに対してObject.getPrototypeOf()関数を使うことで、そのオブジェクトの[[Prototype]]をチェックできます。例えばObject.getPrototypeOf(player1)のようにです。
    • Object.getPrototypeOf(player1)は、Playerコンストラクタの.prototypeプロパティにあるオブジェクト(つまりPlayer.prototype)を返します。
  2. [[Prototype]]は別のオブジェクトである…
    • Player.prototypeの値にはオブジェクトが含まれています。
    • Player.prototypeへの参照は、Playerオブジェクトのすべてのインスタンスに、その[[Prototype]]として保存されています。
    • したがって、player1の[[Prototype]]を取得し、Player.prototypeにあるオブジェクトとの参照の等価性をチェックすると、trueが返されます。
  3. …そして元のオブジェクトはそれから継承し、その[[Prototype]]のすべてのメソッドとプロパティにアクセスできる:
    • ですので、Player.prototypeに定義されたどんなプロパティやメソッドも、作成されたPlayerオブジェクトで利用可能になります!

最後のサブ項目には、もう少し説明が必要です。「プロトタイプに」定義するとはどういうことでしょうか?次のコードを考えてみてください:

Player.prototype.sayHello = function() {
  console.log("Hello, I'm a player!");
};

player1.sayHello(); // logs "Hello, I'm a player!"
player2.sayHello(); // logs "Hello, I'm a player!"

ここでは、Player.prototypeオブジェクトに「対して」.sayHello関数を定義しました。すると、それがplayer1とplayer2オブジェクトが使えるようになりました!同様に、オブジェクトの[[Prototype]](これはPlayer.prototypeです)に定義することで、すべてのPlayerオブジェクトで使いたい他のプロパティや関数を付け加えることができます。

.__proto__

一部のドキュメントやコードベースでは、Object.getPrototypeOf()やObject.setPrototypeOf()を使う代わりに、オブジェクトの[[Prototype]]を取得・設定するために.__proto__が使われているのを見かけるかもしれません。これは歴史的な理由によるもので、.__proto__は非標準で非推奨のアプローチであるため、オブジェクトの[[Prototype]]にアクセスするためにこれを使うことは推奨されません。

Object.getPrototypeOf() と .prototype の違い

よくある混乱の原因の一つは、コンストラクタ関数の.prototypeプロパティを扱うことから来ます。

.prototypeは関数のプロパティで、その関数がnewと共に呼び出されたときに、新しいオブジェクトインスタンスの[[Prototype]]が何に設定されるかを決定します。.prototypeは、オブジェクトの[[Prototype]]にアクセスするためのものではありません - それはObject.getPrototypeOf()のためのものです。

プロトタイプ継承

さて、あなたにも疑問があるかもしれません - オブジェクトの[[Prototype]]にはどんな用途があるのでしょうか?プロトタイプにプロパティや関数を定義する目的は何なのでしょうか?

これは2つの理由に絞り込むことができます:

  1. メモリを節約するために、すべてのオブジェクトに共通するプロパティや関数をプロトタイプに定義できます。すべてのプロパティや関数を定義することは、特に多くの共通のプロパティや関数があり、多くのオブジェクトが作成される場合、多くのメモリを消費します。オブジェクトがアクセスできる、一元化された共有オブジェクトにそれらを定義することで、メモリを節約できます。
  2. 2つ目の理由は、JavaScriptのプロトタイプ継承の仕組みを通して、複数のオブジェクトが振る舞いを共有・再利用できるようにすることです。例えば、player1やplayer2がPlayer.prototypeに定義された.sayHelloのような関数にアクセスできるようにすることです。

では、次のことを試してみましょう:

// Player.prototype.__proto__
Object.getPrototypeOf(Player.prototype) === Object.prototype; // true

// Output may slightly differ based on the browser
player1.valueOf(); // Output: Object { name: "steve", marker: "X", sayName: sayName() }

この.valueOf関数は何で、私たちが定義していないのにどこから来たのでしょうか?これは、Object.getPrototypeOf(Player.prototype)がObject.prototypeという値を持っていることの結果として現れます!これはつまり、Player.prototypeがObject.prototypeから継承しているということです。この.valueOf関数は、.sayHelloがPlayer.prototypeに定義されているのとちょうど同じように、Object.prototypeに定義されています。

この.valueOf関数がObject.prototypeに定義されているということを、どうやって知るのでしょうか?.hasOwnPropertyという別の関数を利用します:

player1.hasOwnProperty("valueOf"); // false
Object.prototype.hasOwnProperty("valueOf"); // true

では、この.hasOwnProperty関数はどこから来たのでしょうか?素早いチェックが助けになります:

Object.prototype.hasOwnProperty("hasOwnProperty"); // true

基本的に、これがJavaScriptがプロトタイプを利用する仕組みです。あるオブジェクトはその[[Prototype]]オブジェクトから継承し、それはさらに自分自身の[[Prototype]]から継承する、というように続いていき、こうしてチェーンが形成されます。プロトタイプを使ったこの種の継承は、そのためプロトタイプ継承と名付けられています。JavaScriptは、あるオブジェクトにどのプロパティが存在する(あるいは存在しない)かを把握し、そのプロパティや関数を見つけるためにチェーンを次のようにたどり始めます:

  1. .valueOf関数はplayer1オブジェクトの一部でしょうか?いいえ、違います。(覚えていますか、Playerオブジェクトの一部なのはname、marker、sayNameプロパティだけです。)
  2. その関数はplayer1の[[Prototype]](つまりObject.getPrototypeOf(player1)の値、すなわちPlayer.prototype)の一部でしょうか?いいえ、その一部なのは.sayHello関数だけです。
  3. では、それはObject.getPrototypeOf(Player.prototype)(=== Object.prototype)の一部でしょうか?はい、.valueOfはObject.prototypeに定義されています!

しかし、このチェーンは永遠に続くわけではなく、もしすでにObject.getPrototypeOf(Object.prototype)の値をログ出力してみたことがあれば、それがnullであることに気づいたはずです。これがチェーンの終わりを示しています。そして、このチェーンの終わりで、特定のプロパティや関数が見つからない場合、undefinedが返されます。

注意:

  1. すべてのプロトタイプオブジェクトは、直接的にであれ間接的にであれ、デフォルトでObject.prototypeから継承します。
  2. あるオブジェクトのObject.getPrototypeOf()の値は一つの値しか持てません(オブジェクトは複数の[[Prototype]]を持つことはできません)。

プロトタイプ継承のための推奨される方法

さて、プロトタイプ継承をどう利用すればよいでしょうか?それを使うために何をする必要があるでしょうか?Object.getPrototypeOf()を使ってオブジェクトの[[Prototype]]を「取得」あるいは表示するのと同じように、Object.setPrototypeOf()を使ってそれを「設定」、あるいは変更できます。Playerの例にPersonオブジェクトコンストラクタを追加し、PlayerがPersonから継承するようにすることで、これがどう機能するか見てみましょう!

function Person(name) {
  this.name = name;
}

Person.prototype.sayName = function() {
  console.log(`Hello, I'm ${this.name}!`);
};

function Player(name, marker) {
  this.name = name;
  this.marker = marker;
}

Player.prototype.getMarker = function() {
  console.log(`My marker is "${this.marker}"`);
};

Object.getPrototypeOf(Player.prototype); // returns Object.prototype

// Now make `Player` objects inherit from `Person`
Object.setPrototypeOf(Player.prototype, Person.prototype);
Object.getPrototypeOf(Player.prototype); // returns Person.prototype

const player1 = new Player("steve", "X");
const player2 = new Player("also steve", "O");

player1.sayName(); // Hello, I'm steve!
player2.sayName(); // Hello, I'm also steve!

player1.getMarker(); // My marker is "X"
player2.getMarker(); // My marker is "O"

このコードから、Playerが継承する元となるPersonを定義したこと、そして作成されたPlayerオブジェクトが、2つの別々の.prototypeオブジェクトに定義されているにもかかわらず、.sayNameと.getMarkerの両方の関数にアクセスできることが分かります!これはObject.setPrototypeOf()関数の使用によって可能になっています。これは2つの引数を取ります - 1つ目は継承する側、2つ目は1つ目の引数に継承させたい相手です。これにより、作成されたPlayerオブジェクトが、プロトタイプチェーンを通して.sayNameと.getMarker関数にアクセスできるようになります。

注意:

Object.setPrototypeOf()を使ってプロトタイプ継承をセットアップするのは簡単な方法に思えますが、プロトタイプチェーンは、どんなオブジェクトも作成する前にこの関数を使ってセットアップされなければなりません。オブジェクトがすでに作成された後でsetPrototypeOf()を使うと、パフォーマンスの問題を引き起こす可能性があります。

一つ警告です…これは機能しません:

Player.prototype = Person.prototype;

Player.prototypeとPerson.prototypeの両方が、メモリ上でまったく同じオブジェクトになってしまいます。これはつまり、Player.prototypeに加えられた変更はPerson.prototypeにも影響してしまうということで、これは意図した振る舞いではありません。その代わり、私たちはPlayer.prototypeとPerson.prototypeを同じオブジェクトにするのではなく、Player.prototypeがPerson.prototypeから継承するようにすべきです。もう一つ例を考えてみましょう:

function Person(name) {
  this.name = name;
}

Person.prototype.sayName = function() {
  console.log(`Hello, I'm ${this.name}!`);
};

function Player(name, marker) {
  this.name = name;
  this.marker = marker;
}

// Don't do this!
// Use Object.setPrototypeOf(Player.prototype, Person.prototype)
Player.prototype = Person.prototype;

function Enemy(name) {
  this.name = name;
  this.marker = "^";
}

// Not again!
// Use Object.setPrototypeOf(Enemy.prototype, Person.prototype)
Enemy.prototype = Person.prototype;

Enemy.prototype.sayName = function() {
  console.log("HAHAHAHAHAHA");
};

const carl = new Player("carl", "X");
carl.sayName(); // Uh oh! this logs "HAHAHAHAHAHA" because we edited the sayName function!

もしこの例でObject.setPrototypeOf()を使っていれば、Playerの関数を変更することなく、安全にEnemy.prototype.sayName関数を編集できていたでしょう。
