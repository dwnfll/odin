前のレッスンでは、ES6モジュールと、モジュール間で何かをインポート・エクスポートするために使われる構文について学びました。より大きく、より複雑なアプリケーションを構築していく中で、すべてを自分自身で書きたいとは思わないかもしれません。他の人が書いたヘルパー関数から、アプリケーションを構築するための完全なフレームワークまで、さまざまな範囲の、何かを私たちの代わりに処理してくれるサードパーティのコードをインポートしたいと思うかもしれません。これらのサードパーティのパッケージを簡単に見つけてインポートするには、npmのようなパッケージマネージャの助けが必要です!

npm

npm(大文字はありません!)はパッケージマネージャです - プラグイン、ライブラリ、その他のツールの巨大なリポジトリであり、これらのツール(「パッケージ」と呼ぶもの)をアプリケーションにインストールするために使えるコマンドラインツールを提供してくれます。それから、インストールしたすべてのパッケージのコードがローカルにあり、それを自分自身のファイルにインポートできるようになります。自分自身のコードをnpmに公開することさえできます!

Foundationsコースで、JavaScriptの演習を行うためにJestテストフレームワークをインストールする際に、npmをインストールしたことを覚えているかもしれません。おかしなことに、npmは「Node Package Manager」の略ではありません。よくそう呼ばれているのを見かけるとしてもです。

もしFull Stack Ruby on Railsパスウェイにいるなら、すでに別のJavaScriptパッケージマネージャであるYarnを紹介されているはずです。このコースでは、npmを使っていきます。

私たちのアプリケーションがより複雑になり、ますます多くのファイルが必要になるにつれて(それが私たち自身のファイルであれ、インストールしてインポートしたパッケージからのファイルであれ)、これらの依存関係の多くを管理することは、特にパッケージが更新されたときに、かなり面倒になることがあります。これは、ブラウザにダウンロードさせるためにたくさんのJavaScriptファイルを送ることになるかもしれないと考えると、さらに面倒になることがあります。次のレッスンでは、バンドラーを紹介します。これは、作業しやすい複数のファイルを書いてから、それらを、最終的にブラウザに代わりに送られる、より少ない小さなファイルにまとめる(バンドルする)ことを可能にしてくれるツールです。

package.json

npmはpackage.jsonと呼ばれるファイルを中心に回っています。これは、プロジェクトの名前や、依存関係とそのバージョン番号などの情報を含むJSONファイルです。npmはこのファイルを読み取り、リストされたすべての依存関係を正しいバージョンでインストールしたり、npmスクリプトとして設定したコマンドを実行したりといったことを行うことができます(npmスクリプトについては後のレッスンで扱います)。

例えば、これは、(あなたが今まさに取り組んでいるこのレッスンを含む)すべてのレッスンファイルを収めている、The Odin Projectのカリキュラムリポジトリのpackage.jsonファイルです:

{
  "name": "curriculum",
  "version": "1.0.0",
  "description": "[The Odin Project](https://www.theodinproject.com/) (TOP) is an open-source curriculum for learning full-stack web development. Our curriculum is divided into distinct courses, each covering the subject language in depth. Each course contains a listing of lessons interspersed with multiple projects. These projects give users the opportunity to practice what they are learning, thereby reinforcing and solidifying the theoretical knowledge learned in the lessons. Completed projects may then be included in the user's portfolio.",
  "scripts": {
    "lint": "markdownlint-cli2",
    "fix": "markdownlint-cli2 --fix"
  },
  "license": "CC BY-NC-SA 4.0",
  "devDependencies": {
    "markdownlint-cli2": "^0.12.1"
  }
}

ここにはたくさんの内容がありますが、今はまだそのすべてを理解する必要はありません。ポイントは、もしカリキュラムのリポジトリをクローンしてnpm installを実行したら、npmはこのpackage.jsonファイルを読み取り、markdownlint-cli2パッケージをインストールする必要があると分かるということです。このパッケージがインストールされれば、そのパッケージを使うどちらのスクリプトも実行できるようになります。カリキュラムのリポジトリ自体には、実際にはmarkdownlint-cli2パッケージのコードは含まれていません。リポジトリをクローンする人は誰でも、npm installを実行するだけで、npmに代わりにそのコードを取得させることができるからです。

私たち自身のプロジェクトでは、npmを使って新しいパッケージをインストールする(あるいはアンインストールする!)につれて、それは自動的にpackage.jsonを新しい詳細情報で更新してくれます。次のレッスンで、Webpackというパッケージを使ってモジュールバンドリングを紹介するときに、これが実際に動作するのを見ることになります。

課題

  1. npm、パッケージ、依存関係についてもう少し読んでみてください:
    1. npmでパッケージをインストールする。
    2. 私たちのアプリケーションの情報の多くを保存するファイルである、package.jsonファイルについて読んでください。
    3. インストールするパッケージはすべて「依存関係(dependencies)」と呼ばれますが、もしあるパッケージが開発プロセス中にのみ使われ、そのコードがユーザー向けのアプリには必要ない場合(Jestテストフレームワークのように)、それらは開発時の依存関係(development dependencies)と呼ばれます。
  2. こちらは、JavaScriptと複数のファイルにまたがるパッケージ管理についての、素晴らしい小さな歴史のレッスンです。「Using a JavaScript module bundler (webpack)」までだけ読んでください。バンドラーとwebpackについては次のレッスンで扱います。
