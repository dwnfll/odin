Restaurant Page

イントロダクション

これまで学んだことを使って、レストランのホームページを動的に描画することで、DOM操作の練習を続ける機会にしましょう!最終的には、JavaScriptだけを使ってウェブサイトのコンテンツ全体を生成することになります!

注意: DOM要素はJavaScriptを使って作成すべきですが、スタイリングは別のCSSファイルで行うことができます。

.gitignore

npmでインストールされたパッケージを扱う際、node_modulesの中身をgitで追跡する必要はありませんし、それらのファイルをGitHubにプッシュする必要もありません。npmのレッスンで学んだように、package.jsonファイルにはすべての依存関係の情報が含まれているため、誰でもあなたのプロジェクトをクローンして、自分のマシンでnpm installを使ってそれらをインストールできます。

プロジェクトのルートに.gitignoreファイルを作ることができ、そこにファイルやディレクトリの名前を書くことで、追跡してほしくないものをgitに伝えることができます。node_modulesはとても大きくなり得るため、.gitignoreに追加するのが慣習です。同様に、distもしばしば無視されます。なぜなら、それは誰かがアプリケーションをバンドル/ビルドするコマンドを実行したときに生成され得るからです。

GitHubで新しいリポジトリを作成する際、.gitignoreテンプレートを指定するオプションがあります。プロジェクトの種類や使用言語に基づいて、通常追跡されない一般的なファイルやディレクトリを含む、多くのテンプレートが存在します。JavaScriptプロジェクト向けには、node_modulesとdistを含むnodeテンプレートがあります。

課題

  1. webpackのチュートリアルプロジェクトを始めたのと同じ方法で、package.jsonファイルを作成し、Webpackをセットアップすることから、このプロジェクトを始めてください。
    • 覚えておいてください、プロジェクトに必要なものだけをインストール・設定すればよいのです。例えば、HTMLテンプレートにローカルの画像ファイルをリンクする予定がないなら、html-loaderをインストール・設定する必要はありません。

  2. プロジェクトのルートに.gitignoreファイルを作成してください。それには、別々の行にnode_modulesとdistというテキストを含めるべきです。

    node_modules
dist

  3. src/template.htmlの中にHTMLの骨組みをセットアップしてください。body内に、異なる「タブ」のためのボタン(リンクではありません!)を含む<nav>を持つ<header>要素を追加してください(例えば「Home」「Menu」「About」などのボタン)。<header>の下に、単一の<div id="content">を追加してください。

  4. src/index.jsの中にconsole.logまたはalert文を書き、それからnpx webpack serveを実行してください。ブラウザでhttp://localhost:8080を開いて、JavaScriptが実行されていることを確認してください。
  5. div#contentの中に、あなたのレストランのホームページを作成してください。画像、見出し、そのレストランがいかに素晴らしいかについてのテキストを含めたいと思うかもしれません。あまり凝ったものにする必要はありません。今のところは、ページ上でどう見えるかを確認するためだけに、これらをHTMLにハードコーディングしても構いません。
  6. 今度は、HTMLからdiv#contentの中身をすべて削除し(まだ<header>とその下に空の<div id="content">を持つ<nav>はあるはずです)、代わりにJavaScriptだけを使ってそれらを作成してください。例えば、ページが最初に読み込まれたときに、それぞれの新しい要素をdiv#contentに追加していく、というようにです。コードを複数のファイルに書く準備がすでに整っているので、この初期のページ読み込み関数を独自のモジュールの中に書き、それからindex.jsの中でそれをインポートして呼び出してみましょう。
  7. 次に、MenuページとContactページにアクセスするためのタブ切り替えブラウジングを使うよう、レストランサイトをセットアップしてください。視覚的なインスピレーションとして、この学生のライブプレビューサイトの挙動を見てみてください。
    1. それぞれの「タブ」の内容を、それ自体のモジュールの中に入れてください。それぞれのモジュールは、div要素を作成し、適切な内容とスタイルをその要素に追加し、それからそれをDOMに追加する関数をエクスポートします。
    2. タブ切り替えのロジックをindex.jsの中に書いてください。ヘッダーのnavbar内のそれぞれのボタンに対して、div#contentの現在の中身を消去し、それから正しい「タブモジュール」を実行して新しい中身で再び埋める、イベントリスナーを持つべきです。

デプロイ

あなたのプロジェクトをGitHub Pagesにデプロイしましょう!これは、以前のプロジェクトよりも少し手間がかかります。なぜなら、GitHub Pagesはプロジェクトのルートにある index.htmlを探そうとしますが、あなたのものはdistの中にあるからです!distディレクトリの中身をGitHub上の独自のブランチにプッシュするために、いくつかのステップを踏む必要があります。そうすることで、GitHub Pagesが提供するための、ルートレベルのindex.htmlを持つことになります。

すべてのコマンドが正確に何をするのかを知る必要はありません - 以下の指示を注意深く従えば大丈夫なはずです。これらの指示は、プロジェクトを最初にデプロイする際にも、後でプロジェクトにさらに変更を加えて再びデプロイする際にも使うことができます。

  1. git branch gh-pagesを実行して、デプロイ元のブランチを新しく作成してください。これは最初にデプロイするときにだけ行う必要があります。残りのステップは、プロジェクトをデプロイまたは再デプロイするたびに行うべきです。
  2. すべての作業がコミットされていることを確認してください。何かコミットする必要のあるものがあるかどうかはgit statusで確認できます。
  3. git checkout gh-pages && git merge main --no-editを実行して、ブランチを切り替え、mainからの変更を同期し、デプロイの準備を整えてください。
  4. さあ、ビルドコマンドを使って、アプリケーションをdistにバンドルしましょう。今のところ、それはnpx webpackです。

  5. さらにいくつかコマンドがあります。これらを順番に実行してください:

    git add dist -f && git commit -m "Deployment commit"
git subtree push --prefix dist origin gh-pages
git checkout main

  6. GitHub Pagesのソースブランチは、あなたのリポジトリの設定で設定されていることを思い出してください。これをgh-pagesブランチに変更してください。それですべてです!
