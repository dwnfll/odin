Testing Basics

イントロダクション

テスト駆動開発、略してTDDは、現代の開発の世界において大きな関心事です。これは、FundamentalsのセクションでJavaScriptの演習と共にずっと前に紹介した概念です。主な考え方は、テストされるコードを書く前に自動化されたテストを書くことから、コードの作業を始めるというものです。このように作業することには数多くの利点があり、それらすべてについては以下のリソースで論じられます。

JavaScriptには、Mocha、Jasmine、Tape、Jestなど、いくつか挙げるだけでも多くのテスト実行システムがあります。幸いなことに、それぞれの構文は非常に似ています。それぞれ独自の特別な機能のセットを持っていますが、基本的な構文はほぼ同一なので、結局のところどれを使うかは重要ではありません。実際、このカリキュラムのためにどのライブラリを使うか選ぶのは、かなり大変でした!

このレッスンはJestを中心に進めていきます。JavaScriptのテストを説明する最良のリソースの一つを持っており、ドキュメントも素晴らしいと分かりました。結局のところ、テストを書くことは構文についてというよりも、TDDの哲学についてのものです。最も重要な問題は、どう書くかよりも、なぜテストを書くのか、何をテストするのかを知ることです。

課題

  1. TDDの基本的なプロセスと利点について読んでください。
  2. Unit Testing in JavaScriptの動画シリーズの少なくとも最初の3本の動画を見てください。

  3. JestのGetting Startedチュートリアルを、「Additional Configuration」のセクションに辿り着くまで、一緒に手を動かしながら進めてください。Jestはtestやexpectのようなグローバル変数も提供してくれますが、ESLintを使っている場合、lintingエラーを防ぐために、テストファイルの中でこれらを明示的にインポートする必要があります(同じチュートリアルの「Using ESLint」のセクションを参照してください)。

    JestでES6のimport文を使う

    デフォルトでは、現在のバージョンのJestはESMを認識しません。そのため、彼らのガイドではCJSの構文(例えばmodule.exports)が使われているのを見ることになります。JestでESMを使えるようにするには、次のことを行う必要があります:

    1. @babel/preset-envをインストールしてください(これを書いている時点では、JestはBabel v7を要求しており、まだ最新のv8とは互換性がありません):

      npm install --save-dev @babel/preset-env@^7

    2. プロジェクトのルートに、次の内容でbabel.config.jsを作成してください:

      export default {
  presets: [["@babel/preset-env", { targets: { node: "current" } }]],
};

    これにより、require/module.exportsの代わりにESMのimport/export構文を書けるようになります。ガイドの他の部分は何も変更する必要はなく、Jestは通常通り実行できます。裏側では、Babelは、Jestを実行する前に、あなたのESMをCJSに変換します(これはすべてメモリ内で起こるため、あなたの実際のファイルを上書きすることはありません)。

  1. Jestの公式ウェブサイトにあるUsing Matchersのドキュメントを読んで、それに従ってください。これは、あなたのテストで使える、他のいくつかの便利な関数を実演してくれます。
  2. この記事は、TDDの背後にある理由/方法と価値についてさらに説明してくれており、それをどう適用するかについてのいくつかの素晴らしい例も含まれています。
