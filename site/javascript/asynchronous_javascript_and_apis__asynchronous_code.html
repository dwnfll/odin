Introduction to asynchronous programming

イントロダクション

JavaScriptはウェブの言語であるため、サーバーからデータを取得してサイトに表示するなど、必然的にかなりの時間がかかる関数がいくつかあります。このため、JavaScriptは非同期関数、つまり別の言い方をすると、コードの残りの部分が実行されている間、バックグラウンドで発生し得る関数のサポートを含んでいます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Promiseとは何かを説明します。
  • どんな状況でPromiseがコールバックより優れているかを説明します。
  • .then()関数が何をするかを説明します。

コールバック

最近まで、これらを扱う最も一般的な方法はコールバックを使うことであり、今でも特定の状況ではかなり多く使われています。

コールバック関数とは、何らかのルーチンやアクションを完了するために、別の関数に引数として渡され、その外側の関数の中で呼び出される関数です(コールバック関数についてのMDNのドキュメント)。

コールバックは、他の関数に渡される関数です。例えば:

myDiv.addEventListener("click", function(){
  // do something!
})

ここでは、addEventListener()関数がコールバック(「do something」関数)を受け取り、それからmyDivがクリックされたときにそれを呼び出します。

このパターンは、JavaScriptのコードで常に起こっていることとして、見覚えがあるでしょう。残念ながら、上記の例のような状況では便利ですが、コールバックを使うことは、特にそれらのいくつかを特定の順序で連結する必要がある場合、手に負えなくなることがあります。このレッスンの残りでは、あなたをコールバック地獄から遠ざけてくれるパターンと関数について論じていきます。

Promise

JavaScriptで非同期コードを扱う方法は複数あり、それらはすべてそれぞれの使いどころがあります。Promiseはそのような仕組みの一つで、他のライブラリやフレームワークを使う際に、ある程度よく見かけることになるものです。それらが何で、どう使うかを知っておくことはかなり役立ちます。

基本的に、Promiseとは、将来のある時点で値を生み出すかもしれないオブジェクトです。以下は例です:

getData()が、サーバーから何らかのデータを取得し、私たちがコードで使えるオブジェクトとしてそれを返す関数だとしましょう:

const getData = function() {
  // go fetch data from some API...
  // clean it up a bit and return it as an object:
  return data
}

この例の問題は、データを取得するのに多少時間がかかるということですが、私たちのコードにそれを伝えない限り、関数内のすべてのことが基本的に瞬時に起こると想定してしまいます。ですので、もし次のようなことをしようとすると:

const myData = getData()
const pieceOfData = myData['whatever']

私たちは問題に遭遇することになります。なぜなら、返されたデータからpieceOfDataを抽出しようとするとき、getData()関数はおそらくまだ取得中であり、myDataは期待されるデータではなくundefinedになってしまうからです。残念です。

この問題を解決し、データの取得が完了するまで続行を待つよう私たちのコードに伝える、何らかの方法が必要です。Promiseがこの問題を解決してくれます。具体的な構文の学習は、これから読む記事に任せますが、基本的にPromiseを使うと次のようなことができるようになります:

const myData = getData() // if this is refactored to return a Promise...

myData.then(function(data){ // .then() tells it to wait until the promise is resolved
  const pieceOfData = data['whatever'] // and THEN run the function inside
})

もちろん、データの取得以外にもPromiseを使いたくなる場面はたくさんあるので、今これらのことを学んでおくことは、あなたにとって非常に役立つでしょう。
