Battleship

イントロダクション

いよいよ本領を発揮するときです。テスト駆動開発(TDD)は、最初は確かに違和感を覚えるかもしれませんが、練習を重ねるうちにより自然に感じられるようになります。今回は、クラシックなゲーム「バトルシップ(Battleship)」を実装していきます。プレイしたことがない場合や、ルールを思い出す必要がある場合は、バトルシップのルールを読んだり、オンライン版のバトルシップをプレイしたりしてみてください。

TDDを行うにあたって、圧倒されすぎないことが重要です。一歩ずつ進めていきましょう。テストを書き、それを通過させる。このプロジェクトは、これまでテストを利用してきたプロジェクトと比べて、複数のモジュールにまたがるより多くの可動部分があるため、何をテストすればよいか、どうテストに取り組めばよいかわからない場合は、More Testingのレッスンのアイデアや課題を見直すことを検討してください。

ウェブページの見た目をテストすることについては、まだ扱っていません。これには別のツール群が必要であり、このユニットの範囲外ですが、カリキュラムの後半で扱うことになります。したがって、この課題ではDOMをテストするべきではありません。代わりに、アプリケーションの機能のあらゆる部分を、実際のDOM操作の部分から切り離すよう最善を尽くしてください。

課題

JestとESM

Jestには、ESMに対する組み込みの安定したサポートがないことを思い出してください。そのため、JestのESM/CJS変換のためにBabelをセットアップする必要があります。

  1. Shipクラス/ファクトリ(どちらでもお好きな方)を作成することから、アプリを始めてください。
    1. あなたの「船(ship)」は、その長さ、被弾した回数、そして沈没したかどうかを含むオブジェクトになります。
    2. 忘れないでください、テストする必要があるのは、オブジェクトの公開インターフェースだけです。「船」オブジェクトの外部で使われるメソッドやプロパティだけが、ユニットテストを必要とします。
    3. 船には、船の「被弾」回数を増加させるhit()関数が必要です。
    4. isSunk()は、船の長さと受けた被弾回数に基づいて、その船が沈没したと見なされるかどうかを計算する関数である必要があります。
  2. Gameboardクラス/ファクトリを作成してください。
    1. まだユーザーインターフェースは何も作成していないことに注意してください。コードがうまくまとまっていっているかどうかは、テストを実行することでわかるはずです。コードが期待通りに動作していることを確認するために、console.logやDOMメソッドに頼るべきではありません。
    2. Gameboardは、shipのファクトリまたはクラスを呼び出すことで、特定の座標に船を配置できる必要があります。
    3. Gameboardには、座標のペアを受け取り、その攻撃が船に命中したかどうかを判定し、命中していれば正しい船に「hit」関数を送り、外れていれば外れた攻撃の座標を記録する、receiveAttack関数が必要です。
    4. Gameboardは、外れた攻撃を正しく表示できるように、それらを記録しておく必要があります。
    5. Gameboardは、自分のすべての船が沈没したかどうかを報告できる必要があります。
  3. Playerクラス/ファクトリを作成してください。
    1. ゲームには2種類のプレイヤー、「本物の」プレイヤーと「コンピューター」プレイヤーが存在します。
    2. 各プレイヤーオブジェクトは、自分自身のgameboardを持つ必要があります。
  4. あなたのクラス/ファクトリを別のファイルにインポートし、イベントリスナーを使ってオブジェクトとやり取りしながらゲームを進行させてください。DOM内で発生すべきアクションを管理する助けとなる、モジュールを作成してください。
    1. この時点で、ユーザーインターフェースの作成を始めるのが適切です。
    2. Playerを作成して、新しいゲームをセットアップしてください。今のところは、あらかじめ決められた座標で、各プレイヤーのGameboardを埋めるだけにしておいてください。プレイヤーが自分の船を配置できるようにする仕組みは、後で実装します。
    3. HTMLの実装は今のところあなたに任せますが、両方のプレイヤーのボードを表示し、Gameboardクラス/ファクトリからの情報を使ってそれらをレンダリングする必要があります。
      • 各プレイヤーのGameboardをレンダリングするためのメソッドが必要になるので、それらを適切なモジュールに配置してください。
    4. あなたのイベントリスナーは、他のオブジェクトのメソッドだけを使って、ゲームをターンごとに進めていく必要があります。もし途中で新しい関数を書きたくなったら、一歩下がって、その関数がどのクラスやモジュールに属するべきかを考えてください。
    5. 攻撃については、ユーザーが敵のGameboard上の座標をクリックできるようにしてください。ユーザーの入力をオブジェクトのメソッドに送り、新しい情報を表示するためにボードを再レンダリングしてください。
      • プレイヤーは、敵のGameboardを攻撃することで、交代でゲームをプレイする必要があります。現在のプレイヤーのターンを記録しておく必要があると感じた場合は、他の(先に触れた)オブジェクトではなく、このモジュールでそれを管理するのが適切です。
      • このゲームはコンピューターを相手にプレイするので、「コンピューター」プレイヤーがランダムなプレイをできるようにしてください。コンピューターが賢い必要はありませんが、与えられた手が合法かどうか(つまり、同じ座標を2回撃つべきではない、など)は把握している必要があります。
    6. 一方のプレイヤーの船がすべて沈没したら、ゲームが終了するような条件を作成してください。この関数も、このモジュールに置くのが適切です。
  5. プレイヤーが自分の船を配置できるようにする仕組みを実装して、仕上げてください。例えば、各船の座標を入力させたり、ランダムな配置を切り替えるボタンを用意したりできます。

追加課題

以下の変更のいずれかを取り入れて、バトルシッププロジェクトをより印象的なものにしてください。

  • ドラッグアンドドロップを実装して、プレイヤーが自分の船を配置できるようにする。
  • ノートパソコンを行ったり来たり手渡ししたり、デスクトップならモニターを回転させたりすることで、ユーザーが交代でプレイできる2人プレイオプションを作成する。プレイヤーがお互いのボードを見てしまわないように、「デバイスを渡す」画面を実装してください!
  • 「命中」した後に隣接するマスを狙わせることで、コンピュータープレイヤーの知能を磨く。
