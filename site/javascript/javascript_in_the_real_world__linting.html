スタイルガイド

コードスタイルは重要です!インデント、好まれる引用符のスタイル、あるいは一般的なコード構造の慣行といったことについて、一貫したスタイルルールのセットを持つことで、あなたのコードはより保守しやすく、読みやすくなります。ネット上には、この種のことについての標準を定めた、いくつかの人気のあるJavaScriptのスタイルガイドがあり、それらが何を強制するかはしばしば異なることに気づくでしょう。どれも「正しい」あるいは「間違っている」わけではなく、ただコードベース全体にわたって一貫性を促進するために何かを強制しているだけです。

以下は、特定の企業が使っているものを含む、スタイルガイドのいくつかの例です:

  1. Airbnb Style Guideは、最も人気のあるものの一つです。
  2. Googleで使われているJavaScriptスタイルガイドもあります。
  3. JavaScript Standard Style。

Linting

上記で言及したスタイルガイドは、あなたのコードをフォーマット・整理・構成するための、本当に役立つアドバイスに満ちています。しかし、ルールがたくさんあります - それらすべてを内面化するのは難しいことがあります。Linterとは、あなたのコードを一連のスタイルルールでスキャンし、見つけたエラーを報告してくれるツールです。場合によっては、エラーを自動修正してくれることさえあります!JavaScriptには多くのlinterが存在しますが、断然最も一般的なのはESLintです。

ESLintはプロジェクトに開発時の依存関係としてインストールされ、コマンドラインを通してどのファイルに対してもチェックを実行できるようにしてくれます。ESLintの公式「Getting Started」ページは、インストールと基本的な設定をカバーしている、始めるのに良い場所です。デフォルトのルールセットは、賢明なデフォルト設定で、最も一般的なシナリオの多くをカバーしています。

特定のフォルダやファイルを含めたり除外したりするなど、変更できるオプションのリストや、特定のルールについての詳細については、ESLintの設定についてのドキュメントも見ておくとよいでしょう。

Formatter

Formatterは素晴らしいものです。それらはlinterと似ていますが、少し異なる機能を果たします。Formatterは、あなたのJavaScriptコードを受け取り、それから一連のルールに従って自動的にそれをフォーマットします。linterとは異なり、スタイルのエラーを探すのではなく、特にコードのレイアウトをターゲットにし、スペース、インデントのレベル、改行といったことについて、賢い決定を下します。

いつも通り、世の中には複数のフォーマッターが存在します。Prettierは、非常に独断的で人気のある選択肢です。いくつかのオプションを除いて、そのフォーマットに関する決定のほとんどはカスタマイズできません。これらの決定の多くがすでにあなたのために決められているため、インデントのサイズやスペースのようなことを決めるのに費やす時間が減り、実際に重要な問題により多くの時間を使えるようになります。

ESLintと同様に、Prettierもプロジェクトに開発時の依存関係としてインストールされるので、その方法についてはPrettierのインストールガイドを読んでください。通常はデフォルトのルールで実行されますが、Prettierの設定ファイルでその設定を変更することもできます。デフォルトのESLint推奨ルールセットを使っているなら、lint/formatのルールが衝突することはないので、eslint-config-prettierを設定することなく、そのままPrettierをインストールするだけで構いません。

Prettierを使うと、コーディングがより速く、簡単になります!インデントを正確に決めることや、すべてのセミコロンを覚えておくことを心配する必要はありません。それらの詳細はPrettierが処理してくれるからです。

lintingとformattingのためのIDE拡張機能

LinterとFormatterは、通常プロジェクトにインストールしてコマンドラインを通して使うパッケージですが、多くの人気のあるツールにはIDE拡張機能もあり、ESLintとPrettierはどちらも、あなたのマシンでlintingとformattingをずっと便利にしてくれる、Visual Studio Code用の拡張機能を持っています。

例えば、インストールすると、ESLint拡張機能は、開いているファイルの中に直接、色分けされた波線としてlinterの警告やエラーを表示でき、コマンドラインでESLintを実行する必要なく、破られた特定のルールについての詳細さえ教えてくれます。Prettier拡張機能を使うと、こちらもターミナルでコマンドを実行する必要なく、IDEのコマンドやカスタムのキーボードショートカットでファイルをフォーマットできます。

それでも、あなたのプロジェクトに、どんな設定ファイルと共に、依存関係としてパッケージがインストールされていることが重要です。拡張機能にはフォールバックのルールが設定されている場合がありますが、もしそれらがあなたのプロジェクトの中に対応するパッケージと設定ファイルを検出したら、それらのルールとインストールされたパッケージのバージョンを使います。そうすることで、プロジェクトは常にどのlinting・formattingルールが適用されるべきかについての信頼できる情報源を保持することになり、もし他のプロジェクトで作業することになっても、あなたのローカル設定から望ましくないスタイルの変更を持ち込んでしまう可能性が低くなります。

要約すると、これらの拡張機能は利便性のための素晴らしいツールですが、プロジェクトのlinting・formattingセットアップについての信頼できる情報源として使われるべきではありません。
