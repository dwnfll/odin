イントロダクション

JavaScriptの基礎のコースで、データを保存・取得するためのオブジェクトの使い方の基本を学んだはずです。このレッスンでは、まず簡単な復習から始め、それからオブジェクトの使い方をより詳しく探っていきます。Rubyトラックの方は、これらの概念のいくつかにはすでに少し馴染みがあるでしょうが、JavaScriptはオブジェクトの使い方において少し柔軟なので、このレッスンも一通り読んでおく価値があります。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • データを整理するためにオブジェクトを使う。
  • 機能を整理するためにオブジェクトを使う。
  • オブジェクトのメソッドとthisキーワード。

復習

JavaScriptでオブジェクトを定義する方法は複数ありますが、多くの場合、次のようなオブジェクトリテラル構文が使われます:

const myObject = {
  property: "Value!",
  otherProperty: 77,
  "obnoxious property": function() {
    // do stuff!
  },
};

オブジェクトから情報を取り出す方法も2つあります: ドット記法とブラケット記法です。

// dot notation
console.log(myObject.property); // "Value!"

// bracket notation
console.log(myObject["obnoxious property"]); // [Function]

どちらの方法を使うかは文脈によります。ドット記法はよりすっきりしていて通常好まれますが、それを使えない状況もたくさんあります。例えば、myObject."obnoxious property"は機能しません。なぜなら、そのプロパティはスペースを含む文字列だからです。同様に、ドット記法で変数を使うこともできません:

const variable = "property";

// "undefined" because it's looking for a property named "variable" in our object
console.log(myObject.variable);

// this is equivalent to myObject["property"] and returns "Value!"
console.log(myObject[variable]);

データ構造としてのオブジェクト

あなたはすでに、キー/値のペアで関連する情報を保存するという、JavaScriptオブジェクトの基本的な使い方を紹介されています。これは、コードを整理し始めるための最もシンプルな方法の一つです!「tic tac toe」ゲームからのこれらの例を見てみましょう - まずはオブジェクトを使わない場合:

// without objects
const playerOneName = "tim";
const playerTwoName = "jenn";
const playerOneMarker = "X";
const playerTwoMarker = "O";

次に、オブジェクトを使う場合:

// with objects
const playerOne = {
  name: "tim",
  marker: "X",
};

const playerTwo = {
  name: "jenn",
  marker: "O",
};

一見すると、最初の方はそれほど悪くないように見えますが…2番目のアプローチの利点は非常に大きいです!値がオブジェクト内のキーに割り当てられているため、長く孤立した変数名の束の代わりに、間違いなく一目で読みやすい、より簡潔な変数名を使うことができ、オブジェクト名がコンテキストを与える助けとなります。通常、nameとmarkerは同じスコープで再利用できませんが、「名前空間分け(namespacing)」を通して、playerOne.nameやplayerTwo.markerなどの一部として引き続き使うことができます。Rubyトラックの方は、Rubyのモジュールを通して似たようなことをするのに馴染みがあるかもしれません。JavaScriptでは、この目的でオブジェクトを使うのは非常に一般的です。

しかし、名前付けだけが利点ではありません。関連するデータをオブジェクトにグループ化することで、すべてのデータをより簡単に受け渡しできるようになります。例えば:

function gameOver(winningPlayer) {
  console.log("Congratulations!");
  console.log(`${winningPlayer.name} (${winningPlayer.marker}) is the winner!`);
}

名前とマーカーのために別々のパラメータを持つ代わりに、オブジェクト全体に対して一つだけ持てばよく、その中のすべてのプロパティにアクセスできます。もしプレイヤーオブジェクトにさらにプロパティを追加し、それらをgameOver関数内で必要とすることになっても、やはり、パラメータを個別に渡すのではなくオブジェクト全体を渡したので、すでにそれにアクセスできます。

しかし、単純な2人用ゲームを作っているわけではない場合はどうでしょうか?大きな在庫を持つオンラインショッピングサイトのような、もっと複雑なものの場合は?それぞれの特定のアイテムの名前、価格、説明などをグループ化するには、オブジェクトを使うのが唯一の方法です。あなたはカリキュラムを通して、このようにオブジェクトが使われ続けるのを見て、自分でも使い続けることになります。

デザインパターンとしてのオブジェクト

オブジェクトのグループ化する力は、データを整理するのに役立つだけでなく、機能を整理するのにも役立ちます!この目的でオブジェクトを使うことは、オブジェクト指向プログラミング(OOP)の中核的な原則の一つです。OOPとは、「オブジェクト」という概念に基づいたプログラミングパラダイムで、オブジェクトはデータとコードを含むことができます。データはフィールド(しばしば属性やプロパティと呼ばれます)の形で、コードはプロシージャ(しばしばメソッドと呼ばれます)の形です。OOPでは、コンピュータープログラムは、互いにやり取りするオブジェクトから作ることで設計されます。

これはつまり、オブジェクトにデータを保存することに限られず、メソッド(オブジェクトの一部である単なる関数)を通してロジックも保存でき、それからそれらのメソッドを使ってデータとやり取りできるということです。

あなたが考えつくほぼどんなものも、オブジェクトとして記述できます。そうするには、自分自身に「私のものにはどんなプロパティ(物理的あるいは概念的な)があるか?」「それとどうやってやり取りできるか?」と問いかけるだけでよいのです。ものの特性や属性はプロパティとして表され、そのものとやり取りする方法はメソッドとして表されます。

何らかのものの例を挙げてみましょう - 車を選びましょう。車にはメーカー、モデル、登録年、色、価格があり得ます。これらはオブジェクトのプロパティとして表現できるかもしれません:

const car = {
  make: "Volkswagen",
  model: "Golf",
  year: 2026,
  color: "blue",
  priceUSD: 40000,
};

車に割引を適用したり、すべての詳細のまとめを一度に取得したりできるようにしたいかもしれません。これには、メソッドを使いたくなるかもしれません。オブジェクトとやり取りするメソッドを作り始める最も簡単な方法は、オブジェクトリテラル構文とJavaScriptのthisキーワードを組み合わせることかもしれません。thisキーワードは、特定のメソッドが呼び出された元のオブジェクトを指すために使われます。

const car = {
  make: "Volkswagen",
  model: "Golf",
  year: 2026,
  color: "blue",
  priceUSD: 40000,

  // a method is just a function assigned to a property
  applyDiscount: function(discountPercentage) {
    const multiplier = 1 - discountPercentage / 100;
    this.priceUSD *= multiplier;
  },
  // shorthand way to add a method to an object literal
  getSummary() {
    return `${this.year} ${this.make} ${this.model} in ${this.color}, priced at $${this.priceUSD} (USD).`;
  },

  // ...any other methods...
};

アロー関数と"this"

thisキーワードは、従来の関数式(ショートハンド構文を含む)と比べて、アロー関数の中では異なる振る舞いをします。今のところ、それがどう、なぜ異なるのかを深く掘り下げる必要はありませんが、もし上記の例でアロー関数を使っていたら、期待通りには振る舞わなかっただろうということだけ知っておいてください。

これらのメソッドは、thisキーワードを使って、それらが呼び出された元のオブジェクト(car)を参照します。thisキーワードは、オブジェクトを指す他のどんな変数に対してもそうするのとまったく同じように、オブジェクトのプロパティを読み書きするために使うことができ、メソッドは関数を使うのとまったく同じように使います - 直感的な名前の下で再利用可能なコードを作ります。それらのことをしたいたびに手動でロジックを書き出すよりも、ずっと素敵ですね。

より抽象的な概念のためのオブジェクト

物理的なアイテムを離れて、ゲームのような、もう少し抽象的な何かをオブジェクトとして記述しようとすることもできます。Foundationsですでにじゃんけんを探ってきたので、それを例として使ってみましょう。

じゃんけんゲームには、いくつかの基本的なことが関わってくるかもしれません:

  • プレイヤーのスコア
  • 1ラウンドをプレイする能力(そして1ラウンドをプレイすると、プレイヤーのスコアが更新されるべきです)

そして、いくつかあると嬉しい機能も含まれるかもしれません:

  • 現在勝っているプレイヤーを判定する能力
  • ゲームをリスタートする能力

ですので、最も基本的な形では、ゲームを表すオブジェクトは(コンピュータープレイヤーと対戦していると仮定して)次のようなものになるかもしれません:

const rps = {
  playerScore: 0,
  computerScore: 0,
  playRound(playerChoice) {
    // code to play the round, update score if needed, then return the result
  },
};

そして、それを肉付けしていくと、私たちのオブジェクトは次のようなものになるかもしれません:

const rps = {
  playerScore: 0,
  computerScore: 0,
  playRound(playerChoice) {
    // code to play the round, update score if needed, then return the result
  },
  getWinningPlayer() {
    // return the player with the most points ("player", "computer", or "tie")
  },
  reset() {
    // reset both players' scores to 0
  },
};

少し遊んで、誰がリードしているか見てみましょう!

rps.playRound("rock"); // returns "player" because we're awesome at RPS
console.log(rps.playerScore); // 1 - we won and so our score increased

rps.playRound("rock"); // returns "computer" because... luck...
console.log(rps.computerScore); // 1

rps.playRound("scissors"); // returns "player" because we're awesome at RPS (again)
console.log(rps.playerScore); // 2
console.log(rps.getWinningPlayer()); // "player" since we're 2-1 up

今日はもう十分楽しんだので、次の人のためにすべてリセットしましょう。

rps.reset();
console.log(rps.playerScore); // 0
console.log(rps.computerScore); // 0

アンダースコアのプロパティ

実際の現場では、_somePropertyのように_で始まるオブジェクトのプロパティを持つコードを見ることがあるかもしれません。これは純粋に、そのプロパティが「プライベート」であることを意図しているということを示す、開発者の慣習です。プライベートなプロパティとは、内部使用のためだけを意図しており、オブジェクト自体の外部から読み取られたり呼び出されたりすることを意図していない(ヘルパーメソッドのような)ものです。

JavaScriptには、少なくともオブジェクトリテラルに関しては、実際にはオブジェクトの本物のプライベートプロパティという概念はありません。開発者は歴史的に、たとえ技術的にはオブジェクトの内部の外からもまだアクセス可能(「パブリック」)であったとしても、あるプロパティがまるでプライベートであるかのように扱われるべきだということを示すために、先頭に_を追加してきました。実際のプライバシー(オブジェクト自体の外からのアクセスを実際に防ぐもの)を実装する方法もありますが、それらはより高度なことを伴い、後のレッスンで扱います。

機械としてのオブジェクト

たった今見てきたように、私たちはオブジェクトを使って、物理的なものだけでなく、じゃんけんのゲームのような概念的なものも表現できます。オブジェクトは、あなたが考えつくほぼどんなものを表現するのにも使うことができます。包括的な例のリストを挙げることは不可能ですが、いくつかの使用例には次のようなものがあります:

  • 配列にアイテムオブジェクトを含む「inventory(在庫)」オブジェクトのような、他のオブジェクトを管理するオブジェクトと、そのアイテムの配列とやり取りするために行えるメソッド
  • 発生したイベントをリッスンし、適切に応答できるオブジェクト(DOM要素の.addEventListenerを思い浮かべてください)
  • 他のオブジェクトのメソッドを呼び出すイベントリスナーを設定し、ウェブページ上に他のオブジェクトからのデータを表示することで、DOMに関連するすべてのことを管理するオブジェクト

最初は、これらの種類のオブジェクトが何を含み得るのかを把握するのに苦労するかもしれませんが、これらのことは経験、特に後々の学びと共に身についてきます。しかし、これらのオブジェクトを概念化する一つの方法は、コードで作っている小さな「機械」だと想像してみることかもしれません。

機械のプロパティは、次のような情報を示すディスプレイのようなものだと考えることができます:

  • あなたが集めたアイテムのリストと、持ち運べるアイテムの最大数
  • あるイベントをリッスンしている関数のリスト
  • インタラクションのためのボタンのDOM要素と、データを表示するための要素

あなたの機械のメソッドは、機械に特定のことをさせるボタンのようなものかもしれません。例えば:

  • リストから所有しているアイテムを取り除き、新しいアイテムを追加する
  • 「click」イベントをリッスンしているすべての関数を発火させる、あるいは「click」イベントをリッスンする新しい関数を追加する
  • どこか他の場所からデータを読み取り、特定のDOM要素の.textContentを設定する

繰り返しますが、オブジェクトはあなたが考えつくほぼどんなものを表現するのにも使うことができます。その限界は、あなたの想像力だけです!

課題

この特定のレッスンには課題はありません!JavaScriptは、多くの異なるプログラミングパラダイムからの概念を含む非常に柔軟な言語ですが、その多くは「オブジェクト指向プログラミング」(OOP)を中心に構築されています。

このレッスンでは、そもそもなぜオブジェクトを使うことがあるのかという基本的な考え方に触れましたが、今後のレッスンで、オブジェクトを作成し使用するための多数のテクニックを通して、これらの概念をずっと実践的に探っていきます。
