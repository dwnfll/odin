Weather App

イントロダクション

これまで話してきたすべてを使って、前のレッスンからのVisual Crossing APIを使った天気予報サイトを作成してください。特定の場所を検索でき、華氏か摂氏でデータを表示するかを切り替えられるべきです。

データに基づいてページの見た目を変えるべきです。おそらく、背景の色を変えたり、天気を表す画像を追加したりすることによってです。(適切な天気関連のgifを見つけて表示するために、Giphy APIを使うことさえできます)。コードでpromiseかasync/awaitのどちらを使っても構いませんが、両方に慣れておくよう努めるべきです。

APIキー、シークレット、セキュリティ

すべてのAPIが無料というわけではなく、それらがどうセットアップされているかによっては、使用ごとにお金がかかることがあります。これにより、それらは、あなたのAPIキーを使うことでお金を払わずにAPIを使おうとする人々にとって、格好の標的になります。それらはレート制限がかかっていることもあり、もし誰かがあなたのAPIキーにアクセスできれば、あなたの使用可能回数をすべて使い果たしてしまう可能性があります。この問題を防ぐ一つの方法は、APIキーをサーバーに保存し、そもそもそれをフロントエンドに送らないようにすることです。これはしばしば環境変数を使って行われ、そのキーをコードがデプロイされているサーバー上でのみ利用可能にします。

APIキーとセキュリティについて話すとき、しばしば「クライアントを決して信頼するな」(クライアントはフロントエンドを意味します)という言葉を耳にするでしょう。多くの場合、これはクライアントから来るデータが有効であると信頼してはいけないという意味ですが、それはまた、クライアントに送るものは何も信頼できないという意味でもあります。このため、APIキーを漏洩させると、GitHubは、あなたがAPIキーを公開してコミットしたことを警告してくれます。このプロジェクトに従い、実際にAPIキーを露出させた後、GitHubがこのアラートを送ってくることに気づくかもしれません。これは、このAPIキーが公開されているものであり、それを露出させても何の影響もないため、このプロジェクトでは完全に問題ありません。これは、すべてのキーがこのようなものだという意味ではありません。後のバックエンドのコースで、これらのトピックを安全に扱う方法を学びます。

課題

  1. JavaScriptファイルとCSSファイルへの適切なリンクを含む、空のHTMLドキュメントをセットアップしてください。
  2. APIにアクセスする関数を書いてください。場所を受け取り、その場所の天気データを返せる関数が欲しいところです。今のところは、単にその情報をconsole.log()してください。
  3. APIから取得しているJSONデータを処理し、あなたのアプリに必要なデータだけを持つオブジェクトを返す関数を書いてください。
  4. ユーザーが自分の場所を入力でき、天気情報を取得できるフォームをセットアップしてください(まだ単にconsole.log()するだけです)。
  5. 華氏か摂氏で温度データを表示するトグルと共に、あなたのウェブページに情報を表示してください。
    • その必要はありませんが、天気アイコンを表示したい場合、インポートすべきものがたくさんあるかもしれないので、動的インポートを見てみてください。インポートのないプレーンなテンプレート文字列とは異なり、Webpackは動的インポートを読み取り、それでも関連するすべてのアセットをバンドルできます。
  6. 好きなスタイリングを追加してください!
  7. オプション: フォームが送信されてからAPIから情報が返ってくるまでの間表示される「読み込み中」コンポーネントを追加してください。DevToolsを使ってネットワーク速度をシミュレートしてください。
  8. その力作をGitHubにプッシュして、以下であなたの解決策を共有してください!
