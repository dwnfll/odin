HashMap

日本語訳

← javascript

Build your very first hash map data structure from scratch

イントロダクション

ハッシュマップの裏側にある魔法については、もう理解しています。今度は、自分自身の実装を書く番です!

制限事項

始める前に、いくつかの基本ルールを定めておく必要があります。JavaScriptの配列の動的な性質により、配列のサイズの範囲外にあるインデックスに対しても、挿入や取得ができてしまいます。例えば、バケットを表すためにサイズ16の配列を作成したとしても、インデックス500に項目を保存することを何も妨げません。これでは、ハッシュマップにおいてストレージサイズを制限するという目的が損なわれてしまうため、いくつかの制約を課す必要があります。

インデックスを通じてバケットにアクセスするときは常に、以下のスニペットを使ってください。範囲外のインデックスにアクセスしようとした場合は、エラーをスローしたいのです:

if (index < 0 || index >= buckets.length) {
  throw new Error("Trying to access index out of bounds");
}

課題

まず、HashMapクラスまたはファクトリ関数を作成することから始めましょう。どちらを使うかはあなた次第です。少なくともload factorとcapacityのための2つの変数を持つ必要があります。load factorが0.75の場合、capacityの初期値はサイズ16にする必要があります。それができたら、以下のメソッドを作成していきましょう:

  1. hash(key)は文字列のキーを受け取り、それを使ってハッシュコードを生成します(現実の世界では、ハッシュマップは数値や他のオブジェクトなど、さまざまなデータ型をキーとして扱うことができますが、ここではシンプルにしておきます)。前回のレッスンで、すでにかなり良いhash関数を実装しました。おさらいすると:

    function hash(key) {
  let hashCode = 0;

  const primeNumber = 31;
  for (let i = 0; i < key.length; i++) {
    hashCode = primeNumber * hashCode + key.charCodeAt(i);
  }

  return hashCode;
}

    これをそのまま使ってもかまいませんし、ハッシュ化アルゴリズムについて自分で調べてみてもかまいません。ただし注意してください、これはとても、とても深い沼です。忘れないでいただきたいのは、(バケット配列の成長にかかわらず)バケットに収まるインデックスを確実に得るために、ハッシュコードを返す前に現在のcapacityで剰余(%)を取る必要がある、ということです。注意すべき重要なエッジケースとして、非常に長いキーの場合、最大安全整数(maximum safe integer)を超えてしまい、計算結果が不正確になってしまうことがあります。そのため、ループが完了した後に一度だけ剰余を取るのではなく、ループの各繰り返しのたびに、現在のcapacityでハッシュコードの剰余を取るほうが賢明です。

    後でキーと値のペアにアクセスする際に、キーとハッシュコードを混同してしまうことがあるかもしれません。強調しておきたいのは、キーとは、あなたのhash関数が入力として受け取るものだ、ということです。ある意味では、キーが重要なのはhash関数の中だけ、とも言えます。というのも、キーを使って直接バケットにアクセスすることは決してなく、常にハッシュコードを使ってアクセスするからです。

  2. set(key, value)は2つの引数を受け取ります。1つ目はキー、2つ目はそのキーに割り当てられる値です。もしそのキーがすでに存在する場合は、古い値が上書きされ、そのキーの値を更新したと言うことができます(例えば、Carlosがキーだとして、これが2回呼び出されたとします: 1回目は値I am the old value.、2回目は値I am the new value.。このロジックに従うと、Carlosには後者の値だけが残るはずです)。

    衝突は、2つの異なるキーが同じハッシュコードを生成し、同じバケットに割り当てられたときに発生することを思い出してください(例えば、RamaとSitaが両方とも3にハッシュ化されたとすると、3はRamaとSitaの両方の場所になります。しかし、キーが異なるため、これは更新ではないとわかります)。私たちの衝突をどう処理するかについては、前のレッスンの衝突への対処のセクションを復習してください。

    • ハッシュマップがload factorに達したときに、バケットをその容量の2倍に成長させることを忘れないでください。この課題の後半で紹介するメソッドが、成長のロジックを扱う際に役立つはずなので、この機能は最後のほうで実装したいと思うかもしれません。とはいえ、バケットがまさに拡張されるタイミングで成長させることが重要なので、ここset()の説明の中で触れています。

  3. get(key)はキーを1つの引数として受け取り、そのキーに割り当てられている値を返します。キーが見つからない場合は、nullを返します。

  4. has(key)はキーを引数として受け取り、そのキーがハッシュマップの中に存在するかどうかに応じて、trueまたはfalseを返します。

  5. remove(key)はキーを引数として受け取ります。指定されたキーがハッシュマップの中に存在する場合は、そのキーを持つエントリを削除し、trueを返す必要があります。キーがハッシュマップの中に存在しない場合は、falseを返す必要があります。

  6. length()はハッシュマップに保存されているキーの数を返します。

  7. clear()はハッシュマップ内のすべてのエントリを削除します。

  8. keys()はハッシュマップ内のすべてのキーを含む配列を返します。

  9. values()はすべての値を含む配列を返します。

  10. entries()は各キー, 値のペアを含む配列を返します。例: [[firstKey, firstValue], [secondKey, secondValue]]

ハッシュマップは、データを取得する際に挿入順序を保持しないことを思い出してください。キーと値が、挿入した順序とは異なる順序で現れるのは、正常であり、想定されていることです。

ハッシュマップをテストする

  1. 新しいJavaScriptファイルを作成してください。

  2. あなたのハッシュマップの新しいインスタンスを作成し、load factorを0.75に設定してください。

    const test = new HashMap() // or HashMap() if using a factory

  3. 以下をコピーして、set(key, value)メソッドを使ってハッシュマップにデータを入れてください:

    test.set('apple', 'red')
test.set('banana', 'yellow')
test.set('carrot', 'orange')
test.set('dog', 'brown')
test.set('elephant', 'gray')
test.set('frog', 'green')
test.set('grape', 'purple')
test.set('hat', 'black')
test.set('ice cream', 'white')
test.set('jacket', 'blue')
test.set('kite', 'pink')
test.set('lion', 'golden')

  4. 上記のデータでハッシュマップにデータを入れ終えると、ハッシュマップの現在の負荷レベルは0.75(満容量)になっているはずです。

  5. ハッシュマップが満杯の状態で、今度はset(key, value)を使っていくつかのノードを上書きしてみてください。これは、ノードの既存のvalueを上書きするだけで、新しいノードを追加するものではないはずなので、length()は同じ値を返し続け、capacityも変わらないはずです。

  6. その後、以下の最後のノードをハッシュマップに追加してください。これにより負荷レベルがload factorを超え、ハッシュマップの成長機能が発動して、そのcapacityが2倍になります:

    test.set('moon', 'silver')

  7. ハッシュマップを正しく実装できていれば、拡張後のハッシュマップの負荷レベルはload factorをかなり下回っているはずで、エントリは拡張後のバケットに均等に分散されているはずです。

  8. 新しくなったハッシュマップに対しても、set(key, value)を使っていくつかのノードを上書きしてみてください。これも、ノードの既存のvalueを上書きするだけのはずです。

  9. get(key)、has(key)、remove(key)、length()、clear()、keys()、values()、entries()など、ハッシュマップの他のメソッドもテストして、ハッシュマップを拡張した後も期待通りに動作しているかを確認してください。

追加課題

  • HashMapと同じように振る舞うものの、valuesを持たずkeysだけを持つ、HashSetクラスまたはファクトリ関数を作成してください。
