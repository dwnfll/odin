Working with APIs

イントロダクション

ウェブ開発者ができる最も強力なことの一つは、サーバーからデータを取得し、それを自分のサイトで創造的に表示することです。多くの場合、サーバーはその特定のサイトのためだけに存在します。サーバーはブログ記事、ユーザーデータ、ゲームのハイスコア、あるいは他の何でも含むことができます。他の場合では、サーバーはそれを使いたい誰にでもデータを提供する、オープンなサービスです(例えば天気データや株価など)。どちらの場合でも、そのデータにアクセスしてから使う方法は基本的に同じです。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • APIとは何かを説明します。
  • APIへのアクセスがどう機能するかを大まかに説明します。
  • APIからデータを取得・抽出する方法を説明します。
  • なぜあなたのAPIリクエストがブラウザにブロックされるかもしれないのか、そしてそれをどう修正するかを説明します。

API

外部での使用(ウェブサイトやアプリ)のために機能を提供しデータを提供するために作られたサーバーは、しばしばAPI、つまり「Application Programming Interfaces」を使ってそれを行います。

APIからデータをリクエストする方法は複数ありますが、それらはすべて基本的に同じことを行います。ほとんどの場合、APIはURLを通してアクセスされ、これらのURLをどうクエリするかの詳細は、使っている特定のサービスによって異なります。例えば、Visual Crossingには、リクエストできるいくつかの種類のデータを持つ天気APIがあります。特定の場所の現在の天気を取得するには、次のように、URLのパスに都市の名前を渡すことができます:

https://weather.visualcrossing.com/VisualCrossingWebServices/rest/services/timeline/london

どんなAPIを使う際の詳細も、通常はそのサービスのウェブサイトに記載されています。Visual Crossing APIのドキュメントをチェックしてみてください。まだであれば、上記の天気のURLに、好きな都市を入れて、ブラウザに貼り付けてみてください…(お待ちしています)。

おそらく、次のようなエラーが出るでしょう:

No API key or session found. Please verify that your API key parameter is correct.

これで、APIについてのもう一つのポイントに辿り着きました。ほとんどの場合、APIのエンドポイント(APIの中で特定の機能やデータにアクセスするために使う特定のURL)からデータを取得しようとする前に、アカウントを作成し、そのAPIサービスに「APIキー」をリクエストする必要があります。取得したら、APIキーは通常、すべてのデータリクエストに含める必要があります。Visual Crossingでは、それはクエリ文字列パラメータとしてです:

https://weather.visualcrossing.com/VisualCrossingWebServices/rest/services/timeline/london?key=11111111111111111

ご想像の通り、APIキーはランダムで、あなただけのユニークなものです。そのため、Visual Crossingのようなサービスは、あなたのAPIキーを、あなたが彼らのデータをどれだけ、どれくらいの頻度でリクエストしているかを含め、あなたのリクエストと関連付けることができます。

APIキーを発行することで、APIサービスは自分たちのシステムやデータの乱用をより良く追跡できるようになります。さらに、それはそれらのサービスが運用コストを緩和し、回収する方法にもなり得ます。例えばVisual Crossingは、無料枠だけでなく、月額150米ドルにもなり得るさまざまな有料プランも提供しています!結局のところ、サーバーを運用するにはお金がかかり、APIも例外ではありません。APIへの単一のリクエストは1セントの何分の一かのコストしかかからないかもしれませんが、そのAPIを使って世界中で使われる素晴らしい天気アプリを作ることを想像してみてください…毎分何千人もの人々がそのデータにアクセスすることになるかもしれません!そのトラフィックを処理するコストは、APIサービスにとってすぐにかなりの金額に膨れ上がる可能性があります。

そのため、すべてとは言わないまでも、ほとんどのAPIサービスが、より頻繁にリクエストできる能力や、より下位のプランでは利用できないより多くの情報へのアクセスが付いてくる、有料プランを提供していることに気づくでしょう。例えば、Visual Crossingの無料版では、限られた量の情報(それでも個人プロジェクトには十分ですが)で1日あたり1000回の呼び出し/リクエストが許可されています。一方、Enterprise版は月間無制限のAPI呼び出しを提供し、エネルギーデータ、海洋データ…そういったすべての付加機能があります(気になる場合はVisual Crossingの価格設定についての詳細)。ですので、もしあなたのアプリが成功して追加の機能が必要になったら、おそらくより良いアカウントにお金を払う必要があるでしょう。

あなたのAPIキーはあなたの、これらのサービスとデータへの鍵であるため、それを保護することは重要な習慣です。特に有料プランを使っている場合はなおさらです。ハードコードされた/保護されていないAPIキーだけを目的にGitHubのリポジトリをクロールするボットがたくさんあり、悪意のある人物があなたがお金を払って手に入れたサービスやデータを利用することを可能にしてしまいます。実際、より目ざとい読者は、上記のデモンストレーションの問題にすでに気づいたかもしれません: APIキーがまさにそのURLリクエストの中にあります。インターネットトラフィックのスニファーがAPIキーを拾い上げるのに、大した労力は要りませんし、まして肩越しに見ている人にとってはなおさらです!

とはいえ、カリキュラムのこの時点では、この点は大部分どうでもよいことです。結局のところ、私たちはAPIへの無料アクセスを利用しているだけであり、私たちのアプリのほとんどは私たちとポートフォリオを見る人だけに使われることになるからです。今のところは、上記で示したようにAPIキーを使うことの深刻な限界を心に留めておくだけにしてください。APIキーを保護するには、サーバーサイドで物事を扱う必要がありますが、私たちはここではフロントエンドの概念だけに焦点を当てています。もしFull Stack JavaScriptパスウェイにいるなら、バックエンドについてはカリキュラムの後の方で扱います。

Visual Crossingに戻りましょう。無料のVisual Crossingアカウントを作成して、APIキーを取得してください。APIキーは、あなたのアカウントのプロフィールページで見つけることができます。キーを手に入れたら、上記の例のように、好きな都市とクエリ文字列パラメータとして渡したAPIキーで、新しいリクエストを試してみてください。うまくいけば、次のような適切なレスポンスが見えるはずです:

データを取得する

では、実際にどうやってAPIからのデータを自分のコードに取り込むのでしょうか?

数年前は、コード内でAPIデータにアクセスする主な方法はXMLHttpRequestを使うことでした。この関数は今でもすべてのブラウザで機能しますが、残念ながら、使い勝手が特に良いわけではありません。構文は次のようなものになります:

// Just getting XHR is a mess!
if (window.XMLHttpRequest) { // Mozilla, Safari, ...
  request = new XMLHttpRequest();
} else if (window.ActiveXObject) { // IE
  try {
    request = new ActiveXObject('Msxml2.XMLHTTP');
  }
  catch (e) {
    try {
      request = new ActiveXObject('Microsoft.XMLHTTP');
    }
    catch (e) {}
  }
}

// Open, send.
request.open('GET', 'https://url.com/some/url', true);
request.send(null);

うっ。それは辛かったですね。

開発者たちは、そのようなものを書き出さなければならない痛みを感じ、それを処理してずっと使いやすくするためのサードパーティのライブラリを書き始めました。より人気のあるライブラリのいくつかには、axiosとsuperagentがあり、どちらもそれぞれの長所と短所があります。

しかし、より最近では、ウェブブラウザは、HTTPリクエストを行うための新しいネイティブ関数を実装し始めています。それが、今のところ私たちが使い続けることになるものです。fetchに会いましょう:

// URL (required), options (optional)
fetch('https://url.com/some/url')
  .then(function(response) {
    // Successful response :)
  })
  .catch(function(err) {
    // Error :(
  });

もし忘れてしまっていたら、上にスクロールして戻り、同じことをするのにXHRをどう使うかを見てみてください。そのコードがいかに素敵ですっきりしているかを称賛しつつ、そこにある.then()と.catch()関数に注目してください。それらが何だったか覚えていますか?(Promiseです!)

この例のために、使うAPIを変えてみましょう。ウェブページにランダムなgifを表示するために、giphy APIでfetchを使う例を見ていきます。このAPIは、giphyにサインアップして無料のAPIキーを取得することを要求します。

Giphyには、GIFを検索・発見するためのいくつかのメソッドがあり、それらについては彼らのドキュメントで読むことができます。今日は、私たちの目的にとって最もシンプルな'translate'エンドポイントだけを使います。適切なURLは、彼らのドキュメントでGiphyのtranslateエンドポイント情報まで下にスクロールすると見つけることができます。それが教えてくれるのは、正しいURLはapi.giphy.com/v1/gifs/translateであり、api_keyとsearch termという2つのパラメータを必要とするということです。結果を絞り込むためにクエリに含められる、他のオプションのパラメータもあります。例えば、ratingパラメータを使うと、異なるレベルのセンシティブさのコンテンツを探すことができます。すべてを(あなたのAPIキーで)正しく組み合わせると、次のようなものが得られるはずです::

'https://api.giphy.com/v1/gifs/translate?api_key=YOUR_KEY_HERE&s=cats&rating=g'
// of course we're searching for cats

そのURLを(あなたのAPIキーで)ブラウザで試してみてください。すべてがうまくいけば、比較的長いデータの文字列が得られ、エラーは出ないはずです。

やってみましょう

今のところ、これらすべてを単一のHTMLファイルに保っておきます。ですので、bodyに単一の空のimgタグと空のscriptタグを持つファイルを作成してください。

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Document</title>
</head>
<body>
  <img src="#">
  <script>
  </script>
</body>
</html>

scriptタグの中で、まずimg要素を選択し、Giphy APIからそれを受け取った後にURLを変更できるように、それを変数に割り当てることから始めましょう。

<script>
  const img = document.querySelector('img');
</script>

上記のURLでfetchを追加するのも比較的簡単です:

<script>
  const img = document.querySelector('img');
  fetch('https://api.giphy.com/v1/gifs/translate?api_key=YOUR_KEY_HERE&s=cats&rating=g')
    .then(function(response) {
      console.log(response.json());
    });
</script>

これで、ブラウザでHTMLファイルを開けるはずです。ページには何も表示されませんが、コンソールには何かログ出力されているはずです。このプロセス全体で最もトリッキーな部分は、サーバーのレスポンスから望むデータにどうたどり着くかを解読することです。この場合、ブラウザのコンソールを検査すると、返ってきているのはさらに別のPromiseであることが分かります…必要なデータを取得するには、もう一つ.then()関数が必要です。

<script>
  const img = document.querySelector('img');
  fetch('https://api.giphy.com/v1/gifs/translate?api_key=YOUR_KEY_HERE&s=cats&rating=g')
    .then(function(response) {
      return response.json();
    })
    .then(function(response) {
      console.log(response);
    });
</script>

これでJavaScriptオブジェクトが手に入りました。十分に注意深く調べてみると、私たちが必要とするデータ(画像のURL)がオブジェクトの中にかなり深くネストされていることに気づくでしょう:

データにたどり着くには、望むものを見つけるまでオブジェクトの層をドリルダウンしていく必要があります!

<script>
  const img = document.querySelector('img');
  fetch('https://api.giphy.com/v1/gifs/translate?api_key=YOUR_KEY_HERE&s=cats&rating=g')
    .then(function(response) {
      return response.json();
    })
    .then(function(response) {
      console.log(response.data.images.original.url);
    });
</script>

これでファイルを実行すると、画像のURLがログ出力されるはずです。あとは、ページ上の画像のsrcを、たった今アクセスしたURLに設定するだけです:

<script>
  const img = document.querySelector('img');
  fetch('https://api.giphy.com/v1/gifs/translate?api_key=YOUR_KEY_HERE&s=cats&rating=g')
    .then(function(response) {
      return response.json();
    })
    .then(function(response) {
      img.src = response.data.images.original.url;
    });
</script>

すべてがうまくいけば、リフレッシュするたびにページに新しい画像が表示されるはずです!

途中で迷ってしまった場合は、このgiphyからのフェッチを実演しているjsbinプロジェクトをチェックしてみてください。素晴らしいスタイリングは別として、これがあなたのバージョンがどう見えるべきかです。

このAPIキーをフロントエンドにプッシュしていますが、これは無料でないキーに対して行うべきことではありません。クライアントサイドで使われるキーは公開情報とみなされるため、機密性が高く無料でないキーには注意が必要です。キーをフロントエンドにプッシュせずに扱う方法は、もしRubyのコースですでに学んでいなければ、後のセクションで教えます。

課題

  1. このPublic APIsのリストをチェックして、想像力を膨らませてみてください。
  2. ページをリフレッシュせずに新しい画像を取得するボタンを追加して、ここでの私たちの小さなプロジェクトを拡張してください。

  3. ユーザーが特定のgifを検索できるように、検索ボックスを追加してください。いくつかのエラー(例えば無効なURLなど)を管理するために、.catch()を追加することも調べておくべきです。APIが応答する限り、たとえ404 Not Foundや他の何らかの2XX以外のステータスレスポンスであっても、それは依然として有効なレスポンスであり、そのためfetchはエラーを投げず、つまり.catch()は実行されないということを心に留めておいてください。それでも、undefinedのプロパティにアクセスしようとするなど、続くJavaScriptコードがエラーを投げた場合や、自分自身で手動でエラーを投げた場合には、それでも実行されることになるかもしれません。

    もしAPIが望むレスポンス(例えば404 Not Foundなど)を与えてくれない状況を条件付きで処理したい場合、.then()の中で手動でこれを行う必要があります。いくつかの便利なプロパティについては、Responseオブジェクトについての MDNのドキュメントをチェックしてみてください。
