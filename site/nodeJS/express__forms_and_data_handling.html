How to use forms and its data validation in Express

イントロダクション

このレッスンでは、フォームと、Expressを使ってそれをどう管理するかについて深く掘り下げていきます。バリデーション(検証)とサニタイゼーション(無害化)のためにexpress-validatorを使うことで、あなたのNode.js/Expressアプリケーションを保護する方法を探っていきます。適切なフォーム処理を理解することは、データの整合性を維持し、あなたのウェブアプリケーションをセキュリティリスクから守るために極めて重要です。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • HTMLのフォーム要素とその動作を理解する。
  • バリデーションとサニタイゼーションのためにexpress-validatorを使う。
  • フォームの設計とデータの整合性のためのベストプラクティス。

HTMLフォームの概要

まず、実際のHTMLについて簡単に復習しておきましょう。

フルネームを収集するための単一のテキストフィールドと、それに関連付けられたlabel要素を持つ、シンプルなHTMLフォームを作ってみましょう。

HTMLの構造は、以下のようなものになります:

<form action="/create" method="POST">
  <label for="fullName">Full Name:</label>
  <input placeholder="John Doe" type="text" name="fullName" id="fullName">
  <button type="submit">Submit</button>
</form>

HTMLのform要素自体があり、actionはサーバー上の何らかのリソースを指しており、methodが定義されています。methodがHTTP動詞(通常はGETかPOSTのどちらか)に対応していることに注目してください。

このフォームは、関連付けられたlabelを持つテキスト入力と、submitボタンで構成されています。

入力のname属性は重要な役割を果たします。それが、サーバーに送信されるフォームデータの中で、その入力がどのように識別されるかを定義するからです。これは、バックエンドでフォームの送信を処理する際に特に重要になります。

type="submit"のボタンによって、ユーザーは入力したデータをサーバーにアップロードできるようになります。

formの属性は、サーバーとどのように通信するかを定義します:

  • action: フォームが送信されたときに、処理のためにデータが送られるリソース/URL。これが設定されていない場合、または空の文字列の場合、フォームは現在のページURLに送り返されます。
  • method: 使用するHTTPメソッド(POSTまたはGET)を定義します。

POSTは、機密情報をURLの外に保っておける――つまりサーバーのログに残らない――ため、一般的により安全であり、サーバーサイドでデータを作成・更新するための標準的な選択肢です。GETは、検索フォームのようにデータを変更しないフォームのため、あるいはフォームの送信結果をブックマークしたりURL経由で共有したりできるようにしたい場合のためのものです。この場合、フォームデータはリクエストURLの一部として、クエリ文字列として送信されます。

フォーム処理のプロセス

フォームのactionは、私たちのコントローラーがそのリクエストを処理できるようにする、サーバー上の何らかのエンドポイントを指します。それからコントローラーはデータベースと通信し、データを処理します。

その後、コントローラーの応答で新しいビューまたは更新されたビューを生成し、クライアントをリダイレクトします。これは、重複したPOSTリクエストを防ぐのに役立つ、Post/Redirect/Get(PRG)というデザインパターンとして知られています。

バリデーションとサニタイゼーション

フォームからのデータがサーバーに送信される前に、2つの重要なステップを考慮する必要があります:

  • バリデーションは、ユーザーの入力が指定された基準(必須フィールド、正しい形式など)を満たしていることを保証します。
  • サニタイゼーションは、悪意のある可能性のある文字を削除またはエンコードすることで、悪意のあるデータが処理されるのを防ぐために、ユーザーの入力をクリーンにします。

データを受け取った瞬間に必ずしもサニタイズする必要はありません――代わりに、それを使う直前にサニタイズする方が理にかなっている場合もあります。

この両方を手助けしてくれる、express-validatorというライブラリを使っていきます。これはこれらのプロセスをずっとシンプルにしてくれますが、この2つの操作の背後にある概念を理解しておくことが重要です。

サニタイゼーションの定義

「サニタイゼーション」という言葉が、受信したデータから文字を削除することだけを指す、もっと厳密な意味で使われているのを見かけることもあります。この場合、特定の文字を置き換える「エンコーディング」とは区別されます。また、文字の削除とエンコーディングの両方を含む、受信データを何らかの形で変更するプロセス全体を指す、もっと緩い意味で使われることもあります。このレッスンの私たち自身のコンテンツの中では、この言葉をこの後者の意味で使っていきます。

express-validatorをインストールする

いつも通り、プロジェクトのルートフォルダに正しいパッケージをインストールすることから始めます。

npm install express-validator

このパッケージの使用を開始するには、まずプロジェクトの中でそれをrequireする必要があります。

const { body, validationResult } = require("express-validator");

express-validatorには、考えられるほぼすべてのフォーム操作のための、多くの関数が付属していますが、このレッスンでは、body()とvalidationResult()に絞って見ていきます。

body()関数を理解する

body()関数を使うと、リクエストボディのどのフィールドをバリデーションおよびサニタイズすべきか、そしてそれをどう処理するかを指定できます。

[
  body("birthdate", "Must be a valid date.")
    .optional({ values: "falsy" })
    .isISO8601() // Enforce a YYYY-MM-DD format.
];

この例では、birthdateフィールドを任意(オプション)としてマークしていますが、それでも入力にISO8601の日付形式を強制しています。これは、{ values: "falsy" }が、undefined、null、false、0、空文字列""以外の値は、それでもバリデーションされることを意味しているためです。

バリデーションをチェーンする

複数のバリデーションメソッドをチェーンし、チェックが失敗した場合に固有のエラーメッセージを表示することもできます。

[
  body("name")
    .trim()
    .notEmpty()
    .withMessage("Name can not be empty.")
    .isAlpha()
    .withMessage("Name must only contain alphabet letters."),  
];

これにより、nameが存在しトリムされているだけでなく、アルファベットの文字のみを含んでいることも保証されます。

ユーザー入力をエスケープする

これは、名前や年齢のように、特殊文字を含まないとわかっている出力には有効かもしれませんが、そうした文字を許容する状況についても考慮する必要があります。例えば、「About Me」の説明を書くとき、もしクライアントが代わりにJavaScriptコードを注入することにしたら、何が起こるでしょうか?

<div>
  About Me: <%- description %>!
</div>

// The client then inputs the following as their page's About Me:
<script>alert("Hacked!");</script>

エスケープされていない場合、これは以下のようにHTMLへレンダリングされてしまいます:

<div>
  About Me: <script>alert("Hacked!");</script>!
</div>

このクロスサイトスクリプティング(XSS)攻撃を防ぐために、出力をエスケープできます(これはエンコーディングと呼ばれることもあります)。エスケープされたHTMLは、<のような特殊文字を、それぞれに対応するHTMLエンティティ――この場合は&lt;――に置き換えます。EJSでは、<%= %>を使って出力をエスケープできます。

<div>
  About Me: <%= username %>!
</div>

// The escaped output is now rendered harmless:
// About Me: &lt;script&gt;alert(&quot;Hacked!&quot;);&lt;/script&gt;!

では、なぜbody()のバリデーションチェーンの最後に.escape()を追加して、データを受け取った時点でエスケープしないのでしょうか?「危険な文字」は、使用される時点で、そして特定の文脈においてのみ危険なのです。HTMLにとって「危険」なものが、SQLにとっては危険ではないこともあり、その逆もまた然りで、それらの文脈で使われるまでは、リスクをもたらすことはありません。

また、もしエスケープした後のHTMLエンティティを含むデータがある場合、エスケープされた出力(<%= %>)を使うと、&lt;は<に戻らず、&lt;というテキストのまま文字通り出力されてしまいます。それらをアンエスケープしてから、エスケープされた出力で再エスケープするか、あるいは、上で示した通り望ましくない.innerHTMLの使用のように、結局エスケープされていない出力(<%- %>)を使うことになってしまいます。

バリデーション結果

バリデーションルールが適用されたら、validationResultを使ってバリデーションエラーを処理できます:

const controller = (req, res, next) => {
  const errors = validationResult(req);
  if (!errors.isEmpty()) {
    return res.status(400).render("index", {
      errors: errors.array(),
    });
  }

  // do stuff if successful
  res.redirect("/success");
};

このセットアップは、失敗したバリデーションチェックがないかを確認し、もしあれば(errors配列が空でない場合)、サーバーは400ステータスコードと、存在する可能性のあるエラーを、私たちのindexビューに送信します。そうでなければ、私たちのルーターの/successルートにリダイレクトされます。

フォームとExpressのルート

最後にもう一つ取り上げるべきことは、Expressでルートをどう処理するかです。結局のところ、私たちのフォームには、データを送る先が必要です。

exports.userUpdateGet = (req, res, next) => {};
exports.userUpdatePost = (req, res, next) => {};

ルーターの中で、コントローラーの関数に対応するルートを割り当てることができます:

const { Router } = require("express");
const usersRouter = Router();
const usersController = require("../controllers/usersController");

// User update routes
usersRouter.get("/:id/update", usersController.userUpdateGet);
usersRouter.post("/:id/update", usersController.userUpdatePost);

module.exports = usersRouter;

私たちのフォームでは、actionは以下のようなものになるでしょう:

<!-- Example using EJS with POST to submit an update to our Express server. -->
<form action="/users/<%= user.userId %>/update" method="POST"></form>

/users/:id/updateは、Expressサーバー上に作成したエンドポイントです。

組み合わせてみる

クライアントがフォームを使ってサーバーにどのようにデータを送るかを実演するために、簡単なExpressアプリケーションを作ってみましょう。

EJSテンプレーティングを使った、新しいExpressアプリをセットアップしてください:

npm init -y
npm install express ejs express-validator

routes、views、controllers、storages用のフォルダと、app.jsファイルを作成してください:

// app.js
const express = require("express");
const app = express();
const path = require("node:path");
const usersRouter = require("./routes/usersRouter");

app.set("views", path.join(__dirname, "views"));
app.set("view engine", "ejs");
app.use(express.urlencoded({ extended: true }));
app.use("/", usersRouter);

const PORT = process.env.PORT || 3000;
app.listen(PORT, (error) => {
  if (error) {
    throw error;
  }
  console.log(`Express app listening on port ${PORT}!`);
});

ほとんどのシンプルなフォームは、サーバーにデータを送信する際にContent-Type: application/x-www-form-urlencodedというHTTPヘッダーを使います。しかし、Expressはそのデータをネイティブには解析できません。express.urlencoded()ミドルウェアを使うことで、これを代わりに処理させ、フォームのデータを自動的にreq.bodyフィールドに設定できます。extendedがfalseの場合、私たちのサーバーはstringかデータの配列しか受け付けなくなるため、多少の柔軟性を持たせるためにtrueに設定します。Content-Typeがapplication/x-www-form-urlencodedに一致しない場合、サーバーはそのデータを空のオブジェクト{}として表示することに注意してください。

routesフォルダに、usersRouter.jsという新しいルーターを作成しましょう:

// routes/usersRouter.js
const { Router } = require("express");
const usersController = require("../controllers/usersController");
const usersRouter = Router();

usersRouter.get("/", usersController.usersListGet);
usersRouter.get("/create", usersController.usersCreateGet);
usersRouter.post("/create", usersController.usersCreatePost);

module.exports = usersRouter;

  • index.ejsは、これまでに作成したすべてのユーザーを一覧表示します。
  • createUser.ejsは、私たちのユーザー作成フォームを表示します。

このルーターのロジックは、私たちのコントローラーの中に置きます:

// controllers/usersController.js
const usersStorage = require("../storages/usersStorage");

exports.usersListGet = (req, res) => {
  res.render("index", {
    title: "User list",
    users: usersStorage.getUsers(),
  });
};

exports.usersCreateGet = (req, res) => {
  res.render("createUser", {
    title: "Create user",
  });
};

exports.usersCreatePost = (req, res) => {
  const { firstName, lastName } = req.body;
  usersStorage.addUser({ firstName, lastName });
  res.redirect("/");
};

そして、作成したユーザーを保持するために、ストレージクラスを使います。実際のシナリオでは、これにはほぼ間違いなくデータベースを使うことになりますが、それについては今後のレッスンでさらに探っていきます。このクラスは、そこにたどり着く前の、実演目的だけのものです。

// storages/usersStorage.js
// This class lets us simulate interacting with a database.
class UsersStorage {
  constructor() {
    this.storage = {};
    this.id = 0;
  }

  addUser({ firstName, lastName }) {
    const id = this.id;
    this.storage[id] = { id, firstName, lastName };
    this.id++;
  }

  getUsers() {
    return Object.values(this.storage);
  }

  getUser(id) {
    return this.storage[id];
  }

  updateUser(id, { firstName, lastName }) {
    this.storage[id] = { id, firstName, lastName };
  }

  deleteUser(id) {
    delete this.storage[id];
  }
}
// Rather than exporting the class, we can export an instance of the class by instantiating it.
// This ensures only one instance of this class can exist, also known as the "singleton" pattern.
module.exports = new UsersStorage();

サーバーは以下でテストできます: node --watch app.js。

http://localhost:3000/createで新しいユーザーを追加できるようになり、またhttp://localhost:3000/で既存のすべてのユーザーを一覧表示できるようになったことがわかるはずです。

望んでいる種類のデータを取得できるように、フォームのバリデーションとサニタイゼーションのためのメソッドを、いくつかusersController.jsに追加してみましょう。

// This just shows the new stuff we're adding to the existing contents
const { body, validationResult, matchedData } = require("express-validator");

const alphaErr = "must only contain letters.";
const lengthErr = "must be between 1 and 10 characters.";

const validateUser = [
  body("firstName").trim()
    .isAlpha().withMessage(`First name ${alphaErr}`)
    .isLength({ min: 1, max: 10 }).withMessage(`First name ${lengthErr}`),
  body("lastName").trim()
    .isAlpha().withMessage(`Last name ${alphaErr}`)
    .isLength({ min: 1, max: 10 }).withMessage(`Last name ${lengthErr}`),
];

// We can pass an entire array of middleware validations to our controller.
exports.usersCreatePost = [
  validateUser,
  (req, res) => {
    const errors = validationResult(req);
    if (!errors.isEmpty()) {
      return res.status(400).render("createUser", {
        title: "Create user",
        errors: errors.array(),
      });
    }
    const { firstName, lastName } = matchedData(req);
    usersStorage.addUser({ firstName, lastName });
    res.redirect("/");
  }
];

matchedData()関数を介してバリデーション済みのすべてのデータを取得し、取得するすべてのデータに、行われたサニタイゼーション(トリムされたデータなど)が確実に反映されるようにします。

そして今度は、これらのエラーをレンダリングするために、createUser.ejsビューを更新する必要があります。新しいパーシャルを作成しましょう。viewsフォルダの中に、partialsという新しいフォルダを作成し、その中にerrors.ejsを作成してください:

<!-- views/partials/errors.ejs -->
<% if (locals.errors) {%>
  <ul>
    <% errors.forEach(function(error) { %>
      <li><%= error.msg %></li>
    <% }); %>
  </ul>
<% } %>

そして、createUser.ejsの中の、フォームのすぐ上にこのパーシャルをincludeします。

<%- include("partials/errors.ejs") %>

もしフォームが正しく入力されていなければ、ページにすべてのエラーが表示されるのがわかるはずです。

これでユーザーを作成できるようになりましたが、それらを変更する方法も必要です。IDと更新したい値を指定できるフォームを作るために、updateUser.ejsという新しいビューを作成しましょう。

<!-- views/updateUser.ejs -->
<!DOCTYPE html>
<html>
  <head>
    <title><%= title %></title>
  </head>
<body>
  <h1><%= title %></h1>
  <%- include("partials/errors.ejs") %>
  <form action="/<%= user.id %>/update" method="POST">
    <input type="text" name="firstName" value="<%= user.firstName %>" required>
    <input type="text" name="lastName" value="<%= user.lastName %>" required>
    <button type="submit">Update User</button>
  </form>
  <a href="/">Back to home</a>
</body>
</html>

そのルートへのGETリクエストを行えるように、それぞれのユーザーの横に新しい「Update」ボタンを含めるために、index.ejsを修正します:

<li>
  ID: <%= user.id %>, Name: <%= user.firstName %> <%= user.lastName %>
  <a href="/<%= user.id %>/update">Update</a>
</li>

ユーザー作成用のルートを追加したのとまったく同じように、更新用のルートも追加します:

usersRouter.get("/:id/update", usersController.usersUpdateGet);
usersRouter.post("/:id/update", usersController.usersUpdatePost);

それから、これらのリクエストのロジックをコントローラーに追加します:

exports.usersUpdateGet = (req, res) => {
  const user = usersStorage.getUser(req.params.id);
  res.render("updateUser", {
    title: "Update user",
    user: user,
  });
};

exports.usersUpdatePost = [
  validateUser,
  (req, res) => {
    const user = usersStorage.getUser(req.params.id);
    const errors = validationResult(req);
    if (!errors.isEmpty()) {
      return res.status(400).render("updateUser", {
        title: "Update user",
        user: user,
        errors: errors.array(),
      });
    }
    const { firstName, lastName } = matchedData(req);
    usersStorage.updateUser(req.params.id, { firstName, lastName });
    res.redirect("/");
  }
];

これでユーザーを更新できるようになったことがわかるはずで、これはユーザーを作成する方法ととてもよく似ています。

最後に、index.ejsビューの中に、もう一つ別のフォームを追加することから始めて、ユーザーを削除する方法も追加しましょう。

<!-- In views/index.ejs -->
<ul>
  <% if (locals.users) { %>
    <% users.forEach(function(user) { %>
      <li>
        ID: <%= user.id %>, Name: <%= user.firstName %> <%= user.lastName %>
        <a href="/<%= user.id %>/update">Update</a>
        <!-- This time we're sending a POST request to our route, so we need a form. -->
        <form action="/<%= user.id %>/delete" method="POST" style="display:inline;">
          <button type="submit" onclick="return confirm('Are you sure you want to delete this user?');">Delete</button>
        </form>
      </li>
    <% }); %>
  <% } %>
</ul>

それから、そのリクエストを処理するロジックをコントローラーに追加します:

exports.usersDeletePost = (req, res) => {
  usersStorage.deleteUser(req.params.id);
  res.redirect("/");
};

新しいルートをルーターに追加するのを忘れないでください!

usersRouter.post("/:id/delete", usersController.usersDeletePost);

すでに/にリダイレクトしているため、ここではGETルートが必要なかったことに気づくでしょう。

フォームを安全に扱うことについては、もっと深く掘り下げることもできますが、ここで止めておきましょう。ここまでで、express-validatorがどれほど役立つか、そしてreq.bodyオブジェクトを使ってほぼどんなことでもできることが、すでにわかったはずです。

検索を実装する

何千人もいるユーザーのリストから、特定のユーザーを検索したい場合はどうすればよいでしょうか?クライアントが私たちのユーザーのリストを検索できるようにする、新しいルートとビューが必要です。

  1. nameまたはemail(あるいはその両方!)を受け付ける、GETメソッドのフォームを(createUser.ejsか別のビューに)追加してください。
  2. GETリクエストを受け付ける、新しいルート/searchを作成してください。
  3. あなたのコントローラーに、一致するユーザーをリストから検索する検索ロジックを追加してください。GETリクエストを介して送信されたフォームデータは、req.bodyでは利用できません。代わりにreq.queryを使う必要があります。
    • あなたのGETリクエストは、ユーザーの検索を処理し、それから検索結果をレンダリングする必要があります。
  4. 検索結果を、新しいビューsearch.ejsに表示してください。
