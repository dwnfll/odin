Environment Variables

日本語訳

← nodeJS

We learn about environment variables and how to use them.

イントロダクション

あなたがコードを実行するとき、そのコードは特定の環境の中で実行されます。別のマシンでコードを実行する?それは異なる環境です。NetlifyやVercelのようなところにウェブサイトをホストする?それはあなたのマシンとは異なる環境です。それぞれの環境は、ツールと設定の一意な組み合わせです。

あなたはこれまで確実に、異なる引数で何度も呼び出す関数をたくさん書いてきたはずです。その関数は、それらの引数に応じて、異なる振る舞いをしたり、異なる値を返したりするかもしれません。関数のパラメータとまったく同じように、あなたのアプリケーション自体も環境変数を利用できます。コードを実行するとき、それらの環境変数に値を渡すことができ、異なる環境には異なる値を与えることができます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • 環境変数とは何か、そしてその利点を説明する。
  • .envファイルを使って、コードの中で環境変数を保存し利用できるようにする。
  • Nodeのprocess.envオブジェクトを使って環境変数にアクセスする。

環境変数

環境変数とは、単に環境固有の値を持つ変数です。例えば、これらは個々の環境に固有であるため、次のような目的で使うことができます:

  • ソースコードを変更することなく、開発中の自分のマシンとデプロイ時のウェブサイトホストのように、異なる環境に異なる値を提供する。
  • データベースのURLや認証情報、APIキーといった機密情報を保存する。

例えば、本番環境では、開発環境と比べて追加のログ記録や分析が欲しいかもしれません。そのため、ソースコードには、それが「dev」モードで動いているか「prod」モードで動いているかについての環境変数があり、それに基づいて異なることを行うかもしれません。これは非常によくあることで、慣習として、この環境変数はNODE_ENVという名前が付けられていますが、他のどんな名前でも問題なく機能します。

あるいは、データベースに接続されたAPIを構築していて、本番用のデータベースの代わりに、開発中は別のテスト用データベースを使いたい場合もあるでしょう。ローカルで開発するときは、テスト用データベースのURLと認証情報をアプリに渡し、デプロイ時には本番用データベースの値を渡すことができます。それに加えて、環境変数の値を、.gitignoreに追加したファイルに保存しておくことで、変更がプッシュされたときにそのファイルの内容が公開されてしまうのを防ぐことができます。

環境変数を読み込む

環境変数を読み込む方法は複数ありますが、中にはより面倒なものや、多くのNodeバージョンでまだ安定してサポートされていないものもあります。一つの方法は、コードを実行するコマンドの中に、環境変数とその値を直接定義することです。単にnode index.jsでアプリを実行する代わりに、以下のように実行できます(スペースや=のような特定の特殊文字を含まない値については、引用符は省略可能であることに注意してください):

NODE_ENV=prod VIDEO_URL="https://www.youtube.com/watch?v=X2CYWg9-2N0" node index.js

上の例では、NODE_ENVとVIDEO_URLという環境変数を定義し、それぞれに値を割り当てています。これで、これらの変数を使うコードのどの部分でも、関数のパラメータとまったく同じように、それらの値が使われるようになります!環境変数の命名規則は、UPPER_SNAKE_CASEを使うことです(時に親しみを込めてSCREAMING_SNAKE_CASEやSHOUTY_CASEと呼ばれることもあります)。

しかし、特に環境変数がたくさんある場合、これはすぐにかなり面倒になってしまうことがわかるでしょう。データベースの認証情報のような機密データがある場合は、さらに悪いことになります。というのも、それらの値がnpmスクリプトの中に含まれているpackage.jsonをプッシュしたくはないはずだからです!

export

コードを実行するコマンドの中に環境変数を直接設定する代わりに、シェルコマンドのexportを使うことができます。これは、環境変数とその値を現在のシェルセッションに保存します。

export NODE_ENV=prod VIDEO_URL="https://www.youtube.com/watch?v=X2CYWg9-2N0"

上のコマンドは、現在のシェル環境にのみ、この2つの環境変数を設定します。つまり、もし新しいシェルを開いたとすると、それは新しい環境であるため、それらの環境変数にアクセスすることはできません。もし最初のシェル(環境変数が設定されているほう)でnode index.jsを実行すれば、NODE_ENV環境変数を使うものはすべて、"prod"という値を持つことになります。代わりに2番目のシェルでnode index.jsを実行すれば、その環境には何も設定されていないため、代わりにundefinedという値になります。なかなか面白いですよね?

これは間違いなく、先ほどのコマンドに直接書き込む方法よりも良く、機密データを本当に隠しておけることを意味します。何らかの変数を上書きするには、上記のように、その変数の新しい値でexportを再実行するだけです。

現在のシェルにあるすべての環境変数を見るには、printenvを実行します。ちょっと待ってください、私たちが自分で設定した覚えのないものがたくさん表示されています!これは、シェル自体が、最初に読み込まれる際にすでに多くの環境変数を設定し読み込んでいるからです。これは少し煩わしいですね、私たちはただ自分のアプリの環境変数だけを扱いたいのに!それに、シェルを終了すると、私たちの環境変数は失われてしまいます。もしたくさんの変数があったらどうでしょうか?それらすべてを覚えておいて、新しいシェルで再びexportするのは悪夢でしょう。そこで……

Nodeのenvファイル

Node(v24.10時点)には、環境変数を含むファイルのための、組み込みの安定したサポートがあります。プロジェクトのルートに(慣習として).envというファイルを作成でき、そこにはNAME=VALUEという形式で、すべての環境変数が含まれます。例えば:

# .env

NODE_ENV=prod
VIDEO_URL="https://www.youtube.com/watch?v=X2CYWg9-2N0"

機密情報が公開されてしまわないようにするため、このファイルは必ず.gitignoreファイルに追加する必要があります!

Nodeは、これを読み込むためのいくつかの方法を提供しています。例えば、--env-file CLIオプションを使う方法(これにより、例えばnode --env-file=.env index.jsを実行できます)や、JavaScriptの中で直接process.loadEnvFile()メソッドを使う方法です。これらはどちらも、.envファイルが見つからない場合、エラーをスローします。

環境変数とデプロイ

環境変数を使うアプリをデプロイする際、あなたのリポジトリには.envファイルが含まれていないため、選んだデプロイサービスが環境変数の値の設定をどう扱っているかを調べる必要があります。通常は、そのサービスのウェブサイトのインターフェースを通じて設定する方法があるはずですが、そうでない場合は、必ずそのドキュメントを確認してください!

このため、開発時と同じように本番環境でも変数を読み込みたいとは思わないはずです。というのも、.envファイルが見つからない場合、おそらくエラーがスローされてしまうからです。代わりに、--env-fileを使わない本番用のnpmスクリプトを追加したり、--env-file-if-existsというCLIオプションを使ったり、process.loadEnvFile()でエラーハンドリングを実装したりといった、さまざまな方法でそれを防ぐことができます。

dotenv

Nodeには、常に環境変数ファイルのための組み込みサポートがあったわけではありません。実際の現場では、dotenvのようなライブラリが使われているのをよく見かけるでしょう。原理は組み込み機能と同じで、そのライブラリ固有の指示が必要になるだけです。そうしたライブラリは、Nodeに組み込まれていない、より洗練された機能を提供していることもあり、より複雑なプロジェクトに取り組んでいるチームにとっては有益かもしれませんが、TOPに関する限り、それらは必要ないでしょう。

とにかく、素晴らしいですね!これで環境変数を読み込めるようになりましたが、実際にコードの中でそれらにどうやってアクセスするのでしょうか?

環境変数にアクセスする

環境変数には、Nodeの組み込みprocessオブジェクト、より具体的にはそのenvプロパティを介してアクセスします。Nodeは、各環境変数を、その名前をプロパティとしてprocess.envオブジェクトに読み込みます。それから、通常のオブジェクトのプロパティと同じようにそれらにアクセスできます。

if (process.env.NODE_ENV === "prod") {
    // do production-specific stuff
}

// don't want to ruin the surprise by hardcoding the URL!
// it might even change every few days!
redirectUserToSuperSecretVideo(process.env.VIDEO_URL);

それらの値をソースコードにハードコーディングする必要はありません!環境変数の値を変更したい場合は、.envファイルの中でそれを変更してから、プログラムを再実行するだけです。また、環境変数は常に文字列であるため、例えば数値や真偽値として使いたい場合は、変換する必要があることにも注意してください。

環境変数をドキュメント化する

あなたのプロジェクトに環境変数が含まれている場合、あなたを助けてくれる人たちは、プロジェクトを実行するためにどの環境変数が必要かを知る必要があります。そのため、どれが必須で、それぞれ何を含めるべきかといったことを、README.mdファイルにドキュメント化しておくことを強くお勧めします。他の人がリネームしてから必要な値で編集できるような、.env.sampleといったダミーの例の.envファイルを含めておくこともできます。

課題

あなたの秘密を守ってください!

環境変数は機密データのためだけのものではありませんが、そのために使うことがよくあります。あなたのプロジェクトでは、必ず.gitignoreに.envを追加し、それを公開しないようにしてください。
