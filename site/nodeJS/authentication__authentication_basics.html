Authentication Basics

日本語訳

← nodeJS

Learn the basics of authentication with passportJS and bcrypt

イントロダクション

ユーザーを作成し、あなたのウェブアプリにログイン・ログアウトできるようにすることは、極めて重要な機能であり、いよいよそれを学ぶ準備ができました!ここには、それなりの量のセットアップが必要ですが、ありがたいことに、そのどれも特にトリッキーではありません。あっという間に使えるようになりますよ!このレッスンでは、私たちの代わりに認証とセッションを処理してくれる優れたミドルウェアである、passport.jsを使っていきます。

ユーザーがサインアップ、ログイン、ログアウトできる、非常に最小限のExpressアプリを構築していきます。今のところ、実演をしやすくするために、ビュー以外のすべてを一つのファイルにまとめておきますが、実際のプロジェクトでは、関心事や機能を別々のモジュールに分割するのがベストプラクティスです。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Passport.jsに必要なミドルウェアの使用順序を理解する。
  • Passport.jsのStrategyとは何かを説明する。
  • LocalStrategyを使ってユーザーを認証する。
  • 認証におけるクッキーの目的を説明する。
  • これまでの学習教材(ルート、テンプレート、ミドルウェア、async/await、Promise)を復習する。
  • Passport.jsを使って、Expressでのユーザー認証をセットアップする。
  • bcryptとは何か、その使い道を説明する。
  • ハッシュとは何か、そしてパスワードのハッシュ化の重要性を説明する。
  • bcryptのcompare関数を説明する。

セットアップ

始める前に、psqlの中に新しいデータベースを作成してください。

まず、usersテーブルをセットアップしましょう。そこで、usernamesの代わりに、usersテーブルを作成します。

CREATE TABLE users (
   id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
   username VARCHAR ( 255 ),
   password VARCHAR ( 255 )
);

次に、非常に最小限のExpressアプリをセットアップしましょう。新しいディレクトリを作成し、npm initを使ってpackage.jsonファイルを開始してから、以下を実行して必要なすべての依存関係をインストールしてください:

npm install express express-session pg passport passport-local ejs

パスワードを保護する

今のところ、私たちはユーザーを単なるプレーンテキストのパスワードで保存しています。これは、実際のプロジェクトにとっては本当に良くない考えです。このレッスンの最後で、bcryptを使ってこれらのパスワードを適切に保護する方法を学びます。その部分を飛ばさないでください。

/////// app.js

const path = require("node:path");
const { Pool } = require("pg");
const express = require("express");
const session = require("express-session");
const passport = require("passport");
const LocalStrategy = require('passport-local').Strategy;

const pool = new Pool({
  // add your configuration
});

const app = express();
app.set("views", path.join(__dirname, "views"));
app.set("view engine", "ejs");

app.use(session({ secret: "cats", resave: false, saveUninitialized: false }));
app.use(passport.session());
app.use(express.urlencoded({ extended: false }));

app.get("/", (req, res) => res.render("index"));

app.listen(3000, (error) => {
  if (error) {
    throw error;
  }
  console.log("app listening on port 3000!");
});

これまでのところ、新しく必要になったexpress-sessionとpassportというモジュール以外は、ほとんど見覚えがあるはずです。実は、私たちがexpress-sessionを直接使うことはありません。これは、passport.jsが背後で使っている依存関係です。express-sessionパッケージが何をしているかについては、Expressのドキュメントで見ることができます。

私たちのビューエンジンはviewsの中のindex.ejsを探しているので、それを作成しましょう:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Home</title>
</head>
<body>
  <h1>hello world!</h1>
</body>
</html>

ユーザーを作成する

まず必要なのは、認証するユーザーを実際に作成できるようにするための、サインアップフォームです!簡潔にするため、ここではサニタイゼーションとバリデーションは省略します。ただし、その段階に到達したときには、それを忘れないでください。後ほどそれらを適用する機会があります。

sign-up-formという新しいテンプレートと、それを指す/sign-up用のルートを作成してください:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Sign Up</title>
</head>
<body>
  <h1>Sign Up</h1>
  <form action="/sign-up" method="POST">
    <label for="username">Username</label>
    <input id="username" name="username" placeholder="username" type="text" />
    <label for="password">Password</label>
    <input id="password" name="password" type="password" />
    <button type="submit">Sign Up</button>
  </form>
</body>
</html>
//// app.js

app.get("/sign-up", (req, res) => res.render("sign-up-form"));

次に、私たちのデータベースにユーザーを追加できるように、サインアップフォーム用のapp.postを作成してください(サニタイゼーションについてのメモや、パスワードをプレーンテキストで保存していることを忘れないでください……)。

app.post("/sign-up", async (req, res, next) => {
  try {
    await pool.query("INSERT INTO users (username, password) VALUES ($1, $2)", [
      req.body.username,
      req.body.password,
    ]);
    res.redirect("/");
  } catch(err) {
    return next(err);
  }
});

改めて言っておきますが、これはデータベースにユーザーを作成する上で、特に安全な方法ではありません……。しかし、これで/sign-upにアクセスし、フォームを送信できるようになったはずです。すべてがうまくいけば、indexにリダイレクトされ、データベースの中に新しく作成されたユーザーを見に行くことができるようになります。psqlでデータベースを開き、クエリを実行して、最初のユーザーを見てみましょう!

認証

これでデータベースにユーザーを入れられるようになったので、彼らがログインして、ホームページで特別なメッセージを見られるようにしましょう!このプロセスを一つずつ順に進めていきますが、まずは少し時間を取って、passport.jsのウェブサイトを眺めてみてください。ここのドキュメントには、それをセットアップするために必要なことがほとんどすべて書かれています。プロジェクトに取り組む際には、これに立ち返って参照したくなるはずです。

Passport.jsは、ユーザーを認証するためにStrategyと呼ばれるものを使います。彼らには500種類以上のこうしたstrategyがありますが、私たちは、最も基本的な(そして最も一般的な)もの――ユーザー名とパスワードによるもの、彼らがLocalStrategyと呼ぶもの――に焦点を当てていきます(LocalStrategyのドキュメント)。すでに適切なモジュールをインストールしrequireしてあるので、それをセットアップしていきましょう!

app.jsファイルに3つの関数を追加し、それから私たちの/log-inパス用にapp.postを追加する必要があります。

関数その1: LocalStrategyをセットアップする

passport.use(
  new LocalStrategy(async (username, password, done) => {
    try {
      const { rows } = await pool.query("SELECT * FROM users WHERE username = $1", [username]);
      const user = rows[0];

      if (!user) {
        return done(null, false, { message: "Incorrect username" });
      }
      if (user.password !== password) {
        return done(null, false, { message: "Incorrect password" });
      }
      return done(null, user);
    } catch(err) {
      return done(err);
    }
  })
);

この関数は、後ほどpassport.authenticate()関数を使う際に呼び出されるものです。基本的には、ユーザー名とパスワードを受け取り、私たちのDBの中でユーザーを見つけようとし、それからそのユーザーのパスワードが与えられたパスワードと一致することを確認します。それらすべてがうまくいけば(DBにユーザーが存在し、パスワードが一致すれば)、私たちのユーザーを認証して先に進みます!この関数を直接呼び出すことはないので、done関数を自分で用意する必要はありません。この関数は少しミドルウェアのように振る舞い、後ほどpassportに認証を依頼する際に、私たちの代わりに呼び出されます。

関数その2とその3: セッションとシリアライゼーション

私たちのユーザーがログインしていることを確認し、アプリの中を移動している間ずっとログインし続けられるようにするために、passportは内部でexpress-sessionの関数を呼び出し、いくつかのデータを使ってconnect.sidと呼ばれるクッキーを作成し、それがユーザーのブラウザに保存されます。この次の2つの関数は、クッキーを作成し、それからそれをデコードする際に、passportがどのようなデータを探しているかを定義します。これらの関数を私たちに定義させる理由は、passportが探しているデータが実際に私たちのデータベースに存在することを、確実に確認できるようにするためです!passport.serializeUserは、セッションデータに保存したい情報を含むコールバックを受け取ります。passport.deserializeUserはセッションを取得する際に呼び出され、そこで私たちが「シリアライズ」したデータを取り出し、最終的にリクエストオブジェクトの.userプロパティ(req.user)に何かをアタッチして、リクエストの残りの部分で使えるようにします。

私たちの目的のためには、passportのドキュメントに載っている関数がそのままうまく機能します:

passport.serializeUser((user, done) => {
  done(null, user.id);
});

passport.deserializeUser(async (id, done) => {
  try {
    const { rows } = await pool.query("SELECT * FROM users WHERE id = $1", [id]);
    const user = rows[0];

    done(null, user);
  } catch(err) {
    done(err);
  }
});

セッションが作成されると、passport.serializeUserは、ログイン成功時に見つかったuserオブジェクトを受け取り、そのidプロパティをセッションデータに保存します。その後の何らかのリクエストの際、そのリクエストに一致するセッションが見つかれば、passport.deserializeUserはセッションデータに保存しておいたidを取得します。それから、そのidを使って指定されたユーザーをデータベースにクエリし、done(null, user)がそのuserオブジェクトをreq.userにアタッチします。これで、リクエストの残りの部分で、req.userを介してそのuserオブジェクトにアクセスできるようになります。

繰り返しになりますが、これらの関数を自分で呼び出すことはなく、ただ定義するだけでよく、それらはpassportによって背後で使われます。

ログインフォーム

それでは、indexテンプレートに直接ログインフォームを追加してみましょう。このフォームは、私たちのサインアップフォームとまったく同じように見えますが、/sign-upにPOSTする代わりに、actionを追加して、代わりに/log-inにPOSTするようにします。以下をindexテンプレートに追加してください:

<h1>please log in</h1>
<form action="/log-in" method="POST">
  <label for="username">Username</label>
  <input id="username" name="username" placeholder="username" type="text" />
  <label for="password">Password</label>
  <input id="password" name="password" type="password" />
  <button type="submit">Log In</button>
</form>

……そして、いよいよ魔法のような部分です!このルートをapp.jsファイルに追加してください:

app.post(
  "/log-in",
  passport.authenticate("local", {
    successRedirect: "/",
    failureRedirect: "/",
    failureMessage: true,
  })
);

ご覧の通り、私たちがしなければならないのは、passport.authenticate()を呼び出すことだけです。このミドルウェアは、裏側で数多くの機能を実行します。その中でも、リクエストボディの中からusernameとpasswordという名前のパラメータを探し、先ほど定義したLocalStrategy関数を実行して、そのユーザー名とパスワードがデータベースに存在するかどうかを確認します。それから、ユーザーのブラウザに保存されるセッションクッキーを作成し、それが今後のすべてのリクエストで、そのユーザーがログインしているかどうかを確認するために使われます。ログインが成功したか失敗したかに応じて、異なるルートにリダイレクトすることもできます。先ほど定義したエラーメッセージにアクセスするために、failureMessageに真偽値を渡すことができ、それを後で後続のミドルウェアの中でreq.session.messages配列を通してアクセスできます。

もし別々のログインページがあったなら、ログインが失敗した場合はそこに戻りたいと思うかもしれませんし、ログインが成功した場合はユーザーのダッシュボードに連れて行きたいと思うかもしれません。私たちはすべてをindexにまとめているので、どちらの場合でも/に戻りたいところです。

今フォームに記入して送信すると、技術的にはすべてうまくいくはずですが、実際にはページ上で何も変わったようには見えません……それを直しましょう。

passportミドルウェアは、ログインしているユーザーがいるかどうかを(reqオブジェクトとともに送られてくるクッキーを確認することで)チェックし、もしいれば、そのユーザーを私たちの代わりにリクエストオブジェクトに追加してくれます。そのため、私たちがすべきことは、ユーザーがログインしているかどうかに応じてビューを変えるために、req.userをチェックすることだけです。

app.get("/")を編集して、以下のようにユーザーオブジェクトをビューに送信するようにしてください:

app.get("/", (req, res) => {
  res.render("index", { user: req.user });
});

そして、以下のように、そのオブジェクトを使うようにビューを編集してください:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Log In</title>
</head>
<body>
  <% if (locals.user) {%>
    <h1>WELCOME BACK <%= user.username %></h1>
    <a href="/log-out">LOG OUT</a>
  <% } else { %>
    <h1>please log in</h1>
    <form action="/log-in" method="POST">
      <label for="username">Username</label>
      <input id="username" name="username" placeholder="username" type="text" />
      <label for="password">Password</label>
      <input id="password" name="password" type="password" />
      <button type="submit">Log In</button>
    </form>
  <%}%>
</body>
</html>

つまり、このコードは、ユーザーが定義されているかどうかをチェックします……もし定義されていれば歓迎のメッセージを表示し、そうでなければログインフォームを表示します。素敵ですね!

最後の仕上げとして……そのログアウトリンクを実際に機能させましょう。ご覧の通り、それは私たちを/log-outに送っているので、app.jsにそのためのルートを追加するだけで済みます。都合の良いことに、passportミドルウェアはreqオブジェクトにlogout関数を追加してくれているため、ログアウトはこれくらい簡単です:

app.get("/log-out", (req, res, next) => {
  req.logout((err) => {
    if (err) {
      return next(err);
    }
    res.redirect("/");
  });
});

これで、/sign-upにアクセスして新しいユーザーを作成し、そのユーザーのユーザー名とパスワードを使ってログインし、それからログアウトボタンをクリックしてログアウトできるようになったはずです!

ちょっとしたヒント

Expressでは、localsオブジェクトを使って、アプリ全体(ビューの中でさえも)でさまざまなローカル変数を設定したりアクセスしたりできます。この知識を使って、ビューの中で現在のユーザーにアクセスする方法をシンプルにしてくれる、カスタムミドルウェアを自分で書くことができます。

ミドルウェア関数とは、reqオブジェクトとresオブジェクトを受け取り、それらを操作して、アプリの残りの部分に渡していく関数のことです。

app.use((req, res, next) => {
  res.locals.currentUser = req.user;
  next();
});

このコードを、passportミドルウェアをインスタンス化する場所と、ビューをレンダリングする場所の間のどこかに挿入すれば、すべてのビューの中でcurrentUser変数にアクセスできるようになり、それが必要なすべてのコントローラーに手動で渡す必要がなくなります。

bcryptでパスワードを保護する

さて、話を戻して、何か問題が起きたときや、誰かが私たちのデータベースへのアクセス権を得てしまったときのために、ユーザーのパスワードを安全に保存する方法を学びましょう。これは、たとえ最も基本的なアプリであっても、非常に重要なことです。

まずnpm install bcryptjsしてください。bcryptという同じことを行う別のモジュールもありますが、これはC++で書かれており、インストールするのが少し面倒なこともあります。C++のbcryptは技術的にはより高速なので、将来的にはそれを動かす価値があるかもしれませんが、今のところ、両方のモジュールは同じように機能するので、単にbcryptjsを使えば十分です。

インストールしたら、app.jsの一番上でそれをrequireする必要があり、それから、パスワードをDBに保存する場所と、LocalStrategyの中でパスワードを比較する場所で、それを使っていきます。

ハッシュ化されたパスワードを保存する

パスワードハッシュは、ユーザーのパスワードを一方向ハッシュ関数に通した結果であり、この関数は可変サイズの入力を固定サイズの疑似ランダムな出力にマッピングします。

app.post("/sign-up")を編集して、以下のように機能するbcrypt.hash関数を使うようにしてください:

//Don't forget to import bcrypt!
const bcrypt = require("bcryptjs");

//...

app.post("/sign-up", async (req, res, next) => {
 try {
  const hashedPassword = await bcrypt.hash(req.body.password, 10);
  await pool.query("INSERT INTO users (username, password) VALUES ($1, $2)", [req.body.username, hashedPassword]);
  res.redirect("/");
 } catch (error) {
    console.error(error);
    next(error);
   }
});

2番目の引数は、ハッシュ関数で使う「ソルト」の長さです。パスワードにソルトを加えるとは、余分なランダムな文字をそれに追加することを意味し、パスワードとその余分なランダムな文字が、それからハッシュ関数に入力されます。ソルトは、同じパスワードを使っているユーザーであっても、パスワードハッシュの出力を一意にするため、そしてレインボーテーブルや辞書攻撃から保護するために使われます。

通常、ソルトはハッシュ化された値と一緒にデータベースに保存されます。しかし、私たちの場合、bcryptjsのハッシュアルゴリズムがソルトをハッシュ自体の中に自動的に組み込むため、ソルトを別々に保存する必要はありません。

hash関数は多少遅いため、すべてのDBストレージ関連の処理はコールバックの中に置く必要があります。パスワード付きで新しいユーザーをサインアップさせて、これがうまく機能しているか確認してみてください。それから、DBのエントリを見に行って、それがどのように保存されているかを確認してください。正しく行えていれば、あなたのパスワードは、本当に長いランダムな文字列に変換されているはずです。

ハッシュ化がどのように機能するか、特にパスワードの文脈においては、このレッスンの範囲外であることに注意することが重要です。

ハッシュ化されたパスワードを比較する

パスワード入力を検証するために、bcrypt.compare()関数を使います。この関数は、リクエストオブジェクトの中のプレーンテキストのパスワードを、ハッシュ化されたパスワードと比較します。

LocalStrategy関数の中で、user.password !== passwordという式をbcrypt.compare()関数に置き換える必要があります。

const match = await bcrypt.compare(password, user.password);
if (!match) {
  // passwords do not match!
  return done(null, false, { message: "Incorrect password" })
}

これで、あなたが作成した新しいユーザー(ハッシュ化されたパスワードを持つユーザー)を使ってログインできるようになったはずです。残念ながら、bcryptを追加する前に保存されたユーザーはもう機能しなくなりますが、それはセキュリティのために支払う小さな代償です!(そして、次のプロジェクトでは最初からbcryptを含めておくべき、良い理由でもあります)
