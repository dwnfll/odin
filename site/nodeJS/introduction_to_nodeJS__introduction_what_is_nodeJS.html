Introduction: What is NodeJS?

Lets take a look at what Node is, and what it means to write code for a server.

イントロダクション

NodeJS(あるいは単に「Node」)は、2009年の誕生以来、着実に人気を高めてきました。インターネットにはNodeについてのコースや記事があふれており、それをインストールすることはほぼどんなバックエンド開発の仕事においても前提条件となっており、そしてもちろん、その知識を必要とする仕事の数も増え続けています。

Nodeとは何ですか?

Node.jsのウェブサイトには、次のように書かれています:

非同期のイベント駆動型JavaScriptランタイムとして、Nodeはスケーラブルなネットワークアプリケーションを構築するために設計されています。

これは、少しかみ砕く必要のある定義です。

最初に理解しておくべき重要な点は、Nodeが「JavaScriptランタイム」であるということです。JavaScriptが最初に作られたとき、それはブラウザの中で動作するように設計されていました。つまり、JavaScriptを使ってウェブサイト以外の種類のプログラムを書くことは不可能だった、ということです。Nodeは、JavaScriptをブラウザの世界の外へと連れ出します。これにより、開発者はJavaScriptを使って、Ruby、PHP、C#、Pythonのような他の人気のあるサーバーサイド言語ができることのほぼすべてを実現できるようになります。つまり、最も基本的なレベルで言えば、Nodeを使うことで、ウェブブラウザを介することなく、ローカルのコンピュータやサーバーのようなマシン上でJavaScriptのコードを実行できるようになるのです。

これを実現するために、Nodeには、ローカルファイルの読み書き、HTTP接続の作成、ネットワークリクエストのリッスンといった、ブラウザベースのJavaScriptには見られない機能がいくつか追加されています。

イベント駆動

Nodeのウェブサイトの定義に戻りましょう: Nodeは非同期のイベント駆動型JavaScriptランタイムです。ここでの非同期とは、コードを書くとき、すべての行が実行される正確な順序を予測しようとしない、ということを意味します。代わりに、ネットワークリクエストのような特定のイベントに応じて呼び出される、より小さな関数の集まりとして、コードを書きます(イベント駆動)。

例えば、あなたがプログラムを書いていて、それに以下のことをさせる必要があるとしましょう。ファイルからテキストを読み込み、そのテキストをコンソールに出力し、データベースにユーザーのリストを問い合わせ、年齢に基づいてユーザーをフィルタリングする、というものです。

コードにこれらのステップを、以下のように順番に行うよう指示する代わりに:

  1. ファイルを読み込む
  2. ファイルの内容を出力する
  3. データベースに問い合わせる
  4. データベースの問い合わせ結果をフィルタリングする

以下のように、タスクを分割できます:

  1. ファイルを読み込む それから ファイルの内容を出力する
  2. データベースに問い合わせる それから データベースの問い合わせ結果をフィルタリングする。

このプログラムを実行すると、Nodeは最初から始めて、ファイルの読み込みを開始します。しかし、それには少し時間がかかる処理であるため、ファイルの読み込みが終わるのを待っている間に、すぐに2番目のステップ(データベースへの問い合わせ)の実行を開始します。

これら2つの処理が実行されている間、Nodeは座ってイベントを待ちます。この場合、ファイルの読み込みとデータベースへの問い合わせという、両方の処理の完了を待っています。これらのタスクのどちらかが終わると、Nodeはイベントを発火させ、私たちが定義した次の関数を実行します。そのため、ファイル読み込みの処理が先に終われば、ファイルの内容を出力します。データベースへの問い合わせが先に終われば、フィルタリングの処理を開始します。プログラマーとしては、2つの処理がどちらの順序で完了するかを知る必要も、気にする必要もありません。もしこのコードが(非同期ではなく)同期的に処理されていたら、次のステップに進む前にプログラムの各ステップを待たなければならず、それによって処理がかなり遅くなってしまう可能性があります。もし読み込む必要のあるファイルが本当に長かったら、データベースへの問い合わせが始まる前に、数秒待たなければならないかもしれません。

このプロセスは、フロントエンドのJavaScriptで、マウスクリックやキーボード入力のようなユーザーの操作を待つためにaddEventListenerを使うのとほぼまったく同じです。主な違いは、そのイベントがネットワークリクエストやデータベースへの問い合わせのようなものになる、という点です。この機能は、コールバックを使うことによって実現されています。コールバックはNodeにとって非常に重要なので、少し時間を取って、このコールバックを理解することについての記事を読み、しっかり理解しておいてください。

実際の簡単な例を見てみましょう:

http.createServer(function (req, res) {
  res.writeHead(200, {'Content-Type': 'text/html'});
  res.end('Hello World!');
}).listen(8080);

このスニペットは、あなたがこの後すぐに進めていくことになるチュートリアルの、まさに最初のレッスンからのものです。基本的にこのコードはサーバーを作成し、「ネットワークリクエストを受け取るたびに、このコールバック関数を実行する」と言っています。この関数はたまたま、'Hello World!'というテキストで応答します。そのため、ブラウザで正しいアドレスとポートに移動すると、画面にそのテキストが表示されるはずです。

Node.jsコースにおけるReactの利用について

まずはサーバーサイドの概念に焦点を当てていくので、Reactのようなクライアントサイドのものは、より複雑なフロントエンドとバックエンドを組み合わせ始める後の段階まで取っておきます。コースは書かれている通りに進めるべきです。指示から逸脱すると、必要以上に難しくなってしまうことがあります。
