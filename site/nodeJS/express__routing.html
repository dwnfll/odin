Routing in Express

イントロダクション

前のレッスンでは、基本的なExpressアプリと、リクエストがその中を通っていく旅路を分解して見ていきました。しかし、実際のアプリでは、さまざまな種類のリクエストをさまざまな目的のために処理したいと考えるでしょう。

ルートは本質的に、リクエストのHTTP動詞(GETやPOSTなど)とURLパスを、適切なミドルウェア関数の集合――コントローラー――に一致させるだけのものです。コントローラーとミドルウェアについては、次のレッスンでより詳しく見ていきます。ここでは、ルートをどのように使えるかに飛び込んでいきましょう。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • ルートがどのように定義されるかを説明する。
  • ルートパラメータとクエリパラメータについて説明する。
  • あるパスに新しいルーターをセットアップする。

ルートの構造

前回の基本的なExpressアプリにあった、唯一のルートに戻ってみましょう。

app.get("/", (req, res) => res.send("Hello, world!"));

app.get("/" ...は、このルートが、appルーター(つまり私たちのサーバー全体です!)を通る、/パスへのあらゆるGETリクエストに一致することを教えてくれます。もし代わりに以下のようなものがあったとしたら:

app.post("/messages", (req, res) => res.send("This is where you can see any messages."));

これは、このルートがappの/messagesパスへのあらゆるPOSTリクエストに一致することを示しています。もし/messagesパスにGETリクエストを送った場合、このルートには一致しません。それぞれのHTTP動詞には、それぞれ専用のExpressルートメソッドがあり、app.all()を使えば、すべての動詞に一致するルートを作ることもできます。

HTTP動詞

HTTP動詞にはたくさんの種類がありますが、ここでは主にGET(サーバーからデータを取得するためだけに使われます)とPOST(フォームなど、サーバーにデータを送るために使われます)を使っていきます。後ほどREST APIを扱う際には、PUTやDELETEといった動詞にもよく出会うことになるでしょう。

パス

ルートに渡す最初の引数は、一致させたいパスであり、これは文字列でも正規表現でも構いません。/messagesはそれと完全に一致するパスにのみマッチしますが、/messages/allは、パスが/messages/allである場合にのみマッチします(/messagesにも/messages/newにもマッチしません)。

文字列のパスでは、{}を使って文字をオプション(省略可能)にすることもできます。例えば:

// Matches both /message and /messages
"/message{s}"

// Matches both / and /messages
"/{messages}"

// Matches both /foo/baz and /foo/bar/baz
"/foo{/bar}/baz"

*(「splat」または「ワイルドカード」)を使うと、任意の数の任意の文字に一致させることができます。Expressのパスにおけるsplatは、必ず名前を後に続ける必要があります。

splatのよくある使い道は、カスタムの404エラーハンドリングのように、他に一致しなかったすべてのパスをまとめて受け止める「キャッチオール」としてのものです。

// Matches / and /odin as well as /sdds8fjsdifhj98sdfh
"/{*splat}"

順番が重要です!

あなたのルートは、サーバーの中で定義された順番通りにセットアップされます。

app.get("/{*splat}", (req, res) => {
  res.send("/{*splat} is a great way to catch all otherwise unmatched paths, e.g. for custom 404 error handling.");
});
app.get("/messages", (req, res) => {
  res.send("This route will not be reached because the previous route's path matches first.");
});

GET /messagesリクエストが/messagesルートに一致するようにするには、ルートが定義されている順番を逆にする必要があります。そうすることで、先に/messagesルートに一致するようになるため、/{*splat}ルートに到達するのを防ぐことができます。

ルートパラメータ

もし、/odin/messagesや/thor/messages、あるいは/theodinproject79687378/messagesのように、任意のユーザー名に対応するすべてのメッセージ用のルートを持ちたい場合はどうすればよいでしょうか?React Routerのときとまったく同じように、ルートパラメータを使うことができ、パスには必要なだけいくつでもこれらのパラメータを含めることができます。

ルートパラメータを示すには、セグメントを:で始め、続けてパラメータの名前(大文字・小文字を区別する英数字か_のみで構成可能)を書きます。ルートパラメータにどんな名前を付けたとしても、Expressはそれ以降のミドルウェア関数の中で、そのパラメータ名をキーとして、パスに渡された値でreq.paramsオブジェクトを自動的に埋めてくれます。

/**
 * GET /odin/messages will have this log
 * { username: "odin" }
 *
 * GET /theodinproject79687378/messages would instead log
 * { username: "theodinproject79687378" }
 */
app.get("/:username/messages", (req, res) => {
  console.log(req.params);
  res.end();
});

/**
 * GET /odin/messages/79687378 will have this log
 * { username: "odin", messageId: "79687378" }
 */
app.get("/:username/messages/:messageId", (req, res) => {
  console.log(req.params);
  res.end();
});

これで、ミドルウェアチェーンの中で使うために、リクエストパスから値を簡単に取り出せるようになりました!

クエリパラメータ

クエリパラメータは、URLの末尾に現れる、独自の任意(オプション)の部分です。?はクエリパラメータの始まりを示し、それぞれのクエリはkey=valueという形式のキーバリューペアで、それぞれのクエリは&で区切られます。これらは特殊なもので、実際にはパス自体の一部とは見なされず、本質的には、あるパスに渡すことのできる追加の引数のようなものです。

例えば、/odin/messages?sort=date&direction=ascendingは、それでもなお/:username/messagesパスのルートに一致しますが、ミドルウェアチェーンの中でsort=dateとdirection=ascendingのキーバリューペアにアクセスできます。

Expressはリクエスト内のあらゆるクエリパラメータを自動的に解析し、見つかったすべてのキーバリューペアでreq.queryオブジェクトを埋めてくれます。もし同じキーが繰り返された場合、Expressはそのキーのすべての値を配列にまとめます。

/**
 * GET /odin/messages?sort=date&direction=ascending will log
 * Params: { username: "odin" }
 * Query: { sort: "date", direction: "ascending" }
 *
 * GET /odin/messages?sort=date&sort=likes&direction=ascending will log
 * Params: { username: "odin" }
 * Query: { sort: ["date", "likes"], direction: "ascending" }
 */
app.get("/:username/messages", (req, res) => {
  console.log("Params:", req.params);
  console.log("Query:", req.query);
  res.end();
});

YouTubeのようなウェブサイトで、すでにこれを見たことがあるかもしれません。すべてのYouTube動画にはコードが割り当てられていて、その動画を見るには、そのコードをvキーのクエリパラメータとして渡しながらhttps://www.youtube.com/watchに移動します。さらに、tキーを使って、動画を何秒地点から再生し始めるかを指定することもできます。そのため、?v=xm3YgoEiEDc&t=424sを追加すると、YouTubeにxm3YgoEiEDc動画の424秒地点からの/watchをリクエストすることになります。

ルーター

ここまでは、それほど多くのルートを使ってきませんでしたし、これまで示したすべてのルートは、私たちのサーバー自体であるappに直接アタッチされてきました。ルートがたくさんある実際のアプリケーションでは、おそらくルートをグループに整理し、それぞれのグループを個別のファイルに抽出したいと思うでしょう。そうすることで、そのファイル内のルートだけに影響を与え、他には影響を与えないものを、より簡単に書けるようにもなります。

図書館アプリを作っていて、本を扱うページと著者を扱うページが欲しいとしましょう。それに加えて、ホームページや、「about」や「contact」のようなその他の雑多なページもあるとします。

サーバーには以下のようなルートを処理させたいと思うかもしれません:

GET /
GET /about
GET /contact
POST /contact

GET /books
GET /books/:bookId
GET /books/:bookId/reserve
POST /books/:bookId/reserve

GET /authors
GET /authors/:authorId

ルートのグループをそれぞれ個別のファイルに抽出できたら素敵ですよね。それは、ルーターを使うことで実現できます!先ほどの基本的なExpressアプリに戻って、それぞれのルートグループを処理するルーターを追加してみましょう。

まず、新しいroutesフォルダに配置できるルーターが必要です。例えば、routes/authorRouter.jsです:

// routes/authorRouter.js
const { Router } = require("express");

const authorRouter = Router();

authorRouter.get("/", (req, res) => res.send("All authors"));
authorRouter.get("/:authorId", (req, res) => {
  const { authorId } = req.params;
  res.send(`Author ID: ${authorId}`);
});

module.exports = authorRouter;

上のコードでは、ExpressオブジェクトをデストラクチャリングしてRouter関数を取り出し、それを使ってauthorRouterを作成しています。サーバーオブジェクト全体の代わりに、このルーターに対して同じ.getや.postメソッドを使うことができ、つまりこのルーターにスコープされたルートやミドルウェアを書くことができます(これらについては次のレッスンでより深く掘り下げます)。このルーターは/authorsで始まるパスに対してのみ使えるようにする予定なので、ここでのルートパスにはそれを含める必要はありません。代わりに、それらは親のパスを拡張します(ルートが/authors/authors/:authorIdに一致してしまうのは望ましくありません)。

他のルートグループのために、残り二つのルーター――routes/bookRouter.jsとroutes/indexRouter.js――を作成してください!それらのミドルウェア関数は多くのことをする必要はなく、どのルートが一致しているかがわかるように、それぞれのルートに何か一意のものを送るだけで十分です。

残り二つのルーターを作成したら、app.jsの中でそれらをサーバーに追加しましょう:

// app.js
const express = require("express");
const app = express();
const authorRouter = require("./routes/authorRouter");
const bookRouter = require("./routes/bookRouter");
const indexRouter = require("./routes/indexRouter");

app.use("/authors", authorRouter);
app.use("/books", bookRouter);
app.use("/", indexRouter);

const PORT = 3000;
app.listen(PORT, (error) => {
  if (error) {
    throw error;
  }
  console.log(`My first Express app - listening on port ${PORT}!`);
});

/authorsで始まるパスを持つすべてのリクエストは、ルートの一致判定のためにauthorRouterを通ることを指定しています。もしリクエストが/booksで始まっていれば、これらのauthorのルートはスキップされ、代わりにbookRouterの中のルートがチェックされます。どちらでも始まらないその他すべてのリクエストは、indexRouterを通ることになります。

これらのルートをテストするには、Postmanを使ってください。これを使えば、ブラウザなしでGETやPOSTリクエストを送信できます(ブラウザのアドレスバーからはPOSTリクエストを送信できません)。
