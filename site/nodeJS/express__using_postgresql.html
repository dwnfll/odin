Using PostgreSQL with node-postgres

イントロダクション

これでPostgreSQLがマシン上で起動して実行されるようになったので、いよいよそれを使って作業する番です。

簡潔にするため、これ以降はdatabase(データベース)をdbと呼ぶことにします。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • PostgreSQLシェルで新しいdbをセットアップする。
  • node-postgresでのセットアップとクエリ。
  • スクリプトを使ってdbにデータを投入する。

Expressアプリをセットアップする

レッスンの前提条件

必ずSQLコースを完了しておいてください。

このレッスンおよびそれ以降のすべてのレッスンは、あなたがSQLの構文と概念を理解していることを前提としています。

Expressアプリケーションを作成することから始めましょう。これには一つの機能しかありません――ユーザーによって提供されたユーザー名をdbに追加することです。以下が、期待されるルートとその機能です:

  • GET / - db内で利用可能なユーザー名をターミナルにログ出力します。今のところは、単純にconsole.log("usernames will be logged here - wip")としてください。
  • GET /new - ユーザー名の入力用テキストフィールドが一つあるHTMLフォームをユーザーに表示します。これは次のルートに送信されます。
  • POST /new - 受信したユーザー名データをdbに保存します。今のところは、単にconsole.log("username to be saved: ", req.body.username)としてください。

上記の機能が動作するようになったら、次のセクションに進んでください。関連するコードはroutesフォルダとcontrollersフォルダにスコープしてください。処理すべきビューは(GET /newの)一つだけなので、ejsを使うか、昔ながらのプレーンなHTMLで済ませるかは、あなた次第です。

dbをセットアップする

ターミナルでpsqlを実行して、PostgreSQLシェルに入ってください。\lコマンドを使って、現在のdbを確認できます。以下のSQL文を実行して、新しいdbを作成してみましょう:

CREATE DATABASE top_users;

もう一度\lを実行して、dbが作成されたかどうか確認してください。それでは、dbに接続してみましょう:

\c top_users

psqlのプロンプトが以下のようになっていることを確認してください:

top_users=#

それでは、usernameデータを保存するためのテーブルとその列を作成してください:

CREATE TABLE usernames (
   id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
   username VARCHAR ( 255 ) 
);

\dを実行して、テーブルが作成されたことを確認してください。出力の中に以下の2つのテーブルが表示されるはずです(簡潔にするため、一部の出力の詳細は省略しています):

|       Name       |   Type   |
+ -----------------+----------+
| usernames        | table    |
| usernames_id_seq | sequence |

アイデンティティ列

ちょっと待ってください、このusernames_id_seqというのは何でしょうか?

GENERATED ALWAYS AS IDENTITY句が原因です。これはid列をアイデンティティ列として定義します。これにより、PostgreSQLはこの列の値を自動的に生成するようになります。デフォルトでは1から始まり、新しい行ごとに1ずつ増加します。さらに、PostgreSQLは暗黙的にusernames_id_seqというシーケンスオブジェクトを作成し、それが次に使われるべき値を追跡します。

やりました、これでdbとテーブルができました……寂しい一人ぼっちのテーブルですね。でも、それも長くは続きません:

INSERT INTO usernames (username)
VALUES ('Mao'), ('nevz'), ('Lofty');

確認してみましょう:

SELECT * FROM usernames;

Expressでnode-postgresを使う

Expressアプリケーションの中で、node-postgres(略してpg)を通してPostgreSQLを扱うことができます。これは、PostgreSQLのdbとやり取りするために使うライブラリです。以下でインストールしてください:

npm install pg

それから、必要な接続情報とともに、アプリケーションの中でそれを初期化できます。dbフォルダを作成し、以下の内容で新しいファイルdb/pool.jsを作成してください:

const { Pool } = require("pg");

// All of the following properties should be read from environment variables
// We're hardcoding them here for simplicity
module.exports = new Pool({
  host: "localhost", // or wherever the db is hosted
  user: "<role_name>",
  database: "top_users",
  password: "<role_password>",
  port: 5432 // The default port
});

<role_name>と<role_password>は変更する必要があることを忘れないでください(これらは前のレッスンですでに設定済みのはずです)!

接続情報を定義する代わりの方法として、Connection URIを使うこともできます。ホスティングされているデータベースサービスに接続する際には、おそらくconnection URIを使うことになるでしょう。上のプロパティに基づくと、以下のようになります:

const { Pool } = require("pg");

// Again, this should be read from an environment variable
module.exports = new Pool({
  connectionString: "postgresql://<role_name>:<role_password>@localhost:5432/top_users"
});

使いたい方法をどちらか選んで、続けていきましょう。

pgで接続する2つの方法

pgには、dbに接続するための2つの方法があります: clientとpoolです。

Clientはdbへの個別の接続であり、あなたが手動で管理します。接続を開き、クエリを実行し、それから閉じます。これは単発のクエリには問題ありませんが、大量のクエリを扱う場合はコストが高くなることがあります。もし何らかの方法でクライアントを保持しておけたら、この問題は緩和されると思いませんか?その通りです!

そこでpoolの登場です。その名前が示す通り、これはクライアントのプールです。プールは接続を保持しています。そして、クエリを実行すると、既存の空いている接続がない限り、プログラム的に新しい接続を開きます。ウェブサーバーにはぴったりです。

pgでクエリする

初期化したPoolがあれば、queryメソッドを使うことができます。新しいdb/queries.jsファイルを作成してください。プロジェクトの要件を見直すと、必要なdb操作が2つあることがわかります――すべてのユーザー名を取得することと、新しいユーザー名を挿入することです。これらの関数を定義してみましょう:

const pool = require("./pool");

async function getAllUsernames() {
  const { rows } = await pool.query("SELECT * FROM usernames");
  return rows;
}

async function insertUsername(username) {
  await pool.query("INSERT INTO usernames (username) VALUES ($1)", [username]);
}

module.exports = {
  getAllUsernames,
  insertUsername
};

パラメータ化

insertクエリの中の$1は何なのでしょうか?

代わりに、クエリを以下のようにすることもできます:

await pool.query("INSERT INTO usernames (username) VALUES ('" + username + "')");

ユーザーが入力した値、つまりusernameを直接クエリに渡しています。悪意のあるユーザーがsike'); DROP TABLE usernames; --のようなものを入力し、大混乱を引き起こす可能性があります。恐ろしいことですね。これはSQLインジェクションと呼ばれます。

pgはこれを防ぐために、クエリのパラメータ化を提供しています。ユーザー入力を直接渡す代わりに、それを配列に入れて2番目の引数として渡します。あとはpgが処理してくれます。

上記の2つの関数を、それぞれのコントローラーの中で呼び出してください(関数名などは異なるかもしれません。重要なのは、db関数がどのように呼び出されるかを理解することです):

const db = require("../db/queries");

async function getUsernames(req, res) {
  const usernames = await db.getAllUsernames();
  console.log("Usernames: ", usernames);
  res.send("Usernames: " + usernames.map(user => user.username).join(", "));
}

async function createUsernameGet(req, res) {
  // render the form
}

async function createUsernamePost(req, res) {
  const { username } = req.body;
  await db.insertUsername(username);
  res.redirect("/");
}

module.exports = {
  getUsernames,
  createUsernameGet,
  createUsernamePost
};

あなたのアプリを試してみてください。うまくいけば期待通りに動作するはずです。

スクリプトを使ってdbにデータを投入する

テーブルを作成してデータを投入するのが、いかに面倒であるかに気づいたかもしれません。幸いなことに、私たちには(c|n)odeの力があります。スクリプトを使ってそれを自動化しましょう。新しいファイルdb/populatedb.jsを作成してください。

#! /usr/bin/env node

const { Client } = require("pg");

const SQL = `
CREATE TABLE IF NOT EXISTS usernames (
  id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  username VARCHAR ( 255 )
);

INSERT INTO usernames (username) 
VALUES
  ('Bryan'),
  ('Odin'),
  ('Damon');
`;

async function main() {
  console.log("seeding...");
  const client = new Client({
    connectionString: "postgresql://<role_name>:<role_password>@localhost:5432/top_users",
  });
  await client.connect();
  await client.query(SQL);
  await client.end();
  console.log("done");
}

main();

PostgreSQLシェルにログインし、top_users dbに接続して、usernamesテーブルをdropしてください:

DROP TABLE usernames;

それから、node db/populatedb.jsを実行するか、package.jsonのスクリプトとして追加することで、このスクリプトを実行できます。

このスクリプトは一度だけ実行されるように設計されていることに注意してください。

ローカルdb対本番db

素晴らしいですね!これで、PostgreSQLを使ってローカルdbをセットアップし、使う方法を学びました。ローカルデータベースは、より高速なやり取り、より簡単な変更を提供し、インターネット接続を必要としないため、開発に理想的です。これは、新しい機能をプロトタイピングしたりテストしたりする際に、特に役立ちます。

プロジェクトを公開する準備ができたら、あなたのローカルマシンから独立した外部サーバー上にホストされた、本番用データベースに移行する必要があります。本番データベースは、グローバルなアクセス可能性、スケーラビリティ、そしてより堅牢なセキュリティを可能にします。デプロイのレッスンで紹介したホスティングプロバイダーのほとんどは、データベースサービスも提供しています。この違いがわかったところで、本番データベースにどうデータを投入できるか見ていきましょう。

本番dbにデータを投入する

ローカルのdb接続情報をスクリプトの中にハードコーディングしました。そのため、このスクリプトはローカルのdbにしかデータを投入しません。本番のdbにもデータを投入する方法が必要です。これを行う一つの方法は環境変数を使うことですが、これは不必要な手間につながります。なぜでしょうか?なぜなら、そうすると、このスクリプトは本番サーバー上でのみ本番dbにデータを投入できることになり、つまりスクリプトを実行するために本番サーバーのCLIにアクセスする必要が出てきてしまうからです。あるいは、こっそりと環境ファイルを編集して本番dbを指すようにし、自分のマシンでスクリプトを実行してから元に戻す、という方法もあります。

スクリプトをできるだけコードベースから独立させることを目指すべきです。

はるかに手間のかからないアプローチは、接続情報をスクリプトへの引数として提供することです。こうすれば、自分のマシン上で、ローカルdb用にも本番db用にもスクリプトを実行できます。引数には、process.argvを通してアクセスできます。

# populating local db 
node db/populatedb.js <local-db-url>

# populating production db
# run it from your machine once after deployment of your app & db
node db/populatedb.js <production-db-url>

課題

  1. pgのドキュメントにざっと目を通してください。このライブラリ自体は軽量で、ドキュメントも同様です。すべてを読む必要はなく、主にリファレンスとして使ってください。
  2. これまで取り組んできた上記のプロジェクトを更新してください。
    1. db接続情報のために環境変数を実装してください。
    2. indexルートに、クエリパラメータを使った検索機能を追加してください。例えば、GET /?search=supは、supを含むすべてのユーザー名を返すべきです。これをJavaScriptで実装しないでください。検索はSQLで行われるべきです。
    3. dbからすべてのユーザー名を削除するための、新しいルートGET /deleteを追加してください。
  3. 以前のMini Message Boardプロジェクトでは、配列を使って一時的なメッセージを実装しました。つまり、サーバーが再起動するとメッセージはリセットされていました。データの永続化が欲しいところです。このプロジェクトに戻り、PostgreSQLのdbとpgを使ってそれを実装してください。
    • 選んだホスティングサービスに新しいdbをデプロイし、その接続情報を取得してください。
    • messagesテーブルを作成し、必要であればデータを投入してください。これはスクリプトを通して行われるべきです。
    • 必要な環境変数を追加し、poolを作成し、必要なdb関数を実装してください。
    • ついでに、ユーザー入力に対する適切なサーバーサイドのバリデーションも追加してください。
