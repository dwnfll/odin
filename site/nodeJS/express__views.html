Views in Express

イントロダクション

これまでにあなたが作ってきた多くのプロジェクトは、SPA(シングルページアプリケーション)だったはずです。提供されるHTMLファイルは本質的に空っぽで、クライアントがJavaScriptを使ってページをレンダリングできるようにする、script タグだけが含まれていました。今度は、サーバー上でHTMLをレンダリングすること、つまりサーバーを使って、ページの内容を実際に含んだHTMLファイルを作成することに焦点を当てていきます。

ビューは、アプリケーションのユーザーに面した部分――この場合はHTMLファイル――です。以前のプロジェクトでも、サーバーがHTMLファイルをユーザーに送信するという形でビューを扱ってきましたが、それらのファイルは静的なものであり、私たちの多くのユースケースでは、ビューがデータに関して動的である必要があります。

そこで、ビューを作成するためにテンプレートエンジンを使います。その名前が示す通り、コードベースの中にテンプレートファイルを書き、それがサーバーリクエストに応答する際にHTMLへと変換されます。テンプレートファイルの中で定義された変数は、実際のデータに置き換えられます。さらに、テンプレートファイルの中に条件分岐やループのロジックを挿入することもできます。例えば、ユーザーがログインしたら、そのユーザー名をレンダリングする、といった具合です。これは、プレーンなHTMLでは不可能なことです。クライアントサイドのJavaScriptは、それでもscriptタグを介して追加できます(ただし、今のところクライアントサイドで凝ったことをする予定はありません)。

このコースでは、EJSを使います。EJSの構文はHTMLの構文にとても似ているため、他のテンプレートエンジンに比べて学習曲線が比較的緩やかです。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

EJSをセットアップする

なぜReactではないのか?

これまで知っているReactとはかなり異なる、React Server Componentsの使い方については教えていません。これらを単独でセットアップすることは、EJSのようなテンプレートエンジンとは違って簡単なことではなく、両端の境界を曖昧にしてより効率的な開発を可能にする、事前設定済みだが高度に抽象化されたフルスタックフレームワークを使ってしまうと、バックエンドの基礎に集中して学ぶのが難しくなってしまいます。

それでは、EJSを始めましょう!ターミナルに以下を入力して、アプリケーションにEJSをインストールしてください:

npm install ejs

プロジェクトのルートに、viewsというサブフォルダを作成してください。

次に、EJSをテンプレートエンジンとして使う予定であることと、ビューファイルをどこで探すべきかを、アプリに伝える必要があります。

app.jsファイルの中で、以下のアプリケーションプロパティを設定してください:

// app.js
app.set("views", path.join(__dirname, "views"));
app.set("view engine", "ejs");

そして、ファイルの上の方で、NodeのPath CommonJSモジュールをインポートしてください:

// app.js
const path = require("node:path");

これにより、EJSがビューエンジンとして有効になり、私たちのアプリが/viewsサブディレクトリの中でテンプレートを探すようになります。

EJSの構文

EJSでは、<%と%>タグを使うことでJavaScriptを使えるようになります。これにより、条件文やforループを書いたり、変数を使ったりできます。

変数を値として出力するには、<%=タグを使います。

配列とループのロジックを含む簡単な例を見てみましょう。

<% const animals = ["Cat", "Dog", "Lemur", "Hawk"] %>

<ul>
  <% animals.map((animal) => { %>
    <li><%= animal %>s are cute</li>
  <% }) %>
</ul>

ExpressでEJSを使う

ExpressでEJSを使ってみましょう。まず、viewsサブディレクトリの中にindex.ejsというEJSテンプレートファイルを作成し、以下を追加してください:

<!-- index.ejs -->
<html>
  <body>
    <%= message %>
  </body>
</html>

そしてapp.jsの中で、あなたのルートの一つで、このテンプレートファイルをレンダリングしてください:

// app.js
app.get("/", (req, res) => {
  res.render("index", { message: "EJS rocks!" });
});

理想的には、このルートは別のルーターファイルの中で定義するべきですが、このレッスンの目的のためには、app.jsの中で定義することにします。

サーバーを起動し、ブラウザで/ルートにアクセスしてください。以下が表示されるはずです:

EJS rocks!

ブラウザの開発者ツールでHTMLを検証すると、message変数がその値に置き換えられて、書いたEJSテンプレートとまったく同じ構造でHTMLが構成されていることがわかります。

/ルートにアクセスすると、res.render("index", { message: "EJS rocks!" });が、レスポンスを送り返す行になります。すでにviewsとview engineのアプリケーションプロパティを定義しているため、res.renderの最初の引数は、「指定されたフォルダの中でindexという名前のテンプレートを探す」ようにプログラムされており、2番目の引数は、その特定のテンプレートで利用可能にしたい変数のオブジェクトです。

EJSのlocals変数

上の例で、テンプレートファイルはどのようにしてmessage変数を知ったのでしょうか?ビューをレンダリングする際、EJSは、res.renderに渡したオブジェクトのプロパティ、そしてExpressのres.localsオブジェクトにあるプロパティにアクセスできます(res.localsは、あるミドルウェア関数の中でビューに値を渡す必要があるものの、res.renderをミドルウェアチェーンの後の方まで呼び出さない場合に役立ちます)。

EJSはこれらのプロパティをlocalsというオブジェクトに格納し、それをビューの中でアクセスできます。ブラウザにおけるグローバルなwindowオブジェクトと同じように、これによってビューの中でlocals.message、あるいは単にmessageとして、message変数にアクセスできます。

localsの中の未定義の変数

res.renderのlocals引数やres.localsの中で定義されていない変数に、レンダリングされたテンプレートファイルの中でアクセスしようとすると、参照エラーが発生することがあります。例えば、未定義のfoo変数にアクセスしようとすると、locals.fooはundefinedを返しますが、fooは参照エラーになります。index.ejsの中でlocals.fooを出力し、それをfooに置き換えることで、これを確かめてみてください:

<!-- index.ejs -->
<html>
  <body>
    <%= message %>
    <!-- replace the below with the output of just foo -->
    <%= locals.foo %>
  </body>
</html>

再利用可能なテンプレート

サイドバーやヘッダーのように、異なるページ間で共有されるウェブページのコンポーネントを含めたいことがあるかもしれません。そのようなコンポーネントをページに挿入するには、includeコマンドを使います。これには、挿入したいファイルの名前と、任意で渡したいデータのオブジェクトが必要です。

以下の"navbar.ejs"というnavbarコンポーネントを作成してください:

<!-- navbar.ejs -->
<nav>
  <ul>
    <% for (let i = 0; i < links.length; i++) { %>
      <li>
        <a href="<%= links[i].href %>">
          <span> <%= links[i].text %> </span>
        </a>
      </li>
    <% } %>
  </ul>
</nav>

navbarはlinks変数を期待していることに注意してください。このデータをnavbarに渡すには、res.render()でテンプレートファイルをレンダリングする際に、それをlocals変数として渡します。navbarを含めるためにindex.ejsをレンダリングします。そのために、"/"ルートハンドラの中で、linksオブジェクトを定義し、index.ejsをレンダリングするrender関数に渡すよう、app.jsを修正してください:

// app.js
const links = [
  { href: "/", text: "Home" },
  { href: "/about", text: "About" },
];

app.get("/", (req, res) => {
  res.render("index", { links: links });
});

次に、先ほど作成したindex.ejsを修正して、<%= message %>の行を削除し、代わりにlinks変数を使って以下のようにnavbarをincludeしてください:

<!-- index.ejs -->
<html>
  <head>
    <title>Homepage</title>
  </head>
  <body>
    <%- include('navbar', {links: links}) %>
  </body>
</html>

これで、index.ejsの中にリンク付きのnavbarが含まれるようになります。サーバーを実行して確認してみましょう!再利用可能なテンプレートは、すべてのページにヘッダーやフッターを含めるために使うことができます。

includeとともに使われている、生の出力タグ<%-に注目してください。これは、HTML出力の二重エスケープを避けるために使われています。

includeを使って、別の方法で変数のリストを動的にレンダリングしてみましょう。app.jsの中で、links変数のすぐ下に以下のusers配列を追加し、indexをレンダリングする際にrender関数に渡してください:

// app.js

const links = [
  { href: "/", text: "Home" },
  { href: "/about", text: "About" },
];

const users = ["Rose", "Cake", "Biff"];

app.get("/", (req, res) => {
  res.render("index", { links: links, users: users });
});

次に、viewsディレクトリの中にuser.ejsという新しいビューを作成してください:

<!-- views/user.ejs -->
<li><%= user %></li>

そして、以下のブロックをindex.ejsに追加してください:

<!-- index.ejs -->
<ul>
  <% users.forEach((user) => { %>
    <%- include('user', {user: user}); %>
  <% }); %>
</ul>

うまくいけば、index.ejsをレンダリングしたときに、Rose、Cake、Biffが表示されるはずです。

viewsフォルダの中のディレクトリ

viewsの中に、EJSテンプレートファイルのネストされたディレクトリを作成してみましょう。viewsディレクトリの中のuser.ejsをusers/user.ejsに変更し、index.ejsの中では、users.forEachブロックのパスをuserからusers/userに変更してください:

<!-- index.ejs -->
<ul>
  <% users.forEach((user) => { %>
    <%- include('users/user', {user: user}); %>
  <% }); %>
</ul>

静的アセットを提供する

EJSで静的アセットを提供するのは、以前HTMLを直接扱っていたときにアセットを提供していた方法と似ています。テンプレートファイルのheadにlinkタグを使って外部ファイルを追加できる点も同じです。主に指摘しておきたいのは、アプリがアセットをどこから提供すべきかを知っている必要があるという点です。expressがインストールされている前提で、app.jsに以下の行を設定してください:

// app.js
const assetsPath = path.join(__dirname, "public");
app.use(express.static(assetsPath));

express.static()は静的アセットの使用を可能にするミドルウェア関数であり、publicディレクトリをルートとしてアセットを探すよう指示しています。

publicディレクトリのルートに、以下のstyles.cssファイルを作成してください:

/* public/styles.css */
body {
  color: red;
}

index.ejsの中でstyles.cssを提供するには、head内に以下のようなlinkタグを設定してください:

<!-- index.ejs -->
<head>
  <link rel="stylesheet" href="/styles.css">
</head>

これで、あなたのindex.ejsファイルは赤色のテキストを表示するはずです!

課題

  1. EJSのドキュメントにもう一度目を通してください。
  2. テンプレートエンジンについてのExpressのリソースを読んでください。このリソースは例にPugを使っており、構文が異なりますが、それでもこのレッスンの有用な補足情報になるはずです。
  3. このレッスンで開発してきたアプリに追加してみましょう!/aboutルートでレンダリングされるべき、aboutページ用のビューを追加してください。
  4. 再利用可能なフッターテンプレートを作成し、アプリのすべてのルートでそれをレンダリングしてください。
