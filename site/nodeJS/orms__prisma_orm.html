Introduction to Prisma ORM and how to use it

イントロダクション

プロジェクトの中で生のSQLクエリを書くのに疲れましたか?このレッスンでは、Object Relational Mapper(略してORM)について話します。ORMは、データベース内のデータを操作できるようにしてくれるツールであり、ソフトウェア業界で広く使われています。Node.jsの世界で人気のあるORMの一つ、Prisma ORMについて深く掘り下げていきます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • ORMとは何か、そしてなぜ使われるのか。
  • Prisma ORMを紹介する。
  • Prisma ORMの機能を説明する。

生のSQLを書くことの課題

これまでに取り組んできたいくつかのプロジェクトで、生のSQLクエリの面倒さに遭遇したことがあるかもしれません。こうした課題のいくつかについて、簡単に議論してみましょう。

あまりにも多くのコード

SELECT文が必要ですか?いいですね、クエリを書きましょう。別のテーブル用のSELECT文が必要ですか?もう一つクエリを書きましょう。あるいは、プログラマーとしての勘が働くなら、SELECT用のユーティリティ関数を作ることもできます。しかし今度は、特定の列だけのSELECT文が必要になりました。ユーティリティ関数を修正する必要があります。フィルタリングやソートはどうでしょう?もうおわかりですね。

上記をinsertクエリとそのすべてのバリエーションについても繰り返してください。あるいは、別の方向に進むこともできます。エンティティごとにモジュールを作成するのです。例えば、booksモジュールには以下のようなものがあるでしょう:

class Book {
  async getBooks(filters) {}
  async getBookById(id) {}
  async createBook(data) {}
  async updateBook(id, data) {}
  async deleteBook(id) {}
  async getBookAuthors(id) {}
  async getBookGenres(id) {}
  // and so on
}

あるいは、この2つのアプローチを組み合わせることもできます。Databaseクラスを作成し、あなたのエンティティクラスでそれを継承するのです。あるいは、コンポジションを好み、純粋関数だけを扱いたいと思うかもしれません。

さて、これを複数のプロジェクトにわたって、それぞれのエンティティについて何度も何度も繰り返してください。もうおわかりですね。より多くのコードを書くことが必ずしも悪いことではない、と主張することもできます。あなたは学び、練習しているところであり、実際それは悪いことではありません。個人プロジェクトにとってはそれで十分ですし、私たちもぜひ上記のアイデアを探ってみることをおすすめします。しかし、チームで作業し、大規模なソフトウェアを扱うようになると、外部ライブラリであれ自前のソリューションであれ、データベースとやり取りするための標準的な方法を持つことが不可欠になってきます。ORMが、ビジネスにとって重要なコードを書くことに集中する上で、いかに役立つかを実感することになるでしょう。

以前のプロジェクトをリファクタリングする

もし以前のプロジェクトで上記のパラダイムのいずれも適用していなければ、戻ってリファクタリングしてみることを強くおすすめします。あなたのプロジェクト用の、とても基本的なミニORMのようなものができあがるかもしれません。これは、適切なORMがどれほどあなたの生活を楽にしてくれるかを、もう少し理解する助けになるはずです。

コードベースを読み解く

すべてのデータベースとのやり取りが生のSQLで行われている場合、コードベースの中には、データベースのテーブル、それらの関係、列のデータ型を理解できる場所がどこにもありません。コードベースが何をしているのかを理解するために、データベースにログインする必要があるかもしれません。プロジェクトについての技術的な理解を得るために、あなたは今やコードベースだけでなく、データベースへのアクセスにも頼ることになります。

世の中のほとんどのORMは、データベースの定義をコードベースに持ち込むことで、この問題を解決します。これは「スキーマ」と呼ばれます。これにより、テーブルのスキーマにさっと目を通して、それがどんな列を持っているか、といったことをすぐに理解できるようになります。

本番データを変更する

プロジェクトの要件が進化するにつれて、データベースは避けられず変化していきます。新しい列を追加したり、既存のデータで新しいテーブルにデータを投入したりする必要があるかもしれません。技術的には、これはマイグレーションと呼ばれます。ORMや類似のライブラリがなければ、あなたはこれらのマイグレーションを手作業で行うことになり、それはエラーが起きやすく面倒な作業になるでしょう。ORMは、チェンジログを介してマイグレーションを標準化し、競合に対処するためのプロセスを備えています。確かに、カリキュラムのプロジェクトではそれほど多くのマイグレーションを実行することはありませんが、実務で働くようになると、一日おきにそれを行うことになるかもしれません。

Prisma ORMを紹介する

ORMは、上記で述べた問題点のほぼすべてを解決してくれますが、良いことばかりというわけではありません。ORMの細部まで完全に理解するには学習曲線があるかもしれませんし、中にはすべてのSQL機能を完全にはサポートしていないものもあります。こうした欠点があっても、ORMを使うことは非常に価値があります。

Node.jsのエコシステムには、選べるORMがたくさんあり、コミュニティはまだ「これ」という定番にたどり着いていません。私たちは、その人気とコミュニティのサポートから、カリキュラムではPrisma ORMを取り上げることに決めました。

Prisma ORMには、このカリキュラムを完了するために必要な機能がすべて備わっており、それ以上のものもあります。Prisma ORMはいくつかのライブラリで構成されているため、npmを使って、アプリケーションが必要とするものだけをインストールできます。まずはその機能のいくつかについて議論し、それから、始めるのに役立ついくつかの公式Prisma ORMガイドにリンクします。

Prismaスキーマ

Prismaスキーマは、あなたのモデルを定義するファイルです。例えば、チャットアプリにおけるmessageテーブルを考えてみましょう:

model Message {
   id        Int      @id @default(autoincrement())
   content   String   @db.VarChar(255) 
   createdAt DateTime @default(now())
   author    User     @relation(fields: [authorId], references: [id])
   authorId  Int     
}

model User {
   // user's fields
}

ここには新しいものがたくさんあります。Prismaのスキーマファイルは、Prisma Schema Languageで書かれています。テーブルの列定義があるだけでなく、Messageモデルの中で別のテーブルへの関係も定義されているのがわかります。これについては、課題の読み物の中でさらに学んでいきます。

このスキーマファイルはあなたのコードベースの中にあり、バージョン管理によって追跡されます。これがどれほど役立つか、もうおわかりでしょう。

Prismaクライアント

クライアントは、データベースとやり取りするために使う、別のライブラリです。Prismaクライアントは、あなたのスキーマに合わせてカスタマイズされているという点で、少し特殊です。ええと……どういうことでしょうか?

// instantiate the client
import { PrismaClient } from '@prisma/client';
const prisma = new PrismaClient();

// when creating a new message
await prisma.message.create({
   data: {
      content: 'Hello, world!',
      authorId: 1
   }
})

// when fetching all messages
const messages = await prisma.message.findMany();

prisma.messageオブジェクトに気づきましたか?Prismaクライアントは、messageというモデルが存在することをどうやって知ったのでしょうか?スキーマファイルを作成または更新したら、あなたがすべきことは、CLIで

npx prisma generate

を実行するだけで、Prisma ORMがあなたの代わりにクライアントを生成してくれます。このクライアントは、結合、フィルタリング、ソート、ページネーションなど、あらゆる種類のクエリを扱うことができます。

Prismaクライアントではどうしてもうまく書けない複雑なクエリがあるかもしれませんし、あるいはクエリを生で書く方が心地よいと感じるかもしれません。そういう場合もできます。Prismaクライアントは生のクエリもサポートしています。

Prisma Migrate

Prisma Migrateは、データベースのマイグレーションを実行するのを助けてくれるツールです。カリキュラムの中でそれをそれほどたくさん使うことはありませんが、それについて知っておくのは良いことです。何らかの方法でスキーマを変更することに決めたら、Prismaマイグレーションを実行して、スキーマの変更をデータベースに適用します。これらの変更は、あなたのコードベースの中のmigrationsフォルダで追跡されます。

Prisma ORMの制限

Using PostgreSQLレッスンでは、Identity列について学びました。PostgreSQLは、SQL標準に準拠しているため、Identity列の使用を推奨しています。しかし、Prisma ORMはこれらの列をサポートしておらず、代わりにPostgreSQL特有のSerial型を作成します。これはおそらくあなたのプロジェクトには影響しませんが、覚えておくと重要になることがあります。SerialとIdentityの違いについての簡単な説明は、このStackoverflowの回答を参照してください。

Visual Studio Code用の公式Prisma拡張機能

VS Codeを使っているなら、シンタックスハイライト、IntelliSense/自動補完、スキーマのリンティング、モデル間のより簡単なナビゲーションといった機能を得るために、公式Prisma VS Code拡張機能をインストールしたいと思うかもしれません。これにより、Prismaのスキーマファイルを扱うのがずっと快適になります。

    PrismaをJavaScriptで動かす

    最近、Prismaは今後Typescriptのみをサポートし続けることを決定しました。つまり、これをJavaScriptで動作させるためには、彼らのクイックスタートガイドを修正する必要があります。

    Prismaのクイックスタートガイドに沿って進めながら、以下で説明する通りにクイックスタートの手順を修正してください。

    ステップ1: 以下のコマンドはスキップしてください:

    npm init
npm install typescript tsx @types/node --save-dev
npx tsc --init

    ステップ2: @types/pgをインストールする必要はありません。「install scripts not yet covered by allowScripts」についての警告が出た場合、Prismaがいずれにせよ後のステップで必要な処理を行ってくれるので、安全に無視して構いません。

    ステップ3: 私たちはTypescriptを使わないので、このステップは完全にスキップします。

    ステップ4: デフォルトの代わりにprisma-client-jsジェネレーターを使いたいので、Prismaのinitコマンドに--generator-provider prisma-client-jsを追加してください。また、Prisma Skillsカタログからデフォルトで何のAI機能もインストールしたくないので、それを無効にするために--no-skillsを追加してください:

    npx prisma init --datasource-provider postgresql --output ../generated/prisma --generator-provider prisma-client-js --no-skills

    また、prisma7.config.tsをprisma7.config.jsにリネームします。

    ステップ5と6: 変更は不要です。

    ステップ7: lib/prisma.tsの代わりに、lib/prisma.jsを作成してください。また、そのファイルの中でPrismaClientをインポートする際には、.jsファイル拡張子を追加する必要があります:

    import { PrismaClient } from '../generated/prisma/client.js';

    ステップ8: 作成されるファイルはscript.jsという名前にするべきで、そのファイルの中でprismaをインポートする際には、.jsファイル拡張子を追加してください。そのため、最初の行は以下のようになります:

    import { prisma } from './lib/prisma.js';

    スクリプトを実行するには、node script.jsを実行してください。

    ステップ9: 変更は不要です。
