We create a private online clubhouse to practice using the auth strategies we've learned

イントロダクション

このプロジェクトでは、メンバーが匿名で投稿できる、特別なクラブハウスを構築していきます。クラブハウスの中では、メンバーは投稿の著者が誰であるかを見ることができますが、外にいる人たちには物語だけが見え、誰がそれを書いたのか不思議に思うことしかできません。

これは、前回のレッスンで学んだ認証のスキルを使う機会になります。また、データベースのスキルも練習することになるので、心構えをしておいてください!

課題

  1. まず、目標を達成するために必要となるデータベースモデルをどうセットアップするか、考えることから始めてください。フルネーム(名と姓)、ユーザー名(これにはメールアドレスを使うこともできます)、パスワード、メンバーシップステータスを持つユーザーが必要です。ユーザーは、タイトル、タイムスタンプ、いくらかのテキストを持つメッセージを作成できるべきです。データベースは、それぞれのメッセージを作成したのが誰かを記録しておくべきです。
  2. PostgreSQLでデータベースをセットアップし、前のステップで設計したモデルを含む、プロジェクトの骨組みを生成するか、別の方法で作成してください。
  3. サインアップフォームから始めて、いくらかのユーザーをあなたのDBに入れられるようにしましょう!フォームのフィールドをサニタイズおよびバリデーションし、bcryptでパスワードを保護するのを忘れないでください。サインアップフォームにconfirmPasswordフィールドを追加し、カスタムバリデーターを使ってそれをバリデーションするべきです。
  4. ユーザーがサインアップしても、自動的にメンバーシップステータスを与えられるべきではありません!誰でも参加できてしまったら、非公開クラブの面白みは何もありませんよね?メンバーが秘密のパスコードを入力することで「クラブに参加」できるページを追加してください。もし彼らが正しくパスコードを入力したら、彼らのメンバーシップステータスを更新してください。
  5. 前回の課題でやったのと同じように、passport.jsを使ってログインフォームを作成してください。
  6. ユーザーがログインしているときは、「新しいメッセージを作成」へのリンクを表示してください(ただし、ログインしている場合にのみ表示してください!)。新規メッセージ用のフォームを作成してください。
  7. ホームページにすべてのメンバーのメッセージを表示してください。ただし、他のクラブメンバーにだけ、メッセージの著者と日付を表示してください。
  8. ユーザーモデルにAdminという任意のフィールドを追加し、それからメッセージを削除する機能を追加してください。ただし、admin == trueであるユーザーだけが削除ボタンを見て、メッセージを削除できるようにしてください。実際にユーザーを「admin」としてマークする方法も追加する必要があるので、別の秘密のパスコードページを追加するか、単にサインアップフォームに「is admin」チェックボックスを置いてください。
  9. ここまでで、サイトを訪れた誰もが、著者名が隠された状態で、すべてのメッセージの一覧を見られるようになっているはずです。ユーザーはサインアップしてメッセージを作成できるべきですが、メンバーであるユーザーだけが、それぞれのメッセージの著者と日付を見られるべきです。最後に、あなたはすべてを見ることができ、かつメッセージを削除する能力も持つ、Adminユーザーを持っているべきです。もちろん、これはちょっとしたおふざけのアプリですが、あなたが練習していること(ユーザーの作成と認証、そしてユーザーに異なる能力と権限を与えること)は、あなたにとって非常に役立つものになるはずです!
  10. あなたの作業に満足したら、選んだPaaS(Deploymentレッスンで紹介したPaaSプロバイダーの一覧)にプロジェクトをデプロイし、以下で共有してください!
