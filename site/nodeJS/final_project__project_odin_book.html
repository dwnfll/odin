You'll use everything you've learned so far to replicate Facebook!

イントロダクション

ここまでよく頑張りました、おめでとうございます!この時点で、あなたは新しいExpressアプリケーションを構築し、PostgreSQLを使ってデータをモデリングし保存することに、快適さを感じられるようになっているはずです。このプロジェクトでは、その知識すべてを試すことになります。簡単ではありませんが、あなたの能力の範囲内に十分収まるはずですし、素晴らしいポートフォリオ作品になるでしょう。

Facebook、X、Myspace、Threadsのような、ソーシャルメディアサイトのクローンを構築していきます。これまでのレッスンと同じように、スタイリングとフロントエンドにどれだけの労力をかけたいかは、あなた次第です。重要なのはデータとバックエンドです。ユーザー、プロフィール、投稿、フォロー、「いいね」といった、プラットフォームのコア機能をまとめ上げていきます。

何らかの形の認証も実装することになります。理想的には、あなたがクローンしているソーシャルメディアサイトを介した認証をサポートするために、passport.jsを使いたいところですが、(Facebookのような)一部のサイトは、最近このプロセスを不可能にしてしまいました。あなたのサイトがそのような場合は、passport-localを使ったユーザー名とパスワードによる認証、またはpassport-github2を使ったGithub経由の認証をサポートするために、passport.jsを使うことができます。

チャット、リアルタイムの更新、通知など、あなたがまだ触れたことのない機能もおそらくあるでしょう。この時点で自分のスキルに本当に自信を持てている場合を除き、それらについては責任を負う必要はありません(例えば、socket.ioを使えば、リアルタイム通信にWebSocketを使うことができます)。

課題

ソーシャルメディアサイトを構築してください!このプロジェクトでは、あなたが選んだサイトのコアなユーザー機能の大部分を構築していきます。希望しない限り、より華やかなフロントエンドについて心配する必要はありませんが、素敵なユーザー体験を得るためにそれが必要というわけでもありません。

このプロジェクトでは、比較的高レベルな要件のセットを受け取り、それを機能するウェブサイトへと変えていく機会が得られます。自分で調べものをしたり、このプロジェクトで使ういくつかのモジュールのドキュメントを読んだりする必要があるでしょう。

始めるにあたって

  1. 何をする必要があるか考えてください。事前に紙やホワイトボード上で計画を書き出しておくことは、本当に役立ちます!今数時間考えることで、何日ものコーディングの時間を節約できます。すべてを洗い出すようにしてみてください。計画を立てる上で重要な部分の一つは、スコープです。(おそらくエンジニアのチーム全体が何年もかけて作り上げた)ウェブサイト全体を構築することは、当然できません。そのため、サイトのコア機能と、「あれば嬉しい」機能を見極める必要があります。残りの作業に取り組む前に、必ずコア機能を完成させてください。すべてを一度にやろうとすると、迷子になり、イライラすることになるでしょう。私たちを信じてください。すべてのことは、あなたが予想するよりも時間がかかります。
  2. これを機能させるために必要なデータアーキテクチャについて、よく考えてください。モデルはたくさんあり、それらの間の関係は、これまでにあなたが行ったどんなものよりも複雑です。飛び込む前に、あなたのアプローチを計画するための時間を取ってください。
  3. 以下のリストを順番にこなしていきましょう!それぞれのステップには新しい挑戦が伴いますが、あなたにはそのためのツールがあります。
  4. npmのFakerモジュールを使って、ユーザーや投稿のようなデータに偽のデータを投入することができます。これを実現するには、あなたのPrismaモデルをインポートし、fakerモジュールを使って新しいユーザーをたくさん生成して保存する、seeds.jsという新しいJavaScriptファイルを作成してください。

要件

以下の要件は、あなたのアプリが持つべき機能の、非常に大まかなリストです。このプロジェクトのオープンエンドな性質上、それらのすべてが、あなたが選んだサイトに当てはまるとは限りませんし、あなたのサイトには、ここで触れられていないコア機能があるかもしれません。

  1. ユーザーは、サインインページ以外の何かを見るためには、サインインする必要があります。
  2. ユーザーは、あなたが選んだ認証方法を使ってサインインできるべきです。
  3. ユーザーは他のユーザーにフォローリクエストを送ることができます。
  4. ユーザーは投稿を作成できます(まずはテキストのみから始めてください)。
  5. ユーザーは投稿に「いいね」できます。
  6. ユーザーは投稿にコメントできます。
  7. 投稿には、常に投稿内容、著者、コメント、いいねが表示されるべきです。
  8. 投稿用のindexページがあるべきで、そこには現在のユーザーと、彼らがフォローしているユーザーからの、すべての最近の投稿が表示されます。
  9. ユーザーはプロフィール写真付きのプロフィールを作成できます。認証をどう扱うか(例えばpassport-github2経由など)によっては、彼らのアカウントの既存のプロフィール写真を使えるかもしれません。そうでない場合は、Gravatarを使ってそれらを生成できます。
  10. ユーザーのプロフィールページには、彼らのプロフィール情報、プロフィール写真、投稿が含まれるべきです。
  11. ユーザー用のindexページがあるべきで、そこにはすべてのユーザーと、まだフォローしていない、または保留中のリクエストがないユーザーに対してフォローリクエストを送るためのボタンが表示されます。
  12. あなたが選んだホスティングプロバイダーに、あなたのアプリをデプロイしてください!

発展課題

  1. 投稿で画像も許可するようにしてください(URL経由だけでも、アップロードによってでも構いません)。もしFile Uploaderプロジェクトの発展課題を行ったなら、ユーザーがアップロードした画像をホストするのに良い選択肢として、CloudinaryやSupabase storageを思い出すかもしれません。それらが提供してくれるURLを、生の画像バイナリデータの代わりに、あなたのデータベースに保存できます。
  2. ユーザーがプロフィール写真を更新できるようにしてください。
  3. 訪問者が、アカウントを作成したり認証情報を提供したりすることなく、ログイン画面をバイパスできる、ゲストサインイン機能を作成してください。これは特に、このプロジェクトをあなたの履歴書に載せる予定がある場合に役立ちます――ほとんどの採用担当者や人事担当者は、アカウントを作成する時間を取ってはくれません。この機能があれば、彼らは面倒なサインアッププロセスを経ることなく、あなたの努力の成果を見ることができます。
  4. 見た目を良くしてみましょう!
