Blog API

日本語訳

← nodeJS

You create the backend for a blog and then plug it into multiple frontend applications

イントロダクション

あなたに何が必要かわかりますか?ブログです。あるいは違うかもしれませんし、もうすでに持っているかもしれませんが、いずれにせよ、このプロジェクトは、APIオンリーのバックエンドを作成することの利点を実践し、確認するための素晴らしい方法になるでしょう。実際に、バックエンドと、あなたのブログ投稿にアクセスして編集するための2つの異なるフロントエンドを作成していきます。一つのフロントエンドのサイトは、あなたの投稿を読んでコメントしたい人たち向けであり、もう一つは、あなたが投稿を書いたり、編集したり、公開したりするためだけのものです。

なぜこのようにセットアップするのでしょうか?なぜなら、そうできるからです!ここでの重要な演習は、APIをセットアップし、それから外部からアクセスすることです。ブログの閲覧用とブログの編集用で別々のウェブサイトをセットアップすることには、いくつかのセキュリティ上の利点がありますが、実際のところ、これは、バックエンドのコードをフロントエンドのコードから分離することの力と柔軟性を示すために、このように行っているだけです。

課題

  1. このプロジェクトをどう構成するかは、あなた次第です。作成する3つのアプリそれぞれについて、コミット履歴を分けておくために別々のGitHubリポジトリを好む人もいます。それぞれのアプリを同じ一つのリポジトリの中の別々のディレクトリに置く、モノレポを好む人もいます。
  2. まず、バックエンドのモデルとスキーマを設計することから始めてください。どう設計するかはあなた次第ですが、いくつか考えておきたいことがあります:
    • あなたのブログには投稿とコメントがあるはずなので、それぞれに含めたいフィールドについて考えてください。
    • ユーザーにコメントとともにユーザー名やメールアドレスを残すことを要求しますか?
    • 投稿やコメントに、日付やタイムスタンプを表示しますか?
    • 投稿にはおそらくタイトルがあるべきですが、コメントにもあるべきでしょうか?
    • ブログにとって便利な機能の一つは、データベースには存在するものの、一般公開されて読まれることのない投稿を持てることです。DBの中で、公開済みの投稿と未公開の投稿をどのように区別しますか?
    • ブログの著者や、普通のユーザーアカウントを含む、userモデルが必要になります。単一の著者だけを持ち、普通のユーザーアカウントは持たないと決めた場合でも、最小限のuserモデルがあれば、認証を通じてルートの保護をより簡単に行えるようになります。
  3. Expressアプリをセットアップし、Prismaでモデルを定義してください。
  4. ルートとコントローラーをセットアップしましょう!これについてはRESTfulな構成を考えてみてください。前のレッスンの例のほとんどは投稿とコメントを中心にしていたので、これはそれほど難しくないはずです。
    • ルートのテストは好きな方法で行うことができます。ターミナルでcurlを使うのは便利な方法の一つですが、ウェブブラウザを使っても同じくらい効果的です。HTMLフォームをセットアップして記入する必要なく、PUTやPOSTリクエストを送信できるプラットフォームもあります。Postmanがおそらく最も人気があります。
  5. 特定のルートは、認証によって保護される必要があります。オンライン上の見知らぬ誰かに、あなたの記事を編集されたくはないはずです!普通のユーザーアカウントも実装する場合は、ログインしていることの背後で、いくつかのルートを保護したいと思うかもしれません。
    • 認証を扱う方法はたくさんありますが、このプロジェクトではJWTを使ってください。
    • JWTを作成し検証するために、jsonwebtokenを使うことができます。特に、すでにログインを処理するためにlocal strategyでPassportをセットアップしている場合は、JWTを検証するためにPassportのJWT strategyを使いたいと思うかもしれません。
    • ログインが成功すると、ユーザーはJWTを付与されます。そのユーザーは、それ以降のあらゆるリクエストにそのJWTを添付でき、あなたのAPIはそのJWTを検証することで、保護されたルートの残りの部分へのアクセスを許可するか拒否するかを判断できます。ユーザーがログアウトしたら、クライアント側でJWTをストレージから削除させることができます。
    • JWTを送信・保存する方法はたくさんあります。クッキーを介する方法、localStorageに保存する方法、アクセス/リフレッシュトークンを使う方法などです。これらの方法の中には、より複雑なもの(ただし、適切に実装すれば、より安全になる可能性もあります)もあり、特に両端をデプロイした後はそうです。例えば、クロスサイトのクッキーは、特定の追加の詳細を知らないと、本当に頭痛の種になり得ます。将来的には、こうした代替手段のいくつかを探ってみたいと思うかもしれません。今のところは、シンプルにしておき、「Bearer」スキーマを使った「Authorization」ヘッダーを介してJWTを送信し、クライアント側ではlocalStorageにJWTを保存させてください。
  6. あなたのAPIが動作するようになったら、フロントエンドのコードに集中できます。実際のところ、これをどう進めるかはあなた次第です。Reactに慣れているなら、それを使ってみましょう!プレーンなHTML、CSS、バニラJavaScriptを使う方が快適であれば、それでも構いません。あなたの投稿をウェブサイトに表示するためにしなければならないことは、正しいAPIエンドポイントをfetchし、それから結果を表示することだけのはずです。フロントエンドの観点からfetchとAPIを扱うことについては、Working with APIsレッスンで扱っています。
  7. あなたの投稿を執筆・編集するための、2つ目のウェブサイトを作成してください。これは好きなようにセットアップして構いませんが、以下の機能が役立つかもしれません:
    • 公開済みかどうかを示す、すべての投稿のリスト。
    • 未公開の投稿を公開したり、公開済みの投稿を非公開に戻したりするためのボタン!
    • 「新規投稿」フォーム。凝ったものにしたければ、TinyMCEのようなリッチテキストエディタを使うこともできます。
    • コメントを管理する(つまり削除や編集ができる)能力。
  8. これについて、フロントエンドのコードにどれだけの労力をかけたいかは、あなた次第です。技術的にはこれはバックエンドに焦点を当てたコースなので、もしよければ、REST APIに集中しても構いません。
  9. 別々のアプリをデプロイすることは、それほど特別なことではありません。DeploymentレッスンのPaaSを使って、これまでのプロジェクトと同じようにAPIをデプロイし、以前フロントエンドをデプロイしたのと同じようにフロントエンドをデプロイしてください。Reactを使った場合は、CV Applicationプロジェクトからいくつかのホスティングの選択肢を思い出してください。
