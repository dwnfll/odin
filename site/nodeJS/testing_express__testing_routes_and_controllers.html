Testing Routes and Controllers

日本語訳

← nodeJS

We learn how to use Supertest to write tests for our routes and controllers

イントロダクション

ユニットテストが重要である理由はたくさんありますが、今ここでそれをすべて取り上げる必要はおそらくないでしょう。すでに私たちの基本的なJavaScriptコースを受講済みであれば、すでにユニットテストに出会っているはずであり、このレッスンの目的は、テストを書くことの哲学やメカニズムを教えることではなく、それらが私たちのExpressアプリケーションとAPIにどのように適用されるかを教えることです。

もし私たちのフロントエンドJavaScriptコースを完了していなければ、先に進む前に戻ってそれらのレッスンに目を通してください。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Expressのルート/コントローラーをテストするためにsupertestモジュールを使う。
  • SuperTestが私たちのExpressアプリケーションをどう扱うかを説明する。
  • superagentがSuperTestに提供する機能を説明する。
  • doneパラメータが何のために使われるかを説明する。
  • .expect()メソッドの機能を説明し、しっかりと理解する。
  • supertestのドキュメントとメソッドに親しむ。

supertestでルートをテストする

コード内の何かをテストするための、最も重要で基本的な要件は、それがエクスポートされたモジュールの中になければならないということです。これはカスタムミドルウェアにもルート/コントローラーにも当てはまるため、まず最初にしなければならないことは、もしまだそうなっていなければ、それらを別々のモジュールに分離することです。

ルートの場合、これをExpress.Routerを使ってどう行うかは、すでに知っているはずです。以下は、とても基本的な例です。

//// app.js
const express = require("express");
const app = express();

app.use(express.urlencoded({ extended: false }));

const indexRouter = require("./index");
app.use("/", indexRouter);

app.listen(3000, (error) => {
  if (error) {
    throw error;
  }
  console.log("running");
});
//// index.js
const express = require("express");
const index = express.Router();

const array = [];

index.get("/", (req, res) => {
  res.json({ name: "frodo" });
});

index.get("/test", (req, res) => res.json({ array }));

index.post("/test", (req, res) => {
  array.push(req.body.item);
  res.send('success!');
});

module.exports = index;

app.jsとindex.jsというこの2つのファイルは、いくつかのルートを定義し、それから私たちのExpressアプリをセットアップして起動します。今のところ、app.jsはExpressアプリを起動して実行するコードしか含んでいないため、これをテストする必要はありません!私たち自身のロジックは何も含まれていないので、テストする必要はないのです。しかし、index.jsには、私たちがテストしたいものがいくつか含まれています。

これらのルートを実際にテストしやすくするために、SuperTestというライブラリを使っていきます。そして、テストの構文に親しむために、このレッスンの例ではそれをJestと組み合わせて使います。npm install jest supertest --save-devを実行し、それがインストールされている間に、少し時間を取って(上でリンクした)SuperTestのGitリポジトリのREADMEに目を通してください。

以下が私たちのテストファイルです:

const index = require("../index");

const request = require("supertest");
const express = require("express");
const app = express();

app.use(express.urlencoded({ extended: false }));
app.use("/", index);

test("index route works", done => {
  request(app)
    .get("/")
    .expect("Content-Type", /json/)
    .expect({ name: "frodo" })
    .expect(200, done);
});

test("testing route works", done => {
  request(app)
    .post("/test")
    .type("form")
    .send({ item: "hey" })
    .then(() => {
      request(app)
        .get("/test")
        .expect({ array: ["hey"] }, done);
    });
});

一つずつ順を追って見ていきましょう。

まず、テストしようとしているモジュールをインポートする必要があります。この場合、それは上のindex.jsファイルです。

const index = require("../index");

次に、supertestとexpressの両方をインクルードします。新しいExpressアプリをセットアップし、それから先ほどインポートしたindexルーターを使っています。ここでこのセットアップを行わなければならない理由は、実際には元のapp.jsファイルには一切触れていないからです。このようにする主な理由は、app.listenコマンドを呼び出してサーバーを起動することを避けられるからですが、それだけでなく、より大きなアプリでは、いくつかの任意の設定ステップをスキップし、テストの目的のために必要な部分だけを含められる、という点でも有用です。より大きなテストスイートでは、この部分を独自のファイルに抽象化し、それぞれのテストファイルにインポートするのが、おそらく有用でしょう。

const request = require("supertest");
const express = require("express");
const app = express();

app.use(express.urlencoded({ extended: false }));
app.use("/", index);

SuperTestライブラリのおかげで、テスト自体は比較的簡単です!私たちがsupertestを、以下で見るように使うrequestという関数としてインポートしたことを思い出してください。これを、私たちが新しく作成したExpressアプリに対して呼び出し、そこにルートを渡し、それからそれを使って、レスポンスが期待する型と内容に一致することを確認します。

テストのコールバックに渡されている、doneというパラメータに注目してください。ほとんどのテストライブラリは、非同期処理の場合にテストが完了したことを知らせるために、これを使います。この場合、SuperTestは、私たちがそれを最後の.expectに渡すことを許してくれ、私たちの代わりにそれを呼び出してくれます。ありがとう、SuperTest!

test("index route works", done => {
  request(app)
    .get("/")
    .expect("Content-Type", /json/)
    .expect({ name: "frodo" })
    .expect(200, done);
});

私たちの2番目のテストは、最初のものととても似ていますが、postメソッドをテストしています。可能なすべての関数については、SuperTestのreadmeを読むことができますし、読むべきです。そのため、ここではそれぞれのステップの詳細には立ち入りません。しかし、最後の部分は私たちにとって重要です。あなたのJavaScriptのキャリアのこの時点までには、Promiseに親しんでいるはずなので、.then()という構文にも見覚えがあるはずです。この場合、私たちはPOSTリクエストが完了するのを待ち、それからそのPromiseが解決したときにGETリクエストを呼び出して、そのアイテムが配列にpushされたかどうかを確認します。

test("testing route works", done => {
  request(app)
    .post("/test")
    .type("form")
    .send({ item: "hey" })
    .then(() => {
      request(app)
        .get("/test")
        .expect({ array: ["hey"] }, done);
    });
});

もしここで実際のデータベースを使っていたなら、テスト用のデータベースかモックデータベースのどちらかを使って、似たようなことをしたいと思うはずです。そうしたもののセットアップについては、別のレッスンで話します。今のところは、本番データベースに対してテストコードを実行したくはない、と言っておけば十分でしょう!

課題

  1. 必ずSuperTestのドキュメントに目を通してください。
  2. SuperTestは実は、SuperAgentという別の関連プロジェクトから機能を取り込んでいます。SuperAgentで呼び出せるメソッドはどれもSuperTestからも呼び出せるので、SuperAgentのドキュメントにも目を通す必要があるでしょう。
