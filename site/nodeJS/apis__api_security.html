API Security

日本語訳

← nodeJS

We learn how to secure our APIs using JSON web tokens

イントロダクション

あなたのAPIを保護することは、重要なステップです。ビューテンプレートを提供するためにExpressを使っていたときは、ユーザーを認証するためにユーザー名とパスワードとともにPassportJSを使いましたが、それはExpressアプリを保護する唯一の方法ではなく、APIの文脈では、別のstrategyを使う方が理にかなっていることがよくあります。以前学んだユーザー名とパスワードのセッションパターンは、もちろんそれでも機能しますが、フロントエンドのコードとバックエンドを分離したことで、少し複雑になります。

もう一つのstrategyは、私たちのバックエンドとフロントエンドのコードの間で、安全なトークンを生成し、渡すことです。そうすることで、ユーザーのユーザー名とパスワードが漏洩しないことを保証でき、さらなるセキュリティのために、ユーザーのセッションを失効させる能力も得られます。基本的な考え方は、ユーザーが私たちのアプリにサインインすると、安全なトークンが作成され、それ以降のすべてのリクエストで、そのトークンが私たちのリクエストオブジェクトのヘッダーの中で渡される、というものです。結局のところ、あなたはすでにpassportを使ってユーザーを認証することに慣れているはずなので、このプロセスは簡単です。

このstrategyは、特にAPIで有用ですが、従来のビューテンプレートのプロジェクトでも使うことができます。ここでの主な違いは、クッキーを設定して確認する代わりに、私たちのリクエストのヘッダーの中で特別なトークンを渡すという点です。以前の認証のチュートリアルでは、Passportミドルウェアが送られてきたクッキーを確認し、それから私たちのユーザーを認証するか拒否するかを判断していました。今回は、それととても似たことを行いますが、クッキーを使う代わりに、トークンを渡すことになります。
