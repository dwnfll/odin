We look at Express for the first time and learn what it does for us

イントロダクション

前のセクションでは、Nodeを使い始めるところまで進みました。サーバー上のファイルからデータを読み書きする方法を学び、それによって複数ページのウェブサイトを提供できるようになりました。このプロセスは、いくぶん冗長で面倒だと感じたかもしれませんし、もっと複雑なユースケースをどうやって扱えばいいのか、疑問に思ったかもしれません。

このコースでは、Expressと呼ばれるバックエンドフレームワークを使っていきます。これは、実装の詳細の多くを私たちの代わりに処理してくれます。Express自体は、意図的に最小限で自分の主張を持たない(unopinionated)フレームワークです。多くのことを自分の好きなように行うことができ、必要な機能だけで拡張できます。しかし、これによって物事の進め方に大きな柔軟性が得られる一方で、複数の有効な選択肢の間で決めるのが、時に少し難しく感じられることもあります。

これから先、Model View Controller(MVC)パターンを使ったフルスタックアプリケーションの作成や、Weather AppやReact Shopping Cartのプロジェクトなどでこれまでに使ったことがあるようなREST APIの作成など、Expressをさまざまな方法で使う方法に深く入っていきます。取り込むべきことがたくさんあるので、着実に進めていってください。そして、TOP Discordサーバーでコミュニティに助けを求めることを恐れないでください!

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • 基本的なExpressサーバーをセットアップする。
  • 受信したリクエストがどのように処理され、最終的にサーバーによって応答されるかを説明する。
  • ミドルウェア関数とは何かを説明する。
  • 変更が加えられたときにアプリケーションを自動的に再起動する方法を説明する。

Expressをセットアップする

基本的なExpressアプリを作ってみましょう。新しいディレクトリの中で、npm init -yを実行してpackage.jsonを作成することから始めます。それが作成されたら、Expressの依存関係をインストールできます。

npm install express

これで、Expressサーバーの起点となるapp.jsファイルを作成できます。このファイルにはindex.jsやmain.jsなど好きな名前を付けられますが、ここではExpressのドキュメントで使われているのと同じ名前を使います。app.jsの中身は以下のようになります:

const express = require("express");
const app = express();

app.get("/", (req, res) => res.send("Hello, world!"));

const PORT = 3000;
app.listen(PORT, (error) => {
  // This is important!
  // Without this, any startup errors will silently fail
  // instead of giving you a helpful error message.
  if (error) {
    throw error;
  }
  console.log(`My first Express app - listening on port ${PORT}!`);
});

これを分解してみましょう。まずexpressをインポートし、それを呼び出してapp変数を初期化します。これが私たちのサーバーです。

次にroute(ルート)があります――app.getで始まる行です。これについては後ほど戻ってきます。

最後に、指定したポートで受信リクエストを待ち受けるよう、サーバーに伝えます。これはlocalhost(基本的にはコンピュータのローカル接続にすぎません)を介して行われます。ポート3000がデフォルトの選択肢ですが、未使用のポートであればどれでも使うことができます(例えば、Viteの開発サーバーはデフォルトでポート5173を使います)。ターミナルに戻ってnode app.jsを実行すると、うまくいけばMy first Express app - listening on port 3000!とログに表示されるはずです。ポートがすでに使用中であるなど、何か問題が起きた場合は、代わりにエラーがスローされます。

おめでとうございます!これで最初のExpressサーバーが起動しました。

portの変数

デモンストレーションのために、上ではポート番号を固定でハードコーディングしました。通常、ポート番号は環境変数から取得され、その環境変数が存在しない場合のフォールバック値が用意されます。

const PORT = process.env.PORT || 3000;

指定したポートがすでに使用中の場合、ソースコードを編集することなく環境変数の値を変更できます。また、一部のホスティングサービスは独自のポートを設定しており、それがハードコーディングされた固定値とは異なることもあります。

リクエストの旅路

これで、私たちのサーバーがポート3000で起動して実行中になったので、リクエストを送ってみましょう!ブラウザでhttp://localhost:3000/に移動してください(最後のスラッシュ/を忘れても心配いりません。ブラウザがその場合は黙って追加してくれます)。この操作は、ローカルホストのポート3000で待ち受けているサーバー(それが私たちのExpressサーバーです!)の/パスにGETリクエストを送信し、応答として受け取ったものをウィンドウに表示するよう、ブラウザに指示します。

どんなウェブURLにこのようにアクセスするときも、本質的にはこれと同じことをしています。アドレスバーからhttps://theodinproject.com/pathsに移動するのは、https://theodinproject.comの/pathsパスにGETリクエストを送信し、応答として受け取ったものを表示するよう、ブラウザに伝えているだけなのです。

http://localhost:3000/に移動すると、ウィンドウにHello, world!が表示されるはずです。まるで魔法のようですね?

サーバーがGETリクエストを受け取ると、Expressはそのリクエストをリクエストオブジェクトに格納します。このリクエストは、ミドルウェア関数と呼ばれる関数の連鎖を通過していき、最終的にはどれか一つのミドルウェア関数がExpressにそのリクエストへ応答するよう指示します。

この例では、リクエストは/パスへのGETリクエストとして届きます。これはapp.jsファイルにあるルートと一致します。

app.get("/", (req, res) => res.send("Hello, world!"));

ルートについては後のレッスンでより詳しく説明しますが、上の行を要約すると、これはExpressに「GETリクエストが/パスに届いたら、そのリクエストを次のミドルウェア関数の連鎖に通してください」と伝えています。ここでは、関数は一つしかありません。

もし複数のルートを定義していた場合、ExpressはリクエストされたHTTP動詞(例えばGET)とパス(/)の両方に一致する最初のルートに、リクエストを通します。ルートの順序は重要です!

Expressは、私たちが渡したコールバック関数を受け取り、リクエストオブジェクトを最初のパラメータ(慣習的にreqと名付けられます)に、そしてレスポンスオブジェクトを2番目のパラメータ(res)に渡します。私たちのコールバックは、レスポンスオブジェクトに対して、(res.sendを介して)文字列"Hello, world!"を送ることでリクエストに応答するよう指示しています。

それ以上実行するコードはなく、関数はreturnします。Expressはリクエストへ応答するよう指示されたので、リクエスト-レスポンスサイクルを終了します。一方、ブラウザは私たちのサーバーからの応答を受け取り、それを画面に表示します。それが私たちの"Hello, world!"という文字列です。応答としてほぼどんなものでも送ることができます。Expressにファイルを送信するよう指示することもできます。

ファイルの変更時にサーバーを自動的に再起動する

node app.jsでサーバーを実行しているとき、プロジェクトディレクトリ内のJavaScriptファイルやJSONファイルに加えた変更は、手動で中断してnode app.jsを再実行しない限り、自動的には反映されません。この手動のプロセスを避けるために、--watchフラグを追加することで、Nodeのウォッチモードを使うことができます。例えばnode --watch app.jsのようにします。Nodeはapp.jsの変更を監視し、それが最終的に依存しているすべてのファイルも監視します。変更を検知すると、WebpackやViteの開発サーバーと同じように、自動的にサーバーを再起動します。

Nodemonというパッケージを見かけることもあるかもしれません。これは高度に設定可能なパッケージで、同じように変更を監視してサーバーを再起動してくれます。Nodeには、常に安定した組み込みのウォッチモードがあったわけではないため、あちこちでNodemonを見かける可能性が高いでしょう。私たちのおすすめは、--watchフラグを介したNodeの組み込みウォッチモードを使い続けることです。これが断然もっともシンプルな方法だからです。
