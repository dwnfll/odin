SVG 日本語訳

SVG is neat!

イントロダクション

SVGは、ウェブ上で非常によく使われる画像フォーマットです。最初は少し分かりにくく感じるかもしれませんが、使い方を知ってしまえば、ウェブサイトのために高品質で動的な画像を作成する、信じられないほど強力なツールになります。

このレッスンでは、SVGとは正確には何なのか、何に使われるのか、そしてどうやってあなたのウェブサイトに埋め込めるのかを学びます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • SVG、ベクターグラフィック、XMLとは何か。
  • シンプルなSVGを作成し、ウェブサイトに追加する方法。
  • いつSVGを使うべきか、いつ別の画像フォーマットの方が適切か。

SVGとは何か?

SVGはスケーラブル(拡大縮小可能)な画像フォーマットであり、これは、ファイルサイズを増やすことなく、簡単にどんなサイズにも拡大縮小でき、品質を保てるということを意味します。また、CSSやJavaScriptを通してプロパティを変更できるため、プログラムで画像を作成したり変更したりする必要がある場合にも非常に便利です。

SVGは、よく以下のような用途に使われます:

  1. アイコン
  2. グラフ/チャート
  3. 大きく、シンプルな画像
  4. パターン化された背景
  5. SVGフィルターを介して他の要素にエフェクトを適用すること

では、それは一体何なのか?

「SVG」は「Scalable Vector Graphics(拡大縮小可能なベクターグラフィック)」の略です。ベクターグラフィックとは、数学によって定義される画像のことであり、画像がピクセルのグリッドによって定義される従来の「ラスターグラフィック」とは対照的です。ラスターグラフィックでは、詳細さはそのピクセルグリッドのサイズに制限されます。画像のサイズを大きくしたい(拡大したい)場合、そのグリッドのサイズを大きくする必要があります。それらの新しいピクセルすべてがどのように見えるべきかを、どう決めればよいのでしょうか?簡単な解決策はありません。さらに、グリッドが大きくなればなるほど、ファイルサイズも大きくなります。

一方、ベクターグラフィックにはグリッドがありません。代わりに、さまざまな形や線のための数式があります。これらは単なる数式にすぎないため、どれだけ大きく、あるいは小さく表示したいかは関係ありません---どんなサイズにも拡大縮小でき、品質やファイルサイズには何の影響もありません。

SVGにはもう一つ興味深い側面があります。それはXMLを使って定義されているということです。XML(別名「Extensible Markup Language」)は、APIからRSS、表計算ソフトやワードエディタソフトまで、多くのことに使われるHTMLに似た構文です。

SVGのソースコードがXMLであるという事実には、いくつかの重要な利点があります。

まず、それが人間が読めるということを意味します。JPEGをテキストエディタで開いたとしたら、単なる意味不明な文字の羅列にしか見えないでしょう。しかしSVGを開いてみると、次のようなものになります:

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100">
  <rect x=0 y=0 width=100 height=50 />
  <circle class="svg-circle" cx="50" cy="50" r="10"/>
</svg>

それでもまだ分かりにくいかもしれませんが、それでも---これらは単語です!タグです!属性です!JPEGのようなバイナリファイル形式と比べれば、間違いなく馴染みのある領域にいます。

XMLの2つ目の利点は、HTMLと相互運用できるように設計されていることです。つまり、上記のコードを何も変更せずにそのままHTMLファイルに配置でき、画像が表示されるはずだということです。そして、これらはHTML要素と同じようにDOM内の要素になれるため、CSSでそれらを対象にしたり、あなたがすでに使ってきたElement WebAPIを使って作成したりできます!

欠点

さて、SVGは明らかに素晴らしいものです!すべての画像をSVGに変換する時が来ましたね?いいえ、そう単純な話ではありません。SVGは比較的シンプルな画像には最適ですが、画像のあらゆる細部をXMLとして書き出す必要があるため、複雑な画像を保存するには非常に非効率です。あなたの画像が写真のようにリアルであるべきものであったり、細かいディテールやテクスチャ(「グランジテクスチャ」が良い例です)を持っていたりする場合、SVGはその仕事に間違ったツールです。

SVGの構造

通常、コード内でSVGをゼロから作成したいとは思わないでしょう。多くの場合、ウェブサイトから、あるいはそれらを作成できる画像エディタから、ファイルをダウンロードするかコードをコピーすることになります(Material iconsやFeather iconsは、人気のあるSVGアイコンライブラリの例です)。しかし、SVGをダウンロードして、ほんの少しだけ微調整したいと思うことはよくあるので、それぞれの部品が何であり、どう機能するのかを知っておくことは非常に役立ちます。

See the Pen Simple SVG Example by TheOdinProject (@TheOdinProjectExamples) on CodePen.

  1. xmlns - 「XML NameSpace」の略です。これは、あなたが使用しているXMLの方言を指定します。私たちの場合、その方言はSVG言語仕様です。これがないと、一部のブラウザは画像をレンダリングしなかったり、正しくレンダリングしなかったりします。
  2. viewBox - SVGの境界を定義します。SVG内の要素のさまざまな点の位置を定義する必要があるとき、これが参照されるものです。また、SVGのアスペクト比と原点も定義します。かなりたくさんのことをしているんですね!上記の例でさまざまな値をいろいろ試して、それが形にどう影響するかの感覚をつかんでみてください。
  3. class、id - これらの属性は、HTMLでのものとまったく同じように機能します。SVGでこれらを使用することで、CSSやJavaScriptを介して要素を簡単に対象にしたり、use要素を介して要素を再利用したりできます。
  4. <circle>、<rect>、<path>、<text>のような要素は、SVG名前空間によって定義されています。これらは私たちの基本的な構成要素です。SVGで非常に複雑な画像を作ることもできますが、それらのほとんどは、これらの基本要素のうちのほんの十数個程度で作成されています。SVG要素の完全なリストはこちらです。
  5. fillやstrokeのような多くのSVG属性は、CSSで変更できます。詳しくは、SVGのプロパティとCSSについてのこの記事で学んでください。

上記のコードをいろいろ試して、何が起きているのかの感覚をつかんでみてください。viewBoxの寸法を変えるとどうなりますか?あるいは、要素の属性を変えると?

SVGを埋め込む

実際にドキュメント内にSVGを配置する方法を決める際、主に2つのアプローチがあります:リンクとインラインです。

SVGをリンクすることは、基本的に他のどんな画像をリンクするのとも同じように機能します。<img>のようなHTML画像要素を使うことも、CSSでbackground-image: url(./my-image.svg)を使ってリンクすることもできます。それでも適切に拡大縮小されますが、SVGの内容はウェブページからアクセスできなくなります。

代わりの方法は、画像としてリンクするのではなく、その内容をウェブページのコードに直接貼り付けることでSVGをインライン化することです。それでも正しくレンダリングされますが、SVGのプロパティがあなたのコードから見えるようになり、CSSやJavaScriptを介して画像を動的に変更できるようになります。

SVGをインライン化することで、その真価を解き放つことができますが、いくつかの深刻な欠点も伴います。コードが読みにくくなり、ページのキャッシュ可能性が下がり、大きなSVGであれば、残りのHTMLの読み込みを遅らせてしまう可能性があります。

SVGコードをインライン化することの欠点のいくつかは、Reactのようなフロントエンドライブラリや、webpackのようなビルドツールを学んでしまえば回避できます。まだそれらに入る準備はできていないので、頭の片隅に留めておくだけにしてください。

今のところは、あなたのユースケースに最も合う方法を選んでください。リンクの方が一般的にクリーンでシンプルなので、HTMLと一緒にSVGコードを微調整する必要がない限り、そちらを優先してください。
