Using Flexbox and Grid

イントロダクション

GridとFlexboxのどちらを使うべきか、そしてどちらかがもう一方より優れているかどうかについて、議論があると言う人もいるかもしれません。実際のところ、これらは互いに補完し合うツールであり、組み合わせて使うことができ、それぞれがCSSの世界において独自の居場所を持っています。

コンテンツ優先設計とレイアウト優先設計

GridとFlexboxのどちらかを決める一つの方法は、あなたのデザインがコンテンツから始まるのか、それともレイアウトから始まるのかを考えることです。

コンテンツ優先設計では、まずコンテンツがどうあるべきかを明確にすることから始め、レイアウトはそれに従います。これはFlexboxを使う絶好の機会です。その柔軟な性質は、論理的なルールを通してアイテムの振る舞いをコントロールする力を与えてくれます。それらがどう成長し、縮小し、互いに対しての理想的なサイズと位置がどうであるか、そのすべてがレイアウトを動的にします。Flexboxはコンテンツをコントロールする力を与えてくれますが、最終的なレイアウトは単なる結果に過ぎません。flexコンテナの寸法によって、全体的なレイアウトは大きく変わり得ます。

レイアウト優先設計では、まずパーツをどう配置したいかを決め、それからコンテンツを埋めていきます。それこそが、Gridが輝く場面です。グリッドの行と列のトラックを定義することで、レイアウトを完全にコントロールできます。グリッド内のコンテンツは、明示的または暗黙的なトラックのスペースしか埋めることができません。ですので、コンテナの全体像がどうあるべきかについてすでにアイデアがある場合は、Gridが明らかな選択肢になります。

コンテンツ優先設計もレイアウト優先設計も、FlexboxかGridのどちらかを使うことを強制するものではありません!多くの人がFlexboxのために取っておくタスクである、1次元のアイテムのセットのレイアウトを、Gridを使って試してみましょう。

See the Pen 1-Dimensional Grid | CSS Grid by TheOdinProject (@TheOdinProjectExamples) on CodePen.

うまくいって、まさに美しく見えますね!しかし、これらのボックスを将来動かしたくなったとしましょう。あるいは例えば、3番目のボックスを2行目に伸ばして、ボックスが1行だけに収まるように縮みすぎないようにしたいとしましょう。これらはどちらもGridでは可能です。しかし、レイアウトをコントロールすることが優先事項でないなら、Flexboxの方が直感的でタスクに適しています。

FlexboxとGridを組み合わせる

1次元のコンテンツがある場合、Flexboxを使うと、そのコンテンツがFlexコンテナ内でどう位置指定されるかをコントロールしやすくなります。一方で、複雑な2次元レイアウトにコンテンツを正確に配置したい場合は、Gridの方が使いやすいことがあります。

全体的なレイアウトをグリッドにしたいが、グリッドアイテムをflexの親として振る舞わせたい、としましょう。こうすることで、グリッドアイテムはGridが可能にする正確な2次元の配置を使って動かすことができる一方で、グリッドアイテムの中のコンテンツはFlexを使って自由に動き回れるようになります。CSS-Tricksからのこの例を見てみてください。

See the Pen Combine Grid and Flexbox by TheOdinProject (@TheOdinProjectExamples) on CodePen.

締めくくりの意見

このレッスンには推奨事項が含まれていますが、FlexboxやGridを使う「正しい」方法や「間違った」方法があるわけではありません。結局のところ、それは個人の好みと、与えられたタスクが何であれ、開発者がどちらがより簡単だと感じるかによります。この時点で、あなたはこれら両方のツールをあなたの道具箱に持っており、それらを一緒に使ったり、一方を他方の代わりに使ったりする方法についても垣間見ました。FlexboxとGridを学ぶ最良の方法は、両方を使ってたくさんのプロジェクトを構築し、異なる状況でどちらを使うべきかについて自分自身の意見を育てていくことです。
