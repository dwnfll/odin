Custom Properties 日本語訳

Learn how to use Variables in your CSS to avoid repeating common values like colors, and keep your styles consistent

イントロダクション

カスタムプロパティ(CSS変数とも呼ばれます)は、CSSファイルを書く際に非常に便利で強力なツールになり得ます。簡単に言うと、これらを使うことで、ファイル全体を通して何度でも好きなだけCSSの値を参照できるようになります。カスタムプロパティを使うことで、特定の値のすべてのインスタンスを一つずつ更新する代わりに(「この赤の色合いは薄すぎるから、これら7つのセレクタすべてで色合いを変えよう」)、たった一つのインスタンス、つまりカスタムプロパティ自体だけを更新すればよくなります。それだけでなく、カスタムプロパティはプロジェクト全体を通して色の一貫性を保つのにも役立ち、プロジェクトが大きくなるにつれて本当に助けになります。

異なるコンテキストの下でカスタムプロパティを再定義することさえ可能で、これは最近多くのウェブサイトで見かけるダークテーマやライトテーマのような、テーマを作成する際に非常に役立ちます。

カスタムプロパティを使う

カスタムプロパティを宣言してアクセスするための構文は、通常のルール宣言の書き方とそれほど変わりません:

.error-modal {
  --color-error-text: red;
  --modal-border: 1px solid black;
  --modal-font-size: calc(2rem + 5vw);

  color: var(--color-error-text);
  border: var(--modal-border);
  font-size: var(--modal-font-size);
}

それだけです!まず、二重ハイフンに続けて、大文字小文字を区別する、ハイフンで区切られたプロパティ名(color-error-textはColor-Error-Textと同じにはなりません)でカスタムプロパティを宣言します。この名前は好きなものにできます。ここではケバブケース(単語を単一のハイフンで区切る)を使うことが非常に重要です。なぜならスペースは無効だからです(--color error textは機能しません)。それから、新しく宣言したカスタムプロパティに、色の値、ショートハンドの値、あるいはより複雑な関数など、有効などんなCSSの値でも保存できます(これらはほんの数例です)。

カスタムプロパティにアクセスしたい場合は、CSSプロパティの値としてvar()関数を使い、そして括弧の中に(先頭の二重ハイフンを含めて)カスタムプロパティを入れます。

フォールバック値

実はvar()関数は2つのパラメータを受け付けます。1つ目のパラメータはすでに説明した通り、割り当てたいカスタムプロパティです。2つ目のパラメータは、オプションのフォールバック値です。カスタムプロパティに加えてフォールバック値が提供されている場合、そのカスタムプロパティが無効であるか、まだ宣言されていない場合に、フォールバック値が使用されます。フォールバックとして別のカスタムプロパティを渡すことさえでき、それがさらに独自のフォールバック値を持つこともできます!

.fallback {
  --color-text: white;

  background-color: var(--undeclared-property, black);
  color: var(--undeclared-again, var(--color-text, yellow));
}

上記の例では、background-colorプロパティの値はblackになり、colorプロパティの値はwhiteになります。もし--color-textカスタムプロパティが無効であるか存在しなかった場合、フォールバックのフォールバックが引き継がれ、colorプロパティの値はyellowになります。

スコープ

上記の最初の例で、同じ宣言ブロックの中でカスタムプロパティを宣言してからアクセスしていることに気づいたかもしれません。それは、カスタムプロパティのスコープがセレクタによって決定されるからです。このスコープには、カスタムプロパティが宣言されたセレクタと、そのセレクタの子孫すべてが含まれます。JavaScriptでスコープがどう機能するかに馴染みがあれば、この種の振る舞いは少し似ていると感じるはずです。

以下の例では、cool-paragraphクラスを持つ要素だけが赤い背景でスタイルされます。なぜなら、それはカスタムプロパティが宣言されている要素の子孫だからです。

<div class="cool-div">
  <p class="cool-paragraph">Check out my cool, red background!</p>
</div>

<p class="boring-paragraph">I'm not in scope so I'm not cool.</p>
.cool-div {
  --main-bg: red;
}

.cool-paragraph {
  background-color: var(--main-bg);
}

.boring-paragraph {
  background-color: var(--main-bg);
}

:rootセレクタ

カスタムプロパティのスコープを制限したい場合もあれば、他の多くの、互いに関連のないセレクタでカスタムプロパティを使えるようにしたい場合もあります。一つの回避策は、たくさんのセレクタに同じカスタムプロパティを宣言することですが、それではそもそもカスタムプロパティを使う目的の一つ(一度に複数のインスタンスの値を変更する容易さ)が損なわれてしまいます。

より良い解決策は、:rootセレクタでそれらのカスタムプロパティを宣言することです。これは基本的にhtmlセレクタと同じものですが、より高い詳細度を持ちます。

<p class="cool-paragraph">Lorem ipsum dolor sit amet.</p>

<p class="exciting-paragraph">Lorem ipsum dolor sit amet.</p>
:root {
  --main-color: red;
}

.cool-paragraph {
  color: var(--main-color);
}

.exciting-paragraph {
  background-color: var(--main-color);
}

上記の例のように:rootセレクタでカスタムプロパティを宣言することで、CSSファイル内の他のどの有効なセレクタからでもそれにアクセスできます。なぜなら、他のどのセレクタも:rootセレクタの子孫とみなされるからです。

カスタムプロパティでテーマを作成する

:rootセレクタは、カスタムプロパティによりグローバルにアクセスできるようにしてくれるだけでなく、ページにテーマを追加する一つの方法も与えてくれます:

See the Pen Theme Toggle | CSS Custom Properties by TheOdinProject (@TheOdinProjectExamples) on CodePen.

まず、CodePenのHTMLタブではルート要素に直接アクセスできないため、設定メニューを使ってデフォルトでdarkクラスを適用しています。ぜひペンを開いて、この設定を変更してどう動作するか見てみてください!次に、CSSで:rootセレクタのカスタムプロパティに2つのスコープを作成しました。一つはhtml(つまりルート)要素がdarkクラスを持つ場合、もう一つはlightクラスを持つ場合です。他のセレクタは、現在ルート要素にどちらのクラスが存在するかに応じて、カスタムプロパティの値を使用します。

メディアクエリ

ユーザー自身にテーマを切り替える能力を与えることは素晴らしいことですが、特定のサイトやアプリケーションで見かけたことがあるかもしれない、テーマを設定するための別の選択肢があります: ユーザーのオペレーティングシステムやユーザーエージェント(ブラウザなど)のテーマ設定を使うことです。これはprefers-color-schemeメディアクエリを使って行うことができ、これによりユーザーのデバイスや設定(画面サイズやテーマの好み(ライト/ダークモード)など)に基づいて異なるスタイルを適用できます。

prefers-color-schemeクエリは、ユーザーがOSやブラウザでテーマを選択しているかどうかをチェックします。心配いりません、メディアクエリについては後でさらに詳しく扱います。今のところは、OSやブラウザのテーマを変更して、例がリアルタイムで更新されるのを見てみてください!

See the Pen Theme Query | CSS Custom Properties by TheOdinProject (@TheOdinProjectExamples) on CodePen.

まず、メディアクエリの外側の:root要素にカスタムプロパティを追加しました。これにより、ユーザーがOSやユーザーエージェントに設定を持っていない場合や、ブラウザがそのメディアクエリをサポートしていない場合に、デフォルトのテーマが得られます。この場合、私たちは「light」テーマの色をデフォルトとして使っています。それから、ユーザーが好みの設定でダークテーマを持っている場合のために、prefers-color-schemeメディアクエリを追加しました。

prefers-color-schemeメディアクエリを使うことは、ユーザーが好みのテーマに手動で変更する必要がないため、ユーザーにとってかなり役立つことがあります。とはいえ、このメディアクエリを使う際に注意すべきことがいくつかあります:

  1. メディアクエリの有効な値はdarkとlightだけなので、これを使ってこの2つの基本的なテーマを超えたテーマを実装することはできません。
  2. メディアクエリのlightという値は、実際にはユーザーがライトテーマを指定している場合、あるいは何も設定していない場合のためのものです。
  3. これはユーザー自身がテーマを変更することを許しません。これは、ユーザーが何らかの理由でOS/ユーザーエージェントの好みとは反対のテーマを使いたい場合には、依然として重要になり得ます。
