イントロダクション

ブラウザは、すべてのウェブページに一連のデフォルトスタイルを適用します。これについて直接考えたことはないかもしれませんが、間違いなく遭遇したことはあるはずです。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • ブラウザのデフォルトスタイルについて学びます。
  • CSSリセットを使って、それらのデフォルトスタイルを削除したり変更したりする方法を学びます。

デフォルトスタイルとは何で、どこから来るのか?

プロジェクトに取り組んできた中で、h1要素の大きく太字な見出しや、a要素の青い下線付きリンクなど、特定の要素に適用されるデフォルトスタイルにおそらく気づいたことでしょう。デフォルトのmarginやpaddingのようなものに苦戦した可能性も十分あります。これらのスタイルはユーザーエージェントスタイルシートの一部であり、CSSがないウェブページに基本的なスタイルを保証してくれます。各ブラウザは独自のユーザーエージェントスタイルシートを持っているため、デフォルトスタイルはブラウザ間で多少異なります。

デフォルトが気に入らない場合はどうする?

ごくわずかな例外を除いて、単に自分自身のCSSルールを書けば済みます。あなたがスタイルシートに書くルールは、ユーザーエージェントのルールよりも優先度が高いため、デフォルトを上書きします。しかし、別の選択肢もあります。

ブラウザ間の不一致に対処し、スタイリングの一貫した出発点を確立するために、一部の開発者はCSSリセットを使い始めました。これらのリセットは、ユーザーエージェントスタイルシートによって設定されたデフォルトを変更または削除することを目的としたCSSルールを含むスタイルシートです。それらを使用することで一貫性を実現する助けとなり、開発者が干渉なくスタイルを適用できる、まっさらな状態を提供できます。

CSSリセットは今でも一般的に使われていますが、必須ではありません。使わないことを選ぶ開発者もいれば、独自のものを作成したり、既製のリセットを利用したりする開発者もいます。リセットは主観的で個人の考え方に基づくものであり、それを作成した開発者の好みを反映しているということを理解しておくのが重要です。あなたは自分自身でどうしたいかを決めることができます。

課題

  1. リセットの素晴らしい歴史と、リセットが個人の考え方に基づくとはどういうことかについて、Reboot, Resets, and Reasoningを読んでください。
  2. Making the case for CSS normalize and reset stylesheets in 2023を読んでください。さまざまなリセットの違いと、なぜそれらを使うことを選ぶかもしれないかについて、見事に論じてくれています。
  3. Josh Comeauのカスタムcssリセットにも、彼が使用する各ルールの背後にある思考プロセスの素晴らしい解説が含まれており、これらの考え方についてどう考えればよいかのイメージを与えてくれます。
