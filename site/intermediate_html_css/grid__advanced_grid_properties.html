Advanced Grid Properties

日本語訳

← intermediate_html_css

Learn some of the more useful, but advanced grid properties.

イントロダクション

ここまでで、グリッドの作成方法、トラックのサイズの調整方法、特定の行と列にグリッド要素を位置指定する方法を学びました。今、あなたはどんな種類の静的なグリッドレイアウトでも作れるだけのツールをすべて持っています。しかし、グリッドをよりレスポンシブに、動的に、あるいは再利用可能にしたい場合はどうすればよいでしょうか?

このレッスンでは、それを助けてくれる、もう少し高度なGridのプロパティについて学びます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • repeat関数を使って、複数のグリッドトラックをより簡単に作成します。
  • 明示的なサイズの代わりにfr単位を使ってグリッドトラックを作成します。
  • 最小・最大・理想のトラックサイズの境界を設定します。
  • auto-fitとauto-fillを使って、動的な数の行や列を持つグリッドを作成します。
  • auto-fit/auto-fillとminmax()を組み合わせて、レスポンシブなグリッドを作成します。

セットアップ

このレッスンには実践的に取り組んでいきます。5列2行のグリッドをセットアップし、すべてが見やすくなるようにいくつかのスタイルを適用しましょう。

grid-item、p、imgセレクタ

ここにあるすべてのプロパティは、グリッドアイテムを少し見栄えよくするためのものです。どれも比較的シンプルなので、詳細に踏み込む必要はありません。

grid-container

コンテナには、当然ながらコンテナをCSS Gridとして描画するためにdisplay: gridを使っています。しかし、次のプロパティはあなたにとって馴染みがないかもしれません: resize: bothです。これは、右下の角をクリックしてドラッグすることで、ユーザーがコンテナをリサイズできるようにするプロパティです。これは、グリッドのサイズに基づいてグリッドトラックをリサイズするプロパティを使い始めるときに役立ちます。

ズームレベルを変更する: コンテナをリサイズする余地ができるように、CodePenの埋め込みを0.5倍か0.25倍で表示することを忘れないでください。

コンテナをグリッドが収まる大きさより小さくリサイズした場合にスクロールを有効にするために、overflow: autoを使っています。

グリッドアイテムをよりよく視覚化できるように、「gutter」エリアを確立するためにgapとpaddingプロパティを使っています。

borderとbackground-colorは、コンテナを見栄えよくするために含まれています。

grid-template-rows: 150px 150px;
grid-template-columns: 150px 150px 150px 150px 150px;

ここが、このレッスンで注目したい場所です。2行5列を作るために、それぞれの行と列のトラックサイズを個別に手動で定義しています。

うわあ、なんて面倒なんでしょう!

まあ、それほど面倒ではなかったかもしれません。しかし、この場合、2x5のグリッドしか作っておらず、これは合計10個のアイテムを保持できます。何百ものアイテムを保持できるグリッドのすべての列と行を定義するのに、この方法を使うことを想像してみてください!

そこで登場するのがrepeat()です。

Repeat

repeat()は、CSS Gridのtemplateプロパティで利用できるCSS関数で、それぞれのトラックのサイズを個別に手動で入力することなく、行や列の数とその望むサイズを定義できるようにしてくれます。例えば、上記の私たちのセットアップでは:

.grid-container {
  grid-template-rows: 150px 150px;
  grid-template-columns: 150px 150px 150px 150px 150px;
}

は、次のように書き換えられます:

.grid-container {
  grid-template-rows: repeat(2, 150px);
  grid-template-columns: repeat(5, 150px);
}

自分で確認してみてください!

フラクショナル単位

たくさんのグリッドトラックを素早く作る方法が分かったので、次はそれらを動的にし始める方法を学ぶ番です。この文脈で動的とは、「柔軟である」あるいは「何らかの形でレスポンシブである」ことを意味します。動的の反対は静的、つまり、このサンプルグリッドのセットアップで使った150pxのように、特定の定義された高さに固定されていることです。

グリッドアイテムを動的にする最も基本的な方法は、frとも呼ばれるフラクショナル単位を使うことです。

fr単位は、グリッドに残っている残りのスペースを分配する方法です。例えば、合計幅400pxの4列グリッドがあり、それぞれの列トラックに割り当てられた4つのグリッドアイテムがサイズとして1frを持っている場合、すべてのグリッドアイテムには、その400pxのスペースの1フラクション(分数)分、つまり100ピクセルが与えられるはずです。

作成したサンプルグリッドの列と行のトラックに、150pxという静的な幅の代わりに1frという動的な幅を与えたらどうなるか見てみましょう:

See the Pen fr Unit 1 | CSS Grid by TheOdinProject (@TheOdinProjectExamples) on CodePen.

グリッドアイテムに、残りのスペースを不均等に分配するよう指示することもできます。例えば、5つの列を分割するときに、最初の2つのトラックサイズを2fr、残りの3つを1frにすると、最初の2つのトラックは他のトラックの2倍の残りスペースを与えられます。この例を前の例と比較してみてください:

グリッドトラックを定義するさまざまな方法

ここではrepeat()関数を使い続けていますが、これは昔ながらのやり方で書くこともできます!

ここでのポイントは、最初の2列には2fr単位が割り当てられ、残りの3列には1frが割り当てられているということです。これはつまり、グリッドが動的に大きくなったり小さくなったりするにつれて、スペースはこれらの列の間で異なる量に分配されるということです。具体的には、最初の2列は残りの3列の2倍のピクセル数を得ることになります。

リサイズすると、上記で述べたように、グリッドアイテムがそれぞれに割り当てられたfr単位の数に比例して大きくなることに注目してください。

ここまでで、グリッドをできる限り大きくリサイズすると、グリッドアイテムがどれだけ大きくなるかに制限がないことに気づいたかもしれません。しかし、できる限り小さくリサイズすると、グリッドがアイテムに許す明確な「最小」サイズがあります。この場合、それは<p>要素か<img>要素のどちらかが、はみ出さずになれる最小のサイズです。このブレークポイントは、アイテムのmin-contentの値です。このCSSキーワードは非常に便利ですが、このレッスンの範囲を超えています。詳細については、min-contentについてのMDNのドキュメントをチェックしてみてください。

最小・最大トラックサイズ: min()とmax()

グリッドを非常に小さくリサイズしたとき、ブラウザがアイテムをmin-contentの値より縮小させないようにしてくれることを知っておくと安心です。しかし、ほとんどの場合、それに頼りたくはありません。開発者として、最も極端な状況であっても、コンテンツがどれだけ小さく、あるいは大きくなるべきかを明示的に決めておく方がずっと良いのです。

min()とmax()については、前のCSS関数についてのレッスンで学びましたが、少し復習しても害はないでしょう。これらの関数はどちらも、あなたが与える引数に基づいて値を返します。min()は渡されたすべての値の中で最も小さいものを返し、max()は最も大きいものを返します。例えば、min(100px, 200px)は毎回100pxという値を返し、max(100px, 200px)は毎回200pxという値を返します。

これらの関数には、好きなだけたくさんの引数を与えることができます:

.grid-container {
  grid-template-rows: repeat(2, min(100px, 200px, 300px, 400px, 500px));
  grid-template-columns: repeat(5, max(100px, 200px, 300px, 400px, 500px));
}

もちろん、これらの関数に静的な単位を与えるのは、計算に意味がなくなるため馬鹿げています。最小値または最大値が常に返されるだけです。上記の例では、グリッドの行は常に100px(5つの値のうち最小)のサイズになり、グリッドの列は常に500px(5つのうち最大)のサイズになります。しかし、これらの引数の一つとして動的な値を与えると、特にGridの文脈において、これらの関数の本当の潜在能力が解き放たれます:

.grid-container {
  grid-template-rows: repeat(2, min(200px, 50%));
  grid-template-columns: repeat(5, max(120px, 15%));
}

この場合、グリッドの行のサイズは、200pxという値とグリッドコンテナの高さの50%という値から計算されます。リアルタイムで、ブラウザはこれら両方の値を比較し、どちらか小さい方をグリッドの行のサイズに適用します。基本的に、これがこのグリッドに伝えているのは、トラックのサイズはグリッドの縦方向の全スペースの50%であるべきだ(行のサイズを定義しているため)ということですが、ただしその数値が200pxを超える場合は除く、ということです。基本的には、トラックの最大高さを設定していることになります。

逆に、グリッドの列のサイズは、120pxとグリッドコンテナの幅の15%という2つの値のうち大きい方に基づいて計算されます。そうすることで、基本的に、グリッドの列サイズの最小幅を120pxに設定していることになります。ここにある例をチェックし、クリックしてドラッグしてグリッドの寸法を変え、グリッドアイテムがどう反応するか見てみてください:

See the Pen min and max | CSS Grid by TheOdinProject (@TheOdinProjectExamples) on CodePen.

動的な最小・最大サイズ

minmax()

minmax()は、特にGridで使われるCSS関数です。以下のCSSプロパティでのみ使うことができます:

  • grid-template-columns
  • grid-template-rows
  • grid-auto-columns
  • grid-auto-rows

これは比較的シンプルな関数で、2つの引数しか取りません:

  1. グリッドトラックが取り得る最小のサイズ
  2. グリッドトラックが取り得る最大のサイズ

min()やmax()とは異なり、両方の引数に静的な値を使うことが理にかなう場合があります。以下は、これまで使ってきたグリッドをminmax()といくつかの静的な値で書いた例です:

.grid-container {
  grid-template-rows: repeat(2, 1fr);
  grid-template-columns: repeat(5, minmax(150px, 200px));
}

grid-template-columnsがminmax()の値で設定されているため、それぞれのグリッドアイテムの幅は、グリッドコンテナが水平方向にリサイズされるにつれて大きくなったり小さくなったりします。しかし、グリッドが縮小していくと、列トラックは150pxで縮小するのをやめ、グリッドが大きくなっていくと、200pxで大きくなるのをやめます。まさに柔軟性の極みです!以下で自分でも確認してみてください:

See the Pen minmax | CSS Grid by TheOdinProject (@TheOdinProjectExamples) on CodePen.

clamp()

minmax()とは異なり、clamp()はグリッドコンテナ内だけでなく、どこでも使えるCSS関数です。min()やmax()と同様に、これについても前のレッスンで学びましたが、簡単に復習しましょう。構文は次の通りです:

clamp(minimum-size, ideal-size, maximum-size)

これが行うのは、アイテムに最小または最大のしきい値のいずれかに達するまで、自身をリサイズさせることです。

clamp()の目的は、制約付きの柔軟にサイズ変更できるトラックを作ることなので、「理想のサイズ」の引数には動的な値を使いたいところですが、最小と最大のサイズには通常静的なサイズを使います。ただし、ここでも動的な値を使うことは可能です。

以下はグリッドではない例です。グリッドについては後ほど改めて見ていきます:

.non-grid-example {
  width: clamp(500px, 80%, 1000px);
}

この要素は、単なるdivだと考えることができますが、親の幅の80%に等しい幅で描画されます。ただし、その数値が500pxより小さい場合や1000pxより大きい場合は、その数値を幅として使います。

さて、私たちのグリッドに戻りましょう:

.grid-container {
  grid-template-columns: repeat(5, clamp(150px, 20%, 200px));
}

See the Pen clamp | CSS Grid by TheOdinProject (@TheOdinProjectExamples) on CodePen.

トラックが最小または最大のしきい値に達するまで、コンテナの幅の20%を保ち続けることに気づきましたか?

clamp()とminmax()を使うことは、私たちのウェブサイトを見栄え悪くしてしまう重要なブレークポイントに達しないようにしながら、グリッドをよりレスポンシブにするための素晴らしい方法です。これは、極端なサイズに追いやられたときにはみ出したり望ましくない形で描画されたりする傾向がある画像や要素を使うときには、不可欠です。

auto-fitとauto-fill

この2つの値は、実はrepeat()関数の仕様の一部ですが、その有用性はminmax()関数を理解するまでは明らかにならないため、レッスンの最後に取っておきました。ユースケースはこうです: グリッドの列数を、グリッドのサイズに応じて柔軟にしたいとします。例えば、グリッドの幅が200pxしかない場合は、列を1つだけにしたいかもしれません。幅が400pxなら2つ、というようにです。ありがたいことに、auto-fitとauto-fillがここで救いの手を差し伸べてくれます!

auto-fillとauto-fitについてのW3の仕様によると、これら両方の関数は、グリッドアイテムがコンテナからはみ出さない範囲で「可能な限り最大の正の整数」を返します。以下は例です:

.example {
  display: grid;
  width: 1000px;
  grid-template-columns: repeat(auto-fit, 200px);
}

このグリッドでは、1000pxという固定の幅があり、それぞれ200pxのトラックで列を埋めるように指示しています。少なくとも5つのグリッドアイテムがある限り、これは何であれ5列のレイアウトになります。この場合、auto-fillも実際には同じことを行います。その違いについてはすぐ後で扱います。

auto-fitとauto-fillの本当の魔法は、minmax()をその方程式に組み込んだときに発揮されます。minmax()を使うと、グリッドがはみ出さないようにminmax()関数の制約を使って各列のサイズを決めながら、できるだけ多くの列を持ちたいということをグリッドに伝えることができます。今、リサイズしたときに私たちのグリッドがどれだけかっこよく見えるか見てみてください!

.grid-container {
  grid-template-columns: repeat(auto-fit, minmax(150px, 1fr));
}

See the Pen autofit 1 | CSS Grid by TheOdinProject (@TheOdinProjectExamples) on CodePen.

リサイズすると、列が自動的にいくつ横に並べられるかを把握することに気づきましたか?もしそれがかっこいいと思わないなら、脈を測ってみた方がいいですよ!

では、repeat(auto-fit, minmax(150px, 1fr));では具体的に何が起きているのでしょうか?auto-fitは、グリッドをはみ出さない最も大きい正の整数を返すことを思い出してください。まず、ブラウザはグリッドのコンテンツボックス(つまり、マージン、ボーダー、パディングを無視したもの)の幅を知る必要があります。

この例のために、私たちのグリッドのコンテンツボックスが現在500pxの幅だと仮定しましょう。次に、ブラウザはその幅にいくつのグリッド列トラックが収まり得るかを知る必要があります。これを行うために、minmax()関数の最小値、つまり150pxを使います。これが最も多くのアイテム数をもたらすからです。もし私たちのウィンドウが500pxの幅なら、これは私たちのグリッドが3列を描画することを意味します。しかし、それだけではありません!ブラウザが何列収まるかを決定したら、次にminmax()関数によって許される最大値まで列をリサイズします。この場合、最大サイズは1frなので、3つの列すべてに利用可能なスペースが均等に割り当てられます。ウィンドウをリサイズするたびに、これらの計算がリアルタイムで行われ、その結果が上記の例で見たものです!

auto-fillはどうか?

ほとんどの場合、auto-fillはauto-fitとまったく同じように機能します。違いが目立つのは、グリッドの行を一度に埋めきるにはアイテムの数が足りない場合だけです。グリッドが、別のグリッドアイテムが収まるかもしれないサイズまで広がっても、収まるアイテムがそれ以上残っていない場合、auto-fitはグリッドアイテムをそのmaxサイズに保ち続けます。auto-fillを使うと、たとえ描画するアイテムがなくても、別のグリッドアイテムを追加できるスペースができた時点で、グリッドアイテムはそのminサイズにサッと戻ります。グリッドが拡大し、新しいグリッドトラックのためのスペースがさらに利用可能になるにつれて、maxまで成長してからminにサッと戻るというパターンを続けていきます。
