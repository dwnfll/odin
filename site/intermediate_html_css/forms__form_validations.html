Form Validation 日本語訳

Learn the basics of validating forms in HTML.

イントロダクション

バリデーションを使うと、ユーザーが入力にどんなデータを入力できるかを決める、特定の制約やルールを設定できます。ユーザーがルールを破るデータを入力すると、メッセージが表示され、入力されたデータの何が間違っていたか、どう修正すればよいかについてフィードバックが提供されます。

バリデーションは、うまく設計されたフォームにおける重要な要素です。バックエンドシステムが不正なデータを受け取ることから守る助けとなり、ユーザーがフォームとやり取りする体験を、できる限り馬鹿正直にシンプルなものにする助けとなります。

このレッスンでは、HTMLフォームで使えるいくつかの組み込みバリデーションを探っていきます。また、CSSでバリデーションをスタイリングすることについても深く掘り下げていきます。

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • カスタムバリデーションを構築する方法を知ります。

必須バリデーション

例えばログインフォームのメールアドレスとパスワードのように、フォームを送信する前に特定のフィールドが入力されていることを確認したい場合がよくあります。

フィールドを必須にするには、required属性を追加します:

See the Pen forms-required-validation by TheOdinProject (@TheOdinProjectExamples) on CodePen.

良いユーザー体験を確保し、アクセシビリティのガイドラインを満たすために、どのフィールドが必須であるかを常に示すべきです。これは、例のように、必須フィールドのラベルにアスタリスク(*)を追加することでよく行われます。アスタリスク(*)の意味をユーザーに明確にするメッセージを追加することもできます。

テキスト長のバリデーション

時には、フィールドに最小または最大の文字数を入力してもらいたい場合があります。これらのバリデーションを使う実世界の例としては、X(旧Twitter)のステータスフィールドがかつて持っていた140文字制限や、ユーザー名フィールドの最小・最大文字数の制約などがあります。

最小長のバリデーション

最小長のバリデーションを追加するには、フォームコントロールに、そのフォームコントロールで許可したい最小文字数を表す整数値を持つminlength属性を与えます:

See the Pen forms-min-length-validation by TheOdinProject (@TheOdinProjectExamples) on CodePen.

テキストエリアに3文字未満を入力してpostボタンをクリックし、バリデーションが実際に動作するのを見てみてください。

minlengthはrequiredを意味しない

上記の例で、入力に何も入力せずに試してみると、それでも送信されてしまいます。これは、MDNのminlengthについてのドキュメントに記載されている通り、「制約バリデーションは、値がユーザーによって変更されたときにのみ適用される」ためです。

最大長のバリデーション

最大長のバリデーションを追加するには、フォームコントロールに、そのフォームコントロールで許可したい最大文字数を表す整数値を持つmaxlength属性を与えます:

See the Pen forms-maximum-length-validations by TheOdinProject (@TheOdinProjectExamples) on CodePen.

最大長のバリデーションを使うと、ブラウザは、ユーザーがmax length属性の値より多くの文字を入力するのを防ぎます。上記の例で自分でも試してみてください。

バリデーションを組み合わせる

HTMLでは、フォームコントロールに好きなだけたくさんのバリデーションを適用できます。例えば、投稿用の<textarea>にminlengthとmaxlengthの両方のバリデーションを与えることができます:

See the Pen forms-combining-validations by TheOdinProject (@TheOdinProjectExamples) on CodePen.

これにより、ユーザーの入力をコントロールする幅がずっと広がります。

数値範囲のバリデーション

テキストベースのフォームコントロールの長さをコントロールする必要があることがよくあるのと同じように、数値ベースのフォームコントロールにユーザーが入力できる値の範囲をコントロールしたい状況もたくさんあります。

これは、min属性とmax属性を使うことで行うことができ、これによりフォームコントロールに入力される値の下限と上限を設定できます。min属性とmax属性は、number、日付、時間の入力のような、数値ベースのフォームコントロールでのみ機能します。サポートされている要素の完全なリストは、MDNのmax属性についてのドキュメントで見ることができます。

これらのバリデーションを使う実世界のユースケースとしては、商品注文フォームでの数量制限や、フライト予約フォームでの乗客数の選択などがあります。

最小値のバリデーション

最小値のバリデーションを追加するには、フォームコントロールに、そのフォームコントロールに受け付けさせたい最小の数値を表す整数値を持つmin属性を与えます:

See the Pen forms-min-validation by TheOdinProject (@TheOdinProjectExamples) on CodePen.

数量を0にしてフォームを送信してみて、バリデーションが実際に動作するのを見てみてください。

最大値のバリデーション

最大値のバリデーションを追加するには、フォームコントロールに、そのフォームコントロールに受け付けさせたい最大の数値を表す整数値を持つmax属性を与えます:

See the Pen forms-max-validation by TheOdinProject (@TheOdinProjectExamples) on CodePen.

乗客数を7人にしてフォームを送信してみて、バリデーションが実際に動作するのを見てみてください。

パターンのバリデーション

ユーザーから正しい情報を確実に得るために、データが特定のパターンにマッチすることを確認したい場合がよくあります。実世界での応用例には、パスワード、クレジットカード番号、郵便番号が正しい形式であるかをチェックすることなどがあります。

パターンのバリデーションを追加するには、フォームコントロールに、値として正規表現(regex)を持つpattern属性を与えます。この例では、パターンのバリデーションを使って、米国の郵便番号が正しい形式(5桁の数字の後に、オプションのハイフンと、さらに4桁の数字が続く)であることを確認しています:

See the Pen forms-pattern-basic-validation by TheOdinProject (@TheOdinProjectExamples) on CodePen.

パターンのバリデーションのための正規表現

これについて正規表現を深く学ぶ必要は実際にはありません。正規表現がどれほど複雑になり得るか、特にHTML属性、JavaScriptの文字列、JavaScriptの正規表現リテラルなどで書くときに正確な構文が異なり得ることを考えると、実際には自分で一から構築しようとするよりも、必要なものに合った実績のある正規表現を探す方が良いでしょう。

不正な郵便番号を入力してフォームを送信すると、ブラウザは「Please match the requested format」というバリデーションエラーを表示します。これは、問題をどう修正すればよいかを伝えてくれないため、あまり役に立ちません。

placeholder属性を使って、ユーザーに入力してもらいたい期待されるパターンの例を示すのは良いプラクティスです:

See the Pen forms-pattern-with-placeholder-validation by TheOdinProject (@TheOdinProjectExamples) on CodePen.

pattern属性は<input>要素にのみ使うことができます。一部の入力要素は、すでに特定のパターンにマッチするデータを検証してくれます。例えば、email入力フィールドは有効なメールアドレスが入力されていることを確認し、url入力要素はURLがhttpまたはhttpsで始まっていることを確認してくれます:

See the Pen forms-built-in-pattern-validations by TheOdinProject (@TheOdinProjectExamples) on CodePen.

バリデーションのスタイリング

:user-validと:user-invalid疑似クラスを使うと、バリデーションに合格したフォームコントロールと失敗したフォームコントロールをターゲットにでき、ユーザーがやり取りするまでは入力フィールドをニュートラルな状態に保つことができます。

これが実際に動作するのを見るために、以前見たemailとwebsiteの例を使ってみます:

See the Pen forms-styling-validations by TheOdinProject (@TheOdinProjectExamples) on CodePen.

最初、emailとURLのフィールドはデフォルトのブラウザスタイルを維持しており、これはユーザーがまだそれらとやり取りしていないニュートラルな状態を表しています。まず、有効な入力をターゲットにして、対応する入力フィールドに緑色の枠線を設定するところから始めます。

ユーザーが無効な値を入力し、その入力からクリックまたはタブで離れると(これは完全なユーザーのやり取りを構成します)、枠線は赤に変わります。それ以降、枠線はその内容の有効性に応じて自動的に緑と赤の間で切り替わります。不正な形式のメールアドレスやURLを入力し、クリックして離れることでバリデーションを発動させ、それから正しい形式と不正な形式の間で値を編集して、これを試してみてください。

まとめ

組み込みのバリデーションは、ユーザーが正しいデータを入力することを確保する上で、あなたを大きく助けてくれます。それらは素早く簡単に追加できます。しかし、限界もあります。

時には、組み込みのバリデーションではできないバリデーションを含める必要があります。例えば、パスワード入力とパスワード確認入力が同じ値を持つことを検証したり、ユーザー名がまだ使われていないことを検証したりすることです。また、バリデーションメッセージとその中のコンテンツをスタイリングできることにも限りがあります。

この場合、JavaScriptとCSSを使ってカスタムバリデーションを作成する、創造的な工夫が必要になります。JavaScriptを通してバリデーションを実現する方法については、今後のレッスンで深く掘り下げます。

クライアントサイドのバリデーションは、ユーザーが正しいデータを入力することを確保するための万能薬ではないことも、覚えておく価値があります。私たちのシステムに入ってくるあらゆるユーザーデータの整合性を確保するために、サーバーサイドのバリデーションも用意しておくべきです。バリデーションのこちらの側面については、カリキュラムの後の方で扱います。
