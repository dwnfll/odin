イントロダクション

ウェブ開発の旅を続けていく中で、あなたの作品のエンドユーザーがさまざまなブラウザを使っている可能性があることを心に留めておくことが重要です。例えば、Chrome、Microsoft Edge、Firefox、Safariなどです。同時に、モバイルOSを使うユーザーの数も急速に増えているため、さまざまなブラウザのモバイル版についても考慮する必要があります。

ブラウザの歴史

現代のブラウジングの歴史は、1990年12月のWorldWideWebブラウザのリリースにさかのぼります。これは、CERNとして知られる欧州原子核研究機構で働いていたTim Berners-Leeによって書かれました。後に、World Wide Webとの混同を避けるためにNexusと改名されました。

Nexusはその種のものとして最初のもので、ユーザーが基本的なスタイルシートを表示したり、ニュースグループを読んだりできるようにし、さらにスペルチェック機能まで持っていました!今日ではそれほど大したことに聞こえないかもしれませんが、当時は本当に画期的なものでした。

しかし、Nexusのリリースは始まりに過ぎず、次の10年間で人々はMosaicブラウザのような、瞬く間に人気を博し世界で最も人気のあるブラウザとなったブラウザの初期のリリースを目の当たりにしました。そこから、OperaやNetscape Navigatorブラウザのリリースにより、World Wide Webの成長は爆発的なものとなりました。

1995年、世界は最初のバージョンのInternet Explorerと出会い、これは市場で支配的な存在となりました。ある時点では、Internet Explorerはすべてのユーザーの90%以上に使われていました。この支配に対抗するため、Netscapeは後にFirefoxを開発・維持することになるMozilla Foundationとなるものを立ち上げました。その直後、2003年にAppleがSafariをローンチし、2008年にGoogleがChromeをローンチしました。

あなたはこれらの名前のほとんど、あるいはすべてに、おそらく馴染みがあることでしょう。今日でもブラウザ間の競争は多く続いていますが、Chrome(およびChromium)が市場で支配的な存在です。

ブラウザ互換性とは何か?

今日、ブラウザを使わずにウェブを想像することは不可能です。私たちは、スタンドアロンのアプリケーションから、アプリケーションがブラウザの中で完全に機能できるようにするHTML5やプログレッシブウェブアプリへの移行を目の当たりにしてきました。例えば、Microsoft WordやExcelは長い間、スタンドアロンのアプリケーションを通してでしか実行できませんでした。今では、ファイルをインストールする必要なく、どんなブラウザを通してでもそれらのアプリケーションを利用できます。

企業が市場シェアを競い合う中で、さまざまなブラウザがウェブページ上に情報を表示するために異なるエンジンを使っています。例えば、ChromeとChromiumはBlinkを利用しますが、SafariはWebKitを使っています。

これらの違いのため、あなたのアプリケーションはブラウザによって異なる振る舞いをするかもしれません。Chromeの優勢さのため、大多数のアプリケーションはChromiumで滑らかに動作するよう設計されており、他のブラウザで同じレベルのパフォーマンスを提供することは二の次になっています。

あなたのウェブ開発プロジェクトがより広い範囲に届くようにするためには、ユーザーが最も使いそうなブラウザに対して、必ずウェブアプリケーションをテストする必要があります。Chrome、Safari、Firefox、そして他のChromiumベースのブラウザ(Microsoft Edge、Braveなど)は、一般的なユーザーの間でより一般的です。しかし、ユーザーベースやあなたが働く会社によっては、あまり一般的でないものもサポートする必要があると分かるかもしれません。Chromiumベースのブラウザについては、Chromeで動作すれば、他の関連ブラウザでも動作するはずです。

ブラウザのリリースと新しいCSS機能

W3CWorld Wide Web Consortiumは、ウェブ体験のアクセシビリティと一貫性を最大化するためのウェブ標準を開発する権威ある組織です。W3CはまたCSSの新機能を開発する権威でもあります。これは、ウェブというコミュニティ全体、そしてウェブブラウザを開発する企業との、密接な協力関係によるアプローチです。

NexusやNetscapeのようなウェブブラウザがリリースされた当時、互換性をより高めるのを助けるW3Cのような組織は存在しませんでした。あなたのアプリケーションは、ブラウザごとに見た目も機能も異なる可能性がありました。さらに悪いことに、あなたのアプリケーションは完全に使い物にならなくなる可能性さえありました。ウェブ開発者はブラウザごとに特定の調整をしなければならず、すべての開発者がそれをすべてのユーザーのために機能させるのに十分なリソースを持っていたわけではありませんでした。

今日、ウェブを取り巻く標準が進化・変化し続け、ウェブ開発者が自分たちのコードベースに新機能を実装し始めるにつれて、ブラウザはそれらの新機能をサポートしなければなりません。もしブラウザのサポート不足によってユーザー体験が損なわれれば、ユーザーは競合他社に流れてしまうかもしれません。

新機能を安全に使えるのはいつか?

新機能を実装することはワクワクすることですが、急ぎすぎるリスクもあります。例えば、あなたのアプリケーションがFirefoxでかつては問題なく動作していたのに、コードベースの変更によって今ではFirefoxで使い物にならなくなり、Safariでは問題なく動作する、といったことをユーザーが発見するのは、良い体験にはならないでしょう。ありがたいことに、この状況を防ぐのに役立つツールがあります。

"Can I Use"は、新機能がブラウザにサポートされているかどうかを検証するのに役立つ、素晴らしいリソースです。どのブラウザやプラットフォームが新しい技術をサポートしているか、さらにはそれらのブラウザのどのバージョンが特定の機能をサポートしているかについての統計を提供してくれます。

一般的に、新機能は、最も一般的なブラウザのほとんどでサポートされるようになってから実装するのが良いアドバイスです。こうすることで、多くのユーザーが直面するような問題に遭遇する可能性が低くなります。

モバイルブラウザ

伝統的に、ウェブはデスクトップコンピューターを第一に考えたものでした。アプリケーションは、デスクトップブラウザで問題なく動作すれば成功でした。しかし、スマートフォンがより人気になるにつれて、毎年ますます多くのユーザーが、主なウェブ向けデバイスとしてモバイルデバイスを使うようになっています。世界の一部の地域では、モバイルユーザーが大多数を占めています。

モバイルデバイスは主にスマートフォンとタブレットで構成されています。最も人気のあるモバイルOSはAndroidとApple社のiOSです。

アプリケーションを開発する際には、あなたのアプリケーションが完全にモバイル対応であるべきかどうかも考慮する必要があります。モバイルブラウザについて心に留めておく必要のある、いくつかの特有の点があります。

  1. iOSとiPadOSでは、ほとんどの地域でSafariが唯一サポートされているブラウザです。確かにChromeやFirefoxをインストールすることはでき、デフォルトに設定することさえできますが、それらは完全なブラウザではありません。それらは依然としてSafariのレンダリングエンジン(WebKit)を使用しています。したがって、あなたのウェブアプリケーションがAppleユーザー向けに動作するようにするには、WebKitやSafariで使われている他の技術のサポートを確実にする必要があります。 モバイルブラウザは、そのデスクトップ版と一対一ではないことを覚えておくことが重要です。デスクトップ版のSafariで動作するプロジェクトでも、同じブラウザのモバイル版で正しく動作させるには、まだ調整が必要な場合があります。
  2. モバイルブラウザについてのもう一つの考慮点は、さまざまな画面サイズの多さです。テストのためにすべての物理デバイスを用意することは事実上不可能ですが、ありがたいことにブラウザは他のデバイスをエミュレートする方法を提供してくれています。覚えておくべき重要な点は、例えばChromeでiPhoneをエミュレートするとき、エミュレートしているのは画面サイズだけだということです。OSに関する特有の考慮事項は再現できないということを心に留めておいてください。つまり、デバイスをエミュレートしたときにChromeですべてが問題なく機能したとしても、実際の携帯電話やタブレットデバイスでは異なる振る舞いをする可能性があるということです。
