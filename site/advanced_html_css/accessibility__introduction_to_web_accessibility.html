イントロダクション

カリキュラムのこの時点で、あなたが選んだどちらのフルスタックパスであっても、非常に価値のある概念を学び、履歴書に書けるような素晴らしいプロジェクトをいくつか作成し、HTMLとCSSのいくつかの概念についてより深い理解を得られたはずです。もしかしたら、今ではCSSを使って作業するのが好きになったとさえ言えるかもしれません…?

しかし、あなたがまだあまり理解していないかもしれないのは、アクセシビリティというトピックです。これはしばしば「a11y」と呼ばれます(最初と最後の文字の間に11文字あるためです)。残念ながら、これは多くの人があまり知らないか、あるいはウェブサイトを開発する際に単に考慮していないトピックです。もしあなたがそのどちらかに当てはまるなら、a11yフレンドリーとは言えない習慣を身につけてしまっているかもしれません。そのような習慣から抜け出し、a11yフレンドリーな概念を実装し始める方法に入る前に、まずウェブアクセシビリティについての基本的な情報を理解することが重要です。

ウェブアクセシビリティとは何か?

ウェブアクセシビリティとは、障がいのある人やその他の状況的な制限を持つ人が、できるだけ障壁なく使えるように、ウェブサイト、ツール、技術が設計・開発されていることを意味します。

障がいにはさまざまな種類があり、聴覚、身体・運動、認知、視覚などが含まれます(これらに限定されません)。障がいは、完全に目が見えない、あるいは耳が聞こえないユーザーのように永続的な場合もあれば、腕を骨折しているユーザーのように一時的な場合もあります。ユーザーは、ある時点で複数の障がいを持っていることもあります。能力が変化していく高齢のユーザーも、障がいを持つ人と似たような状況にあることさえあります。

状況的な制限は少し異なります。明るい日に屋外でスマートフォンを使うこと、片方の手で他のことをしながらもう片方の手でサイトを閲覧すること、インターネットが遅い、あるいは帯域幅が高価な地域に住んでいることは、すべて状況的な制限の例です。これらの制限は、障がいとは異なり、特定の状況でのみユーザーに発生しますが、ウェブサイトを開発する際に心に留めておくことは依然として重要です。

なぜウェブアクセシビリティが重要なのか

まず、少し視点を得るために、ウェブとは関係のない例を見てみましょう。エレベーターのない多階建ての建物にいることを想像してみてください。一部の人にとっては、これは単なる煩わしさに過ぎないかもしれません。「へえ、エレベーターがないのか。じゃあ、何階か階段を上るか」といった具合です。しかし、車椅子を必要とする人にとっては、1階より上のどこかに行くことは不可能か、少なくともずっと難しいことになるでしょう。たとえ車椅子の人に、それぞれの段で車椅子を持ち上げてくれる人がいたとしても、それははるかに困難なプロセスになるでしょう。ここでのポイントは、エレベーターがあればこの建物はもっとアクセシブルになっていただろう、ということです。

その建物があなたのウェブサイトで、エレベーターはさまざまなアクセシビリティ機能やツールの集まりです(…かなり大きなエレベーターですね)。ウェブサイトを開発するとき、あなたはユーザーのためにそれを開発しているのであり、そのウェブサイトが彼らにとって実際に使えるものである必要があります。障がいのある人、能力が変化していく高齢の人、あまりテクノロジーに詳しくない人、何らかの状況的な制限を持つ人も、依然としてユーザーであり、ウェブサイトは彼らにとっても同じくらい使いやすいものであるべきです。

アクセシビリティが重要なもう一つのかなり大きな理由は、国によっては、アクセシビリティの実装を義務付ける法律が実際に存在し得るということです。

課題

  1. W3Cの多様な能力と障壁についての記事に目を通して、障がいのある一部のユーザーがアクセシブルでないサイトによってどう影響を受けるかについて、より深く理解してください。
