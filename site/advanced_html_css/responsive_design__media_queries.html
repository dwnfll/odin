Media Queries

日本語訳

← advanced_html_css

Finally, let's learn about media queries so you can change the layout of your site based on the size of the browser window.

イントロダクション

メディアクエリを使うと、ユーザーの画面サイズに基づいて、ウェブプロジェクトを完全にスタイルし直すことが可能になります。ここまでのレッスンはすべて、レイアウトの個々の要素ができるだけ柔軟であることを確実にすることに焦点を当ててきましたが、時には特定の画面サイズに対応するために、実際にCSSの値のいくつかを変更する必要があります。これらの変更は、より多くのコンテンツを画面に詰め込むためにmargin、padding、font-sizeを調整するといった微妙な変化かもしれませんし、レイアウトの大きく明白な変化かもしれません。正確な変更の性質はあなたのデザインによりますが、その根底にあるテクニックは同じです。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • メディアクエリを通してスタイルを条件付きで適用します。
  • コンテナクエリ。

メディアクエリの構文

メディアクエリの基本的な構文は次の通りです:

body {
  margin: 24px;
}

@media (max-width: 600px) {
  body {
    margin: 8px;
  }
}

上記の例では、marginは画面サイズに基づいて変化します。具体的には、600px以下のすべての画面ではmarginは8pxになり、600pxより大きいすべての画面では24pxになります。

本当に、それだけです。この知識だけでも、いくつかの複雑に変化するレイアウトを作ることができます。単一のドキュメント内に無制限の数のメディアクエリを作成できます(画面をリサイズして変化を見られるように、「Edit on CodePen」ボタンをクリックしてください):

他のクエリ

上記のすべての例では、私たちのクエリはmax-widthを指定しており、これは指定された値以下のあらゆる画面解像度にスタイルを適用します。別の言い方をすると: max-widthクエリは、定義されたmax-widthまでのあらゆる画面に適用されます。また、min-widthを定義することも可能で、これは与えられた値以上のあらゆる画面解像度に適用されます。max-heightとmin-heightも有効です。

メディアクエリを制限する

先ほど述べたように、あらゆる可能な画面サイズに対して無制限の数のメディアクエリを作成することが可能です。しかし、メディアクエリの使用は最小限に抑え、レイアウトの自然な柔軟性により多く頼るのが最善です。上記の2番目の埋め込み例(「my cool site」)を考えてみてください。デスクトップとモバイルのすべてのサイズに対応するために必要なメディアクエリはたった一つだけで、それ以上作る本当の必要はありません。

一般的なブレークポイント

「ブレークポイント」とは、メディアクエリをトリガーする画面サイズを表す用語です。ブレークポイントを正確にどこに設定すべきかについては、かなり多くの異なる意見があることに気づくでしょう。一般的に、ユーザーが使うことになるであろうデバイスや画面の種類について考えることが役立ちます。携帯電話は通常500px未満です。タブレットはしばしば500pxから1000pxの間です。1000pxより大きいものは、おそらく通常のブラウザ画面でしょう。超ワイドな画面もより一般的になってきているので、あなたのサイトが2000pxより広い画面で見られることになり得るということです!

これは、各デバイス向けにメディアクエリを使ってプロジェクトを始めるべきだという意味ではありません。それぞれのプロジェクトは、達成しようとしているデザインに基づいて異なる要件を持つことになります。上記で述べたように、あなたのブレークポイントを、あなたが必要なものだけに限定するようにしてください。多くの比較的基本的なレイアウトでは、500〜600pxあたりに、モバイル中心のブレークポイントを一つだけ設けるだけで十分でしょう。より複雑なレイアウトでは、1200pxより上でフルサイズのレイアウトを、600pxから1200pxの間で変更された「タブレット」レイアウトを、600px未満でモバイルレイアウトを用意することが役立つかもしれません。ここで本当に持ち帰るべきポイントは、ブレークポイントを正確にどこに設定するかはそれほど重要ではなく、あなたのプロジェクトにとって理にかなうことをすればよいということです。

ズーム!

ほとんどのブラウザでは、ウェブページをズームインすると、そのページの実効解像度が変わります。もしブラウザウィンドウがちょうど1000px幅であれば、ズームインすると、ページはあたかも画面がより小さいかのように振る舞い、シミュレートされた/ズームされた画面解像度に基づいてメディアクエリがトリガーされます。ズームアウトは、自分のコンピューター画面より大きい画面で発生する問題をデバッグする際に便利です。ウェブページをズームインまたはズームアウトしたことを忘れてしまうと、ブレークポイントが正しいポイントでトリガーされなくなり、本当に混乱してしまうことがあります。

印刷スタイル

メディアクエリが次のようにscreenキーワードと共に定義されているのをよく見かけるでしょう:

@media screen and (max-width: 480px) {
}

これは必須ではありませんが、メディアクエリのもう一つの非常に便利な機能、つまりメディアタイプに基づいてスタイルを変更するということを示しています。ここまで扱ってきたことはすべて、何らかの画面での表示を特に意図したものだったので、screenを指定するのは冗長です。しかし、printキーワードを使うことで、ウェブサイトがプリンターに送られたり印刷プレビューモードで見られたりするときのために、異なるスタイルのセットを作成することが可能です。

@media print {
  /* print styles go here! */
}

これは私たちのカリキュラムで焦点を当てるものではありませんが、場合によっては活用を検討したいものかもしれません。いくつかの色を変える(つまり、ものを白黒にする)ことや、印刷された環境では役に立たない要素(ボタン、ナビゲーションリンクなど)を隠すためにdisplay: noneを追加することは、かなり一般的です。

コンテナクエリ

メディアクエリを使うと、ビューポートやデバイスなどの特性に基づいてスタイルを条件付きで適用できますが、コンテナクエリ(@container)を使うことで、代わりに「コンテナ」要素の特性に基づいて同じことを行うこともできます。条件付きで適用しようとしている正確なスタイルによっては、どちらか一方を条件のベースにする方がより理にかなうかもしれません。もちろん構文には微妙な違いがありますが、最終的には概念は同じであり、いつも通り豊富なドキュメントが存在します。

課題
