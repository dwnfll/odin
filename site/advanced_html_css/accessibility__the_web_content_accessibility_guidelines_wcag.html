The Web Content Accessibility Guidelines (WCAG) 日本語訳

Learn where to find and how to use the official guidelines for web content accessibility

イントロダクション

前のレッスンを終えて、ウェブアクセシビリティが特定のユーザーにとってどれほど重要であり得るか、そしてそれがすべてのユーザーにとってどれほど有益であり得るかについて、より深い理解が得られたはずです。しかし、何がa11yフレンドリーであるべきかだけでなく、どうやってそれらをa11yフレンドリーにするかを、私たちはどうやって知るのでしょうか?実は、何を、どうやって、を教えてくれる情報源はたくさんあり、実際にアクセシビリティに頼っている人々こそが、私たちが参照できる最良の情報源の一つです。

もう一つの情報源で、ウェブサイトをよりアクセシブルにするのに役立つさまざまな方法を扱っているのが、Web Content Accessibility Guidelines(WCAG)です。このレッスンでは、あなたにより基本的なレベルで馴染んでもらうために、WCAGの表面をさっとなぞっていきます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Web Content Accessibility Guidelinesの目的を説明します。
  • WCAGの4つの原則を挙げます。

Web Content Accessibility Guidelines

WCAGは、ウェブアクセシビリティに関する共有の標準を作るのを助けるために存在しています。ウェブアクセシビリティを目的地だと考え、WCAGをそこに近づくのを助けてくれるツールの一つだと考えてください。

WCAGはa11yの基盤を築く上で非常に役立ち得る一方で、アクセシビリティに関してのゴールではないということを理解しておくことが重要です。名前が示す通り、これらはガイドラインであり、私たちがウェブサイトをよりアクセシブルにする助けとなるだけのものです。

4つの原則

WCAGは、何らかのアクセシビリティ機能を実装する際に心に留めておくべき、4つの中核的な原則(POUR)を中心に構成されています:

  1. 知覚可能(Perceivable): ユーザーは、提示されている情報やユーザーインターフェースを知覚できなければなりません。例えば、明るい背景に明るいテキストは、視覚障がいを持つ一部のユーザーにとって知覚しづらい可能性があります。

  2. 操作可能(Operable): ユーザーは、あらゆるユーザーインターフェースやナビゲーションを操作できなければならず、インターフェースはユーザーが実行できないインタラクションを要求してはいけません。例えば、マウスカーソルがホバーしたときにのみ展開するドロップダウンメニューを持つナビゲーションバーは、それらのメニュー項目にフォーカスを当てるキーボードユーザーにとって操作可能ではありません。

  3. 理解可能(Understandable): ユーザーは、提示されるあらゆる情報やユーザーインターフェースを理解できなければなりません。例えば、あるユーザーがフォームを送信しようとして「Error 113: Bad data」のようなエラーを受け取った場合、そのエラーが実際に何を意味するのか、あるいはそのエラーの原因となったものをどう修正すればよいのかを理解できないでしょう。

  4. 堅牢(Robust): コンテンツは、現在の支援技術やその他のユーザーエージェントからアクセス可能でなければならず、それらの技術が進歩してもアクセス可能であり続けなければなりません。

適合レベル

適合レベルについては、これらのレッスンの他のいくつかの箇所でも言及されるので、ここでは前もってそれが何であるかを簡単に説明するためだけに触れておきます。WCAGには3つの異なる適合レベルがあり、それぞれがそのレベルの適合をうまく満たすために従わなければならない、さまざまな達成基準、つまりルールで構成されています。これらのレッスンの目的のためには、これらの適合レベルのいずれかを完全に満たすことを心配する必要はなく、それらが存在するということだけを知っておく必要があります(幸い、その名前付けはかなり覚えやすいです)。

  • レベルA、つまり必須のサポートは、WCAGの最低限の適合レベルです。
  • レベルAA、つまり理想的なサポートは、多くの組織が目指すレベルです。このレベルを満たすには、レベルAも満たす必要があります。
  • レベルAAA、つまり専門的なサポートは、一部のコンテンツではこの適合レベルを満たすことが不可能になる場合があるため、サイト全体で完全に満たすことは推奨されません。このレベルを満たすには、レベルAとレベルAAの両方も満たす必要があります。

アクセシビリティを実装する(前に)

これに続くレッスンでは、あなたのウェブサイトのアクセシビリティを改善するのに役立ういくつかの概念を深く掘り下げますが、アクセシビリティのあらゆる側面をカバーするわけではありません。これらのレッスンの目標は、今後習慣的にチェックするようになるべき、より一般的な概念のいくつかをあなたに紹介することだけです。

これらのa11yの概念のいくつかしか紹介していませんが、それでもあなたのサイトが十分にアクセシブルではないのではないかと心配になるかもしれません。まず心に留めておくべきことは、どんなサイトも100%アクセシブルになることは決してないということです。ですので、そのような不可能な目標を目指そうとしないでください。時には、サイトの目的や概念そのものが、特定の点でアクセシブルでないことを必要とする場合さえあります。

二つ目に心に留めておくべきことは、アクセシブルなウェブサイトを作るための最初の数歩を踏み出すことそのものが、今後踏み出すことになるさらに多くのステップと同じくらい重要だということです。たとえ今のところウェブサイトにa11y機能を一つ追加しただけだとしても、あなたがマイナーな追加だと思っているものが、実際にはあなたが気づいているよりも多くのユーザーにとって大きな改善になっているかもしれません。ですので、アクセシビリティを実装する際、特にまだ始めたばかりのときには、すべてを完璧にしなければならないとか、すべてを一度に追加する必要があるとか感じないでください。

課題

  1. WCAGの概要のページに目を通してください。今のところ、他のリンクはすべて気にしなくて構いません。このページを読む目的は、含まれている概要についてより理解を深め、実際に他のページを訪れる必要が出てきたときのために、サイト自体に慣れておくことです。
  2. WebAIMのWCAG 2チェックリストにざっと目を通してください。その際、重要な免責事項を読むことを忘れないでください。今のところ、ページに載っているすべての問題を読み通すというよりも、一般的なアクセシビリティの問題についてのイメージをつかむことが目標です。そのうちのいくつかは、このレッスンのセットを終える頃には修正できるようになっているでしょう。しかし、このリソースはブックマークしておいてください。アクセシビリティを積極的に実装し始めるときに、これをチェックリストとして使うのは本当に便利だからです。
