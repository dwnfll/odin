イントロダクション

<div>や<span>要素は汎用のコンテナとして便利ですが、必ずしも最もa11yフレンドリーな要素というわけではありません。コンテナからインタラクティブな領域まで、すべてにそれらを使うのは魅力的、あるいは簡単に思えるかもしれませんが、特定の状況でより適切な要素があるかどうかだけでなく、要素を正しく使えているかどうかもチェックすべきです。

セマンティクスの重要性

ウェブアクセシビリティの観点では、セマンティックHTMLを使うことは意味とコンテキストを提供するため重要です。一部の要素は<p>要素のようにセマンティックな意味を持っていますが、支援技術によってアナウンスされる際に実際にはコンテキストをあまり提供しません。それから、<button>のように、セマンティックな意味を持ちかつ、ユーザーがそれを知覚したり操作したりするのを助けるための何らかのコンテキストと共にアナウンスされる要素もあります。

<div>と<span>要素は、おそらくあなたが使うより一般的な2つの要素ですが、意味的に中立です。つまり、それら自体には意味がなく、支援技術に対して単独ではコンテキストを提供しません。これにより、そのような技術のユーザーがそれらを知覚し、操作し、理解することがより難しくなる可能性があります。しかし、この意味とコンテキストの欠如のせいで、<div>や<span>を二度と使えないと感じる必要はありません。レイアウトのためや汎用のテキストのためなど、汎用のコンテナとしての用途は依然としてあります。

さて、このセマンティクスとコンテキストというもの全体をよりよく理解するために、実際の例を見てみましょう。これまでに完了させたことのあるプロジェクトで、ユーザーが何かをクリックする必要があったものを思い浮かべてみてください: Rock, Paper, Scissors、Calculator、Tic-Tac-Toeなどです。クリック可能なエリアに<div>や<span>要素を使ったなら、おそらく意図した通りに動作していたことでしょう。例えば、Foundationsの頃、Rock, Paper, ScissorsのUIに以下のような似たHTMLを使っていたかもしれません:

<!-- These are buttons... right? -->
<div class="button-container">
  <div class="rock">Rock</div>
  <div class="paper">Paper</div>
  <div class="scissors">Scissors</div>
</div>

要素がインタラクトできる何かのように見えていれば、目の見えるユーザーはおそらくこのゲームを問題なくプレイできるでしょう。しかし、スクリーンリーダーのユーザーは、これらの要素が何を意味するのかまったく分からないでしょう。スクリーンリーダーは要素のテキストコンテンツ("Rock"、"Paper"、"Scissors")をアナウンスし、ユーザーはそれがページ上の単なるプレーンテキストだと思って先に進んでしまうかもしれません。これらの要素とインタラクトすべきである、あるいはそもそもインタラクトできるということを伝えるコンテキストがないのです。

この問題は、セマンティックHTMLを使うことで簡単に修正できます:

<!-- Okay, these are *definitely* buttons -->
<div class="button-container">
  <button class="rock">Rock</button>
  <button class="paper">Paper</button>
  <button class="scissors">Scissors</button>
</div>

<button>要素は意味を持ちコンテキストを提供するため、スクリーンリーダーはテキストコンテンツだけでなく要素の役割もアナウンスします: 「Rock, button」というようにです。

セマンティックHTMLを正しく使う

セマンティックHTMLを正しく使うことに関しては、ユーザーに対するあなたの意図が何であるか、そして彼らにどんなコンテキストを提供したいか(あるいは提供する必要があるか)を考える必要があります。これは状況によって異なりますが、今後絶対にチェックすべきことがいくつかあります:

  • ユーザーが何かをクリックすることを意図しているなら、それが実際のボタンであるかどうかに関わらず、通常は<button>要素を使いたいところです。これにより、ユーザーはその要素をクリックすることでインタラクトできることを知ることができます。
  • 何らかの表形式のデータをユーザーに提供したい場合は、<table>要素をそれに関連する要素と共に使ってください。これにより、ユーザーは提示されているデータをより簡単にナビゲートし理解できるようになります。

  • input要素を使うときは、常にそれと<label>要素との関係を作るべきです。<label>は、支援技術に対してinputが実際に何を意味するかのコンテキストを提供し、inputがアナウンスされるたびにラベルの内容もアナウンスします。それだけでなく、適切な<label>はinput自体のクリック可能な領域を広げてくれるため、小さな項目をクリックするのに苦労するユーザーにとって役立ちます。この関係を作る方法は2つあります:

    <!-- Useful when you need the input itself to have an ID -->
<label for="name">Name</label>
<input type="text" id="name">

<!-- Look, Ma, no ID! -->
<label>
  Name
  <input type="text">
</label>

  • inputについて続けると、意図された用途にとって最も理にかなったtypeを常に使うべきです。type="text"は名前や住所のフィールドにより理にかなっていますが、type="email"やtype="tel"は当然、それぞれメールアドレスや電話番号のフィールドにより理にかなっています。特定のデバイスでは、正しいtypeを使うことで、キーボードに必要な文字や追加の文字だけが表示されることがあります。例えばtype="tel"のinputは、モバイルやタブレットデバイスで、より大きな数字専用のキーを提供することで、ユーザーが電話番号を入力するのをずっと簡単にしてくれるかもしれません。

  • 何らかのリストをユーザーに提示したい場合は、適切なリスト要素(<ol>、<ul>、<dl>)とそれに関連するリストアイテム要素を使うべきです。これにより、ユーザーはリストに入ったり出たりするタイミングだけでなく、リストにいくつのアイテムがあるかも知ることができます。

見出しとランドマーク

見出しは<h1>から<h6>までの要素であり、名前が示す通り、これらの要素はページのセクションに対する見出しとして機能します。一方でランドマークとは、ページの領域として機能するHTML要素です。これらのランドマーク領域を定義するネイティブなHTML要素は7つあります:

  • <aside>
  • <footer>
  • <form>
  • <header>
  • <main>
  • <nav>
  • <section>

ランドマークと見出しを適切に使うことで、支援技術のユーザーに、より操作しやすく理解しやすいページを提供できます。スクリーンリーダーのユーザーは、ナビゲーションのキーボードコマンドを使う(あるいはスクリーンリーダーでメニューを開く)ことでランドマークや見出しを通してページをナビゲートできるだけでなく、これらの要素はさらなるコンテキストを提供するために、その役割もアナウンスされます。

もしこれらのランドマークや見出しの役割を果たすために<div>要素だけを使い、視覚的にスタイリングするためにいくらかのCSSを加えただけだとしたら、スクリーンリーダーのユーザーは特定のセクションにたどり着くためだけにページ全体を通り抜けなければならず、ページ上の何が見出しでランドマークなのかを実際には判別できないかもしれません。

課題

  1. スクリーンリーダーがどう機能するかを理解する最良の方法は、実際に使ってみることです!少し時間を取って、関連するガイドやドキュメントを調べ、いろいろ試してみてください!さらに多くのアクセシビリティの概念や機能を紹介していく中で、そのいくつかをスクリーンリーダーで実際に体験することは非常に貴重であり、アクセシビリティのありがたみを実感するのに本当に役立ちます。もしかしたら、サイトの作り方が変わることさえあるかもしれません!

    多くのスクリーンリーダーがあり、無料のものもあれば有料のものもありますが、どのスクリーンリーダーにアクセスできるかはあなたのOSによります(それらの間には機能やコントロールに多少の違いがありますが、概ね同じです):

    • Windowsユーザー(WSL2を使っている場合にも当てはまります)は、NVDAを無料でインストールできます。
    • macOSにはVoiceOverが組み込まれています。
    • LinuxにはOrcaが組み込まれています。
    • ChromeOSにはChromeVoxが組み込まれています。

  2. スクリーンリーダーがデータテーブルをどうナビゲートするかを読んで、適切な<table>要素がどれほど多くのコンテキストを提供するかの素晴らしい例を見てみてください。

  3. アクセシブルなテーブルの紹介とスクリーンリーダーのデモを見て、スクリーンリーダーがテーブルをどうアナウンスするか見てみてください。
  4. 見出しとランドマークがなぜそれほど重要なのかを見て、スクリーンリーダーが見出しやランドマーク要素とどうインタラクトするか見てみてください。
