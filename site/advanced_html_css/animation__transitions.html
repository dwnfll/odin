イントロダクション

CSS transitionのワクワクする世界に飛び込んで、あなたのHTML要素に洗練された変化を与える時が来ました!

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • CSS transitionとは何で、いつ使うか。
  • どのCSSプロパティがアニメーション可能で、どれがそうでないかを知ります。
  • transitionが滑らかでパフォーマンスの良いものであることを確実にする方法。

Transition

CSS transitionを使うと、要素の初期状態から終了状態への変化をアニメーションできます。白い背景を持つ普通のボタン要素を思い浮かべてください。マウスがボタンから離れているとき、それはただそこにあるだけです。退屈ですね。それから、マウスカーソルをボタンの上にホバーさせると、背景色が時間をかけて白からグレー、そして黒へと滑らかに変化します。これがCSS transitionです。以下のCodepenを見て、実際に動作しているのを見てみてください。

See the Pen CSS Transition (longhand) by TheOdinProject (@TheOdinProjectExamples) on CodePen.

マウスカーソルがボタンから離れているとき、ボタンは初期状態にあります。その上にホバーすると、終了状態、つまりホバー状態を導入することになり、背景色が白から黒へと滑らかに変化します。

これはtransitionプロパティを使って実現されましたが、これは実はtransition-property、transition-duration、transition-timing-function、transition-delayのショートハンドプロパティです。

button {
  /* ... other CSS properties ... */
  transition-property: background-color;
  transition-duration: 1s;
  transition-timing-function: ease-out;
  transition-delay: 0.25s;
}
  • transition-property - これは、どのCSSプロパティがtransitionするかを決めます。この場合はbackground-colorです。
  • transition-duration - これは、transitionが発生する期間を決めます。この場合、色の変化は1秒かけて徐々に起こります。
  • transition-timing-function - これを使うと、transitionの期間中における速度を変えることができます。ここではease-outにしているので、色の変化はtransitionの終わりよりも始めの方が速くなります。
  • transition-delay - これは、transitionが始まるまでの遅延を決めます。この場合、色の変化はカーソルがボタンの上に静止してから4分の1秒後に始まります。

ショートハンドプロパティは次のようになります:

button {
  /* ... other CSS properties ... */
  background-color: white;
  transition: background-color 1s ease-out 0.25s;
}

button:hover {
  background-color: black;
}

上記のtransitionは、:hover疑似クラスで示されているように、ユーザーがマウスをボタンの上にホバーさせたときに発生します。:hoverや他の疑似クラスに加えて、JavaScriptでクラスを追加・削除することでもtransitionをトリガーできます。例えば、ボタンをクリックするとドロップダウンメニューに"open"クラスが追加され、これが開くtransitionをトリガーする、といった具合です。

パフォーマンス

一般的に、CSS transitionのパフォーマンスを保つことは問題にならないでしょう。しかし、心に留めておくべきことがいくつかあります。

一つ目は「スタッキングコンテキスト」です。「スタッキングコンテキスト」とは、親コンテナ内のHTML要素の、z軸(奥行きの次元)に沿った積み重ね、つまり重なりのことを指します。あるスタッキングコンテキスト内での要素の位置は、同じスタッキングコンテキスト内の他の要素に対してのみ相対的です。z-indexプロパティは、要素同士が重なったときに、ある要素がウェブページ上でどれだけ後ろに、あるいは前に表示されるべきかをコントロールします。要素のz-indexを設定することに加えて、transform、opacity、filterなど、いくつかのCSSプロパティも新しいスタッキングコンテキストの作成をトリガーすることがあります。私たちにとって関連のあるシナリオは、以下のようにtransformプロパティをtransitionさせることでしょう:

div {
  width: 100px;
  height: 100px;
  transition: transform 2s 1s;
}

div:hover {
  transform: rotate(180deg);
}

これはスタッキングコンテキストを作成しました。もし他のさまざまな手段を通してさらに多くのスタッキングコンテキストを作っていたら、最初のtransformを描画する際に、私たちのdiv要素だけでなく、そのスタッキングコンテキストでその上に積み重なっているすべての要素も再描画することになります。これを放置すると、かつてはバターのように滑らかだったtransitionが、遅くぎこちないものになってしまうことがあります。

二つ目に心に留めておくべきことは、ウェブページ上でのアニメーションについて絶対的に最高のパフォーマンスを求めるなら、アニメーションがopacityとtransformにのみ影響するようにすべきだということです。そうです、上記の最初の例はbackground-colorの変化しか行っていませんでしたが、それでさえもそれ自体がコストの高い操作でした。

重要なのは、これらの概念をしっかりと理解し、必要なときに応用できるようにすることです。なぜなら、もしホバーされたときにボタンを虹色に変える必要があるなら、その虹色をちゃんとtransitionさせられるようにしておく必要があるのですから!

課題

  1. CSS transitionの使用についてのMDNの記事を、記事内のDefining transitionsセクションのリンクも含めて読んでください。構文に慣れるために、必ず例と一緒に手を動かしてみてください。
  2. スタッキングコンテキストについてのこの記事を読んでください。
  3. CSS Stacking Context inspectorというブラウザ拡張機能を試して、ページ上のスタッキングコンテキストを探索し、その階層を見て、レイアウトや再描画の問題をトラブルシューティングしてみてください。
  4. アニメーション可能なCSSプロパティが描画とパフォーマンスにどう影響し得るかを理解するために、CSS Triggersについて学んでください。background-colorやtransformのようなプロパティを比較して、異なるCSSの変更がブラウザの描画パイプラインにどう影響するかを見てみてください。
  5. このtransitionについてのインタラクティブなガイドを読んでください。
  6. 再描画の問題を捕まえてデバッグする方法について学んでください。
