リデューサーとは何ですか?

リデューサーとは、以前のstateとactionを受け取り、新しいstateを返す純粋関数です。

actionとは、ユーザーが何をしたかを表すtypeプロパティを持つオブジェクトです。このオブジェクトには、リデューサーが新しいstateを生成するために必要な、他のプロパティを含めることもできます。

以下のように、カウンターのstateを更新するリデューサーを定義できます:

function reducer(state, action) {
  switch (action.type) {
    case "incremented_count": {
      return { count: state.count + 1 };
    }
    case "decremented_count": {
      return { count: state.count - 1 };
    }
    case "set_count": {
      return { count: action.value };
    }
    default: {
      throw new Error("unknown action: " + action.type);
    }
  }
}

リデューサーは純粋関数であることを忘れないでください。そのため、stateをミューテートすべきではありません。

いつリデューサーを使うべきですか?

コンポーネントが、いくつかの単純な方法でしかstateを更新する必要がない場合は、リデューサーを使う必要はありません。逆に、stateのロジックのせいでコンポーネントが大きくなりすぎ、読みにくく、デバッグしにくくなった場合には、その逆のことが言えます。

リデューサーを使うことで、stateのロジックを分離し、別のファイルやディレクトリに保存することさえでき、より小さく読みやすいコンポーネントにつながります。

リデューサーはactionを使うため、state関連のバグを、dispatchされたactionまでさかのぼって簡単に追跡できます。また、私たちのリデューサーは単なる純粋関数であるため、それらを単独でテストすることもできます。

useReducerフック

Reactは、useReducerと呼ばれるフックを通して、コンポーネントの中でリデューサーを使えるようにしてくれます。このフックは、リデューサー関数と初期stateを引数として受け取り、現在のstateとdispatch関数という2つの値を持つ配列を返します。

このdispatch関数は、actionオブジェクトを引数として受け取り、それが私たちのリデューサー関数に渡され、そこから返された値がstateの更新に使われます。

const [state, dispatch] = useReducer(reducer, { count: 0 });

function handleClick() {
  dispatch({ type: "incremented_count" });
}

useStateのset関数でReactがstateを更新するのと同じように、Reactはdispatch関数を呼び出した後、次のレンダーでのみstateを更新します。これらの関数は、stateが変化したかどうかを判断するためにObject.is()を使うことを覚えておいてください。変化していなければ、コンポーネントは再レンダーされません。

useStateとuseReducerのどちらを使うかはあなた次第です。どちらも同等であり、同じコンポーネントの中で両方を使うこともあるでしょう。

課題

  1. Reactでリデューサーを使う方法や、useStateをuseReducerにリファクタリングする方法についてさらに学ぶために、ReactドキュメントのExtracting state logic into a reducerを読んでください。最後にある課題を完了することを忘れないでください。
