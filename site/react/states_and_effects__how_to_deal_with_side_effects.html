How To Deal With Side Effects

イントロダクション

Reactの中には、自分自身の外側にあるものとやり取りする必要があるコンポーネントがあります。これらは、サーバーからデータを問い合わせることから、ウェブページ上のコンポーネントの位置を調べたり変更したりすること、あるいは必要に応じてサーバーに何らかのデータを送信することまで、さまざまです。この外の世界とのやり取りは、副作用(side-effect)と呼ばれます。

すでにレンダリングのコードやイベントハンドラの追加には慣れていますが、それだけではすべての用途に十分とは言えません。例えば、サーバーに接続してユーザーに表示するメッセージを取得したい場合などです。エフェクト(effects)を使うと、特定のイベントではなく、レンダリング時やリアクティブ/state値の変化に応じて、必要な形でコンポーネントを同期させるためのコードを実行できます。

useStateフックがあるのと同じように、Reactはコンポーネントの中でエフェクトを使うための、便利なuseEffectフックを提供してくれます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Reactにおけるエフェクトとは何かを理解する。
  • Reactアプリケーションでエフェクトを使う方法を学ぶ。
  • useEffectフックのさまざまな部分を見ていく。
  • Reactでいつエフェクトを使うべきかを見極める。

エフェクトを使えば大丈夫

useEffectフック

あるコンポーネントを例に考えてみましょう。ユーザーがウェブページを読み込んでから何秒経過したかを表示する、Clockコンポーネントを作りたいとします。毎秒それを更新するために、便利なsetInterval関数を使って、counterというstate変数に毎秒1を足すことができます。これをコンポーネントの本体に入れてみましょう。

import { useState } from "react";

export default function Clock() {
  const [counter, setCounter] = useState(0);

  setInterval(() => {
    setCounter(count => count + 1)
  }, 1000);

  return (
    <p>{counter} seconds have passed.</p>
  );
}

ああ、カウンターが暴走してしまいました。これは、setInterval関数が1回だけでなく、stateがレンダーされるたびに呼び出されてしまっているために起こります。

コンポーネントが最初にレンダーされると、最初のsetInterval関数が呼び出されます。このインターバルは毎秒stateを更新し、コンポーネントの再レンダーを引き起こします。しかし、再レンダーのたびにsetIntervalが再び呼び出され、それがより頻繁なstateの更新を引き起こし、それぞれが新しいインターバルを生み出してしまい、あっという間にすべてが制御不能になってしまいます。

ここで、useEffectフックが颯爽と登場し、私たちを救ってくれます。この計算をuseEffectフックの中に包むことで、レンダリングの計算の外に移動させることができます。これは、すべての計算を含むコールバック関数を受け取ります。

import { useEffect, useState } from "react";

export default function Clock() {
  const [counter, setCounter] = useState(0);

  useEffect(() => {
    setInterval(() => {
      setCounter(count => count + 1)
    }, 1000);
  })

  return (
    <p>{counter} seconds have passed.</p>
  );
}

しかし、それでもまだ速すぎるペースで増え続けています!ここで登場するのが、useEffectのもう一つの引数、依存配列(dependency array)です。

依存配列

デフォルトでは、useEffectフックはレンダーのたびに実行されます。stateを設定するとコンポーネントが取り壊される(tear down)ため、レンダーのたびに複数回のsetterの呼び出しが依然として発生してしまい、これでは役に立ちません。

幸いなことに、2番目の引数は依存関係の配列を受け取り、これによってフックはそれらの依存関係が変化したときにのみ再実行されるようになります。つまり、あるstate変数を持っていて、そのstateが変化するたびに何らかの副作用を起こしたい場合は、このフックを使い、依存配列の中でそのstate変数を指定すればよいのです。

この例では空の配列を渡していますが、これは、コンポーネントの最初のレンダー以外のタイミングでuseEffectフックを実行してほしくないからです。

import { useEffect, useState } from "react";

export default function Clock() {
  const [counter, setCounter] = useState(0);

  useEffect(() => {
    setInterval(() => {
      setCounter(count => count + 1)
    }, 1000);
  }, [])

  return (
    <p>{counter} seconds have passed.</p>
  );
}

useEffectの依存関係を管理する

通常、useEffectフックに手動で依存関係を追加する必要はありません。あなたのlinterが、期待される依存関係を教えてくれるはずです。linterが表示するエラーを抑制するのではなく、そのまま表示させて修正することが、通常は最善の考え方です。一般的な注意点として、以下のブロックがこのポイントをうまくまとめています。

useEffect(() => {
  // This runs after every render
});

useEffect(() => {
  // This runs only on mount (when the component appears)
}, []);

useEffect(() => {
  // This runs on mount *and also* if either a or b have changed since the last render
}, [a, b]);

クリーンアップ関数

おお、もう暴走しなくなりました!とはいえ、カウンターが毎秒2回更新されてしまうという問題がまだ残っています。これはReact StrictModeによって引き起こされる挙動として理解できます。StrictModeはバグを見つける手助けをしてくれるはずのものですが、ここでのバグとは何なのでしょうか?

StrictModeでは、Appコンポーネントはマウントされ、アンマウントされ、それから再びマウントされます。このStrictModeの挙動は、開発環境でのみ発生します。useEffectフックが実行されるたびに、新しいsetIntervalが使われることに注目してください。コンポーネントが最初にアンマウントされたとき、setIntervalは停止されず、増分を続けます。この不要な挙動は、コンポーネントがアンマウントされたときにインターバルをクリアすることで防ぐことができます。そして、それこそがuseEffectフックの3つ目の部分、クリーンアップ関数の出番です。

useEffectフックのコールバックから関数を返すことができます。この関数は、次のエフェクトが実行される前に毎回実行され、そしてコンポーネントがアンマウントされるときに最後にもう一度実行されます。この場合は、クリーンアップ関数を使ってインターバルをクリーンアップしてみましょう。

import { useEffect, useState } from "react";

export default function Clock() {
  const [counter, setCounter] = useState(0);

  useEffect(() => {
    const key = setInterval(() => {
      setCounter(count => count + 1)
    }, 1000);

    return () => {
      clearInterval(key);
    };
  }, [])

  return (
    <p>{counter} seconds have passed.</p>
  );
}

ふう!ついに動きました!カウンターが楽しそうに時を刻み続ける中、useEffectフックについてわかったことをまとめてみましょう。

useEffect(
  () => {
    // execute side effect
    return () => {
      // cleanup function on unmounting or re-running effect
    }
  },
  // optional dependency array
  [/* 0 or more entries */]
)

そもそもエフェクトは必要なのか?

useEffectは、Reactが通常適用する概念の外側にある仕組みであり、コンポーネントをサーバー、API、ブラウザのDOMのようなさまざまな外部システムと同期させることを可能にしてくれます。エフェクトを使う前に自分に問いかけられる唯一の質問は、propsやstate以外に、同期する必要があるそのような外部システムが存在するかどうか、というものです。不要なuseEffectフックはコードスメルであり、エラーの原因になりやすく、不要なパフォーマンスの問題を引き起こします。

useEffectを使う必要のない、いくつかのケースを見ていきましょう。

  • レンダリング中にstateに基づいて何かを計算しているだけの場合、エフェクトを使う必要はありません。propsの変化によるコンポーネントの変更については、レンダリング中に計算して設定できます。

    import { useState } from "react";

export default function AdditionDisplay() {
  const [number1, setNumber1] = useState(0);
  const [number2, setNumber2] = useState(0);

  // This is all unnecessary.

  // const [sum, setSum] = useState(0);
  // useEffect(() => {
  //   setSum(number1 + number2);
  // }, [number1, number2]);

  const sum = number1 + number2;

  return (
    <p>{number1} + {number2} = {sum}</p>
  );
}

  • イベントのためにエフェクトを使う必要はありません。コンポーネントが表示されたときに実行されるコードはエフェクトの中に置くべきであり、それ以外はイベントの中に置くべきです。

    import { useState } from "react";

export default function App() {
  const [input, setInput] = useState("");

  const handleInput = (e) => {
    setInput(e.target.value);
  };

  // You should avoid direct manipulation when not necessary

  // useEffect(() => {
  //   document.getElementById("name").addEventListener("change", handleInput);
  //   return () => {
  //     document.getElementById("name").removeEventListener("change", handleInput);
  //   }
  // });

  return (
    <>
      {/* <input id="name" /> */}

      <input onChange={handleInput} value={input} />
      <p>{ input }</p>
    </>
  );
}

  • ほとんどの場合、条件に基づいてstateをリセットするためにエフェクトを使う必要はありません。あなたはすでにReactにおけるkeyについて学んでいます。リストの項目にkeyを使うのとまったく同じように、それがリセットされるべきstateに基づいてコンポーネントにkeyを追加すると、そのstateの値が変化するたびに、そのコンポーネントの一意なバージョンが作られます。

  • stateの管理に問題があり、親や他の子ではないコンポーネントのstateを更新するためにエフェクトを使いたい場合は、stateのリフトアップ(lifting the state)を検討してください。知っているように、Reactではstateは一方向に、一般的にはDOMの下方向に流れます。そのため、親は子にデータを渡す前に、そのデータを知っています。複数の子が単一のstateを利用する必要がある場合、エフェクトのような回避策を使うのではなく、それを必要とするすべてのコンポーネントを持つ親まで、そのstateを引き上げるべきです。

課題

  1. Reactドキュメントのこのレッスンでは、コンポーネントのライフサイクル、レンダリングが行われるさまざまな段階、そしてその中でのuseEffectの役割について説明されています。
  2. Reactドキュメントから、エフェクトが必要ないかもしれない場合についてのさらなる例です。
  3. 初心者がよく犯す間違い、無限のuseEffectループについて説明している、また別の記事です。
