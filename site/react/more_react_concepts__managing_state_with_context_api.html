Managing State With The Context API

イントロダクション

これまでのレッスンを通して、stateを管理する方法や、コンポーネント間でデータとpropsを受け渡す方法を学んできました。しかし、アプリケーションが大きくなるにつれて、stateを管理しデータをやり取りするこのプロセスは、繰り返しが多く不便になるだけでなく、管理も難しくなっていきます。React Routerのレッスンで、outletのコンテキストを使って、親コンポーネントから<Outlet />を通して子コンポーネントにデータを渡す方法について触れました。このレッスンでは、outletを使わない場面でも同じようなことを行うために、Context APIをどう使えるかを扱います。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Context APIを使って、Reactコンポーネントの深いところまでstateやデータを渡す。
  • Context APIの実際の活用例。
  • Context APIを使うことの欠点。

なぜContext APIが必要なのですか?

ReactのContext APIは、propsを使って複数階層のコンポーネントにデータを渡す必要なく、アプリケーションのグローバルなstateを管理できるようにしてくれる機能です。これは、コンポーネントツリーのどこに位置しているかにかかわらず、異なるコンポーネント間でデータや機能を共有する方法を提供してくれます。

より具体的な例を挙げるために、以前すでに構築したプロジェクトに戻ってみましょう。Shopping Cartプロジェクトでは、この非常に素晴らしいショップのような見た目をしている(あるいはしていない)、商品詳細ページがあるかもしれません:

ヘッダーには、現在カートに入っている商品の数を表示するカウンターがあります。「Add to Cart」ボタンを使って、カートに商品を追加できます。

以下の例では、プロジェクトで行ったルーティングや、この例に必要のない他のコンポーネントは省略します。このレッスンに関連するコードだけを見ていきます。

すでに知っている通り、stateを永続させ、コンポーネント間で共有したい場合、行いたいのは、共通の祖先/親にstateをリフトアップすることです。

私たちのアプリケーションのコードは、次のようになるかもしれません:

import { useState } from "react";
// other imports for Header and ProductDetail

export default function App() {
  const [cartItems, setCartItems] = useState([
    /* List of Items in Cart */
  ]);
  const products = /* some custom hook that fetches products and returns the fetched products */

  const addToCart = (product) => {
    // add to cart logic (this adds to cartItems)
  };

  return (
    <>
      <Header cartItemsCount={cartItems.length} />
      <ProductDetail addToCart={addToCart} products={products} />
    </>
  );
}

HeaderコンポーネントとProductDetailコンポーネントに焦点を当てましょう。

私たちのHeaderは、次のような見た目になるかもしれません:

// import for Link

function Links({ cartItemsCount }) {
  return (
    <ul>
      {/* Links */}
      <li>
        <Link to="Link to the cart">
          <span>Cart</span>
          <div className="cart-icon">{cartItemsCount}</div>
        </Link>
      </li>
    </ul>
  );
}

export default function Header({ cartItemsCount }) {
  return (
    <header>
      {/* Other header elements */}
      <nav>
        <Links cartItemsCount={cartItemsCount} />
      </nav>
    </header>
  );
}

私たちのProductDetailコンポーネント:

export default function ProductDetail({ products, addToCart }) {
  const product = products.find(/* Logic to find the specific product */);

  return (
    <div>
      {/* Image of the product */}
      <div>
        {/* elements that align with the design */}
        <button type="button" onClick={() => addToCart(product)}>
          Add to Cart
        </button>
      </div>
    </div>
  );
}

素晴らしいですね。これは非常によくあるパターンで、コンポーネント間でデータや関数を受け渡しているだけで、特に複雑なことはしていません。しかし、細かく管理しなければならないことがたくさんあり、propsを渡さなければならないコンポーネントもたくさんあり、cartItemsCountがApp -> Header -> Linksと渡されていく、ちょっとしたprop drillingも起こっています。

ここまで、Appコンポーネントの中で行ってきたのは:

  • productsとaddToCartをProductDetailコンポーネントに渡す
  • cartItemsCountをHeaderコンポーネントと、Headerの一部であるLinksコンポーネントに渡す

これは非常に基本的なアプリケーションですが、例えばProduct Detail Pageに、さらに多くの機能が追加されて、アプリケーションが大きくなっていく様子を想像してみてください。ネストするコンポーネントがもっと増え、ネストするpropsも増える可能性があります。もしCartコンポーネントやProductListingコンポーネントがあったらどうでしょうか?addToCart以外にも、さらに多くの機能を追加したらどうでしょうか?ご存知の通り、機能が増えれば複雑さも増すため、繰り返しが多く複雑になっていく可能性があります。これは特に、コンポーネントベースのフレームワークでよく起こります。というのも、要素をインラインで書く代わりに、独立した再利用可能なコンポーネントを作りたくなる傾向が強いため、それがさらに多くのネストとpropsの受け渡しを生み出すからです。

Context APIを実装する

アプリケーションを単純化し、複雑さを減らすために、Context APIを実装できます。このAPIには、理解しておく必要がある3つの重要な要素があります:

  1. createContext - これは「コンテキストを作成する」ものです。当たり前ですね……でも、その通りです。これが、コンテキストを作成する方法です。これは、数値、文字列、オブジェクトなど、どんな値でも受け取ることができ、それはコンテキストのデフォルト値と呼ぶことができるもので、コンポーネントにデータを渡すために使えるコンテキストオブジェクトを返します
  2. useContext - このフックは、createContextによって作成されたコンテキストオブジェクトからデータを利用するために使われます。コンポーネントの中でこのフックを使って、必要なデータを取得できます。このフックは、コンテキストオブジェクトを引数として受け取ります
  3. ContextObject - コンテキストオブジェクトは、valueと呼ばれるpropを受け取るコンポーネントです。これは、どれだけ深くネストされていても、コンポーネントに渡されることになるコンテキストの値です。言い換えると、これらのコンポーネントにコンテキストの値を「提供する」方法です。React 19より前は、ContextObjectの代わりにContextObject.Providerが使われていました。そのため、Providerという表記を見かけたら、それはContextObjectを意味しています

reactモジュールからインポートできるcreateContext関数を使うところから始められます。

import { createContext } from "react";

先ほど説明したように、createContextを使って新しいコンテキストを作成する際、そのコンテキストの初期値を指定できます。これは、コンテキストのデフォルト値として知られています。デフォルト値は、文字列、数値、真偽値、あるいはオブジェクトや配列であっても、どんな型の値でもかまいません。このデフォルト値は変化せず、静的なものであることに注意してください。

私たちの場合は、以下のような形のオブジェクトを使います:

const ShopContext = createContext({
  products: [],
  cartItems: [],
  addToCart: () => {},
});

この例では、私たちのデフォルト値は、products、cartItems、addToCartという3つのプロパティを持つオブジェクトです。productsとcartItemsは配列であり、それぞれ商品とユーザーのカートに入っている商品を保持します。addToCartは、カートに商品を追加できるようにしてくれる関数です。

定義したこのオブジェクトは、必須ではありません。もちろん、以下のようにすることもでき、それでもまったく問題ありません:

const ShopContext = createContext(null);

しかし、このオブジェクトを追加している理由は、たとえ何らかの形でProviderの中にネストされていないコンポーネントの中でコンテキストを使ってしまったとしても、デフォルト値を設定しているため、アプリケーションが壊れないようにするためです(これは、値を取得するためにコンポーネントをProviderでラップする必要がないため、テストにも都合が良いです)。また、値としてオブジェクトを持っていると、オートコンプリートのようなIDEの機能も活用できます。コンポーネントの中でこのコンテキストを使うとき、コンテキストから直接プロパティにアクセスできるようになります。これは基本的におまけのようなものです!デフォルト値をオブジェクトにするか、単にnullにするかは、あなた次第です。というのも、いずれにせよこのデフォルト値は上書きすることになるからです。

では、このコンテキストをどう使えばよいのでしょうか?それは、Contextオブジェクトをコンポーネントとして使い、その中に子コンポーネントをネストさせることによってです。この例では、propsを完全に取り除きます。

import { useState, createContext } from "react";
// other imports for Header and ProductDetail

export const ShopContext = createContext({
  products: [],
  cartItems: [],
  addToCart: () => {},
});

export default function App() {
  const [cartItems, setCartItems] = useState([
    /* List of Items in Cart */
  ]);
  const products = /* some custom hook that fetches products and returns the fetched products */

  const addToCart = (product) => {
    // add to cart logic (this adds to cartItems)
  };

  return (
    /* We are going to pass the things that we want to inject to these components using the value prop */
    /* This value prop will overwrite the default value */
    <ShopContext value={{ cartItems, products, addToCart }}>
      <Header />
      <ProductDetail />
    </ShopContext>
  );
}

素晴らしい!では、Headerコンポーネントをもう一度見てみましょう。先ほど定義したすべてのpropsも取り除き、データを取得するために、reactモジュールからインポートできるuseContextフックを使います。

import { useContext } from "react";
// import for ShopContext
// import for Link

function Links() {
  const { cartItems } = useContext(ShopContext); // We must pass the ShopContext object itself as an argument

  return (
    <ul>
      {/* Other links */}
      <li>
        <Link to="Link to the cart">
          <span>Cart</span>
          <div className="cart-icon">{cartItems.length}</div>
        </Link>
      </li>
    </ul>
  );
}

export default function Header() {
  return (
    <header>
      {/* Other header elements */}
      <nav>
        <Links />
      </nav>
    </header>
  );
}

prop drillingの問題を完全に取り除くことができ、コンポーネントがどれだけ深くネストされていても、それがProviderの中にネストされている限りデータを取得できることをすでに知っているため、Linksコンポーネント自体の中でcartItemsを直接、便利に取得できるようになりました。

同じように、ProductDetailコンポーネントも変更しましょう:

import { useContext } from "react";
// import for ShopContext

export default function ProductDetail() {
  const { products, addToCart } = useContext(ShopContext);
  const product = products.find(/* Logic to find the specific product */);

  return (
    <div>
      {/* Image of the product */}
      <div>
        {/* elements that align with the design */}
        <button type="button" onClick={() => addToCart(product)}>
          Add to Cart
        </button>
      </div>
    </div>
  );
}

Headerコンポーネントでは、ShopContextからcartItemsにアクセスするためにuseContext()を使いました。同様に、ProductDetailコンポーネントでも、productsとaddToCart関数を使うことができます。

この実装により、AppコンポーネントからHeaderとProductDetailコンポーネントにpropsを渡す必要がなくなりました。HeaderとProductDetailコンポーネントは、ShopContextからcartItemsstateとaddToCart関数にアクセスできます。

全体として、Context APIの実装によって、複数のコンポーネントにわたってデータを渡す、より効率的で、よりクリーンで、より合理化された方法が可能になりました。createContext()関数とuseContext()フックを使うことで、prop drillingを行うことなく、簡単にstateや関数を子コンポーネントに渡すことができます。データを単一の場所に保持しているため、より集中管理もされています。これらすべてが、私たちのコードについて考えることを容易にしてくれます。

Context APIを使うことの欠点

Context APIは、より大規模なReactアプリケーションでstateを管理するための強力なツールになり得ますが、知っておくべきいくつかの欠点もあります:

  1. パフォーマンスの問題につながる可能性があります: コンテキスト内のstateを更新すると、そのコンテキストを利用しているすべてのコンポーネントが、たとえそれらが使っているstateが変化していなくても、再レンダーされてしまうことがあります。これは、特に同じコンテキストを利用しているコンポーネントがたくさんある場合、パフォーマンスの問題につながる可能性があります。
  2. コードを追いにくくする可能性があります: Context APIを使うと、アプリケーション内のどのコンポーネントからでもstateにアクセスしやすくなります。しかし、これによって、特に同じコンテキストを利用しているネストされたコンポーネントがたくさんある場合、コードが追いにくくなることもあります。混乱を避けるために、コードを整理し、うまく構造化しておくことが重要です。

考えられる解決策

  1. 単一の大きなコンテキストの代わりに、複数の小さなコンテキストを使う。アプリケーションのすべてのstateを管理するために単一の大きなコンテキストを使う代わりに、関連するstateの部分を管理するために複数の小さなコンテキストを使うことを検討してください。これにより、そのコンテキストを利用するコンポーネントの数を減らし、不要な再レンダーを最小限に抑えることができます。
  2. 場合によっては、Context APIが、対処したい問題にとって最善の解決策でさえないこともあります。Robin WieruchによるReact Component Compositionの記事を見てみてください。
  3. ZustandやReduxのような、外部のstate管理システムに頼ることもできます。これらには最適化が数多く組み込まれており、機能も豊富です。残念ながら、これらには学習曲線があるため、このコースの残りの部分ではContext APIを使い続けることをお勧めします。これから構築するプロジェクトの大部分にとって、Context APIは依然として信頼できるものだからです。

課題

  1. ReactのドキュメントにはContext APIについての、より興味深い例や、考えられる最適化が用意されています。Contextを使ってデータを深く渡すことについてのドキュメントに目を通すことで、それを確認できます。それぞれの例を必ず試してみてください!
  2. Kent C. Dodds氏による短い記事、Prop Drillingを読んでください。これは、消化しやすい例を交えながら、prop drillingについての理解を深めるのに最適な記事です。
