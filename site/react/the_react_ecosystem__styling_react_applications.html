Styling React Applications

イントロダクション

これまでのコースで、あなたはたくさんのCSSを学んできており、それらのスキルはすべて、Reactにおいても引き続き通用します。しかし、いくつか強調しておきたい点があります。あなたはおそらくすでに気づいているかもしれませんが、私たちが書くすべてのスタイルはグローバルスコープを共有しているため、アプリケーションが大きくなるにつれて、CSSの管理はますます難しくなっていきます。以下に挙げるツールのいくつかは、この問題を解決する助けとして人々が使っているものです。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Reactアプリケーションにスタイルを付ける方法について知る。

CSSモジュール

通常のCSSは、最もシンプルなスタイリングの方法です。CSSモジュールを使うと、ローカルにスコープされたCSSのスタイル宣言を書くことができ、これにより私たちのクラス名がグローバルスコープの他のクラスと衝突する可能性を、ようやく心配しなくてよくなります。

CSS in JS

JavaScriptの中でCSSを書けるのに、なぜわざわざCSSの中でCSSを書く必要があるのでしょうか?もちろん、冗談です!

CSS-in-JSは、フロントエンドプロジェクトにスタイルを付けるためのパラダイムです。これにより、JavaScriptでCSSを完全に制御し、さまざまな機能でそれを拡張できるようになります。さらに、例えばstateに基づくなど、論理的な形でスタイリングを適用する助けにもなり、CSSモジュールと同じ方法でモジュール化されたCSSもサポートしています。CSS-in-JSにはさまざまなソリューションがあります。Reactのエコシステムの中で最も人気のあるものの一つが、styled-componentsです。

CSSユーティリティフレームワーク

CSSユーティリティフレームワークは、Reactアプリケーションにスタイルを付けるための人気の選択肢です。これらは、HTML、私たちの場合はJSXの中で直接使える、あらかじめ定義されたクラスのセットを提供してくれます。Tailwind CSSが、断トツで最も人気のある選択肢です。

コンポーネントライブラリ

もし、すべてがすでに用意されているとしたらどうでしょうか?コンポーネントライブラリでは、スタイリング、振る舞い、アクセシビリティがすでに面倒を見てもらえます。名前が示す通り、これらのライブラリは、プロジェクトの中で直接使える、適応性があり再利用可能なコンポーネントを提供してくれます。これらのコンポーネントには、ドロップダウン、ドロワー、カレンダー、トグル、タブなど、あなたが思いつくあらゆるコンポーネントが含まれますが、それらに限られるわけではありません。

コンポーネントライブラリについて語るとき、Material UI、Radix、Chakra UIは言及する価値があります。

lucide reactのような、アイコンをコンポーネントとしてプロジェクトに含められるようにしてくれる、アイコンコンポーネントライブラリもあります。

推奨されるスタイリングのアプローチ

このコースを通しての学習目的のためには、CSSフレームワークやコンポーネントライブラリの使用を避け(アイコンコンポーネントライブラリの使用は問題ありません)、代わりにCSSモジュールを使ってコンポーネントのスタイリングをゼロから実装することを強くお勧めします。
