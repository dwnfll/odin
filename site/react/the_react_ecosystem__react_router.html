React Router

イントロダクション

カリキュラムのこの時点まで、私たちは単一ページのアプリケーションを構築してきました。しかし、より大規模なアプリケーションでは、複数のページを持つことになります。幸いなことに、ブラウザはHistory APIを使って、クライアントサイドのJavaScriptがユーザーのナビゲーションの方法を管理できるようにしてくれています。私たちは、React Routerのようなパッケージの助けを借りて、この力を活用してReactでのルーティングを管理できます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • クライアントサイドルーティングとは何かを理解する。
  • クライアントサイドルーティングのためにReact Routerを使う方法を学ぶ。
  • React Routerでネストしたパスや動的なパスを作成する方法を探る。
  • React Routerで「キャッチオール」ルートを追加する方法を発見する。
  • outletを介してレンダーされる子コンポーネントに、親コンポーネントからデータを渡す方法を学ぶ。
  • React Routerで保護されたルートを実装する方法を理解する。
  • React Routerを使うコンポーネントをテストすることについての入門を得る。

クライアントサイドルーティング

クライアントサイドルーティングとは、アプリケーション内のルートを処理する役割をJavaScriptが引き受ける、というタイプのルーティングです。クライアントサイドルーティングは、ユーザーがナビゲートする際にリフレッシュすることなく、シングルページアプリケーション(SPA)を構築するのに役立ちます。例えば、ユーザーがナビゲーションバーの要素をクリックすると、URLが変化し、それに応じてクライアント内でページの表示が変更されます。

鶏肉を料理しているとしましょう。それをきちんと美味しく調理したいなら、次のことをする必要があります:

  1. オーブンに鶏肉を入れ、適切な時間と温度で調理するように設定する
  2. 料理が満足のいく香りを漂わせるまで待つ
  3. さあ、食べ始めましょう!

これはすべてのウェブサイトに共通することです。あなたは望むものにオーブンを設定し(https://theodinproject.com/のような任意のURLにアクセスすることに相当します)、オーブンが調理を終えるのを待ち(ローディング画面)、そしてジャジャーン、美味しい料理を楽しみます(ページが使える準備が整います)。しかし、調理する前にスパイスを加え忘れていたらどうでしょうか?あなたはこの流れをもう一度繰り返さなければなりません:

  1. 席から立ち上がる
  2. 鶏肉にスパイスを加える
  3. オーブンのところに戻り、鶏肉を戻して、再加熱するように設定する
  4. いい感じに温まるのを待つ
  5. これで食べられます!

ここで改めて強調しておきたいのは、あなたは席から立ち上がる必要がある、という点です。一般的なマルチページアプリケーション(MPA)では、ナビゲートするためにリンクをクリックするたびに、ブラウザがリロードされます。クライアントサイドルーティングでは、あなたは今いるページを決して離れません。もし「スパイスを忘れた」問題に遭遇しても席を立たなくて済むように、電子レンジをテーブルに持ってくるようなものです。リンクのリクエストは、サーバーに直接送られる代わりに、あなたが書いたJavaScriptによって傍受されます。

リアクティブな解決策

クライアントサイドルーティングは、よりアプリらしい快適な操作感を可能にしてくれますが(ルートを自分で制御しているため、ルートの変化に合わせて凝ったCSSアニメーションを作ることもできます)、多くの注意点が見落とされがちです。ブラウザがリロードされるとき、それはスクリーンリーダーに読み上げるべき新しいコンテンツがあることを通知しますが、クライアントサイドルーティングの場合、ルートの更新をスクリーンリーダーに手動で通知する必要があります。しかし、堅牢なライブラリの助けを借りれば、こうした懸念にたいてい対処できます!

React Routerは、Reactアプリケーションのための標準的なルーティングライブラリです。React Routerを使うことで、ルートに基づいてレンダーされるReactコンポーネントを指定でき、それ以外にもたくさんのことができます。早速見ていきましょう!

ルーターを追加する

このルーターがどのように実装されているかを理解するために、小さなアプリを作ってみましょう。新しいReactプロジェクトを作成し、まずは例としていくつかのモックページを追加するところから始めましょう。以下のコンポーネントを含む、新しいProfile.jsxファイルを作成してください:

const Profile = () => {
  return (
    <div>
      <h1>Hello from profile page!</h1>
      <p>So, how are you?</p>
    </div>
  );
};

export default Profile;

App.jsxファイルも、いくつかの基本的な内容に置き換えてください:

const App = () => {
  return (
    <div>
      <h1>Hello from the main page of the app!</h1>
      <p>Here are some examples of links to other pages</p>
      <nav>
        <ul>
          <li>
            <a href="profile">Profile page</a>
          </li>
        </ul>
      </nav>
    </div>
  );
};

export default App;

さあ、いよいよルーターを追加するときです!アプリのルートを定義するにはいくつかの方法がありますが、ここではオブジェクトベースのアプローチに従います。

React Routerパッケージをインストールしましょう:

npm install react-router

以下をmain.jsxに追加してください。何が起きているのかについては、少し後で説明します。

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import App from "./App";
import Profile from "./Profile";

const router = createBrowserRouter([
  {
    path: "/",
    element: <App />,
  },
  {
    path: "profile",
    element: <Profile />,
  },
]);

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>
);

これができたら、npm run devを実行して、ホームルートの/とプロフィールルートの/profileの両方を確認してみてください。動きます!でも、ここで何が起きているのでしょうか?

  1. React RouterからcreateBrowserRouterとRouterProviderをインポートします。
  2. createBrowserRouterは、ルートの配列という形で引数を渡すことで、ルーターの設定を作成するために使われます。
  3. この設定用の配列には、pathとレンダーされる対応するelementという、2つの必須キーを持つオブジェクトが含まれています。
  4. 生成されたこの設定は、RouterProviderコンポーネントに渡されることでレンダーされます。

Link要素

しかし、ナビゲーションバーのリンクをクリックすると、React Routerを使う代わりに、ブラウザが次のURLのためにリロードされてしまうことに気づくかもしれません。これは約束されていたものとは違います!これを助けるために、React Routerは、通常のaタグの代わりに使うためのカスタムのLinkコンポーネントをエクスポートしています。ナビゲーションバーのaタグをLink要素に置き換えることができます。

import { Link } from "react-router";

const App = () => {
  return (
    <div>
      <h1>Hello from the main page of the app!</h1>
      <p>Here are some examples of links to other pages</p>
      <nav>
        <ul>
          <li>
            <Link to="profile">Profile page</Link>
          </li>
        </ul>
      </nav>
    </div>
  );
};

export default App;

これで、ナビゲーションバーのリンクをクリックするたびにブラウザがリロードされることはなくなりました!

ネストしたルート、outlet、動的セグメント

では、異なるURLに基づいて、ページのあるセクションを違った形でレンダーしたい場合はどうすればよいでしょうか?ここで登場するのが、ネストしたルートです!ルートを互いの子としてネストさせて追加することで、子が親と一緒にレンダーされるようにできます。Popeye.jsxとSpinach.jsxという2つのコンポーネントを作成してください。

import { Link } from "react-router";

const Popeye = () => {
  return (
    <>
      <p>Hi, I am Popeye! I love to eat Spinach!</p>
      <Link to="/">Click here to go back</Link>
    </>
  );
};

export default Popeye;
import { Link } from "react-router";

const Spinach = () => {
  return (
    <>
      <p>Hi, I am Spinach! Popeye loves to eat me!</p>
      <Link to="/">Click here to go back</Link>
    </>
  );
};

export default Spinach;

では、ルートを以下のように書き直すことができます:

import { StrictMode } from "react"
import { createRoot } from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import App from "./App";
import Profile from "./Profile";
import Spinach from "./Spinach";
import Popeye from "./Popeye";

const router = createBrowserRouter([
  {
    path: "/",
    element: <App />,
  },
  {
    path: "profile",
    element: <Profile />,
    children: [
      { path: "spinach", element: <Spinach /> },
      { path: "popeye", element: <Popeye /> },
    ],
  },
]);

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
);

これにより、Outletコンポーネントを通して、子コンポーネントを親と一緒にレンダーできるようになります!Profileコンポーネントを書き直して、そのルートが訪問されたときにさまざまなプロフィールに置き換わるOutletを追加できます!

import { Outlet } from "react-router";

const Profile = () => {
  return (
    <div>
      <h1>Hello from profile page!</h1>
      <p>So, how are you?</p>
      <hr />
      <h2>The profile visited is here:</h2>
      <Outlet />
    </div>
  );
};

export default Profile;

/profileページを確認してみてください。/profile/popeyeや/profile/spinachページを訪問するには、現在のURLの末尾に/popeyeや/spinachを手動で追加してください。<Outlet />コンポーネントは、それぞれのパスが訪問されると、対応する子コンポーネントに置き換わります。

Profileにパスが何も追加されていないときに、デフォルトのコンポーネントとして何かをレンダーしたい場合は、childrenにindexルートを追加できます!

DefaultProfileコンポーネントを作成してください:

const DefaultProfile = () => {
  return <p>Oh, nothing to see here!</p>;
};

export default DefaultProfile;

では、/profileルートに、DefaultProfileを子として持つindexプロパティを追加してください。

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import App from "./App";
import Profile from "./Profile";
import DefaultProfile from "./DefaultProfile";
import Spinach from "./Spinach";
import Popeye from "./Popeye";

const router = createBrowserRouter([
  {
    path: "/",
    element: <App />,
  },
  {
    path: "profile",
    element: <Profile />,
    children: [
      { index: true, element: <DefaultProfile /> },
      { path: "spinach", element: <Spinach /> },
      { path: "popeye", element: <Popeye /> },
    ],
  },
]);

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
);

これで/profileパスを訪問すると、indexパスがレンダーされる際に、Outletがレンダーされる場所に何らかのデフォルトのコンテンツが表示されるはずです!

しかし、この例は別のジレンマをもたらします。時には、URLに応じてコンテンツをレンダーしたいことがあります。ここでそれが意味するのは、コンポーネント自体から動的にコンテンツをレンダーできるべきだ、ということです。幸いなことに、動的セグメントを使えばそれができます!ルートを以下のように変更してください:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import App from "./App";
import Profile from "./Profile";

const router = createBrowserRouter([
  {
    path: "/",
    element: <App />,
  },
  {
    path: "profile/:name",
    element: <Profile />,
  },
]);

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
);

コロン(:)は、その後ろのパスの部分を「動的セグメント(dynamic segment)」に変えます。動的セグメントは、nameのように、URLのその位置にある動的な(変化する)値にマッチします。これらは「URLパラメータ」、あるいは略して「パラメータ」と呼ばれることもあります。これらは、useParamsフックの助けを借りて使うことができます。そのため、Profileコンポーネントを以下のように書き直すことができます:

import { useParams } from "react-router";
import DefaultProfile from "./DefaultProfile";
import Spinach from "./Spinach";
import Popeye from "./Popeye";

const Profile = () => {
  const { name } = useParams();

  return (
    <div>
      <h1>Hello from profile page!</h1>
      <p>So, how are you?</p>
      <hr />
      <h2>The profile visited is here:</h2>
      {name === "popeye" ? (
        <Popeye />
      ) : name === "spinach" ? (
        <Spinach />
      ) : (
        <DefaultProfile />
      )}
    </div>
  );
};

export default Profile;

不正なURLを処理する

しかし残念なことに、/profileパスでは実際にはパラメータが渡されないため、indexパスはもう機能しなくなってしまいます。実のところ、/profileパスは、実際の名前がなければあまり意味をなしません。そうでなければ、誰のプロフィールを表示すればいいのか、ということになりますよね?そのため、アプリケーションはエラーを表示してしまいます!これは良くありません。では、ユーザーが間違った、または使われていないパスを訪問した場合に、デフォルトのページを表示するにはどうすればよいでしょうか?ここではerrorElement引数を渡すことができます!基本的な「見つかりません」ページを作成してください:

import { Link } from "react-router";

const ErrorPage = () => {
  return (
    <div>
      <h1>Oh no, this route doesn't exist!</h1>
      <Link to="/">
        You can go back to the home page by clicking here, though!
      </Link>
    </div>
  );
};

export default ErrorPage;

設定にerrorElementを追加し、/profileパスや言及されていない任意のパスにアクセスして、エラーページがレンダーされることを確認してください。

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import App from "./App";
import Profile from "./Profile";
import ErrorPage from "./ErrorPage";

const router = createBrowserRouter([
  {
    path: "/",
    element: <App />,
    errorElement: <ErrorPage />,
  },
  {
    path: "profile/:name",
    element: <Profile />,
  },
]);

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
);

ルートをリファクタリングする

ルートの配列を、それ専用のファイルにリファクタリングしましょう。リファクタリングすることで、上の例のように、ルートをmain.jsxにインポートし、そこからブラウザルーターを作成できます。これの便利なところは、このルートの配列を、任意のテストファイルにもインポートできる点です。テストファイルでは、ブラウザルーターの代わりにテスト専用のルーターを使う必要があるかもしれません(これについては後で詳しく説明します)。

新しいroutes.jsxファイルを作成し、ルートの配列をそこに移動してください:

import App from "./App";
import Profile from "./Profile";
import ErrorPage from "./ErrorPage";

const routes = [
  {
    path: "/",
    element: <App />,
    errorElement: <ErrorPage />,
  },
  {
    path: "profile/:name",
    element: <Profile />,
  },
];

export default routes;

ルートをmain.jsxファイルにインポートしてください:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import routes from "./routes";

const router = createBrowserRouter(routes);

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>
);

ずっとすっきりしましたね!

Outletとstate

前に学んだように、ルートを親ルートの子としてネストさせることができ、これにより、親の中で<Outlet />を使って、パスの残りの部分に基づいて適切なelementをレンダーできます。

もし親のelementにstateのようなデータがあり、それをそのoutletによってレンダーされる任意のコンポーネントに渡したい場合は、contextと呼ばれるものを使う必要があります。今のところは、outletと組み合わせたコンテキストに焦点を当てますが、後のレッスンで、outletを使わずにコンテキストを使う方法について、さらに詳しく学びます。

outletにはcontextpropが組み込まれています。このpropには、配列やオブジェクトであっても、好きな値を渡すことができます。そのoutletの中でレンダーされる任意のコンポーネント(「孫」コンポーネントであっても)の中で、useOutletContext()フックを呼び出すことができ、これはそのcontext propに渡したものを何であれ返してくれます。配列やオブジェクトを渡した場合は、それを分割代入することさえできます!

outletを通してコンテキストを渡し、子コンポーネントの中でそのコンテキストにアクセスする方法についてさらに詳しく学ぶために、React RouterのuseOutletContextについてのドキュメントを見てみてください。

保護されたルートとナビゲーション

多くの場合、特定のルートをレンダーすべきかどうかを判断する必要が出てきます。一つの例が認証であり、ユーザーがログインしているかどうかに基づいて、特定のルートをレンダーします。ログインしていれば、The Odin Projectのダッシュボードページのように、ユーザーについての情報を表示します。そうでなければ、サインインページ(これは任意のページでかまいません)にリダイレクトされます。これを行う方法はたくさんありますが、最も簡単な方法の一つは、条件付きでルーター用の設定を作成することです。

ユーザーを別のURLにプログラム的に再ルーティングする必要に、頻繁に出会うことになるでしょう。ここで使えるのがuseNavigateフックであり、これによってURLに移動したり、ユーザーの履歴をさかのぼったりすることさえできます。

React Routerのテスト

React Routerを使うコンポーネントをテストする際は、あなたのアプリがそれらのコンポーネントを直接レンダーすることは決してない、という点を覚えておくことが重要です。代わりに、(例えば<RouterProvider>を介して)ルーターを通してそれらをレンダーします。そのため、これらのコンポーネントをレンダーするテストも、ルーティングのコンテキストの中でそれらをレンダーする必要があります。そうしないと、useNavigateやuseParamsのようなフックや、<Link>コンポーネントがエラーをスローしてしまいます。

たまたま<Link>のようなものを含んでいるだけのコンポーネントをレンダーしているだけであれば(そしてナビゲーションをテストしたり、他のルーター機能に依存したりしていなければ)、それを軽量なMemoryRouterでラップするだけで十分かもしれません。しかし、outletのコンテキストを使ったり、パラメータのマッチングを行ったり、errorElementやリダイレクトを使ったりするなど、コンポーネントがルーターの挙動に依存している場合は、あなたのアプリがそうしているのと同じように、<RouterProvider>をレンダーするほうが理にかなっています。テストはブラウザの中で実行されるわけではないので、createMemoryRouterを使って、routes.jsxと同じルート設定でテスト用のルーターを作成できます。

まとめ

これで、Reactのルーティングを始めるのに十分な基礎が身についたはずです。react-routerには、非常に便利ではあるものの、このレッスンの範囲外である機能がまだまだたくさんあります。上で扱った概念だけで、このReactコースを乗り切るには十分だと確信しています。さらに学びたい場合は、historyオブジェクトやmatchオブジェクトについて調べてみることをお勧めします。基礎に慣れたら、ぜひもっと高度な概念もチェックしてみてください。
