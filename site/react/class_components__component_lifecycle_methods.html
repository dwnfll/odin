Component Lifecycle Methods

イントロダクション

前のセクションで、コンポーネントのライフサイクルについて学びました。関数コンポーネントでは、ライフサイクル全体を通してタスクを実行するために、主にuseEffectフックを使ってきましたが、クラスコンポーネントでは、代わりに特定のライフサイクルメソッドを使わなければなりません。

まずは、コンポーネントのライフサイクルとは何かを簡単におさらいすることから始めましょう。コンポーネントのライフには、マウント、更新、アンマウントという3つの段階があります。クラスコンポーネントでは、それぞれの段階に対応するメソッドが割り当てられており、これがこのレッスンで扱う内容です。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • クラスコンポーネントでライフサイクルメソッドを使う方法を学ぶ。

render()

render関数は最もよく使われるライフサイクルメソッドであり、前回のクラスコンポーネントのレッスンですでに出会っています。これは、クラスコンポーネントの中で唯一必須のライフサイクルメソッドです。コンポーネントのマウント時と更新時に実行されます。renderは純粋であるべきです。つまり、コンポーネントのstateを変更せず、(同じ入力が与えられれば)呼び出されるたびに同じものを返し、ブラウザと直接やり取りすることもありません。

componentDidMount()

このメソッドは、コンポーネントがマウントされた後(DOMツリーに挿入された後)に実行されます。コンポーネントに必要なデータを取得するための呼び出しは、ここで行うべきです。また、コンポーネントがDOMにマウントされていることに依存する操作を行うのにも適した場所です。

componentDidUpdate()

このメソッドは、コンポーネントが再レンダーされた後に実行されます。そのため、このメソッドの中で何を更新するかには注意が必要です。無差別にstateを更新してしまうと、再レンダーが引き起こされ、終わりのないループに陥ってしまいます。stateを更新する際に、以前のpropsと現在のpropsが等しいかどうかについての条件文を使うことで、この問題を避けることができます。

このメソッドの中では、DOMの変化や、変化に応じて何か処理を行いたいstateに対応して、変更する必要のあるものを更新するべきです。例えば、ユーザーが変わったら、ユーザーデータを再取得したいと思うでしょう。

componentWillUnmount()

これは最後のライフサイクルメソッドであり、コンポーネントがアンマウントされて破棄される前に呼び出されます。このメソッドの中では、クリーンアップの操作、つまりネットワークリクエストのキャンセルや、タイマーのクリアなどを行うべきです。

useEffect()はライフサイクルメソッドをどのように組み合わせているか

クラスのライフサイクルメソッドについて学んだところで、関数コンポーネントで使われるuseEffectフックが、本質的にはcomponentDidMount、componentDidUpdate、componentWillUnmountを組み合わせたものであると理解しておくと役立ちます。どのメソッドに関連するかは、その依存配列や、何かを返すかどうかによって変わります。

  • 空の依存配列は、componentDidMountと同等になります。
  • 値を含む依存配列は、componentDidMountとcomponentDidUpdateの組み合わせになりますが、依存関係が変化したときにのみ更新されます。
  • 依存配列がない場合は、componentDidMountとcomponentDidUpdateを組み合わせたものと同等になります。
  • useEffect()フックの中で関数を返すことは、componentWillUnmountと同等になります。

例えば:

  useEffect(() => {
    placeholderFunction();
    return () => cleanupFunction();
  }, [])

このスニペットでは、useEffectはcomponentDidMountの機能を含んでおり、返される関数を通してcomponentWillUnmountの機能も含んでいます。この例では、依存配列が空であるため、componentDidUpdateの機能は含まれていません。

課題

  1. このコンポーネントライフサイクルの図をチェックして、コンポーネントのライフサイクルメソッドの優れた視覚的な表現を見てみてください。

  2. コンポーネントのドキュメントのReferenceセクションにある「constructor(props)」から「componentWillUnmount()」までを読んでください。その際、非推奨のAPIに注意してください。それ以外のAPIについては、補足情報として捉えてください。
