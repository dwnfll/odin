Class Based Components

イントロダクション

ここまでのコンポーネントはすべて、スタイルも構文も関数型のものでした。これは今では一般的なやり方ですが、classベースの別の構文を目にすることもあるでしょう。このレッスンでは、クラスベースのコンポーネントがどのように書かれるか、そしてpropsやstateのような概念がその中でどのように使われるかを見ていきます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • クラスコンポーネントがどのように書かれるか。
  • クラスコンポーネントでpropsとstateを使う方法。
  • クラスコンポーネントにおけるthisキーワードの使い方。

Reactコンポーネントのパターンの歴史

これまでのレッスンで、あなたはすでに関数コンポーネントと、現在コンポーネントが書かれる際の基本的なパターンに触れてきました。しかし、Reactが登場した当初、Reactコンポーネントはこのような見た目ではありませんでした。

古いReactのコードベースを見てみると、たくさんのクラスがあることに気づくでしょう。これらはクラスベースのコンポーネントとして知られています。2019年2月より前は、関数コンポーネントの中でstateを管理する方法がなかったため、関数コンポーネントはステートレス(state-less)とも呼ばれていました。これは、フックが導入されたことで変わり、より簡潔で「すっきりとした」コンポーネントにつながりました。

あなたのキャリアの中で、おそらくレガシーコードを扱うことになるので、クラスコンポーネントを扱う日もあるでしょう。クラスベースのコンポーネントの複雑な部分と、それがどのように機能するかを覗いてみましょう。

クラスコンポーネントを構築する

すでに関数コンポーネントについて知っているので、関数コンポーネントからクラスベースのコンポーネントを構築してみましょう。通常は、使うようなコンポーネントの内容を、より小さく再利用可能なコンポーネントに分割したいと思うでしょうが、この演習の目的のために、すべてを1つのコンポーネントにまとめておくことにします。

まず、まだであればreact-examplesリポジトリをフォークしてクローンしてください。class-components/ディレクトリにcdで移動し、npm installで依存関係をインストールし、npm run devで開発サーバーを開いてください。同じ機能の2つのバージョン、一つは関数コンポーネントで、もう一つはクラスコンポーネントで作られたものがあることがわかるはずです。まずはsrc/components/FunctionalInput.jsxの中の関数コンポーネントを見てみましょう。かなりのボリュームのコードなので、少し時間を取り、水でも飲みながら、数回読んでみてください。

クラスベースのコンポーネントの始まり

src/components/ClassInput.jsxの中に、それを完成させたクラスベースのバージョンがあることがわかるはずです。少し戻って、それが関数版からどのように再現されたのかを、一歩ずつ見ていきましょう。まず必要なのは、ドラムロール、クラスです!ただし、ただのクラスというわけにはいきません。Reactコンポーネントとして認められるための特定のプロパティを持っている必要があります。Reactは、Componentと呼ばれるクラスに、そうしたプロパティをすべて用意してくれています。以下のようにその与えられたクラスを継承(extend)することで、自分たちのコンポーネントを書くことができます:

import { Component } from "react";

class ClassInput extends Component {
  // Some code goes here
}

export default ClassInput;

コンストラクタとpropsの使い方

クラスは一般的にコンストラクタなしでは不完全なので、一つ追加しましょう。

このコンポーネントに渡されたpropsは、クラスのconstructorに渡されます。これは、superメソッドと合わせて、thisのコンテキストの中でpropsを使えるようにしてくれます。このthisは、この場合コンポーネント自身を指します。superが実際に何をしているのか本当に気になる場合は、superキーワードについてのMDNドキュメントを確認してください。

もしコンポーネントにpropsがまったくない場合は、constructorとsuperを引数なしのままにしておいてかまいません。

import { Component } from "react";

class ClassInput extends Component {
  constructor(props) {
    super(props);
  }
  // Some more code goes here
}

export default ClassInput;

JSXをレンダーする方法

これでクラスコンポーネントの中でpropsにアクセスできるようになったので、次の課題は、JSXをレンダーする方法を見つけることです。

実は、それはrenderメソッドからJSXを返すことで実現できます!コンストラクタの中で宣言したpropsも使うことができます!

import { Component } from "react";

class ClassInput extends Component {
  constructor(props) {
    super(props);
  }
  // Some more code goes here

  render() {
    return (
      <section>
        <h3>{this.props.name}</h3>
       {/* The input field to enter Todos */}
        <form>
          <label htmlFor="task-entry">Enter a task: </label>
          <input type="text" id="task-entry" name="task-entry" />
          <button type="submit">Submit</button>
        </form>
        <h4>All the tasks!</h4>
        {/* The list of all the Todos, displayed */}
        <ul></ul>
      </section>
    );
  }
}

export default ClassInput;

最初に見た関数コンポーネントとは異なり、propsがthisによって提供されていることに気づきましたか?

stateの使い方とコンテキストの管理方法

次はstateです。クラスベースのコンポーネントでは、stateはコンストラクタの一部として初期化されます。

import { Component } from "react";

class ClassInput extends Component {
  constructor(props) {
    super(props);

    this.state = {
      todos: [],
      inputVal: "",
    };
  }
  // Some more code goes here

  render() {
    return (
      <section>
        <h3>{this.props.name}</h3>
        <form>
          <label htmlFor="task-entry">Enter a task: </label>
          <input type="text" id="task-entry" name="task-entry" />
          <button type="submit">Submit</button>
        </form>
        <h4>All the tasks!</h4>
        <ul></ul>
      </section>
    );
  }
}

export default ClassInput;

あらかじめ定義されているsetStateメソッドを使えば、それを再び設定できます!stateはミューテートしてはいけないため、毎回新しいstateを設定する必要があることを忘れないでください。

さて、いよいよすべての機能を追加して仕上げるときです!ほとんど同じですが、一つだけ違いがあります。メソッドを宣言するときは、そのメソッドで使うために、メソッドのthisをクラスのthisにbind(バインド)する必要があります。クラスの中のメソッドは、デフォルトではクラスにバインドされていないからです。通常は、これを(renderメソッドのような)実行時ではなく、コンストラクタの中で行います。代わりに、アロー関数の構文を使ってメソッドを定義すれば、thisは自動的にクラスのインスタンスにバインドされるため、コンストラクタの中でバインドする作業を省略できます。

import { Component } from "react";

class ClassInput extends Component {
  constructor(props) {
    super(props);

    this.state = {
      todos: [],
      inputVal: "",
    };

    this.handleInputChange = this.handleInputChange.bind(this);
    this.handleSubmit = this.handleSubmit.bind(this);
  }

  handleInputChange(e) {
    this.setState((state) => ({
      ...state,
      inputVal: e.target.value,
    }));
  }

  handleSubmit(e) {
    e.preventDefault();
    this.setState((state) => ({
      todos: state.todos.concat(state.inputVal),
      inputVal: "",
    }));
  }

  render() {
    return (
      <section>
        <h3>{this.props.name}</h3>
        <form onSubmit={this.handleSubmit}>
          <label htmlFor="task-entry">Enter a task: </label>
          <input
            type="text"
            id="task-entry"
            name="task-entry"
            value={this.state.inputVal}
            onChange={this.handleInputChange}
          />
          <button type="submit">Submit</button>
        </form>
        <h4>All the tasks!</h4>
        <ul>
          {this.state.todos.map((todo) => (
            <li key={todo}>{todo}</li>
          ))}
        </ul>
      </section>
    );
  }
}

export default ClassInput;

これで完成です。こんなにも簡単に、クラスベースのコンポーネントを作ることができました!

課題

完成したクラスベースのコンポーネントができたので、それにさらに機能を追加していきましょう。

  1. 各タスクに削除ボタンを実装してください。削除ボタンは、そのタスクをstateの配列から取り除き、タスク自体を削除するようにする必要があります!今のところスタイリングは優先事項ではありませんが、buttonタグにはデフォルトのスタイルが適用されているはずです。
  2. その時点でのtodoの数を表示する、新しいクラスコンポーネントCountを実装してください。それをClassInputコンポーネントのどこかにレンダーしてください。
  3. 各タスクに編集ボタンを実装してください。これは、todoを入力フィールドに置き換え、ボタン自体を「Resubmit」に変更して、編集内容を保存できるようにする必要があります。これは比較的難しいタスクですが、完成させたらお見事です!
