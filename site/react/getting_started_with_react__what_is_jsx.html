What Is JSX?

イントロダクション

これまでのReactのレッスンから、あなたはおそらくJSXにある程度馴染みがあるでしょう。このレッスンでは、JSXが何であるか、なぜそれを使うのか、そしてReactアプリの中でどうやって使うのかを説明していきます。

JSXとは何ですか?

JSXはJavaScriptの構文拡張であり、JavaScriptファイルの中にHTMLのようなマークアップを書けるようにしてくれます。Reactコンポーネントを書く際にJSXを使うことは必須ではありませんが、JSXを使うとコンポーネントをより簡潔に書けるようになります。

本質的に、JSXはReactのcreateElement関数のためのシンタックスシュガー(糖衣構文)です。この関数はReactの要素、つまり単なるオブジェクトを作成するため、JSXは単純なJavaScriptのオブジェクトへとコンパイルされます。

なぜJSXを使うのですか?

多くの場合、アプリにおいてレンダリングのロジックとマークアップは本質的に結合していますが、通常はロジックとマークアップを別々のファイルに分けることで、それらを分離しています。JSXは、レンダリングのロジックとコンテンツの両方を同じ場所(コンポーネント)に含めることによって、Reactが関心の分離を行えるようにしてくれます。

さらに、これはコードの中でUIを扱うための、より直感的で視覚的な方法であり、Reactがより役立つエラーメッセージや警告メッセージを表示できるようにしてくれます。

JSXのルール

もし有効なHTMLをそのままReactコンポーネントにコピーしたとしても、それは動作しません。これは、HTMLには存在しない、JSXが実装しているいくつかのルールが原因です。

  1. 単一のルート要素を返す。

    コンポーネントの中で複数の要素を返したい場合は、それらを親タグでラップすることでそれができます。これは<div>でもかまいませんし、要素にコンテナを持たせたくない場合は、次のようにReactフラグメントを使うこともできます: <>Children</>

    正しい例:

    function App() {
  // Could replace <></> with <div></div>
  return (
    <>
      <h1>Example h1</h1>
      <h2>Example h2</h2>
    </>
  );
}
 ```

間違った例:

```jsx
function App() {
  return (
    <h1>Example h1</h1>
    <h2>Example h2</h2>
  );
}

  2. すべてのタグを閉じる。

    HTMLでは、多くのタグが自己終了・自己完結するようになっています。しかし、JSXでは、これらのタグを明示的に閉じたり、包んだりする必要があります。

    <input>は<input />になり、<li>は<li></li>になります。

    正しい例:

    function App() {
  return (
    <>
      <input />
      <li></li>
    </>
  );
 }

    間違った例:

    function App() {
  return (
    <>
      <input>
      <li>
    </>
  );
}

  3. ほとんどのものをcamelCaseにする。

    JSXはJavaScriptに変換され、要素の属性はJavaScriptオブジェクトのキーになります。そのため、ダッシュやclassのような予約語は使えません。このため、多くのHTML属性はcamelCaseで書かれます。stroke-widthの代わりにstrokeWidthを使い、classの代わりにclassNameを使います。

    正しい例:

    function App() {
  return (
  <div className="container">
    <svg>
      <circle cx="25" cy="75" r="20" stroke="green" strokeWidth="2" />
    </svg>
  </div>
  );
}

    間違った例:

    function App() {
  return (
    <div class="container">
      <svg>
        <circle cx="25" cy="75" r="20" stroke="green" stroke-width="2" />
      </svg>
    </div>
  );
}

HTMLをJSXに変換する

JSXのルールを確認したので、次はHTMLの塊をJSXに変換する作業を見ていきましょう。

<h1>Test title</h1>
<svg>
  <circle cx="25" cy="75" r="20" stroke="green" stroke-width="2" />
</svg>
<form>
  <input type="text">
</form>

これをReactコンポーネントから返そうとすると、多くのエラーが発生してしまうので、それを直していきましょう!

この例は、必ずローカル環境で実際に試しながら進めてください。あるいは、react.newにアクセスすれば、ウェブブラウザ上ですぐにReact環境を立ち上げて使うこともできます。

最初に発生する問題は、これが単一のルート要素を返していないということなので、コンテナを与えましょう。

<div>
  <h1>Test title</h1>
  <svg>
    <circle cx="25" cy="75" r="20" stroke="green" stroke-width="2" />
  </svg>
  <form>
    <input type="text">
  </form>
</div>

最初の問題を直したことで、別のエラーが表示されるはずです。これは、先ほどの変更によって新しいエラーが生まれたということではなく、単にReactがまだこのエラーを表示していなかっただけです。

さて、2つ目の問題に進みましょう。それは、<input>タグを閉じていない、というものです。

<div>
  <h1>Test title</h1>
  <svg>
    <circle cx="25" cy="75" r="20" stroke="green" stroke-width="2" />
  </svg>
  <form>
    <input type="text" />
  </form>
</div>

実際に手を動かしながら進めているなら、この時点で画面上にエラーが表示されなくなるはずです。今回はコンソールに表示されるようになります。

最後の問題は、属性をcamelCaseにしていないため、JSXにとって無効なDOMプロパティ、具体的にはstroke-widthを使ってしまっている、というものです。

<div>
  <h1>Test title</h1>
  <svg>
    <circle cx="25" cy="75" r="20" stroke="green" strokeWidth="2" />
  </svg>
  <form>
    <input type="text" />
  </form>
</div>

Reactが示してくれたエラーに対するすべての修正を適用したので、これで、Reactコンポーネントの中で何の問題もなく使える、完全なJSXコードになりました。
