Passing Data Between Components

イントロダクション

ここまでで、Reactと再利用可能なコンポーネントがどれほど強力なものであるか、理解し始めているはずです。しかし、「コンポーネント間で情報を共有するにはどうすればいいのだろう?」「コンポーネントを使うたびにその振る舞いをカスタマイズできるのだろうか?」と疑問に思っているかもしれません。このレッスンでは、Reactのprops(propertiesの略)と、propsを使ってコンポーネント間でデータを受け渡す方法について学びます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • コンポーネント間でデータを受け渡す。
  • データを使って、カスタマイズ可能な再利用可能なコンポーネントを作る。

Reactにおけるデータの受け渡し

Reactでは、データは親コンポーネントから子コンポーネントへ、propsを介して受け渡されます。このデータの受け渡しは単方向であり、つまり一方向にしか流れません。このデータに加えられた変更は、そのデータを使っている子コンポーネントにのみ影響し、親コンポーネントや兄弟コンポーネントには影響しません。このようにデータの流れを制限することで、データをより明示的に制御できるようになり、結果としてアプリケーションのエラーが減ります。

Reactでpropsを使う

データがコンポーネント間でどのように転送されるかがわかったので、次はこれがReactにおいてなぜ便利な機能なのかを見ていきましょう。以下のButtonコンポーネントを考えてみてください。これは、私たちのAppコンポーネントの中で複数回レンダーされます。

function Button() {
  return (
    <button>Click Me!</button>
  );
}

export default function App() {
  return (
    <div>
      <Button />
      <Button />
      <Button />
    </div>
  );
}

ここまでは順調ですよね?私たちは、好きなだけ何度でも使える美しい再利用可能なボタンを手に入れましたが、一つだけ小さな問題があります。

もし2番目のボタンの中のテキストを「Don't Click Me!」にしたかったらどうでしょうか?今のままでは、この異なるテキストを持つ2つ目のボタンコンポーネントを作らなければなりません。

function Button() {
  return (
    <button>Click Me!</button>
  );
}

function Button2() {
  return (
    <button>Don't Click Me!</button>
  );
}

export default function App() {
  return (
    <div>
      <Button />
      <Button2 />
      <Button />
    </div>
  );
}

今のところ、これは大した問題には見えないかもしれませんが、もしボタンが10個あったらどうでしょうか?それぞれが異なるテキスト、フォント、色、サイズ、その他あなたが思いつく限りのバリエーションを持っているとしたら。これらのボタンのバリエーションごとに新しいコンポーネントを作っていては、あっという間に大量のコードの重複が生まれてしまいます。

propsを使うことで、たった一つのボタンコンポーネントで、いくつものバリエーションに対応できる様子を見ていきましょう。

function Button(props) {
  const buttonStyle = {
    color: props.color,
    fontSize: props.fontSize + 'px'
  };

  return (
    <button style={buttonStyle}>{props.text}</button>
  );
}

export default function App() {
  return (
    <div>
      <Button text="Click Me!" color="blue" fontSize={12} />
      <Button text="Don't Click Me!" color="red" fontSize={12} />
      <Button text="Click Me!" color="blue" fontSize={20} />
    </div>
  );
}

ここではいくつかのことが起こっています。

  • Button関数コンポーネントは、今度はpropsを関数のパラメータとして受け取るようになりました。個々のプロパティは、コンポーネントの中でprops.propertyNameを介して参照されます。
  • Appの中でButtonコンポーネントをレンダーする際、propの値は各コンポーネントで定義されます。
  • インラインスタイルが動的に生成され、button要素に適用されます。

propsの分割代入

Reactでよく出会うことになる非常によくあるパターンが、propsの分割代入です。propsをコンポーネントのパラメータの中で展開(unpack)することで、より簡潔で読みやすいコードになります。以下の例で、propsの分割代入が実際にどのように使われるか見てみましょう。

function Button({ text, color, fontSize }) {
  const buttonStyle = {
    color: color,
    fontSize: fontSize + "px"
  };

  return <button style={buttonStyle}>{text}</button>;
}

export default function App() {
  return (
    <div>
      <Button text="Click Me!" color="blue" fontSize={12} />
      <Button text="Don't Click Me!" color="red" fontSize={12} />
      <Button text="Click Me!" color="blue" fontSize={20} />
    </div>
  );
}

propsのデフォルト値

上の例で、Appの中でButtonコンポーネントにpropsを定義する際に、いくつか繰り返しがあることに気づいたかもしれません。これらの共通の値を何度も定義するのをやめ、アプリケーションを未定義の値から守るために、propsのデフォルト値を設定するデフォルトパラメータを定義することができます。

function Button({ text = "Click Me!", color = "blue", fontSize = 12 }) {
  const buttonStyle = {
    color: color,
    fontSize: fontSize + "px"
  };

  return <button style={buttonStyle}>{text}</button>;
}

export default function App() {
  return (
    <div>
      <Button />
      <Button text="Don't Click Me!" color="red" />
      <Button fontSize={20} />
    </div>
  );
}

ご覧の通り、これで、Appの中でButtonをレンダーするときに、関数のパラメータで定義されたデフォルト値と異なる場合にのみ、propの値を渡せばよくなりました。

また、一部のコードベースではdefaultPropsの使用に出会うこともあるかもしれません。これは伝統的に、特にクラスコンポーネントにおいて、propsのデフォルト値を設定するために使われてきました。以下がその見た目です:

function Button({ text, color, fontSize }) {
  const buttonStyle = {
    color: color,
    fontSize: fontSize + "px"
  };

  return <button style={buttonStyle}>{text}</button>;
}

Button.defaultProps = {
  text: "Click Me!",
  color: "blue",
  fontSize: 12
};

export default function App() {
  return (
    <div>
      <Button />
      <Button text="Don't Click Me!" color="red" />
      <Button fontSize={20} />
    </div>
  );
}

Reactはもはや、関数コンポーネントに対して後者のアプローチを受け付けませんが、特にクラスコンポーネントや古いコードベースを扱う際には、defaultPropsを理解しておくことは依然として役立ちます。

propsとしての関数

変数をpropsとして子コンポーネントに渡すことに加えて、関数を渡すこともできます。以下の例を考えてみましょう。

function Button({ text = "Click Me!", color = "blue", fontSize = 12, handleClick }) {
  const buttonStyle = {
    color: color,
    fontSize: fontSize + "px"
  };

  return (
    <button onClick={handleClick} style={buttonStyle}>
      {text}
    </button>
  );
}

export default function App() {
  const handleButtonClick = () => {
    window.location.href = "https://www.google.com";
  };

  return (
    <div>
      <Button handleClick={handleButtonClick} />
    </div>
  );
}
  • 関数handleButtonClickは、親コンポーネントの中で定義されています。
  • この関数への参照は、ButtonコンポーネントのhandleClickpropの値として渡されます。
  • この関数はButtonの中で受け取られ、クリックイベントの際に呼び出されます。

ここでいくつか注意すべき点があります。

  • 私たちはhandleButtonClickへの参照だけを渡しています。つまり、関数をButtonに渡す際にかっこを含めていません。もしhandleClick={handleButtonClick()}のようなことをしてしまうと、ボタンがレンダーされる際に関数が呼び出されてしまいます。

  • この関数を呼び出すすべてのButtonは、同じページに遷移します。関数をリファクタリングし、Buttonの中で引数を渡すことで、この機能をカスタマイズできます。

function Button({ text = "Click Me!", color = "blue", fontSize = 12, handleClick }) {
  const buttonStyle = {
    color: color,
    fontSize: fontSize + "px"
  };

  return (
    <button onClick={handleClick} style={buttonStyle}>
      {text}
    </button>
  );
}

export default function App() {
  const handleButtonClick = (url) => {
    window.location.href = url;
  };

  return (
    <div>
      <Button handleClick={() => handleButtonClick('https://www.theodinproject.com')} />
    </div>
  );
}

関数に引数を渡す際、単にonClick={handleClick('https://www.theodinproject.com')}と書くことはできず、代わりに、その引数を使って関数を呼び出す無名関数への参照を渡さなければなりません。前の例と同じく、これはレンダー中に関数が呼び出されてしまうのを防ぐためです。
