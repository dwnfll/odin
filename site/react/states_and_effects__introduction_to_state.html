Introduction To State

イントロダクション

あなたが作るワクワクするようなアプリケーションは、ユーザーがそれを操作している間に変化していく可能性が高いでしょう。その変化は、ドロップダウンメニューを開閉するといった基本的なものから、APIからデータを取得するといった複雑なものまでさまざまです。Reactは、あなたのアプリ、より具体的にはコンポーネントのstateを操作し、それらを動的にするためのプリミティブを提供しています。このレッスンでは、Reactでstateを使う方法を学びます。

始める前に、What is State? by Academindを読んでください。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Reactにおけるstateとは何か。
  • Reactでstateを使う方法。
  • stateが変更されたとき、Reactの中で何が起こるか。

Reactにおけるstateとは何ですか?

Reactではコンポーネントを、それもたくさんのコンポーネントを書きますが、多くの場合、ユーザーやコンピューターとのやり取りの結果として、それらに見た目の変化を起こしてほしいと思うでしょう。そのためには、コンポーネントが自分自身についての何かを「記憶」しておく必要があります。ここで登場するのがstateです。stateはコンポーネントの記憶です。

コードの中でstateをどう使えるか見ていきましょう。react-examplesリポジトリにアクセスし、フォークしてクローンしてください。クローンしたら、state/ディレクトリにcdで移動し、npm installを実行してすべてをセットアップし、それからnpm run devで開発サーバーを起動してください。

開くと、クリックされたボタンに応じて背景色が変わるアプリがあることがわかるはずです。すぐにsrc/App.jsxの中のコードを見ていくので、じっくり時間をかけてコードを読んでください。

useStateフック

useStateフックは、Reactに組み込まれているフック(フックについては後で説明します)で、関数コンポーネントの中でstateを定義できるようにしてくれます。これは初期値をパラメータとして受け取り、分割代入によって以下の2つの要素を取り出せる配列を返します:

  1. 現在のstateの値
  2. stateの値を更新するための関数

useStateによるstateの定義は、一般的に以下のパターンに従います:

const [stateValue, setStateValue] = useState(initialValue);

// adapted for our use case:
const [backgroundColor, setBackgroundColor] = useState(COLORS[0]);

Reactについてあまり知識がなくても、ある程度は何が起こっているのか理解できるでしょう。backgroundColorというstateがこのフックで定義されています。そして、それぞれのボタンに対して、対応する値でsetBackgroundColor関数を呼び出すクリックイベントハンドラを設定しています。すると、まるで魔法のように、新しい色が背景に適用されます。

state変数をさらに追加するのは、useStateの呼び出しをさらに追加するのと同じくらい簡単なはずです。

これで、stateを使えるようになりました!でも、内部では一体何が起こっているのでしょうか?

Reactでstateはどのように機能するのですか?

ここで少し理論を見ていきましょう。

Reactでは、コンポーネントのstateやpropsが変化すると、Reactはあなたのコンポーネント関数を最初からもう一度実行し、新しく設定されたstateとpropsに基づいて何を表示すべきかを判断します。計算されたすべての変更は、その後DOMに適用(コミット)されます。 つまり、ある意味ではコンポーネント全体が再作成されるのですが、今回はuseStateから最新のstateの値が返されます。このプロセスは再レンダーと呼ばれます。再レンダーはReactの重要な機能であり、これによってReactは、背後にあるデータの変化に応じて、ユーザーインターフェースを効率的に更新できるのです。

Reactの調整(reconciliation)アルゴリズム

再レンダーのプロセスは、新しい仮想DOM(Document Object Model)ツリーを生成します。仮想DOMは、ReactがUIの現在の状態を把握しておくために使う、実際のDOMの軽量な表現です。それからReactは、新しい仮想DOMツリーを以前のものと比較し、実際のDOMを更新するために必要な最小限の変更を計算します。これが調整(reconciliation)アルゴリズムです。

上の例で再レンダーを説明する

setBackgroundColorが呼び出されるたびに、私たちのAppコンポーネントは再レンダーされます。本質的には、コンポーネントが再作成されるということは、onButtonClick関数や、私たちのdivとbuttonも再作成されるということです。backgroundColorのstateも再作成されるべきではないか、と疑問に思うかもしれません。実は、最新のstateを把握し、それをコンポーネントに提供する責任は、Reactが担っています。初期のstateの値は、コンポーネントの最初のレンダーでのみ使われ、それ以降のレンダーでは無視されます。

このセクションで扱ったのは、Reactの内部の一部についての簡単な概要に過ぎません。もっと詳しく学びたいと思うかもしれませんが、これはかなり深い沼であることを覚えておいてください。上で扱った内容だけで、このReactコースを進めるには十分です。

フック

フックとは、Reactの機能を使えるようにしてくれる関数です。すべてのフックは、useという接頭辞によって見分けることができます。例えば、useStateはフックです。このコースを進めていくにつれて、これらをもっと多く使うことになります。今のところは、フックには守らなければならないルールがあることを覚えておいてください:

  1. フックは関数コンポーネントのトップレベルからのみ呼び出せます。
  2. フックはループや条件分岐の中から呼び出すことはできません。
