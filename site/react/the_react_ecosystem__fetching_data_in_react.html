Fetching Data In React

イントロダクション

ここまで、インタラクティブなユーザーインターフェースを持つクライアントサイドアプリケーションを構築するために、Reactを使ってきました。しかし、インターネットからデータを取得したい場合はどうすればよいでしょうか?本格的なウェブアプリケーションを作るためには、外部のソースからデータを取得し、それを動的に表示する何らかの方法が必要です。

このレッスンでは、APIコールの基本、コンポーネントのstateの管理、そしてJavaScriptのfetch関数を使った非同期処理の扱い方から始めて、Reactでデータを取得することの詳細を探っていきます。あなたはすでに以前のプロジェクトでデータの取得を行っているので、このレッスンで扱う内容の一部はすでに馴染みがあるでしょう。復習して損はありません!

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • Reactコンポーネントの中でfetchリクエストを行う。
  • エラーを捕捉し処理する。
  • リクエストをコンポーネント階層の上位にリフトアップする。

基本的なfetchリクエスト

Reactでデータを取得することの詳細に飛び込む前に、fetch APIを使ってサーバーからデータを取得する方法を簡単に振り返っておきましょう。

const image = document.querySelector("img");
fetch("https://picsum.photos/v2/list")
  .then((response) => response.json())
  .then((response) => {
    image.src = response[0].download_url;
  })
  .catch((error) => console.error(error));

Picsum APIにリクエストを送って画像を取得し、そのURLを<img>要素のsrcに設定しています。

識別ヘッダーを含める

一部のAPIでは、クライアントが自身のトラフィックを識別する必要がある場合があります。そのような場合は、リクエストオプションの中に、User-Agentや、APIの提供元が指定する他の識別子といった、カスタムの識別ヘッダーを含めることでそれを行えます。これは、他のヘッダーを追加する場合と同じプロセスです。

const image = document.querySelector("img");
fetch("https://picsum.photos/v2/list", {
  headers: {
    "User-Agent": "the-odin-project"
  }
})
  .then((response) => response.json())
  .then((response) => {
    image.src = response[0].download_url;
  })
  .catch((error) => console.error(error));

Reactコンポーネントの中でfetchを使う

では、先ほどの例と同じように、fetchをReactコンポーネントに組み込む方法を見ていきましょう。よくあるユースケースの一つは、コンポーネントがマウントされたときにAPIからデータを取得し、そのデータを画面に表示できるようにすることです。

コンポーネントがレンダーの際にリクエストを送る必要がある場合、そのfetchをエフェクトの中にラップするのが最善であることがよくあります。

import { useEffect, useState } from "react";

const Image = () => {
  const [imageURL, setImageURL] = useState(null);

  useEffect(() => {
    fetch("https://picsum.photos/v2/list", {
      headers: {
        "User-Agent": "the-odin-project"
      }
    })
    .then((response) => response.json())
    .then((response) => setImageURL(response[0].download_url))
    .catch((error) => console.error(error));
  }, []);

  return (
    imageURL && (
      <>
        <h1>An image</h1>
        <img src={imageURL} alt={"placeholder text"} />
      </>
    )
  );
};

export default Image;

useStateによってimageURLというstateを追加でき、一方useEffectによって副作用を実行できます。この場合、その副作用とは外部APIからデータを取得することです。コンポーネントがマウントされたときに一度だけデータを取得する必要があるため、空の依存配列を渡しています。

エラーを処理する

ネットワーク越しの作業は、本質的に信頼性が低いものです。リクエストを送っているAPIがダウンしているかもしれませんし、ネットワークの接続に問題があるかもしれませんし、受け取ったレスポンスにエラーが含まれているかもしれません。うまくいかない可能性のあることはたくさんあり、あらかじめエラーに備えて計画しておかないと、あなたのウェブサイトが壊れてしまったり、ユーザーには反応がないように見えてしまったりすることがあります。

ネットワークエラーをシミュレートするには、先ほどのコードスニペットまでスクロールして戻り、fetchのURLを何かランダムなものに変更してください。ブラウザウィンドウをリフレッシュすると、ページの読み込みが完了したことも、エラーが発生したことも、ユーザーに何一つ示すことなく、真っ白な画面のままになります。

これを直すには、Imageコンポーネントが JSXを返す前に、何かを確認する必要があります。それをerrorと呼ぶことにしましょう。

if (error) return <p>A network error was encountered</p>

return (
  imageURL && (
    <>
      <h1>An image</h1>
      <img src={imageURL} alt={"placeholder text"} />
    </>
  )
);

このerrorを設定するために、コンポーネントのstateにそれを追加します。

const [imageURL, setImageURL] = useState(null);
const [error, setError] = useState(null);

そして最後に、リクエストが失敗したときにerrorに値を代入するために、レスポンスのステータスを確認する条件文を追加し、それを先ほどのconsole.errorの行があった場所に設定します。

useEffect(() => {
  fetch("https://picsum.photos/v2/list", {
    headers: {
      "User-Agent": "the-odin-project"
    }
  })
    .then((response) => {
      if (response.status >= 400) {
        throw new Error("server error");
      }
      return response.json();
    })
    .then((response) => setImageURL(response[0].download_url))
    .catch((error) => setError(error));
}, []);

レスポンスのエラーを処理する

thenブロックの中でもエラーを処理していることに気づきましたか?これは、fetchリクエスト自体は失敗せず、むしろ正常に完了してレスポンスを返すことがあるからです。しかし、受け取ったレスポンスが、私たちのアプリが期待していたものではないことがあります。このケースを処理するために、レスポンスのステータスコードを確認します。

これで、不正なURLが渡されたときや、APIが予期しないレスポンスを返したときに、ページはその情報をユーザーに伝えるようになります。

ローディングstate

エラーを確認するためにstateにerrorの値を追加したのと同じように、リクエストが解決されたかどうかを確認するためのloadingの値も追加できます。

const Image = () => {
  const [imageURL, setImageURL] = useState(null);
  const [error, setError] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch("https://picsum.photos/v2/list", {
      headers: {
        "User-Agent": "the-odin-project"
      }
    })
      .then((response) => {
        if (response.status >= 400) {
          throw new Error("server error");
        }
        return response.json();
      })
      .then((response) => setImageURL(response[0].download_url))
      .catch((error) => setError(error))
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>A network error was encountered</p>;

  return (
    <>
      <h1>An image</h1>
      <img src={imageURL} alt={"placeholder text"} />
    </>
  );
};

カスタムフックを使う

取得のロジックをまるごとカスタムフックに分離できます。これにより、そのロジックを再利用可能で、簡単にテストできるようにできます。

Introduction to stateのレッスンで、Reactのフックとは、(stateやエフェクトなどの)Reactの機能を使えるようにしてくれる単なる関数であり、useの後に大文字が続くという命名規則に従っている(例えばuseStateやuseEffect)、と説明したことを思い出してください。もしuseEffectのようなフックを、getImageURLのような私たち自身の普通のヘルパー関数の中に入れようとすると、Reactはこれを歓迎しません。というのも、Reactはフックが、コンポーネントか別のフックのトップレベルでのみ呼び出されることを望んでいるからです。そのため、フックの命名規則に従うことで、ヘルパー関数を単純にカスタムフック、useImageURLに変えることができます。

私たちの例では、このように行います:

import { useState, useEffect } from "react";

const useImageURL = () => {
  const [imageURL, setImageURL] = useState(null);
  const [error, setError] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch("https://picsum.photos/v2/list", {
      headers: {
        "User-Agent": "the-odin-project"
      }
    })
      .then((response) => {
        if (response.status >= 400) {
          throw new Error("server error");
        }
        return response.json();
      })
      .then((response) => setImageURL(response[0].download_url))
      .catch((error) => setError(error))
      .finally(() => setLoading(false));
  }, []);

  return { imageURL, error, loading };
};

const Image = () => {
  const { imageURL, error, loading } = useImageURL();

  if (loading) return <p>Loading...</p>;
  if (error) return <p>A network error was encountered</p>;

  return (
    <>
      <h1>An image</h1>
      <img src={imageURL} alt={"placeholder text"} />
    </>
  );
};

もし異なるコンポーネントで画像を取得する必要が出てきた場合、その取得のロジックをすべて書き直す代わりに、useImageURLを呼び出すことができます。

複数のfetchリクエストを管理する

人為的な遅延を使う

このセクションでは、setTimeout関数を使って人為的なdelay(遅延)を追加したコード例を使います。もうお気づきかもしれませんが、これはこのレッスンでデータ取得の基本を一つずつ確認していく助けとするためのものです。このセクションを終えたら、これらの遅延を取り除いてからコード例をいろいろ試してみて、概念をさらに定着させることをお勧めします。

本格的なウェブアプリでは、複数のリクエストを送ることがよくあり、それらをどう整理するかに注意する必要があります。新しいReact開発者が、アプリが複数のリクエストを送るようになったときに直面するよくある問題は、リクエストのウォーターフォールと呼ばれます。私たちのreact-examplesリポジトリ(まだであればフォークしてクローンしてください)の例を見てみましょう。今回はfetching-data/ディレクトリです。そこにcdで移動し、npm installを実行してから、npm run devで開発サーバーを起動してください。

fetchリクエストを行う2つのコンポーネントがあります: Profileと、その子コンポーネントであるBioです。これらのファイルの両方で、コンポーネントと、その下にコメントアウトされた別バージョンが見つかるはずです。これらについては、すぐ後で戻ってきます。ProfileとBioのリクエストは、どちらもそれぞれのコンポーネントの中で発火しています。表面的には、これはうまく整理された関心の分離のように見えますが、この場合、それはパフォーマンス上の代償を伴います。

ページを読み込むたびに、Bioの表示に余分に1秒かかっていることに気づきましたか?両方のfetchリクエストは、解決するのに1000msかかるはずなのに、何が起きているのでしょうか?Reactでは、コンポーネントは実際に呼び出されるまでレンダーされません。JSXに条件付きのロジックがある場合、falseの分岐は、それがtrueになるまで決してレンダーされません。Bioは、レンダーを始める前に、Profileの中のリクエストが解決するのを待たなければならず、つまりBioの中のリクエストは送信されていない、ということです。

もしimageURLを待つショートサーキットの条件文を取り除けば、Bioはすぐにリクエストを送るようになりますが、それはローディング画面を諦めることを意味してしまいます。デザインで妥協する代わりに、リクエストをコンポーネントツリーの上位にリフトアップし、そのレスポンスをpropとしてBioに渡すことができます。

これが実際にどう動くか見るために、ProfileとBioの両方のコンポーネントで、それらをコメントアウトし、その下にある別バージョンのコメントを外してください。

これで、Profileがレンダーされるとすぐに、両方のリクエストが発火するようになりました。imageURLのリクエストはbioTextのリクエストより2秒早く解決し、<Bio />を含む私たちのdivがレンダーされます。bioTextが解決すると、stateが更新され、それが<Bio />の再レンダーを引き起こし、そのテキストの説明がページに追加されます。

データ取得ライブラリ

フロントエンドにおけるデータ取得の表面をなぞり始めたばかりです。フロントエンドのデータをサーバーと同期させ続けることは、達成するのが難しいタスクです。「非同期」stateの管理は、機能が追加されるたびにますます複雑になっていきます。

あなたはすでに、このレッスンでデータ取得の複雑さを味わっています。最適なユーザー体験を実現するには、各リクエストは最低でもdata、loading、errorという3つのstateを持つ必要があります。データ取得などを助けてくれるライブラリもありますが、このコースのすべてのプロジェクトでは、素のReactによるデータ取得を使うことを強くお勧めします。そうすることで学べる教訓は、非常に貴重なものになるでしょう。
