stateの構造化の仕方

stateを効果的に管理し構造化することは、間違いなく、アプリケーションを構築する上で最も重要な部分の一つです。正しく行わないと、バグや頭痛の種になってしまうことがあります。

課題の項目でこのトピックを詳しく扱いますが、一般的な経験則として、既存の値、state、propsを使って計算できる値は、stateに入れないようにしましょう。

stateをミューテートしてはいけない

stateをミューテート(mutate、直接変更)することは、予測不可能な結果につながるため、Reactでは踏み込んではいけない領域です。プリミティブはすでにイミュータブル(不変)ですが、もし参照型の値、つまり配列やオブジェクトを使っている場合は、決してそれらをミューテートしないでください。Reactのドキュメントによると、stateはあたかもイミュータブルであるかのように扱うべきです。stateを変更するには、常にsetState関数を使うべきであり、以下の例の場合、それはsetPerson関数です。

function Person() {
  const [person, setPerson] = useState({ name: "John", age: 100 });

  // BAD - Don't do this!
  const handleIncreaseAge = () => {
    // mutating the current state object
    person.age = person.age + 1;
    setPerson(person);
  };

  // GOOD - Do this!
  const handleIncreaseAge = () => {
    // copy the existing person object into a new object
    // while updating the age property
    const newPerson = { ...person, age: person.age + 1 };
    setPerson(newPerson);
  };

  return (
    <>
      <h1>{person.name}</h1>
      <h2>{person.age}</h2>
      <button onClick={handleIncreaseAge}>Increase age</button>
    </>
  );
}

stateの中のオブジェクトと配列

上の例で、私たちが新しいオブジェクトを作成し、それから既存のstateの値をその新しいオブジェクトにコピーしながら、ageには新しい値を渡している点に注目してください。 これは、setStateに新しいオブジェクトを渡さないと、ページが再レンダーされる保証がないためです。そのため、再レンダーを発生させるためには、常にsetStateに新しいオブジェクトを渡すべきです。setStateは、以前のstateと同じかどうかを判断するためにObject.is()を使います。

ネストしたオブジェクトや配列については、ネストした項目もコピーする必要が出てくるため、stateがすぐにやっかいになることがあります。それらを使う際は注意してください。

stateはどのように更新されるか

stateの更新は非同期です。これが意味するのは、setState関数を呼び出すたびに、Reactはその更新を次のコンポーネントのレンダーで適用する、ということです。この概念を理解するには少し時間がかかるかもしれません。たくさん練習すれば、あっという間にコツをつかめるでしょう。

覚えておいてほしいのは、state変数自体がリアクティブなのではなく、コンポーネントがリアクティブだ、ということです。これは、setStateを呼び出すと、その場でstate変数を変更するのではなく、コンポーネント全体が再レンダーされるという事実から理解できます。

function Person() {
  const [person, setPerson] = useState({ name: "John", age: 100 });

  const handleIncreaseAge = () => {
    console.log("in handleIncreaseAge (before setPerson call): ", person);
    setPerson({ ...person, age: person.age + 1 });
    // we've called setPerson, surely person has updated?
    console.log("in handleIncreaseAge (after setPerson call): ", person);
  };

  // this console.log runs every time the component renders
  // what do you think this will print?
  console.log("during render: ", person);

  return (
    <>
      <h1>{person.name}</h1>
      <h2>{person.age}</h2>
      <button onClick={handleIncreaseAge}>Increase age</button>
    </>
  );
}

personのstateは、コンポーネントの現在のレンダーの間、ずっと同じままです。これが「スナップショットとしてのstate」が指しているものです。setStateの呼び出しはコンポーネントの再レンダーを引き起こし、personのstateは新しい値に更新されます。

予期せぬ無限ループ

以下のコードは無限ループを引き起こしますが、Reactは特定の状況下で無限に再レンダーが発生していることを検知し、エラーをスローできます。ここでReactがなぜエラーをスローし、再レンダーが多すぎることを警告するのか、見当がつきますか?TOPのDiscordサーバーに立ち寄って、その理由を教えてください。ポイント獲得のチャンスです!

function Component() {
  const [count, setCount] = useState(0);

  setCount(count + 1);

  return <h1>{count}</h1>;
}

stateの更新関数

ちょっとしたひっかけ問題です。handleIncreaseAgeの別の実装を見てみましょう。これが何をするか、わかりますか?

const handleIncreaseAge = () => {
  setPerson({ ...person, age: person.age + 1 });
  setPerson({ ...person, age: person.age + 1 });
};

きっと、ageを2増やすのだろう、と思いますよね?いいえ、違います。上のコードは、Reactに対してこう言っています:

ねえ、現在のレンダーのpersonを、ageを1増やしたものに置き換えて。それから、現在のレンダーのpersonを、ageを1増やしたものに置き換えて。

「置き換える」という言葉に注目してください。setState関数に値を渡すと、Reactは現在のstateを、渡された値で置き換えます。では、最新のstateを使って複数回stateを更新したい場合はどうすればいいのか、と疑問に思うかもしれません。ここで登場するのが、stateの更新関数です。

const handleIncreaseAge = () => {
  setPerson((prevPerson) => ({ ...prevPerson, age: prevPerson.age + 1 }));
  setPerson((prevPerson) => ({ ...prevPerson, age: prevPerson.age + 1 }));
};

setState関数にコールバックが渡されると、最新のstateがそのコールバックの引数として渡されることが保証されます。

更新関数を使うことが常に必要というわけではありません。以前のstateを使ってstateを変更したく、冗長さよりも一貫性を優先したい場合には、更新関数の使用を検討するとよいでしょう。

Reactはstateの更新をバッチ処理する

上の例には2回のsetPersonの呼び出しがあり、これまで学んできたことからすると、setStateの呼び出しはコンポーネントの再レンダーを引き起こします。ということは、コンポーネントは2回再レンダーされるはずですよね?そう思うかもしれませんが、Reactは賢いのです。可能な限り、Reactはstateの更新をバッチ処理します。ここでは、コンポーネントは1回しか再レンダーされません。これを確認するために、console.logを使ってみることをお勧めします。

制御されたコンポーネント

独自の内部stateを保持するネイティブHTML要素があります。input要素はその良い例です。inputに入力すると、キー入力のたびに自身の値が更新されます。多くのユースケースでは、input要素の値を制御したい、つまり自分でその値を設定したいと思うでしょう。ここで登場するのが、制御されたコンポーネントです。

function CustomInput() {
  const [value, setValue] = useState("");

  return (
    <input
      type="text"
      value={value}
      onChange={(event) => setValue(event.target.value)}
    />
  );
}

inputに独自のstateを保持させる代わりに、useStateフックを使って自分自身のstateを定義します。それから、inputのvaluepropをこのstate変数に設定し、onChangeイベントのたびにstate変数を更新します。これにより、ユーザーがinputに何かを入力するたびに、Reactは最新のコメント、レビュー、投稿(ユーザーが入力していたもの)がvalueに反映されていることを保証してくれます。

このパターンは、ライブバリデーションのように、ユーザー入力をより細かく制御する必要がある場合や、これらのinputから最新のstateの値にアクセスする必要があるその他の場合に、非常に役立ちます。逆に言えば、input要素を非制御のままにしておき、他の方法でその値にアクセスすることもできます。これについては今のところ心配する必要はありません。コースの後半で扱います。今のところは、あなたのコンポーネントを制御しましょう!
