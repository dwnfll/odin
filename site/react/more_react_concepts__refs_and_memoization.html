Refs And Memoization

イントロダクション

素のJavaScriptで普段行っているようなDOM操作は、どうすれば行えるのでしょうか?Reactは宣言的な性質を持っているため、そもそも可能なのでしょうか?パフォーマンスの最適化についてはどうでしょうか?ご存知の通り、stateが変更されると、Reactはコンポーネントを再レンダーしようとします。つまり、Reactによって制御されていないローカル変数はすべて破棄され、再実行されるということです。この考え方は、あなたが作成する通常の関数にも当てはまります。というのも、コンポーネントは単なる関数だからです。そうであるならば、もし非常にコストの高い計算が、再レンダーのたびに再実行されてしまったら、アプリが遅くなってしまうのではないでしょうか?

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • useRefフックとそのユースケース。
  • メモ化と、useCallbackとuseMemoの使い方。
  • React Compilerによる自動メモ化。

useRefフック

useRefフックを使うと、レンダリングには必要ない値を管理できます。これはstateの代替であり、コンポーネントに何らかの情報を「記憶」させたいものの、その情報が新しいレンダーを引き起こしてほしくない場合に、このフックを使うことができます。

これらは、命令的な処理を行ったり、DOMにレンダーされている特定の要素にアクセスしたりする際によく使われます。refは、コンポーネントのライフサイクル全体を通して値を永続させることもできます。つまり、コンポーネントが再レンダーされるたびにrefの値が破棄されることはない、ということです。これは、stateに保存することなく、コンポーネントのライフサイクル全体を通して永続させたい値を保存したい場合に、非常に便利です。

DOM操作

ウェブアプリケーションを構築していると、時にはDOM内の特定の要素をより直接的に制御する必要が出てきます。useRefフックは、それらの要素にアクセスし、やり取りする方法を提供することで、私たちを助けてくれます。

ウェブページにボタンがあり、ページが読み込まれたときにそのボタンにフォーカスを当てたいとします。これはuseRefフックを使うことで実現できます。以下がその仕組みです:

import { useRef, useEffect } from "react";

function ButtonComponent() {
  const buttonRef = useRef(null);

  useEffect(() => {
    buttonRef.current.focus();
  }, []);

  return <button ref={buttonRef}>Click Me!</button>;
}

実装はシンプルです:

  1. reactモジュールからuseRefとuseEffectをインポートしました。
  2. nullという引数でuseRefを呼び出します。これにより、currentと呼ばれるプロパティを持つオブジェクトが返され、その初期値は渡された引数(この場合はnull)に設定されます。この引数は、useStateに渡す引数と同じように、それ以降のレンダーでは無視されます。
  3. コンポーネントのマウント時に一度だけ実行されるuseEffectを作成し、これがボタン要素のfocusメソッドを呼び出そうとします。
  4. buttonRefをボタン要素のref属性に付与しました。これにより、buttonRefとDOM内のボタンとの間に接続が確立されます。

あなたのウェブサイトが読み込まれるたびに、自動的にボタン要素にフォーカスが当たります。初期値がnullなのに、どうやってfocusメソッドを持てるのか、と疑問に思うかもしれません。あなたはすでに、ReactがuseEffectを実行するよりも先に、レンダリングと画面の描画が行われることを知っているはずです。エフェクトが実行される前に、refとボタンとの間の接続はすでに確立されているのです。

また、useRefフックは要素にフォーカスを当てることだけに限定されているわけではないことを覚えておいてください。特定の位置までスクロールする、要素の寸法を測定する、アニメーションを発生させるなど、他のさまざまなDOM操作のシナリオに使うことができ、基本的には、以前素のJavaScriptで行っていたあらゆるDOM操作に使えます。可能性は無限大です!例えば、上のスニペットのuseEffectを変更して、以下のようなことができます。ボタンのテキストを変更し、2秒後にテキストを元に戻す、というものです。これは行うべきではなく、useRefは破壊的でないDOM操作にのみ使うべきですが、あくまで一つの例です:

useEffect(() => {
  buttonRef.current.focus();
  buttonRef.current.textContent = "Hey, I'm different!";
  let timeout = setTimeout(() => {
    buttonRef.current.textContent = "Click Me!";
  }, 2000);

  return () => {
    clearTimeout(timeout);
  };
}, []);

これの興味深い点は、これが決してコンポーネントの再レンダーを引き起こさない、ということです!

頭に浮かぶかもしれないもう一つの疑問は、「以前素のJavaScriptで行っていたように、querySelectorや他のDOM操作メソッドをただ使えばいいのではないか?」というものです。自分自身でDOMを扱うことは、Reactを使う目的を損なってしまいます。可能な限り、DOMそのものへのコミットはReactに任せるべきです。

また、いくつかの値を保存できるという点で、これはuseStateフックに似ていることもわかります。主な違いは、useRefはミュータブルな参照を作成し、再レンダーを引き起こすことなくその値を更新できるという点です。一方useStateは、更新されると再レンダーを引き起こす、イミュータブルなstateを管理します。

useMemoフック

すべての例において、reactモジュールに用意されているProfilerコンポーネントを使うことをお勧めします。よりインタラクティブな代替手段が欲しい場合は、React Developer ToolsのProfilerを使って、レンダリングのパフォーマンスを測定してください。すでに十分速いために、何も最適化する必要がない場合もあることに注意してください。ソフトウェア開発における有名な格言にもある通りです:

Premature optimization is the root of all evil -- The Art of Computer Programming by Donald Knuth

useMemoフックは、コンポーネントの中にメモ化を追加する方法を提供してくれます。これは、コストの高い、あるいは複雑な計算を最適化するために使われ、関数呼び出しの結果をキャッシュしておき、再計算することなく後で使えるように保存しておきます。しかし、メモ化された値が再計算されるのは、useMemoフックの依存関係が変化したときだけです。そして、このフックのパラメータは、あなたがすでに知っているuseEffectフックと同じです。このフックは、calculateValueコールバックとdependencies配列という2つの引数を受け取ります。

コストの高い計算をメモ化する

前回のShopping Cartプロジェクトでは、カートに追加された商品の合計金額を計算するロジックがありました。あなたには、ユーザーがAdd to Cartボタンやヘッダーのカートアイコンをクリックするたびにカートを開けるようにする、ドロワーとして機能するCartコンポーネントがあるかもしれませんし、ないかもしれません。

Cartコンポーネントの例:

function Cart({ products }) {
  const totalPrice = products.reduce(
    (total, product) => total + product.price * product.quantity,
    0
  );

  return (
    <div>
      {/* Some other content in the cart */}
      {/* Products to display */}
      <p>
        Total Price: <strong>${totalPrice}</strong>
      </p>
      {/* Some button to checkout */}
    </div>
  );
}

私たちのCartコンポーネントでは、商品の合計金額がコンポーネントの中で直接計算されています。コンポーネントがレンダーされたり更新されたりするたびに、この計算はゼロからやり直されます!それはあまり良さそうには聞こえません……もしユーザーがカートに数十万個の商品を追加していたらどうでしょうか?その場合、動作の重いユーザー体験につながってしまいます。

reduceメソッドは各商品を反復処理し、カート内のすべてのアイテムについて乗算と加算を行います。この処理は、商品の数が増えるにつれて、ますます時間がかかるようになります。

では、頻繁にカートを開いたり閉じたりするユーザーを想像してみてください。ドロワーが開かれるたびにCartコンポーネントがレンダーされ、コンポーネントの中のすべてが実行されます。これにより、カートの内容が変わっていなくても、同じ値の不要な再計算が発生してしまいます。

これに対処するために、useMemoをどう使えるか見てみましょう:

import { useMemo } from "react";

function Cart({ products }) {
  const totalPrice = useMemo(() => {
    return products.reduce(
      (total, product) => total + product.price * product.quantity,
      0
    );
  }, [products]);

  return (
    <div>
      {/* Some other content in the cart */}
      {/* Products to display */}
      <p>
        Total Price: <strong>${totalPrice}</strong>
      </p>
      {/* Some button to checkout */}
    </div>
  );
}

上の例では、useMemoで計算された値をラップすることで、簡単にその値をメモ化できます。構文はuseEffectとほぼ同じで、動作もほぼ同じだからです。useMemoは、マウント時にコールバックを実行します。それ以降の再レンダーでは、依存関係が変化した場合にのみコールバックを再実行し、そうでなければ、最後に実行されたときのキャッシュされた値を返します。私たちの場合は、productspropが変化するたびに、です。

こうすることで、ユーザーが何度もカートを開いたり閉じたりしても、productsが変化していない限りtotalPriceは再計算されず、キャッシュされた値が使われます。

参照の等価性チェック

この例では、コンポーネントのパフォーマンスを測定するために、reactモジュールのProfilerコンポーネントを使います。また、memoも紹介します。

すでにこちらで用意してあるので、これのためにReactアプリケーションを起動する必要はありません。少し後で、インタラクティブな例を共有しますが、今のところは、何が起こると思うか、何が起こり得るかなどについて、コードを見ながら考えてみてください。これは、コードを読み、それがどう動くかをイメージする、素晴らしい練習にもなるでしょう。

これは非常に基本的な例にすぎないことに注意してください。他のコンポーネントにpropsとして値を渡すこと、そしてレンダーに非常に負荷のかかるコンポーネントには、これから数多く出会うことになるでしょう。

import { useState } from "react";

const ButtonComponent = ({ children, onClick }) => {
  let i = 0;
  let j = 0;
  const ITERATION_COUNT = 10_000;
  while (i < ITERATION_COUNT) {
    while (j < ITERATION_COUNT) {
      j += 1;
    }
    i += 1;
    j = 0;
  }

  return (
    <button type="button" onClick={onClick}>
      {children}
    </button>
  );
};

function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount((prevState) => prevState + 1);
  };

  return (
    <div>
      <h1>{count}</h1>
      <ButtonComponent onClick={handleClick}>Click me!</ButtonComponent>
    </div>
  );
}

スタイリングなどをそこで扱える、独立したボタンコンポーネントが欲しくなるでしょう。そこで、例としてButtonComponentというコンポーネントを作成しました。このコンポーネントはchildrenとonClickpropsを受け取ります。

クリックハンドラはCounterコンポーネントの中で定義されており、それをButtonComponentのonClickpropに渡していることがわかります。

私たちは、コンポーネントがstateまたはpropのどちらかが変化するたびにレンダーされることを知っています。その中にある、Reactによって制御されていないものはすべて破棄され、再実行されます。関数、変数などです。その結果、handleClick関数は毎回再作成され、ButtonComponentのonClickpropも変化します。さて、ここでuseMemoはどう役立つのでしょうか?

私たちはすでに、useMemoを使って値をメモ化できることを知っていますよね?それなら、関数の参照をキャッシュし、それが変化しないように空の依存配列を使えばよいのです。

新しい関数を作成し、memoizedHandleClickという名前を付けましょう:

const memoizedHandleClick = useMemo(() => handleClick, []);

新しい関数を作成する必要はありませんが、これはこの2つの関数を試すためだけのものです。以下のように直接行うこともできます:

// Syntax might be weird, but just remember that `useMemo` can take any value, and a function is also just a value `() => setCount((prevState) => prevState + 1)`

const handleClick = useMemo(
  // first arrow function is useMemo's callback
  // second arrow function is our function that will be called later, this one is going to be the cached value and what's going to be stored in `handleClick`
  () => () => setCount((prevState) => prevState + 1),
  []
);

素晴らしい、これでuseMemoが役立ってくれるはずですよね?もうButtonComponentが再レンダーされることはないはずですよね?いいえ、それでも再レンダーされてしまいます。なぜなら、コンポーネントのstateが変化するたびに、その子コンポーネントも再レンダーされるからです。これは別の言い方をすれば、親が再レンダーされれば、コンポーネント自身も再レンダーされる、ということです。これを解決する方法はあるのでしょうか?はい、あります!ReactはそのAPIの一つとして、memoラッパー関数を提供しています。これにより、コンポーネントのpropsが変化していない場合に、(そう、たとえ親が再レンダーされたとしても)そのコンポーネントの再レンダーをスキップできます。このmemoを使って、ButtonComponentをラップできます。

import { useState, memo } from "react";

const ButtonComponent = memo(({ children, onClick }) => {
  let i = 0;
  let j = 0;
  const ITERATION_COUNT = 10_000;
  while (i < ITERATION_COUNT) {
    while (j < ITERATION_COUNT) {
      j += 1;
    }
    i += 1;
    j = 0;
  }

  return (
    <button type="button" onClick={onClick}>
      {children}
    </button>
  );
});

コンポーネントをmemoでラップすることで、そのコンポーネントより上位で引き起こされる下方向への更新が防がれます。そのため、このコンポーネントは、propsが変化したとき、または自身のstateが変化したときにのみ再レンダーされるようになります。

それはさておき、私たちのreact-examplesリポジトリにアクセスし(まだであればフォークしてクローンしてください)、memoization/ディレクトリにcdで移動して、npm installを実行してからnpm run devを実行してください。時間をかけてコードをいろいろ試してみてください。実験してみましょう!いろいろ試して、壊してみましょう!

起こり得るいくつかのシナリオを紹介します:

  1. handleClickを渡していて、ButtonComponentがmemoを持っている場合。それでも再レンダーされます。参照の等価性チェックが失敗するからです(以前のpropと現在のpropが等しくない)。
  2. memoizedHandleClickを渡していて、ButtonComponentがmemoを持っている場合。再レンダーされません。参照の等価性チェックが通過するからです(以前のpropと現在のpropが等しい)。

これは、propとして渡されるすべての値に当てはまります。Context APIと組み合わせて頻繁に使われているのを見かけるかもしれません:

const value = useMemo(
  () => ({ someState, someFunction }),
  [someState, someFunction]
);

return <Context value={value}>{children}</Context>;

useCallbackフック

useCallbackフックは、値をメモ化するもう一つの方法を提供してくれますが、useMemoのようにどんな値でもというわけではありません。関数だけをメモ化できます。useMemoで関数の参照をメモ化していた、先ほどのスニペットを見ましたか?

const handleClick = useMemo(
  () => () => setCount((prevState) => prevState + 1),
  []
);
// or
const memoizedHandleClick = useMemo(() => handleClick, []);

useCallbackを使えば、そうする必要はありません。これは関数専用に作られています:

import { useCallback } from "react";

// Inside a component
// Without useCallback
const handleClick = () => setCount((prevState) => prevState + 1);
// With useCallback
const handleClick = useCallback(
  () => setCount((prevState) => prevState + 1),
  []
);
// or
const memoizedHandleClick = useCallback(handleClick, []);

やった、アロー関数が一つだけになり、読みやすくなりました。useCallbackには、関数だけをメモ化するということ以外に、特別なことは何もありません。つまり、useMemoとuseCallbackの主な違いは、それが返す値の型だけです。

では、どちらを使うべきなのでしょうか?あらゆる型の値にはuseMemoを使い、関数には特にuseCallbackを使ってください。結局のところ、両者は小さな違いはあるものの似たようなことをしているので、好きな方を使ってください。

React Compiler

今では、React Compilerというものもあります。これは比較的新しいビルド時ツールで、私たちのReactアプリを自動的に最適化してくれます。私たちのコードを分析し、適切なコンポーネントとフックをメモ化してくれます。主に、更新のパフォーマンス(既存コンポーネントの再レンダー)を改善することに焦点を当てています。つまり、ほとんどの場合、コンポーネントやフックを手動でメモ化する必要はない、ということです。

では、React Compilerが私たちのフックやコンポーネントを自動的にメモ化してくれるなら、React.memoや、useMemo、useCallbackのようなフックについて知る必要はあるのでしょうか?簡単に言えば、答えはイエスです。手動でのメモ化を理解することは、React Compilerが内部で何をしているかを理解する助けになりますし、既存のコードベースで手動のメモ化のテクニックにほぼ間違いなく出会うことになる、ということも言うまでもありません。最後に、useEffectの依存関係が不必要に変化してエフェクトが発火してしまわないように、それが確実にメモ化されるようにする場合など、React Compilerが自動的に行うことよりも、何がどのようにメモ化されるかについて、より細かく制御する必要があるケースもあるかもしれません。

まとめ

ふう、長いレッスンでしたね。refとメモ化は理解するのが難しい概念ですが、練習を重ねればきっと理解できるはずです。特にrefは、いくつかのユースケースにおいて本当に便利です。自動メモ化については、追加のコードを書くことなく、アプリの最適化を助けてくれます。手動でのメモ化も、特定のケースでは必要になるかもしれませんが、それは本当に必要なときにだけ使うべきです。これらのトピックは、面接の質問としても優れているので、useMemoとuseCallbackの違いを必ず理解しておいてください!

課題

  1. Kent C. Dodds氏による記事、When to useMemo and useCallbackは、useMemoとuseCallbackをいつ使うべきか、そしていつわざわざ使う必要がないかについて、さらに多くの例を紹介しています。
  2. 私たちは、useRefフックの基本的な実装についてしか学んでいません。その使い方や、なぜこのフックの使用に注意すべきか(ガイドの中で提供されているリンクにさらに詳しく書かれています)についてのさらなる例については、ReactドキュメントのuseRef hookのインタラクティブなガイドをチェックしてみてください。
  3. DOMノードに安全にアクセスし変更する方法についてさらに深く掘り下げるために、Manipulating the DOM with RefsについてのReactドキュメントをチェックしてみてください。
  4. 学んできた通り、useRefフックには、私たちが主に扱ったDOM操作以外にも、他の使い道があります。Dan Abramov氏によるこの素晴らしい記事、Making setInterval Declarative with React Hooksで、そのユースケースについてさらに詳しく知ってください。
  5. React Compilerのドキュメントに目を通して、それについてもう少し詳しく学び、プロジェクトへのインストール方法や設定方法を確認してください。
