Command Line Basics

日本語訳

← foundations

The command line: loved, hated, and feared... but no longer by you.

イントロダクション

コマンドラインが怖いと感じていますか?あなただけではありません。開発者といえば、黒い画面をじっと見つめ、白や緑の文字が点滅する中、企業のメインフレームをハッキングするために意味不明なコマンドを猛烈に打ち込んでいる(その間もソーダをがぶ飲みし、キーボードについたネオンオレンジ色のチートスの粉を拭いているに違いない)というイメージがありますよね。

プロンプトと点滅するカーソルが表示されたあの何もない画面やウィンドウが、コマンドラインインターフェース(CLI)です。ここでは、コンピューターに実行してほしいコマンドを入力できます。上で描写したようなシーンを再現する必要はありませんが、コマンドラインを扱うことは、開発者として学ぶべき重要なスキルです。コマンドラインは私たちの作戦基地のようなもので、そこから他のプログラムを起動し、やり取りできます。学ぶべき独自の構文がありますが、同じコマンドを何十回も入力することになるため、最もよく使うコマンドはすぐに身につくでしょう。

このコマンドラインの入門レッスンでは、コマンドラインを快適に使いながら、コンピューター内を移動し、ファイルやディレクトリ(フォルダとも呼ばれます)を操作する方法を学びます。思っているほど難しくないことがすぐに分かるでしょう。このレッスンで学ぶコマンドは非常に単純明快なので、初めてコマンドラインを使うことに気後れする必要はありません。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • コマンドラインとは何かを説明する。
  • コンピューターでコマンドラインを開く。
  • コマンドラインを使ってディレクトリを移動し、ディレクトリの内容を表示する。
  • コマンドラインを使って新しいディレクトリと新しいファイルを作成する。
  • コマンドラインを使ってディレクトリやファイルの名前を変更したり削除したりする。
  • コマンドラインを使ってプログラムでファイルやフォルダを開く。

ターミナルを試してみる

コンピューターでターミナルを開いてみましょう。

  • Linux: プログラムメニューを開いて「Terminal」を検索してください。キーボードでCtrl + Alt + Tを押してターミナルを開くこともできます。

  • macOS: 「アプリケーション」>「ユーティリティ」フォルダを開いて「ターミナル」を探してください。Spotlight検索を使ってターミナルを開くこともできます。Cmd + Spaceを押してSpotlightを開き、「ターミナル」を検索してください。Enterを押して開きます。

開いたウィンドウはほとんど何もない状態で、オペレーティングシステムによって異なる多少のテキストがあるだけです。Linuxや古いMacでは行の末尾が$になり、新しいMacでは%になります。この記号は「プロンプト」と呼ばれ、ターミナルがあなたのコマンド入力を待っていることを示します。実際に試してみましょう。whoamiと入力してEnterを押してください。

あなたのユーザー名が返されます。クールですね!

ターミナルの使い方についてのガイドや説明では、$ whoamiのように、記号を先頭に付けてコマンドを示すことがよくあります。これは、そのコマンドをターミナルに入力すべきだということを示していますが、$自体は入力しないでください。また、新しいMacを使っている場合、%は$と同じものであることを覚えておいてください。

なぜ今これを学ぶのか?

このカリキュラムを通じて、あなたはコマンドラインを盛んに使うことになります。この後のインストールプロジェクトでは、コマンドラインを使ってさまざまなソフトウェアプログラムをインストールする必要があります。さらに、Gitも主にコマンドライン内で使うことになります(詳しくは後述します)。より大きな視点で見れば、ソフトウェア開発者としてのキャリアの中で日常的にコマンドラインを使うことになる可能性が高く、それはあなたのツールセットに欠かせないスキルとなります。

ターミナルでパスワードを入力する

ターミナルで(sudoのような)認証のためにパスワードの入力が必要なコマンドを使うとき、入力している文字が表示されないことに気づくでしょう。ターミナルが反応していないように見えるかもしれませんが、心配いりません!

これは、ウェブサイトのパスワード入力欄がアスタリスクやドットを使うのと同じように、機密情報を保護するためのセキュリティ機能です。入力した文字を表示しないことで、ターミナルはあなたのパスワードを安全に保っています。

パスワードは通常通り入力でき、Enterキーを押せば送信できます。

プロのようにコマンドラインを使う

プログラマーについて知っておくべき重要なことがあります。プログラマーは怠け者です。それも、本当に怠け者なのです。何かを何度も繰り返し行わなければならないとき、代わりにそれを自動化する方法を見つけ出す可能性が高いのです。良いニュースは、彼らがこれまでに作り出してきた数々のショートカットを、あなたも活用できるということです。それでは、プロのようにコマンドラインを使う方法(つまり、本当に怠惰なやり方)を学んでいきましょう。

まず、コマンドライン内でのコピー&ペーストが思っていたようには動作しないことに、すでに気づいているかもしれません。コマンドライン内では、コピーにはCtrl + Shift + C(Mac: Cmd + C)を、ペーストにはCtrl + Shift + V(Mac: Cmd + V)を使います。例えば、ブラウザからコマンドラインにコマンドをコピー&ペーストするには、コマンドのテキストを選択していつも通りCtrl + Cを使い、それからCtrl + Shift + Vを使ってターミナルにペーストします。試してみましょう!

次に、タブ補完について学ぶ必要があります。本当に、このコツはあなたの時間ともどかしさを大きく節約してくれます。コマンドラインの中にいて、~/Documents/Odin-Project/foundations/javascript/calculator/のような、遠く離れたフォルダに移動する必要があるとしましょう。これは打ち込むには長いコマンドで、動作させるためにはすべてを正確に入力する必要があります。いいえ、そんなことをするにはあまりにも怠け者です!基本的に、Tabを押すことで、選択肢が一つしかなくなった時点で、コマンドラインはあなたが入力し始めたコマンドを自動的に補完してくれます。例えば、ホームディレクトリにDocumentsフォルダとDownloadsフォルダの両方があるのはごく一般的です。cd Dと入力してからTabを押すと、コマンドラインはどちらを指しているのか分からないことを、ここまで入力した内容に一致する異なる選択肢を示すことで知らせてくれます:

$ cd D
Documents/ Downloads/
$ cd D

しかし、もう少し多く入力すれば、コマンドラインが名前を補完してくれるので、上記のフルパスをcd Doc[tab]O[tab]f[tab]j[tab]cal[tab](コンピューター内にある他のフォルダによって異なります)というごくわずかな入力だけで書き出せるようになります。実際に試してみて、これがどう機能するかに慣れてください。きっと気に入るはずです。

3つ目に、プロジェクトディレクトリ内のすべてを開くための、とても便利なショートカットがあります: .です。テキストエディタをインストールしたら、このショートカットを使ってプロジェクト全体とそのすべてのファイルを一度に開くことができます。このショートカットは、ディレクトリ内のすべてのファイルをGitのステージングエリアに追加するgit add .のようなコマンドで、Git(後で詳しく扱います)でもよく使われます。例えば、VS Codeがインストールされている場合、プロジェクトディレクトリにcdで移動してからcode .(ピリオド付き)と入力できます。これによりVS Codeが起動し、サイドバーにプロジェクトフォルダが開かれます。より詳しい例は、このレッスンの次のセクションを参照してください。

コマンドラインからVSCodeでファイルを開く

  • Linux: codeと入力することでコマンドラインからVSCodeを開くことができ、その後に場所の名前を付け加えることでフォルダやファイルを開くことができます: code my_awesome_project/。

  • macOS: いくつかのセットアップが必要です。VSCodeをインストールしたら、好きな方法で起動してください。起動したら、Cmd + Shift + Pでコマンドパレットを開きます。表示される小さなダイアログにshell commandと入力します。表示される選択肢の一つにShell Command: Install 'code' command in PATHがあります。そのオプションを選択し、ターミナルを開いている場合は再起動してください。

  • WSL2: WSL2のコマンドラインからVSCodeを開くのは、Linuxの場合と同じくらい簡単です。codeと入力するだけで、WSL2でVSCodeが開きます。

課題

Desktopフォルダを作成する

これ以降のリソースの一部は、あなたのシステムにDesktopフォルダが存在することを前提としています。しかし、システム内のどこにもそれが見当たらない場合は、次のことを行ってください。ターミナルを開き、コマンドラインにcd ~と入力してホームディレクトリにいることを確認します。次に、mkdir Desktopと入力してenterを押します。コマンドがうまくいったことを確認するには、lsと入力して、他のディレクトリの中にDesktopフォルダが表示されているか確認してください。

正しいOSを使う

これらのリソースの多くは、あなたがMacまたはLinux環境を使用していることを前提としています。前のインストールレッスンをすでに終えていれば、デュアルブートまたは仮想マシンにLinuxがインストール済みのはずです。あるいは、macOSを使用しているかもしれません。macOSも公式Ubuntuフレーバーもインストールしていない場合は、インストールのレッスンに戻ってください。

  1. Software Carpentry Foundationが設計したThe Unix Shellコースを訪れてみましょう。そこには、CLIの使い方についての一通りのレッスンが揃っていますが、今はまず以下のレッスンを終えることだけに集中してください:

    WSL2でSWCarpentryコースを行う

    Download filesセクションに記載されているリンクとwgetコマンドを使って、WSL2環境にzipファイルを取得してください(wget https://swcarpentry.github.io/shell-novice/data/shell-lesson-data.zip)。また、sudo apt install unzipコマンドでunzipをインストールし、unzip shell-lesson-data.zipでファイルを解凍する必要もあります。このコース全体を通して、あなたのターミナルの出力はレッスンで示されているものと多少異なって見えるかもしれないことを覚えておいてください。コースがDesktopに移動するよう指示している場合は、代わりにホームディレクトリに移動してください。これはcdコマンド(cd ~)を使って行えます。

- [Download files](https://swcarpentry.github.io/shell-novice/#download-files) - このセクションの指示にのみ従ってください。ソフトウェアをインストールする必要はなく、このリストの次の項目に進んで構いません。
- [Introducing the Shell](https://swcarpentry.github.io/shell-novice/01-intro.html)
- [Navigating Files and Directories](https://swcarpentry.github.io/shell-novice/02-filedir.html)
- [Working With Files and Directories](https://swcarpentry.github.io/shell-novice/03-create.html)

  1. 新たに発見したCLIの超能力を使って、前のステップで紹介したmkdir、touch、cdコマンドを使ってフォルダといくつかのファイルを作成する練習をしましょう。例えば、基本的なウェブサイトには、メインのindex.htmlファイル、style.cssという名前のCSSスタイルシートファイル、そしてimages用のフォルダがあるかもしれません。これらのファイルをコマンドでどう作成できるかを考え、実際にやってみましょう!

  2. ファイルやディレクトリを作成し、削除する練習をしてみましょう!以下のステップのコマンドをターミナルに入力する必要があります。ターミナルの開き方を思い出せない場合は、上にスクロールして確認してください。

    1. ホームディレクトリにtestという名前の新しいディレクトリを作成する。
    2. testディレクトリに移動する。
    3. test.txtという名前の新しいファイルを作成する。ヒント: touchコマンドを使いましょう。
    4. 新しく作成したファイルをVSCodeで開き、何か変更を加え、保存して閉じる。
    5. testディレクトリから元のディレクトリに戻る。
    6. testディレクトリを削除する。

    以上です---練習は完了です!これから先、ほとんどのタスクをコマンドラインから行うことに徹すれば、これらのコマンドは自然と身についていきます。ファイルの移動やコピーは、今の時点では少し面倒に感じられても、コマンドラインを使う方がはるかに効率的です。
