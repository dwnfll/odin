Work with links and images in HTML

イントロダクション

リンクはHTMLの主要な機能の一つです。リンクによって、ウェブ上の他のHTMLページにリンクできます。実際、これこそが「ウェブ」と呼ばれる理由です。

このレッスンでは、リンクの作り方と、画像を埋め込むことでウェブサイトに視覚的な華やかさを加える方法を学びます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • インターネット上の他のウェブサイトのページへのリンクを作成する方法。
  • 自分自身のウェブサイト内の他のページへのリンクを作成する方法。
  • 絶対リンクと相対リンクの違い。
  • HTMLを使ってウェブページに画像を表示する方法。

準備

このレッスンを通してリンクと画像を使う練習をするために、作業対象となるHTMLプロジェクトが必要です。

  1. odin-links-and-imagesという名前の新しいディレクトリを作成してください。
  2. そのディレクトリ内に、index.htmlという名前の新しいファイルを作成してください。
  3. VS Codeでそのファイルを開き、いつものHTMLボイラープレートを記述してください。
  4. 最後に、以下のh1をbodyに追加してください:
<h1>Homepage</h1>

アンカー要素

HTMLでリンクを作成するには、アンカー要素を使用します。アンカー要素は、リンクにしたいテキストや他のHTML要素を<a>タグで囲むことで定義されます。

先ほど作成したindex.htmlページのbodyに以下を追加し、ブラウザで開いてみてください:

<a>About The Odin Project</a>

このリンクをクリックしても何も起きないことに気づいたかもしれません。これは、アンカータグ単体では、どこにリンクしたいのかが分からないためです。リンク先を伝えてあげる必要があります。これはHTML属性を使うことで行います。

HTML属性は、HTML要素に追加の情報を与えるもので、常に要素の開始タグの中に置かれます。属性は通常、名前と値の2つの部分で構成されますが、すべての属性が値を必要とするわけではありません。今回の場合、開始アンカータグにhref(ハイパーテキスト参照)属性を追加する必要があります。href属性の値が、私たちのリンクを送り届けたい行き先です。

先ほど作成したアンカー要素に以下のhref属性を追加し、もう一度クリックしてみてください。新しい変更が反映されるよう、ブラウザを更新するのを忘れないでください。

<a href="https://www.theodinproject.com/about">About The Odin Project</a>

デフォルトでは、href属性のないアンカータグで囲まれたテキストは、プレーンテキストのように見えます。href属性が存在する場合、ブラウザはそれがリンクであることを示すために、テキストを青色にして下線を引きます。

アンカータグは、他のHTMLドキュメントだけでなく、インターネット上のあらゆる種類のリソースへのリンクに使用できることは注目に値します。動画、pdfファイル、画像などにリンクすることもできますが、ほとんどの場合、あなたは他のHTMLドキュメントにリンクすることになるでしょう。

新しいタブでリンクを開く

上記で示した方法では、リンクはそれを含むウェブページと同じタブで開かれます。これはほとんどのブラウザのデフォルトの動作であり、比較的簡単に変更できます。必要なのは、もう一つの属性、target属性だけです。

hrefがリンク先を指定するのに対し、targetはリンクされたリソースがどこで開かれるかを指定します。存在しない場合、デフォルトでは_selfという値になり、現在のタブでリンクが開かれます。リンクを新しいタブまたはウィンドウ(ブラウザの設定によります)で開くには、以下のように_blankに設定できます:

<a href="https://www.theodinproject.com/about" target="_blank" rel="noreferrer">About The Odin Project</a>

上記でこっそりrel属性を追加していたことに気づいたかもしれません。この属性は、現在のページとリンクされたドキュメントとの関係を説明するために使用され、複数の値を取ることができます。今ここで議論するのに最も関連性が高いのは以下のものです:

  • noopener: 新しいタブが元のページにアクセスすることを防ぎます。これにより、タブナビングのようなフィッシング攻撃の可能性が開かれてしまうところでした。最近のブラウザはすべて、target="_blank"を持つすべてのリンクに対してこれを自動的に設定しますが、古いブラウザとの互換性のために、手動で設定されているのを見かけることも今なおよくあります。
  • noreferrer: noopenerと同じですが、さらに元のページについてのある種の詳細情報が新しいページに渡されるのを防ぎます。リファラー情報は常に共有することが望ましいわけではありません。

絶対リンクと相対リンク

一般的に、作成するリンクには2種類あります:

  • インターネット上の他のウェブサイトのページへのリンク。
  • 自分自身のウェブサイト内にあるページへのリンク。

絶対リンク

インターネット上の他のウェブサイトのページへのリンクは、絶対リンクと呼ばれます。典型的な絶対リンクは、scheme://domain/pathという部分で構成されます。絶対リンクには、必ずリンク先のスキームとドメインが含まれます。

すでに実際に動作する絶対リンクを見てきました。先ほど作成したThe Odin ProjectのAboutページへのリンクは、スキームとドメインを含んでいたため、絶対リンクでした。

https://www.theodinproject.com/about

相対リンク

自分自身のウェブサイト内の他のページへのリンクは、相対リンクと呼ばれます。相対リンクにはドメイン名が含まれません。同じサイト内の別のページであるため、ドメイン名はリンクを作成したページと同じであることが前提とされています。

相対リンクには、リンクを作成しているページから見て相対的な、他のページへのファイルパスだけが含まれます。これはかなり抽象的なので、例を使って実際に見てみましょう。

odin-links-and-imagesディレクトリ内に、about.htmlという名前の別のHTMLファイルを作成し、以下のコードを貼り付けてください:

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Odin Links and Images</title>
  </head>

  <body>
    <h1>About Page</h1>
  </body>
</html>

indexページに戻って、aboutページへのリンクを作成するために以下のアンカー要素を追加してください:

<body>
  <h1>Homepage</h1>
  <a href="https://www.theodinproject.com/about">About The Odin Project</a>

  <a href="about.html">About</a>
</body>

ブラウザでindexファイルを開き、aboutリンクをクリックして、すべてが正しくつながっていることを確認してください。リンクをクリックすると、先ほど作成したaboutページに移動するはずです。

これがうまくいくのは、indexページとaboutページが同じディレクトリにあるためです。つまり、リンクのhrefの値として、その名前(about.html)を使用できるということです。

しかし、通常はウェブサイトのディレクトリをもう少しうまく整理したいと思うでしょう。通常、ルートディレクトリにはindex.htmlだけを置き、他のすべてのHTMLファイルはそれ専用のディレクトリに置きます。

odin-links-and-imagesディレクトリ内にpagesという名前のディレクトリを作成し、about.htmlファイルをこの新しいディレクトリに移動してください。

ブラウザでindexページを更新し、aboutリンクをクリックしてください。今度はリンクが壊れているはずです。これは、aboutページのファイルの場所が変わったためです。

これを直すには、about用のリンクのhref値にpages/ディレクトリを含めるように更新するだけで済みます。それが、indexファイルから見て相対的な、aboutファイルの新しい場所だからです。

<body>
  <h1>Homepage</h1>
  <a href="pages/about.html">About</a>
</body>

ブラウザでindexページを更新し、もう一度aboutリンクをクリックしてみてください。今度は正常に動作するはずです。

多くの場合、これで問題なく動作しますが、このアプローチでも予期しない問題に遭遇することがあります。リンクの前に./を付けることで、多くの場合こうした問題を防げます。./を追加することで、現在のディレクトリから見て相対的にファイル/ディレクトリを探し始めるべきだということを、コードに指定していることになります。

<body>
  <h1>Homepage</h1>
  <a href="./pages/about.html">About</a>
</body>

たとえ話

絶対リンクと相対リンクは、うまく頭の中でイメージを作るのが難しい概念です。たとえ話が役立つかもしれません:

あなたのドメイン名(town.com)を町、あなたのウェブサイトが置かれているディレクトリ(/museum)を博物館、あなたのウェブサイトの各ページを博物館内の部屋(/museum/movie_room.htmlや/museum/shops/coffee_shop.html)だと考えてみてください。./shops/coffee_shop.htmlのような相対リンクは、現在の部屋(博物館の映画室/museum/movie_room.html)から別の部屋(博物館のショップ)への道案内です。一方、絶対リンクは、プロトコル(https)、ドメイン名(town.com)、そしてそのドメイン名からのパス(/museum/shops/coffee_shop.html)を含む完全な道案内です: https://town.com/museum/shops/coffee_shop.html。

画像

ウェブサイトがテキストしか表示できないとしたら、かなり退屈なものになるでしょう。幸いなことに、HTMLはあらゆる種類の異なるメディアを表示するための多種多様な要素を提供しています。その中で最も広く使われているのが画像要素です。

HTMLで画像を表示するには<img>要素を使用します。これまで出会ってきた他の要素とは異なり、<img>要素はボイド要素です。このコースの前半で見たように、ボイド要素は本質的に空であり、いかなるコンテンツも含まないため、終了タグを必要としません。

開始タグと終了タグでコンテンツを囲む代わりに、画像ファイルがどこにあるかをブラウザに伝えるsrc属性を使って、ページに画像を埋め込みます。src属性は、アンカータグのhref属性とよく似た働きをします。絶対パスと相対パスの両方を使って画像を埋め込むことができます。

例えば、絶対パスを使うことで、The Odin Projectのサイトにある画像を表示できます:

See the Pen absolute-path-image by TheOdinProject (@TheOdinProjectExamples) on CodePen.

自分自身のウェブサーバーでホストされている画像をウェブサイトに表示するには、相対パスを使用できます。

Linux, macOS, ChromeOS
  1. odin-links-and-imagesプロジェクト内にimagesという名前の新しいディレクトリを作成してください。
  2. 次に、練習用の画像をダウンロードし、先ほど作成したimagesディレクトリに移動してください。
  3. 画像の名前をdog.jpgに変更してください。
WSL2

インターネットからファイルをダウンロードすると、Windowsのセキュリティ機能により、ダウンロードしたファイルと同じ名前の隠しファイルZone.Identifierが作成されます。これはmypicture.jpg:Zone.Identifierのような見た目になります。このファイルは無害ですが、それをコピーしてディレクトリを散らかしてしまうことは避けたいです。

  1. odin-links-and-imagesプロジェクト内にimagesという名前の新しいディレクトリを作成してください。

  2. 次に、ストックの犬の画像をダウンロードしてください。

  3. Chromeウィンドウ下部にある新しいダウンロードを右クリックし、「Show in folder」を選択してください。

    1. あるいは、Chromeウィンドウの下部に何も表示されない場合は、「Customize and control Google Chrome」の三点リーダーメニューを開き、「Downloads」の項目を選択してください。これにより、すべてのダウンロードが表示され、それぞれに「Show in folder」ボタンが付いています。

  4. 画像の名前をdog.jpgに変更してください。

  5. ダウンロードフォルダからVSCodeのファイルブラウザへ、新しいimagesディレクトリの中にファイルをドラッグしてください。

    1. あるいは、Ubuntuターミナルを使って、画像をコピーしたいフォルダに移動してください(例:cd ~/odin-links-and-images)。

    2. cp <space>と入力してください。

    3. Windowsエクスプローラーのウィンドウからdog.jpg画像をドラッグし、ターミナルウィンドウにドロップしてください。すると、"/mnt/c/users/username/Downloads/dog.jpg"のように表示されるはずです。

    4. <space> .と入力して、現在の作業ディレクトリにファイルをコピーしたいことをcpに伝えます。完全なコマンドは次のようになります:

    cp "/mnt/c/users/username/Downloads/dog.jpg" .
    1. Enterを押してコマンドを完了させ、lsを使ってファイルが存在することを確認してください。

WindowsからVSCodeのファイルブラウザにファイルをドラッグすることで、Zone.Identifierファイルがコピーされてしまうのを防げます。今後、このような写真やその他のダウンロードしたファイルをWSL2にコピーする必要があるときは、いつでもこの方法で行うことができます。万が一これらのZone.Identifierファイルを誤ってWSL2にコピーしてしまっても、問題なく安全に削除できます。

最後に、index.htmlファイルに画像を追加してください:

<body>
  <h1>Homepage</h1>
  <a href="https://www.theodinproject.com/about">About The Odin Project</a>

  <a href="./pages/about.html">About</a>

  <img src="./images/dog.jpg">
</body>

index.htmlファイルを保存し、ブラウザで開いて、Charlesの雄姿をご覧ください。

使用する画像は、意図した用途に対して無料であるべき

無料で利用できる画像はたくさんありますが、プロジェクトの中で画像の制作者にクレジットを表記するようにしてください。

クレジットを表記する簡単な方法は、リポジトリのREADMEファイルに制作者の名前と連絡先情報を含めるか、アトリビューションを行うことです。

そうした画像を見つけるには---Google画像検索を使い、画像の検索結果で「ツール」→「使用権」→「クリエイティブ・コモンズ」を選択します。画像を選んでクリックし、ライセンスの詳細をクリックしてください。

使用したい画像のライセンス要件は、常に確認することをお勧めします。

親ディレクトリ

aboutページで犬の画像を使いたい場合はどうすればよいでしょうか?まず、pagesディレクトリから1つ上の階層、つまりその親ディレクトリに上がり、そこからimagesディレクトリにアクセスできるようにする必要があります。

親ディレクトリに移動するには、相対ファイルパスの中で../のようにドット2つを使う必要があります。実際に見てみましょう。about.htmlファイルのbody内で、先ほど追加した見出しの下に以下の画像を追加してください:

<img src="../images/dog.jpg">

これを分解してみましょう:

  1. まず、pagesディレクトリの親ディレクトリであるodin-links-and-imagesに移動します。
  2. 次に、その親ディレクトリからimagesディレクトリに入ります。
  3. 最後に、dog.jpgファイルにアクセスできます。

先ほど使ったたとえ話を使うなら、ファイルパスの中で../を使うことは、現在いる部屋から出て、別の部屋に行けるように、メインの廊下に足を踏み出すようなものです。

alt属性

src属性に加えて、すべての画像要素にはalt(代替テキスト)属性も持たせるべきです。

alt属性は画像を説明するために使用されます。画像を読み込めなかった場合、その画像の代わりに使用されます。また、視覚障害のあるユーザーに対して、その画像が何であるかを説明するためにスクリーンリーダーでも使用されます。

以下は、先ほど使用したThe Odin Projectのロゴの例にalt属性を含めた場合の見た目です:

See the Pen image-alt-attribute by TheOdinProject (@TheOdinProjectExamples) on CodePen.

画像のサイズ属性

厳密には必須ではありませんが、画像タグにheightとwidth属性を指定しておくことで、ブラウザがページのレイアウトを組む際に、ページがガタついたり点滅したりするのを防ぐ助けになります。

画像がすでに正しいサイズであったり、CSSでそれを調整していたりする場合でも、常にすべての画像にこれらの属性を指定しておくことは良い習慣です。これは、画像の読み込み時にコンテンツがガタつくのを防ぐためです。サイズを指定する際は、画像の実際の寸法を使用してください。
