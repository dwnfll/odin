Now that you know what Git is it's time to learn how to use it.

イントロダクション

このレッスンでは、プロジェクトを管理し、作業内容をGitHubにアップロードするために使う一般的なGitコマンドを扱います。これらのコマンドを基本的なGitワークフローと呼びます。Gitを使うとき、これらは70〜80%の時間で使うことになるコマンドです。これらを身につけられれば、Gitの習得はもう半分以上終わったようなものです!

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • GitHub上でリポジトリを作成する方法。
  • GitHubとの間でファイルをやり取りする方法。
  • コードの「スナップショット」を取る方法。

課題

始める前に!

  • GitHubは最近、デフォルトブランチの命名方法を更新しました。つまり、最近のバージョンのgit(2.28以降)を使用していることを確認する必要があります。バージョンは以下を実行することで確認できます: git --version
  • まだ設定していない場合は、ローカルのデフォルトGitブランチをmainに設定してください。以下を実行することで設定できます: git config --global init.defaultBranch main
  • masterからmainへの変更についての詳細は、GitHub's Renaming Repositoryを参照してください。

リポジトリを作成する

  1. Setting Up Gitのレッスンで、すでにGitHubアカウントを作成しているはずです。

  2. GitHubのホームページから、右上の「+」ボタンをクリックし、「New repository」を選択して新しいリポジトリを作成してください。小さいビューポートを使用している場合、そのボタンは隠れているかもしれません。その場合は右上のプロフィール画像をクリックすると、プロフィール名の隣にボタンが表示されます。

  3. リポジトリ名の入力欄に「git_test」という名前を入力してください。「Add README」オプションをオンにします(これにより、新しいリポジトリにREADME.mdファイルが自動的に作成されます)。それから、ページ下部の「Create repository」ボタンをクリックしてリポジトリを作成してください。

  4. これにより、GitHub上の新しいリポジトリにリダイレクトされます。このリポジトリをローカルマシンにコピー(クローン)する準備をするために、緑色の「Code」ボタンをクリックしてください。これは、現在のブランチを表示するボタン(通常はmainブランチが表示されます)の右側にあるはずです。それから「Clone」セクションでSSHオプションを選択し、その下の行をコピーしてください。注意: 正しいURLを取得するには、必ずSSHオプションをクリックする必要があります。

  5. ローカルマシンのコマンドラインを使って、あなたのすべてのOdinプロジェクト用の新しいディレクトリを作成しましょう。ホームフォルダでmkdirコマンドを使ってreposという名前のディレクトリを作成してください。あなたのホームフォルダは~で表されます。OSによっては、ホームディレクトリの違いがあることに注意してください---~が/Users/your_usernameを表すこともあれば、/home/your_usernameを表すこともあります。自分がホームフォルダにいるか分からない場合は、cd ~と入力してください。作成できたら、cdコマンドでその中に移動しましょう。

    mkdir repos
cd repos/

  6. さあ、git cloneの後に前のステップでコピーしたURLを続けて入力し、GitHubから新しく作成したreposディレクトリにリポジトリをクローンする時です。完全なコマンドはgit clone git@github.com:USER-NAME/REPOSITORY-NAME.gitのようになるはずです。もしURLがhttps://github.com/USER-NAME/REPOSITORY-NAME.gitのようになっている場合、必要なSSHオプションではなくHTTPSオプションを選択してしまっています。

    git clone git@github.com:USER-NAME/REPOSITORY-NAME.git

  7. これで完了です!GitHub上で作成したリポジトリとローカルマシンの接続に成功しました。これを確認するには、cd git_testを実行してダウンロードされた新しいgit_testフォルダに移動し、コマンドラインでgit remote -vと入力してください。以下のような出力が表示されるはずです。USER-NAMEの部分はあなたのGitHubユーザー名です:

    origin  git@github.com:USER-NAME/git_test.git (fetch)
origin  git@github.com:USER-NAME/git_test.git (push)

    これは、あなたがGitHub上で作成したリポジトリのURLを表示しており、それがあなたのローカルコピーのリモートです。git remote -vの出力の先頭にoriginという単語があることにも気づいたかもしれません。これはあなたのリモート接続の名前です。「origin」という名前は、リモートリポジトリのデフォルトであると同時に慣習でもありますが、「party-parrot」や「dancing-banana」という名前にすることも同じくらい簡単にできました(「origin」の詳細については今は気にしなくて大丈夫です。このチュートリアルの終盤で再び登場します)。

Gitワークフローを使う

  1. touch hello_world.txtコマンドを使って、git_testフォルダ内に「hello_world.txt」という新しいファイルを作成してください。

  2. ターミナルでgit statusと入力してください。出力の中で、あなたのhello_world.txtファイルは赤色のテキストで表示され、「Untracked files」というタイトルのセクションにも記載されているはずです。これは、そのファイルがまだステージングされていないことを意味します。

  3. git add hello_world.txtと入力してください。このコマンドは、hello_world.txtファイルをGitのステージングエリアに追加します。ステージングエリアは、Gitでコミットを行うための2段階のプロセスの一部です。ステージングエリアを、コミットするまでの変更内容の「待合室」のようなものだと考えてください。では、もう一度git statusと入力してください。出力の中で、あなたのファイルが緑色で表示され、「Changes to be committed」というタイトルのセクションにあることに注目してください。これは、このファイルが今やステージングエリアにあることを意味します。

  4. git commit -m "Add hello_world.txt"と入力し、それからもう一度git statusと入力してください。出力は「nothing to commit, working tree clean」となり、変更がコミットされたことを示しているはずです。「upstream is gone」というメッセージが表示されても心配いりません。これは、クローンしたリポジトリに現在ブランチが存在しない場合にのみ表示される、正常なものです。このプロジェクトの残りのステップに従っていくと解消されます。

    「Your branch is ahead of 'origin/main' by 1 commit」というメッセージは、あなたが今、リモートリポジトリにあるものよりも新しいスナップショットを持っているということを意味しているにすぎません。このスナップショットは、このレッスンの後の方でアップロードすることになります。

  5. git logと入力して出力を見てください。「Add hello_world.txt」コミットのエントリが表示されるはずです。また、コミットを行った作者やコミットが行われた日時など、他の詳細も表示されます。ターミナルの下部に(END)と表示された画面で止まってしまった場合は、「q」を押して抜け出してください。この設定は後で変更できますが、今はあまり気にしなくて大丈夫です。

ファイルを1つか2つ変更する

  1. お好みのテキストエディタでREADME.mdを開いてください。この例では、リポジトリ内でcode .コマンドを使ってVisual Studio Codeでディレクトリを開きます。

    macOSユーザーの方へ: ターミナルに「command not found: code」と表示される場合は、Command Line Basicsに戻り、記載されている手順に従ってこのコマンドが使えるようにする必要があります。

  2. README.mdの新しい行に「Hello Odin!」を追加し、VS Codeが自動保存になっていない場合はCtrl + S(Mac: Cmd + S)でファイルを保存してください。

  3. ターミナルに戻るか、Visual Studio Codeを使用している場合はCtrl + `(バッククォート)を押して組み込みのターミナルを開いてください。それからgit statusと入力します。出力が、ステージングエリアに追加する前にhello_world.txtファイルを作成したときと似ていることに気づくでしょう。ただし、README.mdファイルは「Changes not staged for commit」というタイトルのセクションに記載されています。これは、そのファイルがまだステージングエリアに追加されていないという点で、「Untracked files」セクションと似た意味です。

  4. git add README.mdでREADME.mdをステージングエリアに追加してください。

  5. 今git statusが何を出力するか予想できますか?README.mdは「Changes to be committed」というタイトルのセクションに緑色のテキストで表示されます。つまり、README.mdがステージングエリアに追加されたということです。hello_world.txtファイルは、コミット以降変更されていないため表示されません。

  6. hello_world.txtを開き、何かテキストを追加して保存し、ステージングしてください。git add .を使うと、現在のディレクトリとそれ以下のすべてのディレクトリのファイルをステージングエリアに追加できます。それから、もう一度git statusと入力すると、すべてがステージングエリアに入っているはずです。

  7. 最後に、ステージングエリアにあるすべてのファイルをコミットし、分かりやすいコミットメッセージを追加しましょう。git commit -m "Edit README.md and hello_world.txt"。それから、もう一度git statusと入力すると、先ほどコミットしたときと同じ「nothing to commit」というメッセージが出力されます。

  8. git logと入力して、コミット履歴を最後にもう一度確認してみましょう。今度は3つのエントリが表示されるはずです。

作業内容をGitHubにプッシュする

最後に、このチュートリアルの最初に作成したGitHubリポジトリに、あなたの作業内容をアップロードしましょう。

  1. git pushと入力してください。より正確に言うと、git push origin mainと入力します。(main以外の)別のブランチや、(上述したような)別のリモートを扱っているわけではないので、キー入力を少し省くためにgit pushのままにしておいて構いません。注意: この時点で「Support for password authentication was removed on August 13, 2021. Please use a personal access token instead.」というメッセージを受け取った場合、手順を誤って実行しており、SSHではなくHTTPSでクローンしてしまっています。リモートURLをHTTPSからSSHに切り替える手順に従ってリモートをSSHに変更してから、もう一度GitHubへのプッシュを試みてください。

  2. 最後にもう一度git statusと入力してください。「Your branch is up to date with 'origin/main'. nothing to commit, working tree clean」と出力されるはずです。

  3. GitHub上のリポジトリページを更新すると、ローカルマシンからプッシュしたばかりのREADME.mdとhello_world.txtファイルが表示されるはずです。

GitHub上で直接編集するのは避ける

README.mdのタイプミスを直そうとするときのように、リポジトリ内のファイルにちょっとした変更を加えたくなったとき、GitHub上で直接その変更を行いたくなるかもしれません。しかし、これは避けるのが最善です。この段階で扱いたい以上に高度なGitの知識を必要とする問題を引き起こしてしまうからです(これは今後のレッスンで扱います)。今のところは、ローカルファイル経由ですべての変更を行い、準備ができたらターミナルでGitコマンドを使ってコミット・プッシュすることをお勧めします。

チートシート

これは、最もよく使われるGitコマンドのリファレンスリストです。(この便利なページをブックマークしておくとよいでしょう。)最終的にすべて覚えられるように、これらのコマンドに慣れ親しんでおきましょう:

  • リモートリポジトリに関連するコマンド:
    • git clone git@github.com:USER-NAME/REPOSITORY-NAME.git
    • git pushまたはgit push origin main(この文脈ではどちらも同じ目的を達成します)
  • ワークフローに関連するコマンド:
    • git add .
    • git commit -m "A message describing what you have done to make this snapshot different"
  • ステータスやログ履歴の確認に関連するコマンド
    • git status
    • git log

基本的なGitの構文はprogram | action | destinationです。

例えば、

  • git add .はgit | add | .と読め、ピリオドは現在のディレクトリ内のすべてを表します。
  • git commit -m "message"はgit | commit -m | "message"と読めます。
  • git statusはgit | status | (no destination)と読めます。

Gitのベストプラクティス

Gitの使い方について学ぶべきことはたくさんあります。しかし、より良い協力者になれるよう、いくつかのベストプラクティスを取り上げるために時間をかける価値があります。Gitは他の人と協力するときだけでなく、一人で作業するときにも役立ちます。今後、古いコードを見直す際に、あなた自身のコミット履歴にますます頼ることになります。

考慮すべき2つの有用なベストプラクティスは、アトミックコミットと、それを活用して将来の協力者にとってより役立つコミットメッセージを作ることです。

アトミックコミットとは、プログラムの1つの機能やタスクにのみ関連する変更を含むコミットのことです。これを行う主な理由は2つあります。1つ目は、変更した何かが問題を引き起こすことが判明した場合に、他の変更を失うことなくその特定の変更だけを簡単に元に戻せることです。2つ目は、より良いコミットメッセージを書けるようになることです。良いコミットメッセージがどのようなものかについては、今後のレッスンで詳しく学びます!

Gitのコミットメッセージエディタを変更する

Visual Studio Codeを使用している場合(このカリキュラムに従っているならそうしているはずです)、メッセージフラグ(-m)を付けずにgit commitを使っても、Vimでコミットメッセージを書く羽目にならないようにする方法があります。

Vimを使いたいのでない限り、誤ってフラグを付け忘れた場合に備えて、デフォルトのメッセージエディタを変更しておくのは良い考えです。変更しても不利益はありません。なぜなら、ターミナルで書くか、快適なVS Code上で書くかを選べるようになるからです。

以下のコマンドでこの設定を行います。このコマンドをターミナルに入力(またはコピー&ペースト)し、Enterを押してください。

git config --global core.editor "code --wait"

このコマンドを入力した後、ターミナルには確認メッセージや出力は何も表示されません。

これで、git commit -m "your message here"を使うか、git commitを使ってVisual Studio Codeでメッセージを入力するかを選べるようになりました!

Visual Studio Codeをテキストエディタとしてコミットを行うには、git commitと入力するだけです。Enterを押すと、コミットメッセージを書くためのVS Codeの新しいタブが開きます。コミットメッセージの一部として、複数行にわたってより詳しい説明を記述することもできます。コミットメッセージを入力したら、Ctrl + S(Mac: Cmd + S)で保存し、タブを閉じてください。コマンドラインに戻ると、コミットメッセージと変更内容の概要が表示されます。
