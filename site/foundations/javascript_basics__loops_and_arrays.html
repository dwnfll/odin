Loops and Arrays 日本語訳

In this lesson we learn about loops and arrays.

イントロダクション

プログラミングの課題の一つは繰り返しです。手動での繰り返しが完全に問題ない場合もありますが、時には繰り返しの指示をより読みやすくするために効率化したいことがあります。もう一つの課題は、大量のデータを扱うことです。例えば、クラスの生徒全員の名前を保存したい場合、どうすればよいでしょうか?それぞれの名前用に変数を作ることもできますが、それは面倒で非効率的です。管理や更新も難しくなります。後で名前を変更したりアクセスしたりしたい場合はどうでしょうか?

幸いなことに、これらの問題に対処する方法があります。このレッスンでは、コードのブロックを繰り返し実行できるようにする制御構造である、ループについて学びます。また、1つの変数に複数の値を保存できるデータ構造である配列についても学びます。配列は、大量のデータを整理し操作するのに非常に役立ちます。ループは、配列の各要素に対して同じ操作を行うのに便利なことがよくあります。最後に、コード自体を書く前にそのコードのテストを書くという実践である、テスト駆動開発(TDD)を紹介します。

ループ

コンピューターは疲れることがなく、本当に、本当に速いです!そのため、計算を何度も行う必要がある問題を解決するのに適しています。場合によっては、人間なら何時間もかかるようなタスクを、コンピューターはほんの数秒で何千回、あるいは何百万回も繰り返すことができます(もちろん、ここでの速さは計算の複雑さとコンピューター自体の速度によります)。

一連の指示を何度も繰り返すには、ループを使用できます。ループについての以下のリソースに目を通してください。中には配列を使った例が含まれているものもありますが、それについては次のセクションでさらに詳しく扱います。今のところは、配列が単なる項目のリストであることを知っておくだけで十分です。

配列

文字列や数値は私たちの構成要素かもしれませんが、スクリプトがより複雑になるにつれて、それらの大量の集まりを扱う方法が必要になります。幸いなことに、JavaScriptにはまさにそのために使われるいくつかのデータ型があります。配列とは、項目(文字列、数値、その他のもの)の順序付けられた集まりです。以下のリソースのいくつかで示されている配列メソッドの中には、ループと似たことを行うものがあることに気づくかもしれません。実際のループを通してより多くの制御が必要な場合もありますが、適切な配列メソッドで十分に済み、その読み方の方が好ましい場合もあります。

  1. このJavaScript Arrays crash courseは、JavaScriptにおける配列の概要を約6分で説明してくれます。
  2. JavaScript.infoのこの配列への入門を読み通してください。ページ最後の演習を行う必要はありません。
  3. JavaScriptのさらなる配列メソッドをより深く見るために、JavaScript.infoの配列メソッドガイドを読み通してください。こちらもページ最後の演習を行う必要はありません。後で戻ってきます。
  4. MDNのArrayのドキュメントをブックマークしておいてください。ここにあるものを暗記する必要はありません。ここには、すべての組み込みの配列プロパティとメソッド、そのドキュメントがあります。コーディングや問題解決をする中で、定期的に立ち返ることになるはずです。

配列マジックの例

配列は、データを保存するための手早く便利な方法であるだけでなく、そのデータを非常に強力な方法で操作するための関数一式も備えています。これらの関数にもっと慣れてくると、あちこちでそれらを使う方法が見えてくるようになります!実際にはこうした関数はほんの一握りしかありませんが、すぐに分かるように、それらでできることの可能性はほぼ無限です。

私たちが言おうとしていることの例として、sumOfTripledEvens関数を考えてみましょう。これは:

  1. 配列を受け取ります。
  2. すべての偶数について、それを3倍にします。
  3. それからそれらの偶数をすべて合計します。

疑似コードを使って、そのような関数をどう実装できるか考えられますか?

  1. 偶数だけに操作を行う必要があります。
  2. それらの数値を3倍することで変換する必要があります。
  3. 最後に、前の変換からの結果を合計する必要があります。

そのロジックを使うと、次のようなものを実装することになるかもしれません:

function sumOfTripledEvens(array) {
  let sum = 0;
  for (let i = 0; i < array.length; i++) {
    // Step 1: If the element is an even number
    if (array[i] % 2 === 0) {
      // Step 2: Multiply this number by three
      const tripleEvenNumber = array[i] * 3;

      // Step 3: Add the new number to the total
      sum += tripleEvenNumber;
    }
  }
  return sum;
}

上記のコードには、考慮すべき3つの重要な断片があります:

  • if (array[i] % 2 === 0):与えられた数値が偶数かどうかを確認します。
  • const tripleEvenNumber = array[i] * 3:その数値の3倍を得ます。
  • sum += tripleEvenNumber:その数値だけ合計を増やします。

それぞれの部分が、私たちのコードにおける重要な問題を解決しています。しかし、いくつかの配列メソッドを使って同じことを行うこともでき、その結果は時に少し読みやすく理解しやすくなります。少し時間を取って、それらのいくつかをどう使えるか見てみましょう。

mapメソッド

mapはそのような関数の一つです。これは引数としてcallbackを期待しますが、これは「私の関数に別の関数を引数として渡してほしい」という気取った言い方です。

numを引数として受け取り、そのnumに1を加えたものを出力するaddOneという関数と、数値の配列[1, 2, 3, 4, 5]があるとしましょう。addOne関数を使って、これらの数値すべてに1を加えたいとします。

forループを作って上記の配列を反復処理する代わりに、map配列メソッドを使うことができます。これは配列を自動的に反復処理してくれます。使いたい関数を渡すだけで、それ以外の余計な作業をする必要はありません:

function addOne(num) {
  return num + 1;
}
const arr = [1, 2, 3, 4, 5];
const mappedArr = arr.map(addOne);
console.log(mappedArr); // Outputs [2, 3, 4, 5, 6]

mapは新しい配列を返し、元の配列を変更しません。

// The original array has not been changed!
console.log(arr); // Outputs [1, 2, 3, 4, 5]

このようにmapを使うことは、forループを書いて配列を反復処理するよりエレガントかもしれません。しかし、さらに良くすることができます。addOneを他のどこでも使っておらず、単純な関数なので、次のようにアロー関数を使ってmapの中に直接インラインで定義できます:

const arr = [1, 2, 3, 4, 5];
const mappedArr = arr.map((num) => num + 1);
console.log(mappedArr); // Outputs [2, 3, 4, 5, 6]

filterメソッド

filterはmapにいくらか似ています。配列を反復処理し、すべての項目にコールバック関数を適用する点は同じです。しかし、配列内の値を変換する代わりに、コールバック関数がその項目に対してtrueを返した場合にのみ、その項目が含まれる新しい配列を返します。

数値が奇数であればtrueを、そうでなければfalseを返すisOddという関数があるとしましょう。

filterメソッドは、callbackがtrueかfalseのどちらかを返すことを期待します。trueを返せば、その値は出力に含まれます。そうでなければ含まれません。前の例の配列[1, 2, 3, 4, 5]を考えてみましょう。この配列からすべての偶数を取り除きたい場合、次のように.filter()を使用できます:

function isOdd(num) {
  return num % 2 !== 0;
}
const arr = [1, 2, 3, 4, 5];
const oddNums = arr.filter(isOdd);
console.log(oddNums); // Outputs [1, 3, 5];
console.log(arr); // Outputs [1, 2, 3, 4, 5], original array is not affected
  • filterはarrを反復処理し、すべての値を1つずつisOddコールバック関数に渡します。
  • 値が奇数であればisOddはtrueを返し、この値が出力に含まれることになります。
  • 偶数であれば、isOddはfalseを返し、最終的な出力に含まれません。

reduceメソッド

最後に、arrの中のすべての数値を1 * 2 * 3 * 4 * 5のように掛け合わせたいとしましょう。まず、totalという変数を宣言し、1で初期化する必要があります。それから、forループで配列を反復処理し、totalに現在の数値を掛けていきます。

しかし、実際にはそのすべてを行う必要はありません。その作業をやってくれるreduceメソッドがあります。.map()や.filter()と同様に、コールバック関数を期待します。しかし、この配列メソッドには2つの重要な違いがあります:

  • コールバック関数は1つではなく2つの引数を取ります。最初の引数はaccumulator(累積値)で、これはループのその時点での結果の現在の値です。最初の実行時、この値はinitialValue(次の項目で説明します)に設定されるか、initialValueが提供されていない場合は配列の最初の要素に設定されます。コールバックの2番目の引数はcurrent(現在の)値で、現在反復処理されている項目です。
  • reduce自体も、(コールバックの後の)任意の2番目の引数としてinitialValueを受け取ります。これは、初期値を配列の最初の要素にしたくない場合に役立ちます。例えば、配列内のすべての数値を合計したい場合はinitialValueなしでreduceを呼び出せますが、配列内のすべての数値を合計して10を足したい場合は、initialValueとして10を使用できます。
const arr = [1, 2, 3, 4, 5];
const productOfAllNums = arr.reduce((total, currentItem) => {
  return total * currentItem;
}, 1);
console.log(productOfAllNums); // Outputs 120;
console.log(arr); // Outputs [1, 2, 3, 4, 5]

上記の関数では、私たちは:

  • コールバック関数、つまり(total, currentItem) => total * currentItemを渡しています。
  • 2番目の引数でtotalを1に初期化しています。

つまり、.reduce()が行うことは、arrのすべての要素を巡回し、それにcallback関数を適用することです。配列自体を実際に変更することなくtotalを更新します。終わったら、totalを返します。

まとめ

map、filter、reduceという3つの強力な配列メソッドについて学びました。これらは、より読みやすい可能性のあるコードを書くことを可能にし、それによってバグが起きにくくなるかもしれません。

これらの配列メソッドを簡単に復習するために、サンドイッチに例えて視覚的に説明してくれるこの画像を見てみましょう:

課題の前に、簡単な練習をしてみましょう!これら3つのメソッドを使ってsumOfTripledEvens(array)関数を書き直してください。終わったら、関数が正しく動くことをテストし、以下の解答を確認してみてください。

解答 
function sumOfTripledEvens(array) {
  return array
    .filter((num) => num % 2 === 0)
    .map((num) => num * 3)
    .reduce((acc, curr) => acc + curr);
}

テスト駆動開発

テスト駆動開発(TDD)は、開発の世界でよく耳にするフレーズです。これは、実際にコードを書く前に、そのコードがどう動作すべきかを記述する自動テストを書くという実践を指します。例えば、いくつかの数値を足し合わせる関数を書きたい場合、まずその関数を使い、期待される出力を与えるテストを書きます。コードを書く前はテストは失敗し、テストが通ったときにコードが正しく動作していることが分かるはずです。

多くの点で、TDDはテストなしでコードを書くよりもはるかに生産的です。上記の加算関数のテストがなければ、うまく動いていると確信できるまで、さまざまな数値を入れながら自分でコードを何度も実行しなければなりません……基本的なadd(2, 2)ならたいした問題ではありませんが、三目並べ(tic tac toe)で誰かが勝ったかどうかを確認するような、もっと複雑な関数の場合を想像してみてください:(game_win(["o", null,"x",null,"x",null,"x", "o", "o"]))。TDDをしていなければ、関数が正しく動いているかをテストするためだけに、実際に自分自身を相手に何度もゲームをプレイしなければならないかもしれません!

実際にこれらのテストを書く技術については、コースの後半で教えます。今のところは、以前からのJavaScriptの演習に引き続き取り組んでください。
