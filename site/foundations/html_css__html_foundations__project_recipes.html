イントロダクション

これまでに身につけたHTMLの知識をすべて実践する時が来ました。このプロジェクトでは、基本的なレシピウェブサイトを構築します。

このウェブサイトは、いくつかのレシピへのリンクを持つメインのindexページで構成されます。完成した時点でウェブサイトはあまり見栄えの良いものにはなりませんが、このプロジェクトの目的はあなたのHTMLの腕を磨くことにあるという点を心に留めておくことが重要です。このプロジェクトには、後でCSSを使ってスタイルを付けるために再び戻ってきます。

プロジェクトのGitHubリポジトリをセットアップする

Introduction to Gitのレッスンで述べた通り、あなたはすべてのプロジェクトをポートフォリオのように整理し、他の人に見てもらえるようGitHubにリンクさせたいと思うでしょう。

GitHub上でファイルを作成する際の注意

GitHubでは、サイト上で直接変更を加えることができます。リポジトリをマシンにクローンした後にこれを行うと、あなたのローカルコードがリモートより1バージョン古くなってしまい、作業をプッシュする際に余計な問題が生じます。ほとんどの場合、ファイルはローカルで作成するべきです。

コースを進めていく中で、こうした状況への対処法を学んでいきますが、今のところは、シンプルな道筋にとどまるために、指示を注意深く守ることが重要です。

リポジトリのセットアップ方法が分からない場合は、以下のステップに進む前に、Git Basicsにあるステップ1と2の指示に従って、その方法を学んでください:

  1. GitHub.com上でこのプロジェクト用の新しいリポジトリを作成し、odin-recipesという名前を付けてください。

  2. Git Basicsのレッスンで以前作成したreposフォルダの中に、そのリポジトリをローカルマシンにクローンしてください。コマンドはgit clone git@github.com:username/odin-recipes.gitのようになるはずです(SSHを使用してください)。

  3. 次に、ローカルマシン上にできたodin-recipesプロジェクトディレクトリにcdで移動してください。

  4. README.mdファイルをセットアップし、現在のプロジェクトが何であるか、そして完成させたときにどのようなスキルを示せているかについての簡単な紹介を書いてください。(これはプロジェクトの終わりに自己振り返りとして行うこともでき、学んだことを復習する良い方法になります。)

うまくいかない場合:

  • すべてのGitコマンドは、プロジェクトのフォルダ内から実行する必要があります(odin-recipesフォルダにcdで移動するのを忘れていませんか?)。

  • GitHubからSSHでクローンするために、SSHキーを作成する方法の手順に従ったか確認してください。

  • Git Basicsのレッスンにあるワークフローを参照してください。

いつコミットすべきかのヒント

Commit Messagesのレッスンで扱ったことをすべて忘れないでください!

プロジェクトを構築する際、git push origin mainでGitHubにプッシュする準備ができるまでに、おそらくgit add + git commitのサイクルを何度も行うことになるでしょう。

コードを書くとき、早めに、こまめにコミットすることがベストプラクティスとされています。コードに意味のある変更があるたびにコミットしてください。これにより、あなたの進捗のタイムラインが作られ、完成したコードが何もないところから突然現れたわけではないことが示されます。

git push origin mainを入力したら、ブラウザに切り替えてGitHub上のリポジトリを開いてください。プッシュしたばかりのすべてのファイルが表示されているはずです。

さて、Gitについてはこれで十分です---いよいよ実際に何かを作る時間です!

自分のプロジェクトを完成させる前に、他人の完成したプロジェクトコードを見ることについての警告

しかし先に進む前に:私たちのすべてのプロジェクトには、完成したコードやプロジェクトの実際のウェブサイトを投稿するための「Student Solutions(受講生の解答)」セクションが下部にあります。これらは、あなたが完成させたコードと比較したり、他の人がプロジェクトのコードやデザインでどのような別のルートを選んだかを見たりするために用意されています。

行き詰まったときやどこから始めればいいか分からないとき、解答を見たくなる誘惑があるのは承知していますが、それはしないでください!その理由をいくつか挙げます:

  • 投稿されたプロジェクトはすべて、他の学習者の解答です。つまり、それらは同じくまだ学習中の他の人々によって書かれたものであり、必ずしも「ベストプラクティス」や質の高いコードを代表しているとは限りません。
  • 解答を見ることは、問題解決力や調査力を伸ばす機会をあなたから奪ってしまいます。現実の世界では、参照できる「解答」が常にあるとは限らず、自分自身で編み出さなければなりません。
  • 同じ最終結果に到達する方法はたくさんあります---「万人に合う唯一の正解」というものはありません。
  • たとえ話をすると:「完成したコードを見てコーディングの仕方を学ぶのは、焼き上がったピザを見てピザ生地の作り方を学ぶようなものだ。」最終的な成果物だけを見て、そこに至るまでのプロセスを見ないと想像する以上に、実際にはもっと多くのことが関わっています。

プロジェクトを完成させたら、他の解答を自由に見て、プロジェクトの別の完成のさせ方を確認してみてください。

覗き見しないでください。私たちのDiscordサーバーに来て助けを求めましょう!(そのチャンネルを見るには、まずDiscordサーバーに参加する必要があります)。

課題

イテレーション1: 初期構造

  1. odin-recipesディレクトリ内に、index.htmlファイルを作成してください。
  2. いつものボイラープレートHTMLを記述し、bodyに「Odin Recipes」というh1見出しを追加してください。

イテレーション2: レシピページ

  1. odin-recipesディレクトリ内に新しいディレクトリを作成し、recipesという名前を付けてください。
  2. recipesディレクトリ内に新しいHTMLファイルを作成し、それが含むレシピにちなんだ名前を付けてください。例えばlasagna.htmlのようにです。自分の好きな料理の名前を使っても構いませんし、アイデアが必要な場合はAllrecipesで使えるレシピを見つけることもできます。いつものボイラープレートHTMLを必ず含めてください。このボイラープレートコードは、あなたが作成するすべての.htmlファイルに含まれているべきです。
  3. 今のところは、レシピの名前を内容とするh1見出しだけを含めてください。
  4. index.htmlファイルに戻って、先ほど作成したレシピページへのリンクを追加してください。例:<h1>Odin Recipes</h1>見出しの下に、次のようにリンクを書き出します:<a href="recipes/recipename.html">Recipe Title</a>。リンクのテキストは、やはりレシピの名前にしてください。

  5. ナビゲーションを簡単にするために、レシピページにindexページへのリンクを追加してください。このリンクは、レシピページ(例:lasagna.html)の上部か下部に配置できます。以下は例です:

    <a href="../index.html">Home</a>

    これにより、ユーザーはレシピを見た後、すばやくホームページに戻ることができます。

イテレーション3: レシピページのコンテンツ

新しいレシピページには、以下のコンテンツを含めるべきです:

  1. 先ほど追加したh1見出しの下に、完成した料理の無料画像を配置してください。

  2. 画像の下に、適切なサイズの「Description(説明)」見出しを配置し、その後にレシピを説明する1〜2段落を続けてください。

  3. 説明の下に、「Ingredients(材料)」見出しを追加し、その後にレシピに必要な材料の順序なしリストを続けてください。

  4. 最後に、材料リストの下に、「Steps(手順)」見出しを追加し、その後に料理を作るために必要な手順の順序ありリストを続けてください。

イテレーション4: レシピを追加する

  1. さらに2つのレシピページを作成してください。最初のレシピページとまったく同じレイアウトになるようにしてください。
  2. indexページに新しいレシピへのリンクを追加するのを忘れないでください。また、すべてのリンクが1行に並ばないよう、順序なしリストにまとめることも検討してください。

例:

 <ul>
    <li><a href="recipes/yourrecipe.html">Recipe Title 1</a></li>
    <li><a href="recipes/yourrecipe.html">Recipe Title 2</a></li>
    <li><a href="recipes/yourrecipe.html">Recipe Title 3</a></li>
  </ul>

あなたのリンクは派手にはなりませんが、今のところはそれらを組み立てることだけに集中してください。

ウェブ上でプロジェクトを表示する

自分の作品(プロジェクト)を他の人に見せたい場合や、以下で解答を提出したい場合は、あなたのサイトをローカルマシン上だけでなく、他の人がウェブからアクセスできるように公開する必要があります。良いニュースは、(上記で説明したように)プロジェクトをGitHubに置いているなら、これは簡単に行えるということです。

GitHubでは、GitHubリポジトリから直接ウェブプロジェクトを公開できます。これを行うと、your-github-username.github.io/your-github-repo-nameからあなたのプロジェクトにアクセスできるようになります。

プライベートリポジトリからの公開

プライベートリポジトリからウェブプロジェクトを公開するには、GitHubの有料アカウントが必要です。無料アカウントはパブリックリポジトリからのみ公開できます。

これを行う方法はいくつかありますが、最も簡単なのは次の方法です:

  1. メインのHTMLファイルがindex.htmlという名前であり、かつリポジトリのルート(最上位)ディレクトリに置かれていることを確認してください。
  2. ウェブ上であなたのGitHubリポジトリに移動し、下のスクリーンショットのようにSettingsボタンをクリックしてください。
  3. 左サイドバーのPagesをクリックしてください。
  4. Branchをnoneからmain branchに変更し、Saveをクリックしてください。
  5. 数分かかる場合があります(GitHubのウェブサイトには最大10分と書かれていますが、1時間かかるのを見たこともあります。プロジェクトに「theme」を追加しないでください。git競合が発生する可能性があります。代わりに辛抱強く待ってください。)が、あなたのプロジェクトはyour-github-username.github.io/your-github-repo-nameからウェブ上でアクセスできるようになるはずです(もちろん、リンク内はご自身の詳細に置き換えてください)。
  6. 1時間経ってもプロジェクトが公開されない場合は、リポジトリのルートにindex.htmlという名前のファイルがあること、そしてすべての設定が正しく行われていることを確認してください。GitHub上であなたのリポジトリに移動してActionsをクリックし、エントリが何もなければ、設定に戻ってBranchをmain branchからnoneに変更してSaveをクリックし、それからBranchをnoneからmain branchに戻してSaveをクリックしてください。

コミュニティからの提出作品

多くのコミュニティ提出作品にはスタイルが適用されている

今後のレッスンでは、CSSを学び、このプロジェクトにスタイルを追加します。コミュニティの提出作品を見ると、すでにこのスタイルを追加しているものが多いことに気づくでしょう。

(プロジェクトを完成させた後に)コミュニティの解答を見る際は、いくつかのことを心に留めておいてください:

  • 学習者は、ポートフォリオのために古いプロジェクトを改善しようと後で見直すことがよくあります。
  • カリキュラムを始める前にすでにプログラミング経験がある人もいます。
  • プロジェクトの要件は時間の経過とともに変わることがあります。

自分を他人と比較するのではなく、プロジェクトの要件を満たすことに集中してください。コミュニティの提出作品は、さまざまなアプローチを見るのに役立ちますが、この段階であなたのプロジェクトが「どうあるべきか」を表しているわけではありません。

これは今後のプロジェクトにも当てはまります。詳しくは"Becoming a TOP Success Story"の「Learning Code」を読んでみてください。
