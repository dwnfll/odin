イントロダクション

Gitは非常に人気のあるバージョン管理システムです。TOPを通じてこのソフトウェアに非常に慣れ親しんでいくことになるので、今の時点で理解することにあまり心配しなくて大丈夫です。カリキュラムの後半には、Gitに焦点を当てたレッスンがたくさんあります。

GitHubは、優れたウェブインターフェースを通じて、Gitを使ってコードをアップロード、ホスティング、管理できるようにしてくれるサービスです。

GitHubとGitは名前が似ていますが、同じものではなく、同じ会社が作ったものでもありません。

GitとGitHubを設定する

  1. GitHub.comにアクセスして、アカウントを作成しましょう!アカウント設定の途中でメールアドレスを尋ねられます。これは実在するメールアドレスである必要があり、デフォルトではあなたの貢献を識別するために使用されます。プライバシーを気にする場合、あるいは単にメールアドレスを公開したくない場合は、サインイン後にEmail Settingsページで以下の2つのチェックボックスに必ずチェックを入れてください:

    これら2つのオプションを有効にしておくことで、GitやGitHubを使う際に個人のメールアドレスが誤って公開されてしまうのを防げます。

    Keep my email addresses privateオプションの下にメールアドレスが表示されていることにも気づくかもしれません。これはあなたの非公開GitHubメールアドレスです。これを使うつもりであれば、次のステップでGitを設定する際に必要になるので、今のうちにメモしておいてください。

    1. (任意) GitHubの二要素認証(2FA)を有効にしましょう。これは、ウェブサイトやアプリにログインする際に使われる追加のセキュリティ層です。2FAでは、ユーザー名とパスワードでログインした上で、自分だけが知っている、あるいはアクセスできる別の認証手段を提供する必要があります。

      GitHub 2FAのドキュメントにアクセスし、設定手順に従ってください。ステップ1では、時間ベースのワンタイムパスワード(TOTP)アプリであるGoogle Authenticatorをお勧めします。Google Account Helpにアクセスし、AndroidまたはiPhone & iPadをクリックして、ダウンロードとセットアップの手順に従ってください。

      2FAの認証情報やアカウント復旧コードへのアクセスを失った場合

      セキュリティ上の理由により、二要素認証の認証情報を失ったり、アカウント復旧手段へのアクセスを失ったりした場合、GitHubサポートは二要素認証が有効なアカウントへのアクセスを復元することができません。

  1. Gitが正しく機能するためには、ローカルのGitユーザー(あなた)をGitHubに結びつけられるよう、自分が誰であるかをGitに伝える必要があります。チームで作業する場合、これによって、誰が何をコミットしたか、各行のコードを誰がコミットしたかを他の人が確認できるようになります。

    以下のコマンドでGitを設定します。引用符の中には必ず自分自身の情報を入力してください(ただし引用符自体は残してください!)。GitHubでメールアドレスを非公開にすることを選んだ場合は、ステップ1で確認した特別な非公開GitHubメールアドレスを使用してください。

    git config --global user.name "Your Name"
git config --global user.email yourname@example.com

    例えば、GitHubでメールアドレスを非公開に設定した場合、2つ目のコマンドは次のようになります:

    git config --global user.email 123456789+odin@users.noreply.github.com # Remember to use your own private GitHub email here.

    GitHubは最近、新しいリポジトリのデフォルトブランチをmasterからmainに変更しました。以下のコマンドを使って、Gitのデフォルトブランチを変更してください:

    git config --global init.defaultBranch main

    正しく機能しているかを確認するために、以下のコマンドを入力し、出力があなたの名前とメールアドレスに一致しているか確認してください。

    git config --get user.name
git config --get user.email

    macOSユーザー向け

    以下の2つのコマンドを実行して、Finderでフォルダを見るときに自動的に作成される.DS_Storeファイルを無視するようGitに指示してください。.DS_Storeファイルはユーザーには見えず、そのフォルダのカスタム属性やメタデータ(サムネイルなど)を保持していますが、これを無視するようGitを設定していないと、うっとうしい.DS_Storeファイルがコミットに紛れ込んでしまいます。これらの各コマンドを、忘れずにターミナルにコピー&ペーストしてください。

    echo .DS_Store >> ~/.gitignore_global
git config --global core.excludesfile ~/.gitignore_global

  2. SSHキーを作成しましょう。これは暗号学的に安全な識別子です。あなたのマシンを識別するために使われる、とても長いパスワードのようなものです。GitHubはSSHキーを使うことで、毎回ユーザー名とパスワードを入力しなくてもリポジトリにアップロードできるようにしてくれます。

    複数のSSHキー

    The Odin Projectを始める前に、別のマシンですでにGitHubとのSSHキーペアをセットアップ済みの場合、GitHubではアカウントに複数のキーペアを関連付けることができます。この手順をもう一度実行するだけで、別のキーペアをセットアップしてGitHubに登録できます。

    まず、Ed25519アルゴリズムのSSHキーがすでにインストールされているかを確認する必要があります。以下をターミナルに入力し、出力を下の情報と照らし合わせて確認してください:

    ls ~/.ssh/id_ed25519.pub

    コンソールに「No such file or directory」というテキストを含むメッセージが表示された場合、まだEd25519 SSHキーを持っていないということなので、新しく作成する必要があります。そのようなメッセージがコンソールの出力に表示されなかった場合は、そのまま次のステップに進んで構いません。

    新しいSSHキーを作成するには、ターミナル内で以下のコマンドを実行してください。

    ssh-keygen -t ed25519

    生成されたキーの保存場所を尋ねられたら、そのままEnterを押してください。

    次に、パスフレーズを尋ねられます。このパスフレーズは、コンピューター上に保存される秘密のSSHキーを暗号化するために使われ、これらのキーを使ってSSHを利用するたびにこのパスフレーズを入力する必要があります。パスフレーズを使わない場合、あなたのコンピューターにアクセスできる人なら誰でもその秘密鍵を読み取ることができ、あなたのすべてのGitHubリポジトリを変更できるようになってしまいます。希望する場合は入力してください。必須ではありません。パスフレーズを使わないことを選ぶ場合は、何も入力せずにそのままEnterを押してください。

  3. さて、毎回パスワードを入力せずにコードをプッシュできるように、あなたのSSHキーが何であるかをGitHubに伝える必要があります。

    まず、GitHubがSSHキーを受け取る場所に移動します。GitHubにログインし、右上のプロフィール画像をクリックしてください。それから、ドロップダウンメニューの中のSettingsをクリックします。

    次に、左側にあるSSH and GPG keysをクリックします。それから、右上にあるNew SSH Keyという緑色のボタンをクリックしてください。このSSHキーがどのデバイスのものか思い出せるよう、分かりやすい名前を付けましょう。例えばlinux-ubuntuなどです。次のステップを行う間、このウィンドウは開いたままにしておいてください。

    次に、公開SSHキーをコピーする必要があります。そのために、ファイルの内容をコンソールに読み出すcatというコマンドを使います。(この場合、.pubという拡張子が重要であることに注意してください。)

    cat ~/.ssh/id_ed25519.pub

    コマンドの出力全体を選択してコピーしてください。上記の手順に従っていれば、出力はおそらくssh-ed25519で始まり、あなたのusername@hostnameで終わっているはずです。

    では、ブラウザウィンドウでGitHubに戻り、コピーしたキーをキー欄に貼り付けてください。キーの種類はAuthentication Keyのままにして、Add SSH keyをクリックします。これで完了です!SSHキーの追加に成功しました!

  4. GitHubのSSH接続テストの手順に従って、キーをテストしてください。ターミナルに表示されるフィンガープリントの出力が、GitHubの4つの公開フィンガープリントのいずれかと一致することを確認してください。

    ターミナルには次のような応答が表示されるはずです: Hi username! You've successfully authenticated, but GitHub does not provide shell access. GitHubがシェルアクセスを提供しないことを気にする必要はありません。このメッセージが表示されれば、SSHキーの追加に成功しており、先に進んで構いません。出力が正しく一致しない場合は、これらの手順をもう一度試すか、私たちのDiscordサーバーに来て助けを求めてください。

これで完了です!

どうだったか教えてください!基本的なインストールのセクションを完了しました。よくやりました!カリキュラムを進めていく中で、他にもインストールすべきツールが出てくるので、注意しておいてください!
