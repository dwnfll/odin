CSSのカスケード

時には互いに競合するルールがあり、予期しない結果になってしまうことがあります。「でもこの段落は青にしたかったのに、なんで他の段落と同じ赤色になっているの?!」これはもどかしいことですが、CSSが私たちの意図に反して勝手に何かをするわけではないということを理解しておくのが重要です。CSSは私たちが指示したことしか行いません。この例外の一つが、ブラウザによって提供されるデフォルトのスタイルです。これらのデフォルトスタイルはブラウザによって異なり、一部の要素が他の要素との間に大きな「隙間」を作ったり、そのようにスタイルするCSSルールを書いていないにもかかわらずボタンがあのような見た目になっていたりする理由です。

そのため、このような予期しない動作に遭遇した場合、それはこれらのデフォルトスタイルのせいか、あるプロパティの働き方を理解していないせいか、あるいはカスケードと呼ばれるこの小さな存在を理解していないせいのいずれかです。

カスケードとは、実際にどのルールが私たちのHTMLに適用されるかを決定するものです。カスケードがこれを決定するために使用する要因にはいくつかの種類があります。ここではそのうち3つの要因を検討していきます。これによって、「CSSなんて大嫌い」というもどかしい瞬間を避ける助けになれば幸いです。

詳細度

より詳細度の高いCSS宣言は、詳細度の低いものよりも優先されます。前のレッスンで扱ったインラインスタイルは、セレクタと比較して最も高い詳細度を持ち、それぞれのタイプのセレクタは、宣言がどれだけ詳細であるかに寄与する独自の詳細度レベルを持っています。他のセレクタも詳細度に寄与しますが、ここではこれまでに扱ったものだけに焦点を当てます:

  1. IDセレクタ(最も詳細度の高いセレクタ)
  2. クラスセレクタ
  3. タイプセレクタ

詳細度は、ある要素を対象とする複数の競合する宣言がある場合にのみ、いわばタイブレーカーのような形で考慮されます。IDセレクタは、いくつのクラスセレクタに対しても常に勝ちます。クラスセレクタは、いくつのタイプセレクタに対しても常に勝ちます。そして、タイプセレクタは、それより詳細度の低いどんなセレクタに対しても常に勝ちます。詳細度の比較で勝敗が決まらない場合は、同じカテゴリ(ID、クラス、またはタイプセレクタ)内のセレクタの数を比較します。セレクタの数が多いルールが優先されます。

詳細度がどのように機能するかを視覚的に理解するために、いくつかの簡単な例を見てみましょう。 以下のHTMLとCSSのコードを考えてみてください:

<!-- index.html -->

<div class="main">
  <div class="list subsection">Red text</div>
</div>
/* rule 1 */
.subsection {
  color: blue;
}

/* rule 2 */
.main .list {
  color: red;
}

上記の例では、両方のルールがクラスセレクタのみを使用していますが、ルール2はより多くのクラスセレクタを使用しているためより詳細度が高く、color: red宣言が優先されます。

では、少し内容を変えてみましょう:

<!-- index.html -->

<div class="main">
  <div class="list" id="subsection">Blue text</div>
</div>
/* rule 1 */
#subsection {
  color: blue;
}

/* rule 2 */
.main .list {
  color: red;
}

上記の例では、ルール2の方がルール1よりも多くのクラスセレクタを持っているにもかかわらず、IDはクラスに勝つため、ルール1の方が詳細度が高くなります。この場合、color: blue宣言が優先されます。

そして、もう少し複雑な例です:

<!-- index.html -->

<div class="main">
  <div class="list" id="subsection">Red text on yellow background</div>
</div>
/* rule 1 */
#subsection {
  background-color: yellow;
  color: blue;
}

/* rule 2 */
.main #subsection {
 color: red;
}

この最後の例では、最初のルールはIDセレクタを使用しており、2つ目のルールはIDセレクタとクラスセレクタを組み合わせています。そのため、どちらのルールも、もう一方より詳細度の高いセレクタを使用しているわけではありません。そこでカスケードは、各セレクタタイプの数を確認します。両方のルールとも、IDセレクタは1つずつしかありませんが、ルール2にはIDセレクタに加えてクラスセレクタもあるため、ルール2の方が詳細度が高くなります!

color: red宣言が優先される一方で、background-color: yellow宣言についてはそれと競合する宣言がないため、そのまま適用されます。

すべてが詳細度に加算されるわけではない

セレクタを比較していると、ユニバーサルセレクタ(*)や、結合子(+、~、>、そして空白)といった特殊な記号に出くわすことがあります。まだ見たことのないものについては、カリキュラムの後半で扱うので、今はまだ深く掘り下げる必要はありません。核心となる考え方は、これらの記号は本質的に追加の詳細度を伝えるものではないということです。

/* rule 1 */
.class.second-class {
  font-size: 12px;
}

/* rule 2 */
.class .second-class {
  font-size: 24px;
}

ここでは、ルール1とルール2はどちらも同じ詳細度を持っています。ルール1はチェインセレクタ(スペースなし)を使用し、ルール2は子孫結合子(空白)を使用しています。しかし、どちらのルールも2つのクラスを持っており、結合子の記号自体は詳細度に加算されません。

/* rule 1 */
.class.second-class {
  font-size: 12px;
}

/* rule 2 */
.class > .second-class {
  font-size: 24px;
}

この例も同じことを示しています。ルール2が子結合子(>)を使用しているにもかかわらず、これは詳細度の値を変えません。どちらのルールも2つのクラスを持っているため、同じ詳細度の値になります。

/* rule 1 */
* {
    color: black;
}

/* rule 2 */
h1 {
  color: orange;
}

この例では、ルール2の方が詳細度が高く、この要素についてはorangeという値が優先されます。ルール2は最も低い詳細度の値を持つタイプセレクタを使用しています。しかし、ルール1は詳細度の値を持たないユニバーサルセレクタ(*)を使用しています。

継承

継承とは、ある要素に適用された特定のCSSプロパティが、その子孫に対して明示的にルールを書いていなくても、その要素の子孫に継承されることを指します。タイポグラフィ関連のプロパティ(color、font-size、font-familyなど)は通常継承されますが、他のほとんどのプロパティは継承されません。あるプロパティが継承されるかどうかは、MDNのそのプロパティのドキュメントを開き、Formal Definition(正式な定義)セクションを見ることで確認できます。例えば、CSSのcolorプロパティの正式な定義ではcolorが継承されるプロパティであることが示されており、一方displayプロパティの正式な定義ではdisplayが継承されないことが示されています。

この例外となるのは、要素を直接対象とする場合です。これは常に継承に勝ちます:

<!-- index.html -->

<div id="parent">
  <div class="child"></div>
</div>
/* styles.css */

#parent {
  color: red;
}

.child {
  color: blue;
}

parent要素がIDによってより高い詳細度を持っているにもかかわらず、child要素にはcolor: blueスタイルが適用されます。その宣言がchild要素を直接対象としているのに対し、親からのcolor: redは継承されているだけだからです。

ルールの順序

最後の要因、行き着く先、タイブレーカーの中のタイブレーカーです。他のすべての要因が考慮された後でも、ある要素を対象とする複数の競合するルールがまだ残っているとしましょう。カスケードはどのルールを適用するかをどうやって決めるのでしょうか?

最後に定義されたルールが勝者になります。

/* styles.css */

.alert {
  color: red;
}

.warning {
  color: yellow;
}

alertクラスとwarningクラスの両方を持つ要素の場合、カスケードは継承(ここでは該当なし)や詳細度(どちらのルールももう一方より詳細というわけではない)を含む他のすべての要因を確認していきます。.warningルールが最後に定義されたものであり、他のどの要因もどちらのルールを適用すべきかを決められなかったため、この要素にはこちらが適用されることになります。
