Problem Solving 日本語訳

In this lesson we will explore how to approach solving programming problems.

イントロダクション

かなり洗練されたJavaScriptに掘り下げていく前に、問題解決について話し始める必要があります。これは開発者が必要とする最も重要なスキルです。

問題解決は、ソフトウェア開発者が行うことの核心です。彼らが使うプログラミング言語やツールは、この基本的なスキルに対して二の次です。

著書『Think Like a Programmer』の中で、V. Anton Spraulはプログラミングにおける問題解決を次のように定義しています:

問題解決とは、特定のタスクの集合を実行し、明示されたすべての制約を満たす、独自のプログラムを書くことである。

タスクの集合は、小さなコーディング演習を解くことから、Facebookのようなソーシャルネットワークサイトや、Googleのような検索エンジンを構築することまで多岐にわたります。それぞれの問題には独自の制約があります。例えば、高いパフォーマンスやスケーラビリティは、コーディング演習ではあまり重要でないかもしれませんが、毎日何十億もの検索クエリを処理する必要があるGoogleのようなアプリでは不可欠です。

新人プログラマーは、問題解決を身につけるのが最も難しいスキルだと感じることがよくあります。駆け出しのプログラマーが構文やプログラミングの概念をすらすらと学んでいくのに、いざ自分で何かをコーディングしようとすると、どこから始めればいいか分からず、テキストエディタをぼんやりと見つめてしまうことは珍しくありません。

問題解決能力を向上させる最良の方法は、たくさんのたくさんのプログラムを作ることで経験を積むことです。練習を積めば積むほど、現実世界の問題を解決する準備がより整っていきます。

このレッスンでは、問題解決のプロセスに役立てられるいくつかのテクニックを見ていきます。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • 問題解決プロセスの3つのステップを説明する。
  • 疑似コードとは何かを説明し、それを使って問題を解けるようになる。
  • 問題を小さな部分問題に分解できるようになる。

問題を理解する

問題を解決するための最初のステップは、その問題が正確に何であるかを理解することです。問題を理解していなければ、いつそれをうまく解決できたのかが分からず、間違った解決策に多くの時間を無駄にしてしまうかもしれません。

問題を明確に理解するために、それを紙に書き出し、自分にとって意味が通るまで平易な言葉で言い換え、役立つのであれば図を描いてみましょう。誰か他の人にその問題を平易な言葉で説明できるようになったとき、あなたはそれを理解しているのです。

計画を立てる

解決しようとしていることが分かったところで、まだコーディングに飛び込まないでください。まずはどうやってそれを解決するかを計画する時です。 このプロセスのこの段階で答えるべき質問のいくつかを挙げます:

  • あなたのプログラムにはユーザーインターフェースがありますか?それはどのような見た目になりますか?インターフェースにはどのような機能がありますか?これを紙にスケッチしてみましょう。
  • あなたのプログラムにはどのような入力がありますか?ユーザーがデータを入力するのか、それとも他の場所から入力を得るのですか?
  • 望ましい出力は何ですか?
  • 入力が与えられたとき、望ましい出力を返すために必要なステップは何ですか?

最後の質問は、問題を解決するためのアルゴリズムを書き出すところです。アルゴリズムは、特定の問題を解決するためのレシピだと考えることができます。それは、疑似コードでコンピューターが問題を解決するために取る必要のあるステップを定義します。

疑似コード

疑似コードとは、プログラムのロジックをコードの代わりに自然言語で書き出すことです。これは、あなたが立ち止まって、プログラムが問題を解決するために経なければならないステップをじっくり考える助けになります。

入力された数までのすべての数値を出力するプログラムの疑似コードが、どのようなものになるかの例を挙げます:

When the user inputs a number
Initialize a counter variable and set its value to zero
While counter is smaller than user inputted number increment the counter by one
Print the value of the counter variable

これは、疑似コードがどのようなものかを示すための基本的なプログラムです。課題にはさらに多くの疑似コードの例が含まれています。

分割統治

計画を立てる中で、あなたが解決しようとしている大きな問題のいくつかの部分問題を特定できているはずです。前のセクションで書き出したアルゴリズムの各ステップが部分問題です。最も小さい、あるいは最も単純なものを選び、そこからコーディングを始めましょう。

必要になるかもしれないすべてのステップを前もって知っているとは限らないため、あなたのアルゴリズムは不完全かもしれない、ということを覚えておくのが重要です---それで構いません。計画段階で特定した部分問題の一つに取り組み、それを解決することで、次に取り組める部分問題が見えてくることがよくあります。あるいは、すでに次の部分問題が分かっている場合でも、最初の部分問題を解決しておくと、それがよりシンプルになることがよくあります。

多くの初心者は、大きな問題を一度に解決しようとします。これはやめてください。問題が十分に複雑であれば、自分自身をがんじがらめにしてしまい、物事をはるかに難しくしてしまいます。問題をより小さく、解決しやすい部分問題に分解することの方が、はるかに優れたアプローチです。分解は複雑さに対処するための主要な方法であり、問題を解決し理解しやすく、取り組みやすいものにしてくれます。

つまり、大きな問題を分解し、大きな問題を解決し終えるまで、それぞれの小さな問題を解いていくということです。

Fizz Buzzを解く

このワークフローが実際に動くところを示すために、Fizz Buzzを解いてみましょう。

問題を理解する

ユーザーの入力を受け取り、1からユーザーが入力した数までの数を出力するプログラムを書いてください。ただし、3の倍数についてはその数の代わりにFizzを、5の倍数についてはBuzzを出力してください。3と5の両方の倍数である数についてはFizzBuzzを出力してください。

これが、私たちが解決しようとしている大きな全体像の問題です。しかし、言い換えることで、常により明確にすることができます。

ユーザーが数を入力できるようにし、1からユーザーが入力した数までの各数を出力するプログラムを書いてください。ただし、3で割り切れる数については代わりにFizzを出力してください。5で割り切れる数についてはBuzzを出力し、最後に3と5の両方で割り切れる数についてはFizzBuzzを出力してください。

計画を立てる

あなたのプログラムにはインターフェースがありますか?それはどのような見た目になりますか? 私たちのFizzBuzzの解決策はブラウザのコンソールプログラムになるので、インターフェースは必要ありません。唯一のユーザーとのやり取りは、ユーザーが数を入力できるようにすることだけです。

あなたのプログラムにはどのような入力がありますか?ユーザーがデータを入力するのか、それとも他の場所から入力を得るのですか? ユーザーはプロンプト(ポップアップボックス)から数を入力します。

望ましい出力は何ですか? 望ましい出力は、1からユーザーが入力した数までの数のリストです。ただし、3で割り切れる各数はFizzを出力し、5で割り切れる各数はBuzzを出力し、3と5の両方で割り切れる各数はFizzBuzzを出力します。

疑似コードを書く

望ましい出力を返すために必要なステップは何ですか? この問題についての疑似コードによるアルゴリズムは以下の通りです:

When a user inputs a number
Loop from 1 to the entered number
If the current number is divisible by 3 then print "Fizz"
If the current number is divisible by 5 then print "Buzz"
If the current number is divisible by 3 and 5 then print "FizzBuzz"
Otherwise print the current number

分割統治する

私たちが作成したアルゴリズムから分かるように、最初に解決できる部分問題はユーザーから入力を得ることです。それでは、そこから始めて、入力された数を出力することでうまくいくか確認しましょう。

JavaScriptでは、「prompt」メソッドを使用します。

let answer = parseInt(prompt("Please enter the number you would like to FizzBuzz up to: "));

上記のコードは、ユーザーに数を尋ねる小さなポップアップボックスを作成するはずです。返ってきた入力は、私たちの変数answerに保存されます。

parseInt関数を使う

ユーザーの入力から数値が返されるように、prompt呼び出しをparseInt関数で包みました。

それができたら、次の部分問題に移りましょう:「1から入力された数までループする」。JavaScriptでこれを行う方法はたくさんあります。一般的な方法の一つ---実際にJava、C++、Rubyなど他の多くの言語で見られるもの---はforループを使うことです:

let answer = parseInt(prompt("Please enter the number you would like to FizzBuzz up to: "));

for (let i = 1; i <= answer; i++) {
  console.log(i);
}

これを見たことがなく、奇妙に見える場合でも、実際には単純です。私たちは変数iを宣言し、それに1を代入します。これがループにおける変数iの初期値です。2番目の節、i <= answerが私たちの条件です。iがanswerより大きくなるまでループしたいのです。3番目の節、i++は、ループに対して繰り返しごとにiを1ずつ増やすよう指示します。結果として、ユーザーが10を入力した場合、このループはコンソールに1から10までの数を出力します。

ループを1から始める

ほとんどの場合、プログラマーは0からループすることになります。私たちのプログラムのニーズにより、私たちは1から始めています。

それが動くようになったら、次の問題に移りましょう:現在の数が3で割り切れる場合、Fizzを出力する。

let answer = parseInt(prompt("Please enter the number you would like to FizzBuzz up to: "));

for (let i = 1; i <= answer; i++) {
  if (i % 3 === 0) {
    console.log("Fizz");
  } else {
    console.log(i);
  }
}

ここでは、現在の数を3で割るために剰余演算子(%)を使用しています。前のレッスンを思い出すと、剰余演算子は除算の余りを返します。つまり、除算から余り0が返される場合、それは現在の数が3で割り切れることを意味します。

プログラムが形になり始めています。基本構造がすでに整っており、残りの部分問題はすでにある条件のバリエーションにすぎないので、最後のいくつかの部分問題は簡単に解決できるはずです。次のものに取り組みましょう:現在の数が5で割り切れる場合、Buzzを出力する。

let answer = parseInt(prompt("Please enter the number you would like to FizzBuzz up to: "));

for (let i = 1; i <= answer; i++) {
  if (i % 3 === 0) {
    console.log("Fizz");
  } else if (i % 5 === 0) {
    console.log("Buzz");
  } else {
    console.log(i);
  }
}

今プログラムを実行すると、ユーザーが10を入力した場合、次のような出力が見られるはずです:

プログラムを完成させるために、もう一つ解決すべき部分問題があります:現在の数が3と5の両方で割り切れる場合、FizzBuzzを出力する。

let answer = parseInt(prompt("Please enter the number you would like to FizzBuzz up to: "));

for (let i = 1; i <= answer; i++) {
  if (i % 3 === 0 && i % 5 === 0) {
    console.log("FizzBuzz");
  } else if (i % 3 === 0) {
    console.log("Fizz");
  } else if (i % 5 === 0) {
    console.log("Buzz");
  } else {
    console.log(i);
  }
}

動くようにするために、条件分岐を少し並べ替える必要がありました。最初の条件は、iが単に3で割り切れるかどうかを確認する代わりに、iが3と5の両方で割り切れるかどうかを確認するようになりました。これを行う必要があったのは、もし元のままにしておくと、最初の条件if (i % 3 === 0)が実行され、iが3で割り切れる場合にはFizzが出力され、たとえiが5でも割り切れたとしても、そのままイテレーションの次の数に進んでしまうからです。

条件if (i % 3 === 0 && i % 5 === 0)を最初に持ってくることで、else if条件で3または5それぞれで割り切れるかどうかを個別に確認する前に、iが3と5の両方で割り切れることを確認します。
