Understanding Errors 日本語訳

In this lesson we will learn how to read error messages and understand how to resolve them.

イントロダクション

エラーメッセージを読んで理解することは、開発者としての必須条件です。一見すると、多くの初心者はエラーメッセージから尻込みしてしまいます。なじみのない用語が含まれているために「怖く」、理解しにくいものに見えるからです。

しかし、エラーメッセージは開発者に知識の宝庫を提供してくれ、それを解決する方法について知る必要のあることをすべて教えてくれます!恐れることなくエラーメッセージや警告を解析できるようになれば、アプリケーションを効果的にデバッグし、他の人から有意義な助けを得て、エラーに直面したときに前進する力を自分自身に与えられるようになります。

レッスン概要

このセクションでは、このレッスンで学ぶトピックの概要を説明します。

  • JavaScriptのエラーの種類を少なくとも3つ挙げる。
  • エラーがどこから発生しているかを見つけるのに役立つ、エラーメッセージの2つの部分を特定する。
  • エラーを調査し解決する方法を理解できるようになる。

エラーの構造

エラーとは、JS言語に組み込まれたオブジェクトの一種であり、名前(型)とメッセージで構成されます。エラーには、そのエラーの原因となっているコードを特定し、なぜこのエラーが発生しているのかを判断し、エラーを解決するのに役立つ重要な情報が含まれています。

HTMLページにリンクされたscript.jsファイルに、以下のコードを書いたとしましょう:

const a = "Hello";
const b = "World";

console.log(c);

このコードは実行されますが、エラーを発生させます。専門用語では、これはエラーを「スロー(throw)」すると呼ばれます。エラーの最初の部分は、エラーの種類を表示します。これは、あなたが何に対処しているのかについての最初の手がかりを与えてくれます。さまざまなエラーの種類については、このレッスンの後半で詳しく学びます。この例では、ReferenceErrorが発生しています。

ReferenceErrorは、現在のスコープ内で宣言および/または初期化されていない変数を参照したときにスローされます。私たちのケースでは、エラーメッセージはc is not defined(cは定義されていません)が原因でエラーが発生したことを説明しています。

このタイプのさまざまなエラーは、何がReferenceErrorを引き起こしているかに応じて異なるメッセージを持ちます。例えば、遭遇するかもしれない別のメッセージにはReferenceError: can't access lexical declaration 'X' before initializationがあります。

見て分かる通り、これは上記の元のReferenceErrorとはまったく異なる理由を指し示しています。エラーの種類とエラーメッセージの両方を理解することが、なぜそのエラーを受け取っているのかを理解する上で極めて重要です。

エラーの次の部分は、エラーが見つかるファイルの名前(この場合は私たちのscript.js)と、行番号を教えてくれます。

これにより、コード内の問題のある行に簡単に移動できます。ここでは、エラーはscript.jsの4行目から発生しており、これはエラーメッセージの下にat script.js:4というテキストのリンクとして表示されます。このリンクをクリックすると、ほとんどのブラウザは開発者ツールのSourcesタブで、コードの正確な行とスクリプトの残りの部分に移動します。

ブラウザのコンソールは、エラーが発生している行の中の列(または文字)も表示することがあります。私たちの例では、これはat script.js:4:13になります。

エラーのもう一つの重要な部分はスタックトレースです。これは、アプリケーション内でいつエラーがスローされたのか、そしてエラーに至るまでにどの関数が呼び出されたのかを理解するのに役立ちます。例えば、以下のコードがあるとしましょう:

const a = 5;
const b = 10;

function add() {
  return c;
}

function print() {
  add();
}

print();

私たちの関数print()はadd()を呼び出すはずで、add()はcという名前の変数を返しますが、これは現時点で宣言されていません。対応するエラーは以下の通りです:

スタックトレースは、以下のことを教えてくれます:

  1. add()のスコープ内でc is not defined(cは定義されていません)であり、add()は5行目で宣言されている。
  2. add()は9行目で宣言されているprint()によって呼び出された。
  3. print()自体は12行目で呼び出された。

つまり、スタックトレースを使うことで、エラーの経緯をその発生源まで遡ることができ、ここではそれがadd()の宣言です。

よくあるエラーの種類

これらは、あなたが遭遇することになる最も一般的なエラーのいくつかなので、理解しておくことが重要です。

構文エラー

構文エラーは、実行しようとしているコードが正しく、つまりJavaScriptの文法規則に従って書かれていない場合に発生します。例えば、次のようなコードです:

function helloWorld() {
  console.log "Hello World!"
}

これは以下のエラーをスローします。console.log()のかっこを忘れているからです!

参照エラー

このレッスンの最初の例で参照エラーを扱いましたが、これらは、参照しようとしている変数が(現在のスコープ内に)存在しない、あるいはスペルが間違っているために発生する、ということを覚えておくのが重要です!

型エラー

これらのエラーは、いくつかの異なる理由でスローされます:

MDNによると、TypeErrorは以下の場合にスローされることがあります:

  • 演算子や関数に渡されたオペランドや引数が、その演算子や関数が期待する型と互換性がない場合。
  • 変更できない値を変更しようとした場合。
  • 値を不適切な方法で使用しようとした場合。

以下のように、1つのメッセージを作るために結合したい2つの文字列があるとしましょう:

const str1 = "Hello";
const str2 = "World!";
const message = str1.push(str2);

ここでは、str1.push is not a functionというメッセージを伴うTypeErrorが発生します。これはよくあるエラーメッセージで、学習者を混乱させます。なぜなら、.push()が確かに関数であることを知っているかもしれないからです(例えば、以前配列に項目を追加するために使ったことがあれば)。

しかし、それがポイントなのです---.push()はStringメソッドではなく、Arrayメソッドです。したがって、Stringメソッドとして見つけられる「関数ではない」ということになります。.push()を、適切なStringメソッドである.concat()に変更すれば、私たちのコードは意図通りに動作します!

TypeErrorに直面したときに心に留めておくべき良い注意点は、メソッドや操作を実行しようとしているデータ型について考えることです。おそらく、それがあなたの思っているものではないか、あるいはその操作やメソッドがその型と互換性がないことに気づくでしょう。

エラーを解決するためのヒント

この時点で、これらのエラーをどう解決すればよいのか疑問に思っているかもしれません。

  1. まず、エラーメッセージはあなたの敵ではなく味方であると理解することから始められます。エラーメッセージは、あなたのコードの何が間違っているのか、そしてエラーの原因を見つけるためにどの行を調べるべきかを正確に教えてくれます。エラーメッセージがなければ、コードをデバッグするのは悪夢でしょう---なぜなら、それでも動かないままなのに、なぜなのか分からないからです!
  2. さあ、エラーをGoogleで検索する時です!おそらく、StackOverflowやドキュメントで修正方法や説明を見つけられるでしょう。それ以外にも、なぜこのエラーを受け取っているのかについて、より明確に分かるようになります。
  3. デバッガーを使いましょう!前述の通り、デバッガーはより複雑なトラブルシューティングに最適であり、開発者にとって重要なツールです。ブレークポイントを設定したり、アプリケーションの実行中の任意の時点で任意の変数の値を確認したり、コードを1行ずつステップ実行したりなど、さまざまなことができます!これは非常に価値のあるツールであり、すべてのプログラマーがその使い方を知っておくべきです。
  4. コンソールを活用しましょう!console.log()はすばやいデバッグのための人気の選択肢です。より複雑なトラブルシューティングにはデバッガーを使う方が適切かもしれませんが、console.log()を使うのは、関数をステップ実行することなくすぐにフィードバックを得るのに最適です。console.table()やconsole.trace()など、他にも便利なメソッドがあります!

エラーと警告

最後に、多くの人は警告に遭遇すると、それをエラーとして扱ってしまいます。エラーは、あなたのプログラムや実行しようとしている何らかのプロセスの実行を止め、それ以上の動作を妨げます。一方、警告は、実行時に必ずしもプログラムをクラッシュさせるとは限らない、あるいはまったくクラッシュさせない潜在的な問題についての洞察を与えてくれるメッセージです!

可能であれば、できるだけ早くこれらの警告に対処すべきですが、警告はエラーほど重大ではなく、情報提供的なものである可能性が高いです。警告は通常黄色で表示され、エラーは通常赤色で表示されます。これらの色は決まりというわけではありませんが、どのプラットフォームで遭遇するかにかかわらず、この2つの間には頻繁に視覚的な区別があります。

課題

  1. さあ、ドキュメントに目を通す時です!MDNドキュメントからReferenceError、SyntaxError、TypeErrorについて詳しく学びましょう。今すぐすべてのドキュメントを完全に理解する必要はありません。目標は、概念に慣れ親しむことです。例では「try...catch」文が使われており、これは「try」ブロック内のコードを実行します。エラーが発生した場合、それは自動的に「catch」ブロックによって捕捉されます。これにより、スクリプトを終了させてしまう前にエラーに対処でき、「catch」ブロック内でそれらを適切に処理できるようになります。今のところは、「try...catch」文が存在すること、そしてカリキュラムを進めていく中でそれが役立つようになることだけを覚えておいてください。

  2. 「What went wrong? Troubleshooting JavaScript」に取り組んでみましょう。意図的なエラーが含まれているスターターコードを必ずダウンロードしてください。
